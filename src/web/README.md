# src/web — пульт продукта CrewHarness

Страница в браузере в три колонки: список сессий (поиск, закреплённые, проекты), разговор с агентом (ответ обычным
текстом, рабочие строки свёрнуты, карточка правок, поле ввода) и сведения о сессии (окружение, контекст, результаты,
фоновые задачи). Светлая и тёмная темы. Обычный HTML, CSS и JavaScript-модули, **без фреймворка, без npm, без сборки**.
Страница живёт либо на потоке событий-заглушке (`?mock=1`), либо на настоящем сервере по сокету `/ws`
([`src/server/`](../server/README.md), задание 099): список сессий, создание, разговор, запросы разрешения и отмена хода идут через него.
Задания: [093](../../doc/tasks/093-console-skeleton/task/message.md) (скелет),
[094](../../doc/tasks/094-console-claude-layout/task/message.md) (раскладка и стиль).

## Раскладка

| Колонка | Что в ней |
|---|---|
| Левая (264 px) | заголовок «Сессии» и переключатель темы; поиск по названию; «Новая сессия» (форма: агент, название, проект); группы «Закреплённые» и по проектам (заголовок группы серым, справа «+» — новая сессия в этом проекте); сессия — строка с точкой состояния (отвечает, ждёт разрешения, отказ, ошибка, отмена), кнопка закрепления; дочерние сессии с отступом и уголком; активная подсвечена; внизу статус соединения |
| Центр | верхняя полоса: название сессии, агент, состояние, кнопка правой колонки; лента разговора колонкой до 800 px: сообщение владельца — серая плашка справа, ответ агента — обычный текст (абзацы, списки, `код` в строке и блоки кода), рабочие строки, карточка «Изменено файлов», под ответом копирование и «N мин назад», идущая работа — строка с точками и таймером; поле ввода с подсказкой, «Отмена хода» и «Отправить»; рядом — клавиатурная подсказка и индикатор контекста; слот модели в шапке добавляет задача 131 |
| Правая (288 px) | карточки: «Окружение» (проект, папка, ветка, агент), «Контекст» (процент, полоска, красная от 90 %; заголовок сворачивается), «Результаты» (файлы с видом `create`/`edit`/`delete`, «Показать ещё»), «Фоновые задачи» (название, время, значок состояния, «Показать ещё», «Завершено: N») |

**Рабочие строки.** Вызовы инструментов, запросы разрешений (после решения они остаются строкой) и фоновые команды,
идущие подряд, сворачиваются в одну серую строку-сводку («Выполнено действий: 3 · с ошибкой: 1», а для одной
записи — её описание); клик (или Enter и пробел на кнопке, `aria-expanded`) раскрывает подробности. Текст ответа до
и после инструмента делится по номеру шага, а не по порядку прибытия.

**Ширина.** От 1101 px три колонки, правую можно свернуть кнопкой в верхней полосе. До 1100 px правая колонка скрыта
и выезжает поверх разговора по той же кнопке. Меньше 800 px список и разговор показываются по одному («К сессиям»
возвращает к списку). Горизонтальной прокрутки нет.

## Темы

Светлая (тёплая нейтральная) — по умолчанию, тёмная — той же формы. Переключатель в левой колонке по кругу: как в
системе → светлая → тёмная. «Как в системе» следует `prefers-color-scheme`; выбор запоминается в `localStorage`
(ключ `crew-console-theme`, внешних запросов нет; закрытое хранилище страницу не ломает). `theme.js` ставит выбор на
`<html data-theme>` до первой отрисовки, чтобы не мигала чужая тема. Токены цветов — переменные в `app.css`
(тёмные значения заданы дважды: для системы и для ручного выбора; их равенство и контраст текста и фона не ниже
4,5:1 проверяет `test/theme.test.mjs`). Подложка центральной области — `--center`: белая в светлой теме, в тёмной
равна `--bg` (проверяет `test/center.test.mjs`). Цели нажатия не меньше 40 px (`--hit`).

Значки — свои простые контуры в одном файле-спрайте `icons.svg` (`<use href="icons.svg#i-имя">`), цвет — от темы.

## Как открыть

Без сервера продукта, на заглушке:

    node src/web/serve.mjs            # печатает адрес: http://localhost:8093/?mock=1

Откройте напечатанный адрес. `serve.mjs` — крошечная раздача файлов на `127.0.0.1` (нужна, потому что браузеры не
грузят модули со страницы `file://`; без `?mock=1` страница ждёт сокет `/ws` и показывает «Подключение…», а из
файла пишет, что сервера нет). Сервис продукта позже будет отдавать эти же файлы сам.

В заглушке четыре готовых сессии (закреплённая, идущая дочерняя с красным контекстом, отказ, ошибка) и три
сценария ответа на любое ваше сообщение:

- обычное сообщение — ответ кусками и строка работы, пока идёт; в это время доступна кнопка «Отмена хода»; контекст растёт;
- сообщение со словами «тест», «прогон», «собери», «проверь», «отчёт» — ответ с несколькими вызовами инструментов,
  фоновой командой, обновлением контекста, результатами-файлами и карточкой правок на три файла;
- сообщение со словами «файл», «удали», «команда», «запусти», «разреши» — агент просит разрешения; диалог
  «Разрешить / Отклонить» показывает действие и саму команду (многострочная — целиком, в прокручиваемом блоке):
  «Разрешить» — продолжение и ответ, «Отклонить» — отказ агента.

Времена готовых сессий сдвигаются к моменту открытия страницы (последнее событие — за 5 секунд до него), поэтому
«N мин назад» и таймер идущей работы живые.

С настоящим сервером (сессии, агент, хранилище): соберите и запустите `crew-harness serve` из обычного окна с консолью,
откройте `http://127.0.0.1:8099/` (адрес и порт — в настройках) без `?mock=1` ([`src/server/README.md`](../server/README.md), «Run»).
Страница ничего не хранит: при подключении сервер присылает по сессии один массив событий — всю историю из журнала, дальше —
каждое новое событие всем подключённым страницам; перезагрузка страницы, второе окно и перезапуск службы видят одно и то же.
Идентификатор сессии (`trace`) задаёт страница при создании; код хода (`turn`) сервер ставит свой — id события движка с
сообщением владельца (`input-3`); `id` события — `<сессия>/<id движка>`. Если агент не запустился, сервер шлёт событие `error`
(его нет в журнале).

## Формат события

Событие самодостаточно, пульт его только рисует. Поля:

| Поле | Что |
|---|---|
| `id` | строка, уникальна; повтор с тем же `id` игнорируется |
| `trace` | цепочка событий; для пульта — id сессии |
| `step` | целое от 0, номер шага в цепочке; куски ответа склеиваются в порядке `step`, а не прибытия |
| `kind` | вид (ниже) |
| `input` | объект с данными вида |
| `time` | миллисекунды эпохи |

Виды и их `input`:

| `kind` | `input` | Что делает с видом |
|---|---|---|
| `session_created` | `{ name, agent }` | заводит сессию, состояние «Ожидает» |
| `session_model` | `{ model, model_id?, models?, effort?, effort_name?, efforts?, mode?, modes? }` | заменяет явно сообщённое имя модели; пустое значение — «Модель не сообщена», событие с устаревшим `step` игнорируется. Списки — то, что агент отдал выбрать (задача 192): под полем ввода кнопка режима слева и кнопка «модель + усилие» справа, меню вверх с галочкой и номерами-клавишами; выбор страница отправляет событием `session_setting` `{ setting, value }` и ждёт нового `session_model`; нет списка — кнопки нет |
| `user_message` | `{ turn, text }` | сообщение владельца; состояние «Отвечает» |
| `agent_chunk` | `{ turn, text }` | кусок ответа; запоздалый после отмены, отказа или конца игнорируется |
| `agent_done` | `{ turn }` | ход закончен, «Ожидает» |
| `agent_refused` | `{ turn, reason }` | отказ агента, «Отказ» |
| `permission_request` | `{ turn, request, action, detail }` | открывает диалог, «Ждёт разрешения» |
| `permission_decision` | `{ request, decision }` | `decision` — `allow` или `deny`; закрывает диалог |
| `cancel` | `{ turn }` | «Ход отменён»; закрывает диалог |
| `error` | `{ turn, message }` | ошибка, «Ошибка» |
| `usage_update` | `{ used, size, cost? }` | занятость окна контекста; `cost` — число или `{ amount, currency }`; негодное (`size` не больше 0, `used` меньше 0) и более старое по `step` пропускается |
| `tool_call` | `{ id, title, kind, status, turn?, detail? }` | вызов инструмента; `kind` — `read`/`edit`/`delete`/`move`/`search`/`execute`/`think`/`fetch`/`other` (неизвестный — `other`), `status` — `pending`/`in_progress`/`completed`/`failed` (неизвестный — `pending`); без `id` пропускается; повтор `id` игнорируется |
| `tool_call_update` | `{ id, status?, detail? }` | меняет состояние и подробности; чужой `id`, мусорное состояние и событие старше последнего обновления (по `step`) пропускаются |
| `output_file` | `{ path, kind }` | файл-результат; `kind` — `create`/`edit`/`delete` (неизвестный — `edit`); список без повторов по пути, «создан, затем правлен» остаётся «создан» |
| `file_diff` | `{ path, added, removed, turn? }` | строка карточки «Изменено файлов»: добавлено и убрано строк (не числа — ноль); повтор пути заменяет запись |
| `background_task` | `{ id, title, status, started, turn? }` | фоновая команда; `status` — `running`/`completed`/`failed`/`stopped` (неизвестный — `running`); `started` — миллисекунды эпохи (нет — время события); повтор `id` игнорируется |
| `background_task_update` | `{ id, status }` | новое состояние; чужой `id` и мусорное состояние пропускаются |

`session_created` может нести необязательные `project`, `folder`, `branch`, `parent` (id сессии-родителя) и `pinned`.
`turn` у `tool_call`, `file_diff` и `background_task` необязателен: без него событие относится к последнему ходу. Отмена хода
(`cancel`) снимает идущие инструменты (`cancelled`) и фоновые команды хода (`stopped`).

`turn` — код хода: его задаёт владелец в `user_message`, остальные события хода его повторяют. Событие чужой
цепочки без `session_created` и неизвестный `kind` игнорируются.

Пример потока:

    {"id":"a1","trace":"s1","step":0,"kind":"session_created","input":{"name":"Проба","agent":"opencode"},"time":1792314000000}
    {"id":"a2","trace":"s1","step":1,"kind":"user_message","input":{"turn":"t1","text":"Привет"},"time":1792314001000}
    {"id":"a3","trace":"s1","step":3,"kind":"agent_chunk","input":{"turn":"t1","text":"мир"},"time":1792314001600}
    {"id":"a4","trace":"s1","step":2,"kind":"agent_chunk","input":{"turn":"t1","text":"Привет, "},"time":1792314001300}
    {"id":"a5","trace":"s1","step":4,"kind":"agent_done","input":{"turn":"t1"},"time":1792314002000}

Ответ агента здесь — «Привет, мир»: шаг 2 стоит перед шагом 3, хотя пришёл позже.

По `/ws` событие идёт JSON-ом: одно или массив. Решения владельца (`session_created`, `user_message`, `cancel`,
`permission_decision`) страница отправляет теми же событиями, но у себя их не применяет: оно появляется на экране,
когда сервер вернёт его в потоке (заглушка делает то же самое).

### Соответствие `Event` из движка (задача 091)

Движок (`src/engine/types.nv` задачи 091) называет событие так: `Event { id, trace, step, kind: EventKind, name,
request: Option[str], input: str, at }`. Формат страницы — его проекция; расхождения, которые закрывает
сервер при отправке в `/ws` (или тонкий адаптер на странице):

| Страница | Движок | Расхождение |
|---|---|---|
| `id` | `id` | движок выдаёт `"<класс>-<номер>"`; странице всё равно, нужна уникальность |
| `trace` | `trace` | то же |
| `step` | `step` | то же |
| `kind` (`user_message`, `agent_chunk`…) | `name` | у движка `kind` — **класс** (`Input`, `Progress`, `Answered`, `Refused`, `Expired`), у страницы `kind` — **имя** события |
| — | `kind` | класс странице не нужен: он выводится из имени |
| `input` (объект) | `input` (строка) | сервер кладёт в строку JSON, страница ждёт объект |
| `input.turn`, `input.request` | `request: Option[str]` | у движка `request` — id запроса, на который отвечает событие; страница держит его в `input` |
| `time` | `at` | то же значение, другое имя |

Видов, которых у движка нет: `session_created`, `permission_request`, `permission_decision`, `error` — они
возникают при подключении к ACP и доске сессий; их место в машине состояний решается в следующих задачах.

## Правила страницы

- **Нет встроенного кода.** Страницу отдаёт сервис целиком с запретом встроенных `<style>` и `<script>` (CSP);
  страница со встроенным блоком пуста. Стили, скрипт — отдельные файлы.
- **Нет внешних ресурсов.** Ни CDN, ни шрифтов, ни картинок с чужих адресов; шрифты системные.
- Все локальные `href`, `src`, `url()` и импорты модулей указывают на существующие файлы; все `var(--x)` определены.
- **Никакой разметки из данных.** Текст события попадает в DOM только как текст (`textContent`); `innerHTML` и родня
  в модулях запрещены. Ответ показывается как текст с переносами и блоками кода (```` ``` ````); Markdown — отдельной
  задачей.
- Все надписи — из `strings.js`; в `index.html` видимого текста нет.

## Проверки

Из корня репозитория:

    node --test "src/web/test/*.test.mjs"

Кавычки нужны: Node 24 принимает маску, но не папку (`node --test src/web/test/` ищет файл с таким именем и падает).

- `work.test.mjs` — новые виды событий (инструменты, контекст, файлы, правки, фоновые задачи): повтор `id`, мусор, устаревшие обновления, отмена, чужая цепочка;
- `list.test.mjs` — фильтр и группировка списка сессий, лента разговора по шагам, абзацы и код в строке, подписи времени и чисел, цикл темы (всё без DOM);
- `theme.test.mjs` — контраст текста и фона не ниже 4,5:1 в обеих темах, равенство двух блоков тёмной темы, нет цветов вне токенов;
- `center.test.mjs` — центральная подложка: `--center` белый в светлой теме, в тёмной равен `--bg`, применён на
  центральную область, боковая панель остаётся на `--side`;
- `state.test.mjs` — редьюсер чист и детерминирован; куски по номерам шагов; дубль события не ломает вид; отмена,
  отказ, ошибка; диалог разрешения открывается и закрывается решением; безопасное разбиение текста;
- `mock.test.mjs` — заготовленный журнал (закреплённая, дочерняя, красный контекст, правки, фоновые задачи) и три сценария заглушки складываются в нужные виды;
- `transport.test.mjs` — выбор режима, заглушка с отменой, сокет с обратным отсчётом повтора (поддельные таймеры
  и сокет);
- `strings.test.mjs` — каждый ключ `strings.js` использован, каждый `t('ключ')` существует, все значения по-русски,
  в `index.html` нет видимого текста;
- `page.test.mjs` — проверка страницы (`test/page-check.mjs`, аналог `check-page.py` образца): внешних ссылок нет,
  встроенного кода нет, локальные ссылки существуют, переменные определены, тёмная тема есть, нет `innerHTML`,
  `icons.svg` найден и каждый значок `'i-имя'` из модулей в нём есть, в файлах страницы нет имени образца.
  Красные пробы вшиты в тесты: переименовать файл, убрать переменную, добавить внешнюю ссылку, встроенный блок
  или `innerHTML` — проверка краснеет. Руками: `node src/web/test/page-check.mjs`.
