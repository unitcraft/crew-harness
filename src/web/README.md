# src/web — пульт продукта CrewHarness (скелет страницы)

Страница в браузере: список сессий, чат с агентом, запрос разрешения, строка статуса. Обычный HTML, CSS и
JavaScript-модули, **без фреймворка, без npm, без сборки** (по образцу страницы `claude-limits`). Сейчас
страница живёт на потоке событий-заглушке; настоящий сервер (`/ws`) и агент подключаются следующими задачами.
Задание: [message.md](../../doc/tasks/093-console-skeleton/task/message.md).

## Как открыть

Без сервера продукта, на заглушке:

    node src/web/serve.mjs            # печатает адрес: http://localhost:8093/?mock=1

Откройте напечатанный адрес. `serve.mjs` — крошечная раздача файлов на `127.0.0.1` (нужна, потому что браузеры не
грузят модули со страницы `file://`; без `?mock=1` страница ждёт сокет `/ws` и показывает «Подключение…», а из
файла пишет, что сервера нет). Сервис продукта позже будет отдавать эти же файлы сам.

В заглушке два готовых разговора и два сценария ответа на любое ваше сообщение:

- обычное сообщение — ответ кусками и «Агент отвечает…», пока идёт; в это время доступна кнопка «Отмена хода»;
- сообщение со словами «файл», «удали», «команда», «запусти», «разреши» — агент просит разрешения; диалог
  «Разрешить / Отклонить»: «Разрешить» — продолжение и ответ, «Отклонить» — отказ агента.

Светлая и тёмная темы выбираются системой (`prefers-color-scheme`).

## Формат события

Событие самодостаточно, пульт его только рисует. Поля:

| Поле | Что |
|---|---|
| `id` | строка, уникальна; повтор с тем же `id` игнорируется |
| `trace` | цепочка событий; для пульта — id сессии |
| `step` | целое от 0, номер шага в цепочке; куски ответа склеиваются в порядке `step`, а не прибытия |
| `kind` | вид (ниже) |
| `input` | объект с данными вида |
| `time` | миллисекунды эпохи |

Виды и их `input`:

| `kind` | `input` | Что делает с видом |
|---|---|---|
| `session_created` | `{ name, agent }` | заводит сессию, состояние «Ожидает» |
| `user_message` | `{ turn, text }` | сообщение владельца; состояние «Отвечает» |
| `agent_chunk` | `{ turn, text }` | кусок ответа; запоздалый после отмены, отказа или конца игнорируется |
| `agent_done` | `{ turn }` | ход закончен, «Ожидает» |
| `agent_refused` | `{ turn, reason }` | отказ агента, «Отказ» |
| `permission_request` | `{ turn, request, action, detail }` | открывает диалог, «Ждёт разрешения» |
| `permission_decision` | `{ request, decision }` | `decision` — `allow` или `deny`; закрывает диалог |
| `cancel` | `{ turn }` | «Ход отменён»; закрывает диалог |
| `error` | `{ turn, message }` | ошибка, «Ошибка» |

`turn` — код хода: его задаёт владелец в `user_message`, остальные события хода его повторяют. Событие чужой
цепочки без `session_created` и неизвестный `kind` игнорируются.

Пример потока:

    {"id":"a1","trace":"s1","step":0,"kind":"session_created","input":{"name":"Проба","agent":"opencode"},"time":1792314000000}
    {"id":"a2","trace":"s1","step":1,"kind":"user_message","input":{"turn":"t1","text":"Привет"},"time":1792314001000}
    {"id":"a3","trace":"s1","step":3,"kind":"agent_chunk","input":{"turn":"t1","text":"мир"},"time":1792314001600}
    {"id":"a4","trace":"s1","step":2,"kind":"agent_chunk","input":{"turn":"t1","text":"Привет, "},"time":1792314001300}
    {"id":"a5","trace":"s1","step":4,"kind":"agent_done","input":{"turn":"t1"},"time":1792314002000}

Ответ агента здесь — «Привет, мир»: шаг 2 стоит перед шагом 3, хотя пришёл позже.

По `/ws` событие идёт JSON-ом: одно или массив. Решения владельца (`session_created`, `user_message`, `cancel`,
`permission_decision`) страница отправляет теми же событиями, но у себя их не применяет: оно появляется на экране,
когда сервер вернёт его в потоке (заглушка делает то же самое).

### Соответствие `Event` из движка (задача 091)

Движок (`src/engine/types.nv` задачи 091) называет событие так: `Event { id, trace, step, kind: EventKind, name,
request: Option[str], input: str, at }`. Формат страницы — его проекция; расхождения, которые закрывает
сервер при отправке в `/ws` (или тонкий адаптер на странице):

| Страница | Движок | Расхождение |
|---|---|---|
| `id` | `id` | движок выдаёт `"<класс>-<номер>"`; странице всё равно, нужна уникальность |
| `trace` | `trace` | то же |
| `step` | `step` | то же |
| `kind` (`user_message`, `agent_chunk`…) | `name` | у движка `kind` — **класс** (`Input`, `Progress`, `Answered`, `Refused`, `Expired`), у страницы `kind` — **имя** события |
| — | `kind` | класс странице не нужен: он выводится из имени |
| `input` (объект) | `input` (строка) | сервер кладёт в строку JSON, страница ждёт объект |
| `input.turn`, `input.request` | `request: Option[str]` | у движка `request` — id запроса, на который отвечает событие; страница держит его в `input` |
| `time` | `at` | то же значение, другое имя |

Видов, которых у движка нет: `session_created`, `permission_request`, `permission_decision`, `error` — они
возникают при подключении к ACP и доске сессий; их место в машине состояний решается в следующих задачах.

## Правила страницы

- **Нет встроенного кода.** Страницу отдаёт сервис целиком с запретом встроенных `<style>` и `<script>` (CSP);
  страница со встроенным блоком пуста. Стили, скрипт — отдельные файлы.
- **Нет внешних ресурсов.** Ни CDN, ни шрифтов, ни картинок с чужих адресов; шрифты системные.
- Все локальные `href`, `src`, `url()` и импорты модулей указывают на существующие файлы; все `var(--x)` определены.
- **Никакой разметки из данных.** Текст события попадает в DOM только как текст (`textContent`); `innerHTML` и родня
  в модулях запрещены. Ответ показывается как текст с переносами и блоками кода (```` ``` ````); Markdown — отдельной
  задачей.
- Все надписи — из `strings.js`; в `index.html` видимого текста нет.

## Проверки

Из корня репозитория:

    node --test "src/web/test/*.test.mjs"

Кавычки нужны: Node 24 принимает маску, но не папку (`node --test src/web/test/` ищет файл с таким именем и падает).

- `state.test.mjs` — редьюсер чист и детерминирован; куски по номерам шагов; дубль события не ломает вид; отмена,
  отказ, ошибка; диалог разрешения открывается и закрывается решением; безопасное разбиение текста;
- `mock.test.mjs` — заготовленный журнал и оба сценария заглушки складываются в нужные виды;
- `transport.test.mjs` — выбор режима, заглушка с отменой, сокет с обратным отсчётом повтора (поддельные таймеры
  и сокет);
- `strings.test.mjs` — каждый ключ `strings.js` использован, каждый `t('ключ')` существует, все значения по-русски,
  в `index.html` нет видимого текста;
- `page.test.mjs` — проверка страницы (`test/page-check.mjs`, аналог `check-page.py` образца): внешних ссылок нет,
  встроенного кода нет, локальные ссылки существуют, переменные определены, тёмная тема есть, нет `innerHTML`.
  Красные пробы вшиты в тесты: переименовать файл, убрать переменную, добавить внешнюю ссылку, встроенный блок
  или `innerHTML` — проверка краснеет. Руками: `node src/web/test/page-check.mjs`.
