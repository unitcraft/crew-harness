# Задание: /crew — минимум текста, подписи на английском

Заказчик: владелец репозитория `unitcraft/crew-harness` (он же отвечает на вопросы и принимает результат).
Репозиторий: `unitcraft/crew-harness`, ветка `main`. Дата задания: 2026-10-17.
Источник: 2026-10-17 владелец при разборе вопроса о переводе текстов плагина на `owner_language` (открытый вопрос #2, `doc/open-questions.md`)
сказал: «в /crew нужно уменьшить количество текста до минимума, оставшийся сделай на анг., общается crew должен на моем языке». Экран
`/crew` (`formatStatuses` в `opencode-plugin/status.ts`) сейчас длинный: заголовок «ВАС ЖДУТ: …», абзацы про «вопрос устарел: к … с … (…)»,
планы, строки «не убрана N ч», строки шагов приёмки, пояснения, русские названия состояний, видов сессий и шагов. Обычный словарь строк на
каждый язык не нужен: подписи интерфейса станут английскими и короткими, а содержимое, которое пишут вкладки и владелец (названия
задач, вопросы, варианты, письма), остаётся на языке владельца, как есть.

Задача полная: разбор, реализация, сдача. Быстрый путь. Основа — свежий `origin/main`.

## Что нужно

1. **Разбор:** что выводит `/crew` сейчас по строкам (`formatStatuses`, `planLines`, `uncleanedLines`, `acceptanceReports`, `waitingLine`,
   блоки «ВАС ЖДУТ», вопросы, «вопрос устарел», «ждёт», шаги, лимиты, ошибки конфигурации, разное); откуда каждая строка; что из этого
   действительно нужно владельцу на экране «кто чего ждёт», а что служебное или дублирует панель; соответствие «было → где теперь».
2. **Минимальный экран.** По проекту: заголовок (название проекта), строки только по существу: кто ждёт владельца (с вопросом как есть),
   затем вкладки и задачи — значок, номер и название задачи как есть, роль и состояние одним коротким английским словом, время ожидания
   (`since`), для сессий задач с папкой — код и вид сессии (`С2-5 spec review`). Не больше одной строки на вкладку (строка состояния
   вопроса владельцу — отдельная). Всё остальное (устаревшие вопросы, планы, неочищенные задачи, отчёты приёмки, ошибки настроек,
   «лимиты», пояснения) — либо одна короткая строка-счётчик («+2 plans · 1 uncleaned · /plans»), либо уходит в свои команды
   (`/plans`, `/ask`, `/crew-doctor`, `/crew-progress`); ничего из сведений не теряется — указывается, где теперь доступно.
3. **Подписи — на английском и одним источником.** Один перечень слов состояний и видов сессий (`STATE_WORDS`, `SESSION_KIND` — рядом со
   словами панели, `progress.ts`): waiting you / question / working / watch / reply / idle / done и т. п.; виды сессий по-английски (spec,
   spec fix, spec review, plan, plan fix, plan review, work, work review, delivery …) — по перечню методики. Содержимое от вкладок и
   владельца (названия задач, текст вопроса и вариантов, письма, фразы ожидания) не переводится и не сокращается за пределами одной строки
   на вкладку. Слова панели Crew (боковая) этой задачей не меняются — только `/crew`; если общий перечень слов используется панелью,
   панельные слова остаются прежними, а английский перечень — отдельный для `/crew` (решение в разборе, без поломки панели 068).
4. **Язык общения.** Текст вопросов, писем и отчётов вкладок владельцу — на `owner_language` (уже так: настройка проекта и подсказка
   вкладок); проверить в разборе, что `/crew` ничего не подменяет, и записать это в README плагина.
5. **Тесты:** красная проба до кода (снимок `/crew` на живом наборе вкладок: ожидающий владельца, работающая, наблюдение, задача без папки, с
   папкой, неочищенная, с планом; проверка «ни одного русского слова вне содержимого вкладок» — по списку кириллицы в подписях; не больше
   N строк на вкладку); полный `npm test` по 8 параллельно ([AGENTS.md](../../../../AGENTS.md), п. 9); golden — только изменившиеся ключи.
6. README плагина — абзац о `/crew` (минимальный экран, где искать остальное).
