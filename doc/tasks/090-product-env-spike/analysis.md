## 4. Что не работает или расходится (для интегратора Nova)

1. `--toolchain msvc` не собирает даже hello: `error C2099` в сгенерированном `hello.c` (константа инициализируется другой константой: `FLOAT_POW5_INV_BITCOUNT`, `FLOAT_POW5_BITCOUNT`); `auto` выбирает Clang и проходит.
2. Документация и пример Polaris (`docs/websocket.md`, `examples/08-websocket-echo`) пишут `mut w = sock` и `w.close(...)`: Oracle 0.1.0 отвергает (`E_VIEW_BINDING_FORBIDDEN`, D180; `D157-consume-via-view`); компилируется `consume w = sock` (воспроизведение — `repro_mut_binding/`).
3. Пример polaris `examples/08` зависит от `path = "../.."`, Oracle 0.1.0 отвергает такую зависимость (`E_DEP_PATH_OUTSIDE_REPO`).
4. Квикстарт называет архив `nova-v0.1.0-windows-x64.zip`, настоящее имя `nova-oracle-0.1.0-windows-x86_64.zip`.
5. `setup-env.ps1` печатает русский текст кракозябрами в Windows PowerShell 5.1 (файл UTF-8 без BOM).
6. `nova check` и `nova build` печатают десятки предупреждений линтера зависимости `compress` (`[new-then-cap]`, 49 штук): ошибки теряются.
7. Кэш рантайма пишется на уровень выше распакованной папки, libuv пересобирается в каждом проекте (25–30 с холодной сборки).
8. Не Нова: в Node 24 на Windows `process.exit()` сразу после закрытия WebSocket падает с `Assertion failed: !(handle->flags & UV_HANDLE_CLOSING)`; скрипт проверки использует `process.exitCode`.

## 5. Пригодность для первого среза

Оценка исполнителя и оркестратора: **готово, блокеров нет**: дочерний процесс по каналам, сервер, WebSocket и ACP-ответ работают на Oracle 0.1.0 на Windows с Clang; нужны обходы (собирать Clang, писать `consume w = sock`, фильтровать шум линтера).
Риски, которые нужно проверить следующими задачами: одновременная работа `Proc` и WebSocket в одном процессе (чтение ответов агента в отдельной fiber и раздача по `/ws`), построчный JSON-RPC с накоплением буфера, закрытие дочернего процесса при обрыве вкладки,
парсинг и сериализация JSON (`std.encoding`, serde-атрибуты), кириллица и UTF-8 в потоках.

Порядок следующих задач: (1) каркас движка стейт-машин и самодостаточных событий на Нове с `nova test`; (2) ACP-клиент поверх `Proc` (`initialize`, `session/new`, `session/prompt`, поток `session/update`, построчный JSON-RPC), на заглушке-агенте и на `opencode acp` до `authenticate`;
(3) сервер сессий: `Router` и WebSocket, соединяющий вкладку с ACP-клиентом, страница-пульт, закрытие по обрыву вкладки; (4) сквозная проба с реальным агентом после решения владельца по входу.
