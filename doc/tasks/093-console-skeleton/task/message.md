# Задание: пульт продукта CrewHarness — скелет страницы в браузере на потоке событий-заглушке

Заказчик: владелец репозитория `unitcraft/crew-harness` (он же принимает результат).
Репозиторий: `unitcraft/crew-harness`, ветка `main`. Дата задания: 2026-10-18.
Эпик: [001-crew-service](../../001-crew-service/) (REQ-32 пульт в браузере: страницу отдаёт сервис на `localhost`, пульт не хранит состояние, только показывает и передаёт решения; ADR-0005); третья дочерняя задача этапа «продукт на Нове»
(090 — разведка среды, 091 — каркас движка событий).
Источник: слова владельца в чате оркестратора, 2026-10-18: «в браузере иметь возможность открыть сессии и поговорить с агентом»; «на чём делать фронт для продукта?» — рекомендация: как в `claude-limits` (обычный HTML, CSS и JavaScript модулями, без фреймворка и сборки) — «заводи 3, делай быстрым способом»;
«в папке src делай, как обычно в claude-limits» (владелец назвал путь папки на своей машине).

Задача полная: разбор, реализация, сдача. Быстрый путь. Основа — свежий `origin/main`. Параллельно идут 091 (пакет Нова в корне, `src/engine/`) и 092 (плагин): эта задача трогает только `src/web/` и свои тесты, конфликтов с ними нет.

## Чего хочет владелец

- Фронт продукта — как у `claude-limits`: обычный HTML, CSS, JavaScript-модули, без фреймворков и сборки; все файлы страницы под `src/web/`.
- Первый срез: открыть сессию в браузере и поговорить с агентом. В этой задаче — скелет страницы на потоке событий-заглушке (реальный сервер и агент подставятся следующими задачами).
- Ядро продукта — движок событий: событие самодостаточное (вход → выход); страница рисует поток событий и передаёт решения владельца такими же событиями.

## Что нужно

1. **Образец.** Прочитать `claude-limits/src/web/` (соседний репозиторий владельца) (`README.md`, `index.html`, `app.css`, `app.js`, `format.js`, `live.js`) и `claude-limits/scripts/check-page.py` (только чтение). Перенять правила: страницу отдаёт бинарник целиком, поэтому **нет встроенных `<style>` и `<script>` (CSP)**, **нет внешних ресурсов** (ни CDN, ни шрифтов с внешних адресов, ни внешних картинок), все локальные `href`/`src` существуют, все `var(--x)` определены; чистая логика (без DOM) — в отдельных модулях и под тестами.
2. **Каталог `src/web/`:** `index.html`, `app.css` (переменные темы, светлая и тёмная по `prefers-color-scheme`), `app.js` (вход), `state.js` (чистый редьюсер: событие → модель вида, без DOM), `view.js` (рисование DOM по модели), `transport.js` (адаптер: WebSocket к `/ws` и воспроизведение заглушки по `?mock=1`), `mock.js` (заготовленные журналы событий), `strings.js` (все тексты интерфейса по-русски в одном файле, чтобы позже вынести в словарь),
   `README.md` (как открыть, как устроено, правила страницы). Без npm, без сборки.
3. **Формат события для страницы** — по методике и задаче 091 (самодостаточное): `{ id, trace, step, kind, input, time }`; виды минимума: `session_created`, `user_message`, `agent_chunk`, `agent_done`, `agent_refused`, `permission_request`, `permission_decision`, `cancel`, `error`. Описать форматом в `README.md` (поля, примеры); соответствие `Event` из 091 — таблицей, расхождения — в отчёт.
4. **Экраны:** (а) список сессий (имя, агент, состояние, время) и кнопка «Новая сессия» с выбором агента из списка заглушки (OpenCode, второй позже); (б) чат сессии: сообщение владельца, потоковый ответ агента кусками (без мерцания, прокрутка вниз, если владелец у конца), «Отмена хода» во время ответа, состояния (ожидает, отвечает, отказ, ошибка);
   (в) запрос разрешения агента — диалог «Разрешить / Отклонить» с описанием действия и записью решения событием; (г) строка статуса соединения (подключено, воспроизведение заглушки, разрыв, повтор через N с). Markdown в ответе — отдельной задачей (сейчас — безопасный текст с переносами и блоками кода, без HTML из потока: никакой вставки `innerHTML` из данных события).
5. **Заглушка:** `mock.js` отдаёт два сценария (обычный ответ кусками; ответ с запросом разрешения и отказом) с таймингами; воспроизводится по `?mock=1` без сервера (открыть `index.html` из файла или простым статическим сервером).
6. **Проверки (Node 24, без npm, `node --test src/web/test/`):** редьюсер чистый и детерминированный (два прогона — тот же вид); потоковые куски склеиваются в порядке номеров шагов и дубль события (тот же `id`) не ломает вид; отмена и отказ переводят состояние; диалог разрешения открывается и закрывается решением; тексты из `strings.js` — все ключи использованы; **проверка страницы** (аналог `check-page.py` на Node): внешних ссылок 0, встроенных блоков 0, локальные `href`/`src` существуют, все `var(--x)` определены (красная проба: переименовать файл или убрать переменную — проверка краснеет).
   Красная проба до кода: первый тест красный на пустом каркасе. UI-проверка: открыть страницу в браузере (если есть встроенный или локальный — иначе описать как проверить владельцу) и приложить описание, что видно.
7. **README и сдача:** README `src/web/`; в отчёте — команда запуска проверок, список файлов, что не вошло.

## Критерии приёмки

- `node --test src/web/test/` зелёный, красная проба до кода показана; проверка страницы зелёная и краснеет на нарушении.
- Страница открывается по `?mock=1` без сервера, показывает список сессий, чат с потоковым ответом, отмену, диалог разрешения, строку статуса; тексты по-русски из `strings.js`; светлая и тёмная темы.
- Нет `innerHTML` из данных событий, нет встроенных блоков, нет внешних ресурсов, нет npm и сборки.
- Только `src/web/` (и тесты в нём) и `doc/tasks/093-console-skeleton/` в коммите; стражи — 8 и больше, FAIL 0; коммит по правилам AGENTS.md (английское сообщение, `-s`, без `#число`).
