## Находки

1. Строка DNC-02 утверждает больше, чем ловит команда: «записи порога сжатия нет ни в одной форме». Команда ловит основные
   формы, но не все, и даёт ложные срабатывания на безобидной записи.
   Чем доказано (проба 3, временный репозиторий, ветка из 20 добавленных строк, шаблон дословно из плана, из корня и из
   подпапки одинаково):
   не находит запись `cfg.compaction!.reserved = 4`, `(cfg.compaction as any).reserved = 4`, `cfg.compaction.reserved += 4`,
   строковый ключ `"compaction.reserved": 5`, вызов `set(cfg, "compaction.reserved", 5)`, ключ через переменную, конец строки
   сразу после `=`;
   находит без записи порога: `const compaction = cfg.compaction ?? {}` (локальная переменная), `const { compaction = {} } =
   cfg` (значение по умолчанию при чтении), `a ? compaction : b`, шаблонную строку `compaction: ${n}` (этот случай план
   уже называет правилом про числа в сообщениях), поле интерфейса без знака вопроса.
   Основные формы (`x.compaction = N`, `x.compaction.reserved = N`, ключ в объекте и в начале строки, `{"compaction": N}`,
   `["compaction"]`, `["compaction"]["reserved"]`, `Object.assign(cfg, { compaction: ... })`, `fn({compaction:{...}})`)
   находятся все. Чтение, деструктуризация без значения по умолчанию, упоминание в комментарии и в тексте — пусто.
   Оценка: слишком узкой команда не стала (запись в файл окон закрывает вторая страховка — ячейка `DNC-02`, ключ `compaction`
   в содержимом файла, и сам код файла окон строит только `limit`); ложные срабатывания реализация снимает
   переименованием переменной. Поэтому поверхностная. Исправление одной фразой: вместо «ни в одной форме» писать «в основных
   формах (…); остальное — ячейка теста и просмотр diff», а переменную не называть `compaction`.
   критичность: поверхностная (тонкие формы записи; основной вид нарушения ловится, вторая страховка есть)
   уровень: план

2. Команда (3) AC-18 (`git ls-files -o --exclude-standard | xargs -r cat`) молча пропускает новые файлы, в имени которых
   есть пробел или не латинская буква: git печатает такое имя в кавычках с восьмеричными кодами, `cat` его не находит.
   Чем доказано: проба 5 — в новой папке файлы с пробелом и с кириллическим именем, в обоих строка с путём диска; команда
   вывела только ошибки `cat`, совпадений 0; форма `git ls-files -o -z --exclude-standard | xargs -0 -r cat` нашла оба
   файла. План сам называет новые файлы латиницей без пробелов (`profiles.ts`, `crew-profiles-*.test.mjs`), страж
   `guard-secrets.py --tree` обязательной парой смотрит все файлы, поэтому на этом плане пропуск не случится.
   Исправление: добавить `-z` и `-0`.
   критичность: поверхностная (имена файлов задаёт сам план; страж ловит)
   уровень: план
