2. **Проверка связей REQ-34 не определяет ни охват (все наборы или включённый), ни основу (закоммиченные данные со слоем или

   уровень: требования.

   («при командах окна») отказывает, а тот же объект через `crew_config set` отказывает по AC-39. Заодно «те же данные в файле
   при загрузке дают проблему REQ-33», хотя набор не включён и REQ-33 к нему не относится. (б) основа. REQ-34: «действующие

   рабочую копию (Ф-07); AC-39 при этом говорит «в том же вызове или в рабочей копии». Два вызова агента подряд (сначала

   Цитата: «В справочнике такие профили записать можно» (REQ-24); «отказ по проверке связей REQ-34 по объединённым данным …;
   те же данные в файле при загрузке дают проблему REQ-33» (AC-39).

4. **Файл окон «в корне проекта» не учитывает устройство основного проекта владельца: корень — не репозиторий, он накрывает

   владельца собственный проектный `.opencode/opencode.jsonc`») оставлен неизвестным. Проверено на настройках владельца (проба 7):
   (а) у основного проекта ключ `root` указывает на папку выше папки настроек (схема: «виртуальный проект из многих
   репозиториев»), и эта папка **не репозиторий git**: общего каталога git для `.git/info/exclude` у неё нет, спецификация для
   такого корня не говорит, что делать; (б) в том же корне лежит **рукописный** `.opencode/opencode.jsonc` с `limit` для
   `claude-code` opus и sonnet 520000 и haiku 220000 — он по Ф-11 сильнее файла плагина на том же уровне, поэтому окна Claude
   из профиля там не вступят в силу вообще, а числа стартового справочника (720000, глобальные) не равны действующим в этом
   проекте (520000); REQ-10 «было → стало» верно только если показывает действующие значения, а не поля профиля; (в) папка

   папки») это знает, но не делает вывода для места записи.

   затрагивается состоянием другого проекта (REQ-25)» (REQ-11).
