# Задание: дефекты замка вливания (номер задачи у держателя, снятие замка без сверки)

Заказчик и владелец: владелец репозитория `unitcraft/crew-harness` (он же отвечает на вопросы и принимает результат).
Репозиторий кода: `unitcraft/crew-harness` (https://github.com/unitcraft/crew-harness, ветка `main`). Дата задания: 2026-10-08.
Источник: разбор задачи 005 ([спецификация](../../005-faster-landing/spec.md), вопрос 6 и ответ владельца «по рекомендации»).

Задача полная: разбор, план, реализация, сдача. Начинается после слияния задачи 005 (правки замка пересекаются).

## Что есть сейчас (по разбору задачи 005)

- Замок вливания проекта помнит только сессию держателя. Тот же держатель при повторном `crew_task merge` для другой задачи
  молча меняет в замке номер задачи.
- Снятие замка (`releaseMergeLock`) не сверяет номер задачи: приёмщик, держащий замок для задачи A, при действии над задачей B
  снимает замок A.
- У проекта nova (`reviewer: acceptor`) дефект не проявляется: там у каждой задачи свой приёмщик и замок берётся для одной
  задачи за раз; проявляется там, где один приёмщик ведёт несколько задач (`reviewer: integrator`).

## Чего хочет владелец (его слова, 2026-10-08)

- «по рекомендации» на вопрос «завести ли отдельную задачу на дефекты замка» (рекомендация: да, потому что правка замка
  нарушает границу задачи 005, а у nova дефект не проявляется) и на порядок «после слияния 005».

## Что нужно

Замок знает, для какой задачи он взят; `merge` другой задачи тем же держателем отказывает с причиной; снятие замка сверяет
номер; поведение без новых флагов не ломает работающие проекты (есть флаг проекта, прежнее поведение по умолчанию либо явная
миграция — решает разбор).

## Что надо выяснить в разборе

- Какие пути вызывают `takeMergeLock` и `releaseMergeLock` (`merge`, `accept`, `rework`, `cancel`, `unlock` из задачи 005,
  брошенный замок) и что должно происходить в каждом при несовпадении номера.
- Что делать с уже существующими замками на диске при обновлении плагина.
- Тесты на гонки замка: держатели должны быть живыми (без карточки и задачи замок «перехватывают» все).
