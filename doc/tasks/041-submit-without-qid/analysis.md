# Разбор задачи 041: сдача явным действием `crew_task submit`

Дата: 2026-10-14. Задание — `task/message.md`. Быстрый путь, основа — ветка `quick-040`.

## 1. Где сдача завязана на `qid`

| Место | Что делает | Как с `submit` |
|---|---|---|
| `core.ts`, `crew_send`, блок «ОТЧЁТ ПО ЗАДАЧЕ» | `isReport` = `reply_to` совпал с `qid` своей задачи; отказ «уже отправлен», проверка файла и формы задачи-плана, `settleObligation`, `report`, `executor_role`, событие `submitted`, после доработки — `addObligation` приёмщику и `postExpected` (будит) | вынесено в одну функцию `submitTask` (замыкание плагина); `crew_send` вызывает её, когда `isReport`; `crew_task submit` — тоже |
| `crew_send`, письмо автору | тихое (`wake: false`) с `reply_to` | `submit` кладёт такое же письмо автору (`reply_to: qid`), `closeAskedByLetter`, `host.posted` |
| `crew_send`, `me.spawned` без задачи | закрывает карточку «вопрос порождённой сессии» | к задаче не относится, остаётся только в `reply_to`-пути |
| `expectedLetters` (`core.ts`) | письмо о доработке (`reworkLetter` в `review.ts`) и письмо приёмщику «Доработка сдана» по статусу | не зависят от пути сдачи: `submitTask` ставит тот же статус и текст |
| `index.ts`: напоминания и письмо о возобновлении | подсказывали ответ на `qid` | для задачи исполнителя называют `submit`, `reply_to` — запасной |
| письма задачи, задачи-плана, подталкивание (`push`) | подсказывали `reply_to` | `submit` основной, `reply_to` запасной |

Единственное отличие, снятое при выносе: раньше обязательство исполнителя снималось до проверки формы плана, то есть
отказ «Не сдано» оставлял его снятым. Теперь снимается после успешной проверки: отказавшая сдача не гасит напоминания.

## 2. Что видит интегратор

Как у старого пути: отчёт тихий (`wake: false`), приходит с его следующим ходом; приёмщика после доработки будит
`postExpected`. `submit` не будит автора.

## 3. Подсказки

- `crew_send`: исполнитель задачи в `starting`/`running`/`rework`, письмо без `reply_to` автору, приёмщику или интегратору
  (по ключу роли или по карточке-интегратору) — отправка как раньше, в ответе строка «Задача #N ещё не сдана … `crew_task submit`».
- `review` в `rework`/`running`: к отказу добавлено, что исполнитель не сдал, и его команда; запасной путь — `reply_to`.

## 4. Тексты

Письмо с задачей, письмо задачи-плана, письмо о доработке и синхронизации, подталкивание, напоминание и письмо
возобновления в `index.ts`, ответ `assign`, справка (`ПРИЁМКА`), описание `crew_task` (строка `submit - executor - n, text - …`,
действие в `enum`, описание `text`), README плагина, инструкции MCP-сервера.
