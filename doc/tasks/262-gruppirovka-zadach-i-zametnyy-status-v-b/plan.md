# План 262 — Группировка задач и заметный статус в боковой панели

## Диагноз

Панель (`sidebarLines` в `opencode-plugin/status.ts`, рисует `sidebar.tsx`) выводит вкладки одним списком по ORDER:
работающие задачи, приёмка, стоящие между ходами и простаивающие вкладки перемешаны; статус задачи у названия не
подписан — только значок вкладки. HOLD/STOP (записи сторожа шага, `idle-watch.ts` `Rec.hold`) в панели не видны
вовсе, только в /crew: задача под HOLD со старой карточкой «working» выглядит работающей.

## Решение

Только отрисовка панели: `sidebarLines` (status.ts) + экспорт `holdsOf` из idle-watch.ts. Рисунок (sidebar.tsx) не
меняется.

1. Секции после блока «Ждут вас»: вкладки без задачи (не idle) → «В работе · N» → «На приёмке · N» → «Пауза · N» →
   idle-вкладки без задачи → «HOLD/STOP · N» → служебные строки как раньше → foot без изменений.
2. Классификация группы задачи: HOLD/STOP — по записи сторожа (`holdsOf`: метка + открытая задача) — старше всего,
   вкладки такой задачи скрыты, одна строка на задачу «■ NNN HOLD · название»; иначе есть вкладка в state working —
   «В работе»; иначе статус задачи submitted/reviewing — «На приёмке»; иначе — «Пауза».
3. Заголовок задачи: `<значок> <NNN> <слово> · <название>`; слово и значок: «нужен ответ» (вкладка owner/question,
   значок markOf вкладки, тон accent) > «в работе» («•») > «на приёмке» («✓») > «принята» («✓», accepted) >
   «пауза» («‖»); у задачи с папкой — без значка, как раньше. Символ всегда со словом (текстовая альтернатива цвету).
4. Порядок детерминирован: внутри секции сначала группы «нужен ответ», затем по номеру задачи; порядок не зависит от
   порядка входного списка. Бюджет SIDE_MAX=9 вкладок сохраняется (срез собранного порядка), счётчик секции — число
   реально показанных групп (+ свёрнутые группы задач с папкой, они вне бюджета, как раньше); скрытые срезом — в foot «+N».
5. Строка вкладки стоящей задачи со статусом running — «стоит», а не «в работе» (WORD_OF_TASK.running): без хода
   (state working) слова «работает/в работе» не пишем.
