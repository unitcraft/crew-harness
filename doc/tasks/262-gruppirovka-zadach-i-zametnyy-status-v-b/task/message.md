## Что нужно

1. Минимально улучшить боковую панель плагина OpenCode: активные задачи наверху отдельным блоком «В работе · N», далее «На приёмке», задачи HOLD/STOP отдельно ниже компактно (сворачивать только если поддерживается существующим UI без широкой переделки). Явный статус непосредственно у номера/названия задачи, с текстом и символом, не только цветом. Главная цель: владелец сразу видит реально выполняющиеся задачи, они не теряются среди пауз и служебных пояснений. Не расширять до всех пяти предложенных улучшений: согласованы группировка и явный статус у названия. Сначала красные тесты. Изучить фактический API панели и текущие источники данных, не угадывать возможности OpenCode. Новая выделенная сессия и отдельное дерево.

## Критерии приёмки

1. Активные задачи группируются выше приёмки и HOLD/STOP, порядок детерминирован, счётчики соответствуют реально показанным задачам. 2. У названия различимы работа/приёмка/нужен ответ/пауза; HOLD/STOP не выдаются за активную работу даже если старая карточка имеет статус in_progress. 3. Статус задачи не смешан с активностью процесса: без подтверждения running не писать «сейчас работает»; очередь/ожидание использовать только из проверенных данных, не выводить из давности письма. 4. Узкая панель сохраняет номер и статус, Unicode/цвет имеют текстовую альтернативу, длинные названия не скрывают статус. 5. Регрессионные тесты рендера/сортировки/счётчиков и полного плагина, стражи через machine queue, независимая приёмка. 6. Отчёт exact SHA, команды, результаты, необходимость применения/перезапуска.
