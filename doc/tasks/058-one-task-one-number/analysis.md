# Разбор 058: одна задача — один номер

Коротко: путаницу даёт не слово, а два счётчика. Плагин считает свои записи `#N` и в проекте crew-harness заводит
запись на каждую сессию методики (С1, С2, С4…), а папка `doc/tasks/NNN-…` — одна на задачу. Слово «поручение» в
плагине почти не встречается: его придумали агенты, чтобы отличить `#N` от `NNN`. Уберём второй счётчик — слово
станет не нужно.

## 1. Где живёт номер сейчас

| Что | Где | Как устроено |
|---|---|---|

Папки видны только в одном каталоге: папки из неслитых веток счёт не видит (044) |
| Номер папки `NNN` | `doc/tasks/NNN-<slug>/` | выбирают руками; плагин его только читает (`docTaskNumbers`, панель «Ход работ» — `progress-scan.ts`); каталог `doc/tasks` вписан в код, настройки проекта для него нет |
| Номер плана | `plans_dir` (по умолчанию `docs/plans`), `TaskPlan.n` | третий номер — у задач-планов (Нова: `#88 «план 274.16: …»`); задача 058 его не трогает |

Слово «поручение»: в коде плагина — один комментарий (`tasks.ts`, о временном фиксе 044); в Каноне, README,
описаниях инструментов и тестах его нет. Оно живёт в речи интегратора и оркестратора и в документах задач (`log.md`
папки 045, задания 033, 035, 044, 058). Плагин во всём, что видит владелец, уже говорит «задача #N» — и называет так
и задачу-папку, и одну сессию. Путаница — в двух значениях одного слова при двух номерах.

## 2. Записи задач и приёмка

- Запись `tasks/<проект>/<N>.json` — одна на номер: исполнитель (`executor`, прежние — `executors`, попытка —
  `attempt`), приёмщик (`reviewer`, `review_kind`, `reviewers`), статус, дерево и ветка, отчёт, шаги приёмки,
  предпроверка и замок вливания, история.
- **Приёмщик — не отдельная запись**: он в той же записи, его сессия называется `#N прм`. Но в crew-harness почти
  каждая запись — сессия методики, и у каждой своя приёмка плагина: проверочная сессия С2 (#23) сдавалась и
  принималась плагинным приёмщиком, хотя проверкой по методике была она сама. Приёмка удваивается.
- `reassign` передаёт запись новой сессии под тем же номером (`attempt` растёт, письмо — `task-<проект>-<N>-<попытка>`).
- `order` — запись-заказ другому проекту (`parent: "проект#N"` у задачи исполнителя) — ссылка по номеру, работает
  при любом способе нумерации.

## 3. Как ведутся сессии методики сейчас (папка 045, ручной цикл)

Данные службы (только чтение): в проекте crew-harness 25 записей, из них 23 — сессии методики с кодом в названии
(«С2: проверка спецификации задачи 013, заход 2», «С4-3: проверка исправленного плана, папка 045»). Работа папки 045
шла двумя способами сразу:

- **сессия — новая запись:** #23 (С2), #50 (С4, заход 2), #57 (С4-3) — у каждой своё дерево и ветка
  (`task/50-s4-plan-…`, `review/045-s4-3`) и своя приёмка плагина;
- **сессия — передача записи:** #22 — С1, продолжение С1, С3, С3п: `reassign` три раза (попытка 4, прежних
  исполнителей 3).

Номер запуска уже есть — по методике: интегратор пишет в `progress.log` строку `С4 0/0 [время] запуск №3` и запись
`пуск` в `log.md` («запуск №1 С4 … поручения Crew #50», «запуск №2 С3п … в поручении Crew #22», «запуск №3 С4 …
предметный заход 3»). Номер запуска сквозной в задаче; заход — свой у каждого кода проверки (С4: заходы 1, 2, 3). У
раннера методики тот же номер — `state.launches` (`task-runner.md`, «Строки progress.log»). Идентификатор сессии
внутри задачи у методики уже есть; плагин его не знает и выдаёт свой `#N`.

Номера пересекаются: записи #22, #23, #50, #57 — сессии задачи 045, а папки 022, 023, 050, 057 — другие задачи.

## 5. Что из этого следует для проекта

1. Номер задачи в проекте с папками — номер папки; запись плагина получает тот же номер. Сессии — внутри записи,
   их идентификатор — номер запуска методики (`№n`), для чтения — код и его порядковый номер (`С4-3`).
2. Папку заводит тот, кто выдаёт номер, иначе гонка. Счёт должен видеть папки во всех деревьях и ветках, а агент вне
   OpenCode — брать номер тем же способом.
3. Писать папку в основную копию `main` нельзя (`AGENTS.md`, пп. 3 и 11): папка заводится в дереве задачи на её
   ветке и попадает в `main` на первых воротах — так уже делается руками (коммит `d8fc423` этой задачи).
4. Приёмка плагина — у задачи один раз (вливание её ветки), а не у каждой сессии; проверки методики — сами сессии.
5. Слово «поручение» уходит само, когда второго номера нет; Канон фиксирует слова «задача» и «сессия задачи».
6. Пересекаются: 053 (строка `запуск`, `journal.ts`, `progress.ts`) — плагин сам пишет строку `запуск №n`; 057
   (`reassign` с текстом) — передача сессии. Шаг 2 идёт после их слияния или сводит места с их ветками.
