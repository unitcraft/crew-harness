# 058 — Одна задача — один номер

## Цель

Владелец видит один номер на одну работу: в проекте с папками задач номер задачи — номер её папки, сессии (исполнитель,
проверки методики, приёмщик) — части задачи без своих номеров, срочная часть работы — подзадача со своим номером и
папкой. Слова «поручение» в том, что видит владелец, нет. Разбор — [analysis.md](analysis.md).

## Результат и куда он попадает

- Модель «задача, сессия задачи, подзадача», правило различения и слова — Канон, `doc/canon/process.md` (новый раздел
  «Задача, сессия, подзадача»); строка «Папка задачи» таблицы параметров раннера в `doc/canon/README.md`.
- Поведение плагина (номер, заведение папки, сессии, показ) и новые ключи настроек — `opencode-plugin/README.md`
  (раздел «Tasks»), справка `crew_help` и её снимок в тестах, описания инструментов `crew_spawn` и `crew_task`.
- Код — `opencode-plugin/`; правило стража о повторе номера папки — `scripts/guards/check-task-docs.py` и его самотест.
- Этот файл и `analysis.md` после сдачи — история; действующее описание модели — только в Каноне.

## Модель

**Задача** — работа с одной целью владельца, своей приёмкой и своим попаданием в `main`. Номер — один:

- проект с папками задач (`tasks_dir`, у нас `doc/tasks`) — номер папки `NNN`; запись плагина
  `tasks/<проект>/<N>.json` получает тот же номер; в показе — `045` (три цифры, без `#`);
- проект без папок (Нова, ai-dev-methodology) — номер записи плагина, как сейчас; в показе — `#88`.

**Сессия задачи** — один запуск агента внутри задачи: исполнитель (`исп`), приёмщик (`прм`), сессия методики (С1, С2,
С3п, С4, С5д, С6…). Своего номера задачи у сессии нет. Идентификатор — номер задачи, код и порядковый номер этого кода
в задаче: `045 С4-3`; в записи и журналах к нему добавляется номер запуска методики `№n` — сквозной в задаче, тот же,
что в строке `запуск №n` журнала хода и в `state.launches` раннера (`045 С4-3 №3`). Где он записан:

- запись задачи — список сессий: код, порядковый номер кода, номер запуска, сессия OpenCode, статус, место (дерево и
  ветка), время начала и конца, отчёт сдачи;
- `progress.log` папки — строка `С4 0/0 [2026-10-15 22:17] запуск №3`, её пишет плагин до старта сессии;
- `log.md` папки — строка `2026-10-15 22:17 пуск: запуск №3 С4-3 …` при запуске и `документ: С4-3 сдала: …` при сдаче;
- отчёт сессии — файл методики в папке (`plan-review-3.md`, `review-2.md`…); текст сдачи — в записи задачи.

**Подзадача** — отдельная задача со своим номером и папкой; в `task/message.md` первая строка «Часть задачи 045
«Реестры контрактов…».», в `log.md` родителя — строка о заведении, в записях — связь `part_of` / `parts`.

**Правило различения** (пишется в Канон): своя приёмка или отдельное попадание в `main` — подзадача; следующий шаг той
же работы (проверка, правка по находкам, продолжение, передача другой сессии) — сессия.

Примеры:

| Ситуация | Что это | Идентификатор |
|---|---|---|
| Третий заход проверки плана задачи 045 | сессия | `045 С4-3 №3` |
| Правка плана по находкам С4-2 | сессия | `045 С3п-2 №2` |
| Срочно починить страж, найденный при проверке 045, с отдельным вливанием | подзадача | `059`, папка `059-…`, «Часть задачи 045» |
| Быстрая задача без методики | задача с одной сессией | `060 исп`, приёмка — `060 прм` |
| Задача Новы | как сейчас | `#89 исп` |

## Заведение задачи и папки

- Номер: `1 + max` по записям проекта, папкам `tasks_dir` во всех рабочих деревьях репозитория (реестр git
  `.git/worktrees`), именам папок `tasks_dir` во всех локальных ветках и ветках `origin` (`git ls-tree`). Занимается
  атомарным созданием файла записи (`wx`, как сейчас): все окна пишут в одно хранилище службы, поэтому два окна одного
  номера не получат. Агент вне OpenCode берёт номер тем же кодом через скрипт репозитория (вопрос В-05).
- Папка пишется не в основную копию `main` (она живая, `AGENTS.md`, пп. 3 и 11), а в дерево задачи на её ветке от
  целевой ветки: `task/message.md` и `log.md` с первой строкой; плагин коммитит их на ветке задачи (`git commit -s`,
  сообщение `Add task 059: <slug>`). В `main` папка попадает на первых воротах, как сейчас.
- `task/message.md` пишет интегратор: полный текст в поле `message` (как пишутся задания crew-harness — со словами
  владельца и датой); без него плагин собирает задание по шаблону из полей `goal`, `criteria`, `boundaries`,
  `open_questions` (вопрос В-06).
- Папка уже есть (завёл агент, как эту 058) — `crew_spawn {task: 58, …}` заводит запись с номером 58 и не пишет папку;
  папка ищется по номеру в деревьях и ветках. Номер занят открытой старой записью — отказ с её названием.
- Заказ другому проекту (`order`) берёт номер из того же счёта, папку не заводит: в номерах папок остаётся пропуск
  (пропуски уже есть: 038).

## Переход

- Старые записи не переписываются и доживают со своими номерами и прежним показом (`#57 исп`); новые номера идут после
  наибольшего из всех записей и папок (в crew-harness — с 059).
- Задача с папкой, номер которой занят закрытой старой записью (например 013 и запись #13), при первом заведении
  сессии получает новую запись; старая запись переносится без изменений в `tasks/<проект>/legacy/<N>.json` и видна в
  `crew_task list all` (вопрос В-07). Занят открытой — отказ с её названием.
- Нова и проекты без папок — без изменений. Ссылка заказа `parent: "crew-harness#45"` принимается как сейчас.
- Нужен перезапуск службы (код провайдера и записи задач): готовится целиком, владелец предупреждается заранее
  (`AGENTS.md`, п. 12).

## Связь с раннером 013/031

- Раннер методики ведёт задачу по сессиям и нумерует запуски (`state.launches`); здесь — то же число: номер запуска
  `№n` из записи задачи и строк `запуск` журнала. Раннер возьмёт список сессий записи как источник запусков или
  перенесёт его в свой `state.json` — формат записи сессии совпадает по полям (номер, код, время, отметка журнала).
- Не мешаем: регламент 031 и реестры 045 — данные, мы их не трогаем; хранение состояния раннера (031, DNC-02) не
  проектируем; переходы фаз и ворота ведёт интегратор вручную, как сейчас.

## Требования

REQ-01 — Ключ настроек проекта `tasks_dir` (по умолчанию `doc/tasks`): папки задач включены, когда этот каталог есть в целевой ветке; пустая строка выключает. Счёт номера, заведение папки и обход журналов хода (`progress-scan.ts`) берут каталог из ключа.

REQ-02 — Номер новой задачи — `1 + max` по записям проекта, папкам `tasks_dir` во всех рабочих деревьях и папкам `tasks_dir` во всех локальных ветках и ветках `origin`; занимается атомарным созданием файла записи; два одновременных заведения из разных окон получают разные номера.

REQ-03 — `crew_spawn` и `crew_task assign` в проекте с папками заводят папку `NNN-<slug>/` в дереве задачи на ветке задачи: `task/message.md` (текст поля `message` дословно, без него — шаблон из полей задачи) и `log.md` с первой строкой `ГГГГ-ММ-ДД ЧЧ:ММ документ: задание заведено …`; плагин коммитит их на ветке задачи с подписью `-s` и сообщением `Add task NNN: <slug>`. Основную копию целевой ветки плагин не меняет.

REQ-04 — `crew_spawn {task: N}` для задачи, чья папка уже есть (в любом дереве или ветке), заводит запись с номером N без записи папки; папки с таким номером нет — отказ; номер занят открытой записью другой работы — отказ с её названием.

REQ-05 — Сессия задачи: `crew_spawn {task: N, session: "<код>"}` добавляет в запись задачи сессию с кодом, порядковым номером кода (`С4-3`) и номером запуска `№n` (`1 + max` по сессиям записи и строкам `запуск` журнала хода во всех копиях); новой записи задачи не заводит.

REQ-06 — Перед стартом сессии плагин пишет строку `<код> 0/0 [ГГГГ-ММ-ДД ЧЧ:ММ] запуск №<n>` в `progress.log` той копии, где сессия работает, и строку `пуск: запуск №<n> <код>-<k> …` в `log.md` задачи; формы — общими функциями журнала (задача 053).

REQ-07 — Место сессии: по умолчанию — дерево и ветка задачи; `place: "own"` — своё дерево и ветка от ветки задачи по шаблонам `{repo}-{n}-{session}` и `task/{n}-{session}` (`task/045-s4-3`); значение по умолчанию для кодов проверок — по ответу на В-04.

REQ-08 — Сдача сессии (`crew_task submit {n}` из сессии): статус сессии «сдана», отчёт — в записи, строка `документ: <код>-<k> сдала: <начало отчёта>` в `log.md`, письмо интегратору; приёмка плагина не начинается, задача остаётся открытой.

REQ-09 — Приёмка плагина (review, precheck, merge, accept, cleanup) — одна на задачу: у задачи с одной сессией `исп` — после её сдачи, как сейчас; у задачи с сессиями методики — по действию интегратора `crew_task {action: "deliver", n, text}`, которое передаёт ветку задачи на приёмку.

REQ-10 — `reassign` в задаче с сессиями передаёт сессию: новая сессия того же кода с k+1 и новым номером запуска; прежняя — «передана»; текст уточнения — по задаче 057.

REQ-11 — Подзадача: `crew_spawn {part_of: N, …}` заводит новую задачу со своим номером и папкой; первая строка `task/message.md` — «Часть задачи NNN «<название>».»; в `log.md` родителя — строка `документ: заведена подзадача MMM «…»` в дереве родителя, если оно есть, иначе запись в истории родителя и письмо интегратору; в записях — `part_of` и `parts`.

REQ-12 — Панель «Crew» группирует сессии под задачей: строка задачи `NNN <название>`, под ней строки `↳ <код>-<k>` или `↳ прм` с состоянием; ширина строк — прежняя (32 знака).

REQ-13 — Заголовок сессии в OpenCode: `NNN <код>-<k> исп|прм <значок> <слово> <название задачи>`; у задачи без сессий методики — `NNN исп …`.

REQ-15 — Проект без папок: номер, показ, письма и действия — как сейчас (`#N`).

REQ-16 — Подстановка `{n}` в `branch_name` и `worktree_name` проекта с папками даёт три цифры (`task/045-…`); в проекте без папок — как сейчас.

REQ-18 — Справка `crew_help`, описания `crew_spawn` и `crew_task`, системный блок и README плагина описывают модель словами «задача», «сессия задачи», «подзадача»; слова «поручение» в текстах плагина, README и Каноне нет.

## Сценарии и критерии приёмки

AC-01 — Когда в целевой ветке есть папки 001…056 и 058, а папка 057 есть только в другой ветке, тогда новая задача получает 059. Тест `crew-task-numbers` (временный репозиторий с ветками).

AC-02 — Когда два заведения задачи идут одновременно (два процесса), тогда номера разные и обе папки заведены. Тест с двумя процессами Node.

AC-03 — Когда `crew_spawn` заводит задачу с `message`, тогда на ветке задачи есть коммит с `task/message.md` (текст дословно) и `log.md` (одна строка нужной формы), а основная копия не изменена (`git status` чист). Тест на временном репозитории.

## Тип задачи, проверка, риски

Размер M (22 REQ). Риск — данные: записи задач службы и ветки репозитория; живая служба — изменение требует

## Вопросы владельцу

В-01 — Как показывать сессию: `045 С4-3` (код и его порядковый номер), а номер запуска `№3` — только в записи и журналах; или всегда `045 С4 №3`?
Рекомендация: `045 С4-3` в показе, `№n` в записи и журналах — потому что «С4-3» вы уже так называете, а номер запуска нужен машине для единственности строки `запуск` и раннеру.

В-02 — Номер задачи в проекте с папками писать без `#` (`045`), а в проекте без папок оставить `#88`?
Рекомендация: да — по виду номера сразу видно, есть ли у задачи папка, а Нова не меняется.

В-03 — Приёмка плагина (приёмщик, вливание, уборка) — одна на задачу, а сессии методики сдаются интегратору без приёмки плагина?
Рекомендация: да — сейчас каждая проверка С2/С4 сама проходит ещё одну приёмку плагина (у #23, #50, #57 был свой приёмщик), это двойная работа без пользы.

В-04 — Где работают проверочные сессии (С2, С4, С6): в своём дереве от ветки задачи или в дереве задачи?
Рекомендация: в своём дереве по умолчанию — так уже велась 045 (`review/045-s4-3`): проверяющий не видит незакоммиченного автора и не мешает ему; авторские сессии (С1, С3, С5…) — в дереве задачи.

В-05 — Агент вне OpenCode (оркестратор быстрых задач) берёт номер скриптом репозитория из того же реестра плагина?
Рекомендация: да — иначе быстрые задачи и `crew_spawn` будут брать один номер наперегонки; страж повтора номера (REQ-20) ловит остаток, но уже после коммита.

В-06 — Текст `task/message.md`: интегратор передаёт его целиком, а шаблон из полей — только когда текста нет?
Рекомендация: да — задания crew-harness пишутся со словами владельца и датой, шаблон их не заменит; проектам попроще хватит шаблона.

В-07 — Старую закрытую запись с номером существующей папки (например #13 при папке 013) переносить в `legacy/` при первом заведении записи этой задачи?
Рекомендация: да — содержимое не меняется, история видна в `crew_task list all`, а номер освобождается для задачи; другой путь — вести новые записи под другим именем файла, это вторая нумерация в хранилище.

В-08 — Заказ другому проекту (`order`) берёт номер из общего счёта без папки, оставляя пропуск в номерах папок?
Рекомендация: да — заказ — работа другого проекта, папки у нас ей не нужно, а отдельный счёт заказов вернул бы второй номер; пропуски номеров уже бывают.
