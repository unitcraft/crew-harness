## Что нужно

1. **Источники:** `src/server/` (особенно `hub.nv`: тип `Dialog` держит `Engine[ChatSession, ChatState]`, функции вызывают `dialog_session(@settings.idle_term_ms)`, `begin_engine`, `resume_engine`; `settings.nv`; `README.md`), `src/chat/chat.nv` (`dialog_session` — многооборотная машина: после ответа, отказа, срока и отмены сессия возвращается в `Idle`; `chat_step`, `dialog_awaiting`), `src/chat/chat_test.nv`, `chat_engine_test.nv`, `src/server/dialog_test.nv`, `src/server_live/hub_test.nv` и `src/server_pg/hub_pg_test.nv` (десять сценариев над файлами и PostgreSQL), `src/server/test/e2e.mjs` (35 проверок на подставном агенте), `src/server/test/real-agent.mjs`; машины и интерпретатор: `src/machine_run/` (`PortolanMachine`, `PortolanState`, `load_portolan_machine`, `portolan_machine_with`, запись сценариев), `src/machine_chat/` (равенство однооборотного чата с машиной на Нове), `src/machine/machines/chat.portolan.md`, `src/machine_text/README.md`, `src/machine/README.md`; движок: `src/engine/README.md` (`Machine[S]`, `Engine`, снимок); `spikes/env/README.md` (пп. 1–43: нет обобщённых функций с выводом параметров — типы пишутся явно; один каталог — один юнит; вывод юнита ≤ 4096 байт; юнит со многими прогонами убивается около 100 с).
2. **Многооборотная машина на Портолане.** Существующая `chat.portolan.md` — ОДНООБОРОТНАЯ (конец `ГОТОВО`). Записать многооборотную как `src/machine/machines/dialog.portolan.md` (перевод в `dialog.portolan.json`, вшить в `data.nv`): состояния и строки по `chat_step` и `dialog_awaiting` (после ответа, отказа, срока, отмены возврат в `Idle`; лишние события в `Idle` игнорируются с записью, как у машины на Нове; журнальные коды и параметры те же; счётчик попыток и номер запроса `<сторона>-<попытка>`); срок тишины — параметр проекта (`Параметры`, столбец «переопределение проектом»: `проект.срок_бездействия`), значение даёт сервер из `idle_term_ms` через таблицу параметров (метка П-9 формата).
3. **Доказательство равенства.** Все сценарии `src/server/dialog_test.nv` и `chat_engine_test.nv` (многооборотные и однооборотные) идут на движке над обеими машинами (`dialog_session` на Нове и `PortolanMachine` с `dialog.portolan.json`) и сравниваются по состоянию, данным, всем строкам журнала с конвертом, запросам, очереди, подтверждениям и итогу — по образцу `src/machine_chat/`; плюс сценарии по строкам таблицы (покрытие строк, как у «Шага агента»: метка `taken`) в `src/machine/scenarios/dialog-*.scenario.test.json`; намеренная правка JSON даёт красное (проверено).
4. **Хаб на `PortolanMachine`.** `src/server/hub.nv`: `Dialog.engine` — `Engine[PortolanMachine, PortolanState]`; все места, зовущие `dialog_session(...)`, `ChatState`, `user_says`, `user_cancels`, `state_name`, заменить на `PortolanMachine` из вшитой машины (одна загрузка при старте хаба; ошибка загрузки — отказ запуска понятным сообщением); события страницы (`page_event`, штамп `id`, `step`, `time`) и подсказки состояния для страницы («Ожидает», «Работает») берутся из тех же журнальных кодов и имён состояний — страница `src/web/` и протокол `/ws` не меняются; перезапуск сервера посреди сессии находит сессии по хранилищу и продолжает через `resume_engine` (снимок `PortolanState` как вложенный объект; сессии старого формата снимка не мигрируются: в продуктовой базе их нет, записать в README). Машина на Нове `dialog_session` остаётся в `src/chat/` как эталон для доказательства равенства; её удаление — слово владельца, не в этой задаче. Переключателя «nova/portolan» в настройках не вводить (хаб работает на Портолане).
5. **Хост примитивов.** `PortolanMachine` получает хозяина примитивов: у многооборотного чата примитивов нет (проверить; если нужны — реальные `time_now`, `new_id` на `std`: `Time`, `Random`), в `src/server` собрать `PrimitiveHost` для движка; без побочных эффектов внутри ядра.
6. **Проверки.** Красная проба до кода (заглушки или тесты: многооборотный сценарий на Портолане красный, число красных в `log.md`); весь набор: `nova test src --jobs 4` и `--strict-effects` (на временном контейнере PostgreSQL: `src/pg/testdb.ps1`, затем `-Stop`); десять сценариев хаба над файлами (`src/server_live`) и над PostgreSQL (`src/server_pg`) зелёные на Портолане; `node src/server/test/e2e.mjs` (35 проверок, после сборки `nova build src/crew_hub.nv -o target/crew-hub.exe` и `src/crew_harness.nv -o target/crew-harness.exe`) зелёный; `node src/server/test/real-agent.mjs` (handshake настоящего `opencode acp`, без модели) зелёный; тесты страницы 093/094 зелёные; не менее 120 новых проверок; стражи 8 и больше, FAIL 0; коммиты по правилам AGENTS.md (по темам: многооборотная машина и сценарии; равенство; хаб; хост примитивов; README и отчёт).
7. **README** `src/server/README.md` (английский): сервер исполняет чат на Портолане, откуда берётся машина, как задаётся срок тишины, как проверялось равенство; ограничения Oracle — `spikes/env/repro_*` и пункты README после п. 43 при находках.
8. **Не входит:** «Шаг агента» внутри чата (нужна сторона `machine` и вложенные вызовы: следующая задача), Раннер и остальные машины, Markdown и переключатели пульта, перенос на PostgreSQL по умолчанию.
