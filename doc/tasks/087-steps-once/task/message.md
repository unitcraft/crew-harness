# Задание: шаги приёмки показываются в панели один раз, под строкой приёмщика

Заказчик: владелец репозитория `unitcraft/crew-harness` (он же принимает результат).
Репозиторий: `unitcraft/crew-harness`, ветка `main`. Дата задания: 2026-10-18.
Источник: слово владельца в чате оркестратора, 2026-10-18: скриншот панели Crew по задаче 101 («Исправить @eq и проверить ключи») и вопрос «почему повторяются суб-записи»; затем «заводи 087».
На скриншоте под названием задачи две одинаковые строки: «↳ прм  проверка 1/12: criteria — критерии приёмки задачи…» и «↳ исп  проверка 1/12: criteria — критерии приёмки задачи…».
Причина (разбор оркестратора, чтение): шаги приёмки и текущая проверка (`steps`, `checking`) хранятся на уровне задачи; `status.ts` кладёт их в `task` каждой карточки задачи — и исполнителя, и приёмщика;
строка под каждой сессией печатает `stepProgress(s.task)` (около `status.ts:758–769`), поэтому одна и та же строка стоит под «прм» и под «исп»; у задачи с несколькими сессиями (С4-3, С4-4…) — под каждой.
Реально проверяет шаги только приёмщик.

Задача полная: разбор, реализация, сдача. Быстрый путь. Основа — свежий `origin/main`.

## Чего хочет владелец

- «почему повторяются суб-записи» и «заводи 087» (владелец, 2026-10-18, чат оркестратора): шаги приёмки в панели — один раз.

## Что нужно

1. **Разбор:** все места, где строка шагов приёмки (`проверка N/M: id — название`, `шаги N/M`) выводится из `stepProgress`: панель (`sidebarLines`), `/crew` (`formatStatuses`), блок «Ход работ» (`progress-view`) и всё, что берёт
   `task.steps`/`task.checking`; где она повторяется под несколькими сессиями одной задачи (исполнитель, приёмщик, сессии методики). Показать на живых записях (чтение `status/`, `tasks/`), на каких задачах это видно сейчас.
2. **Правило:** строка шагов приёмки печатается **один раз на задачу** и принадлежит сессии, которая проверяет шаги, — приёмщику (`task.as === "reviewer"`); у исполнителя и у завершённых сессий её нет. Если приёмщика среди показываемых сессий нет,
   а шаги есть — одна строка под названием задачи. Состояние ожидания (вопрос, наблюдение, ответ) сессии показывается как раньше. Тоны и знаки (`↳`, `·`) не менять.
3. **Те же правила в `/crew` и в «Ходе работ»:** ни одной повторяющейся строки шагов для одной задачи.
4. **Тесты:** красная проба до кода (источник: задача со шагами и двумя сессиями — исп и прм: одна строка под прм, ни одной под исп; три сессии одной задачи — одна строка; нет приёмщика — одна строка под названием; задача без шагов — без изменений;
   сессия методики с видом (`↳ С2-5 проверка спецификации`) не теряется); обновить ожидания тестов (`crew-sidebar`, `crew-sidebar-hierarchy`, `crew-progress`, `crew-status`, golden — только изменившиеся ключи);
   полный `npm test` не больше чем по 4 параллельно (на машине идут другие задачи; [AGENTS.md](../../../../AGENTS.md), п. 9).
5. README плагина — одна-две фразы.

## Критерии приёмки

- Красная проба до кода падает на источнике и проходит после правки.
- В панели, `/crew` и «Ходе работ» строка шагов приёмки на задачу одна, под приёмщиком; на скриншотном случае (задача с исп и прм) повторов нет.
- Полный `npm test` зелёный (красные, нестабильные под нагрузкой, перепроверены по одному; перечень в сдаче); стражи — 8 и больше, FAIL 0.
