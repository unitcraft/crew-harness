# Задание: замеры и сверка агентов (этап 1 эпика)

Заказчик и владелец: владелец репозитория `unitcraft/crew-harness` (он же отвечает на вопросы и принимает результат).
Репозиторий кода: `unitcraft/crew-harness` (https://github.com/unitcraft/crew-harness, ветка `main`). Дата задания: 2026-10-10.
Эпик: [001-crew-service](../../001-crew-service/) (дочерняя задача «замеры и сверка агентов»). Закрывает требования эпика: REQ-42, REQ-43, REQ-44;
сценарий AC-26. Источник: [спецификация эпика](../../001-crew-service/spec.md), [следование](../../001-crew-service/spec-trace.md) (D-16) и
решения владельца 2026-10-09 в [журнале эпика](../../001-crew-service/log.md).

Задача полная: разбор, план, реализация, сдача.

## Чего хочет владелец (его слова, 2026-10-10)

- «по рекомендации, но раннер на паузе» — разбиение эпика одобрено: эта задача идёт первой, параллельно раннеру, который на паузе.
- Решения 2026-10-09 («по рекомендации»), которые входят в замеры: транспорт MCP (HTTP в сервисе основной, подкоманда `crew mcp`
  запасная — выбор по замеру на трёх агентах); сверка с Agent Host Protocol; размер исполняемого файла и антивирус.

## Что есть сейчас

- Сверки возможностей Claude Code, Codex CLI и Kimi Code по официальной документации нет; про HTTP-транспорт Codex и Kimi
  проверенных сведений нет (в спецификации помечено неизвестным).
- Замеров расхода лимитов подписок, фонового режима Claude Code на Windows и работы 20–30 сессий нет.

## Что нужно

- **Записка сверки CLI** (REQ-42, AC-26): для Claude Code, Codex CLI и Kimi Code по каждому свойству, нужному драйверу (запуск без
  окна, продолжение сессии, статус «работает/ждёт/закончил», остановка по номеру процесса, хуки, поток событий, передача
  картинки, лимиты ходов и времени, MCP по HTTP и по stdio) — ответ по официальной документации с адресом и датой чтения.
- **Замеры** (REQ-43): расход лимитов подписок при 10 и 20 агентах Claude и 5 Codex и Kimi; фоновый режим Claude Code на Windows под
  20–30 сессий; транспорт MCP на каждом из трёх агентов в двух вариантах; размер исполняемого файла и реакция антивируса.
- **Разбор Agent Orchestrator и Emdash** (REQ-44): что взять в доску, драйверы, вид терминала; код не копируется без решения.
- **Сверка с Agent Host Protocol:** ложатся ли на его схему доска, карточка задачи, терминал, чат и ворота; решение — сервис как хост
  протокола или только идеи.
- Результат — записка в `doc/research/` и записи для плана эпика (языки и транспорт, выбор по замерам).

## Что надо выяснить в разборе

- Какие замеры безопасны для нагруженной машины владельца: тяжёлые прогоны (десятки агентов, нагрузка) — только через очередь
  машины и по слову владельца; что можно снять без нагрузки (чтение документации, один агент).
- Что считается «расход лимитов» у каждого вендора и где он виден без вмешательства в бинарник (Claude Code не модифицируется).

## Связи

- Зависит от: —
- Блокирует: координацию, драйверы (выбор транспорта, возможности CLI) — [019](../../019-coordination-tasks/)
- Пересекается (файлы): `doc/research/`; журнал эпика
- Начинается после: слов владельца; раннер на паузе и задачу не блокирует

## Границы

- Только чтение документации, замеры и записка; код сервиса и драйверов не пишется. Учётные данные подписок не читаются и не
  вводятся ([ADR-0004](../../../canon/decisions/ADR-0004-agent-drivers-on-subscriptions.md)).
- Репозитории других проектов только читаются (п. 16 AGENTS.md).
- Машина общая и нагруженная: замеры нагрузки — по слову владельца и через очередь машины ([AGENTS.md](../../../../AGENTS.md)).
