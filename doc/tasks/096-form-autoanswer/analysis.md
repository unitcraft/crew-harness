# Разбор 096: плагин сам отвечает на формы встроенного вопросника по рекомендации

Задание — `task/message.md`. Источник: слова владельца в чате оркестратора, 2026-10-19: «answer_mode: recommendations работает только для текстовых вопросов определённого вида - я был уверен, что это автоответы на вопросники, это упущение, надо доделать»; «по рекомендации, с учетом выше сказанного тут». Быстрый путь. Правки — только `opencode-plugin/`, дополнение к ADR-0010 и эта папка.

## 1. Что было

- `answer_mode` (ADR-0010, задача 007) закрывал только текстовые блоки «В-NN … ?» с `Тип:`, `Рекомендация:`, `Автоответ: допустим`. Форма встроенного вопросника (инструмент `question`, запись в `forms/`) ждала владельца; ответ ставил оркестратор командой `crew-answer` по слову владельца, плагин применял его прерыванием хода и письмом (задача 059, `owner-answer.ts`).

## 2. Что сделано

Новый модуль `opencode-plugin/form-auto.ts`, подключён в проход форм `index.ts` (`formWatch`: `formTick`, `autoTick`, `answerTick`, `loopTick`).

| Условие задания | Где | Как |
|---|---|---|
| режим `recommendations` для типа | `judgeForm`, `loadConfig` | настройки проекта с блоком `local`; тип формы — `default` или `Тип:` из текста; `Тип: gate` — владельцу; неизвестный тип — сомнение |
| одна пометка «(Recommended)», у первого | `judgeForm` | нет / две / не первая / нет вариантов — «нет рекомендации» |
| закрытый список | `CLOSED_LIST`, `closedHits` | таблица из 17 строк: gates, approval, accept, push, merge, delete, restart, live, release, force, secret, money, owner-word, answer-keys, boundaries, ceiling, environments (плюс тип gate); слова ищутся в заголовке, тексте вопроса, подписи и описании рекомендованного варианта; тест на каждую строку |
| `answer_max` подряд | `seriesOf` | считаются файлы `answers/` сессии после последнего ответа владельца; слово владельца во вкладке обнуляет счёт |
| не заменена, не устарела, не повтор | `autoTick` | пропускаются отменённые Esc, в повторе, исчерпанные; нужен идущий ход |
| задержка | `answer_delay_sec` | ключ (60, 0 — сразу), только человек (`crew_config set` отвергает); ответ владельца и его слово снимают автоответ |
| доставка | `owner-answer.ts` | источник plugin: служебное письмо «не слово владельца», `answers/auto-<форма>.json`, событие задачи, строка журнала |
| показ | `answer.ts`, `status.ts`, `index.ts` | счётчики в `/crew`, строка боковой панели, строка `crew_doctor` |
| выключено по умолчанию | `judgeForm` | нет ключа или `owner` — ни файла, ни отметки |

Смерть между изменениями (правила 13 и 34(е) методики): файл-ответ получает статус `applying` с записью формы и ответа до снятия записи формы и до прерывания; после перезапуска `applying` достраивается без второго прерывания и второго письма.

## 3. Проверки

- Красная проба до кода: `crew-form-auto` и `crew-form-auto-flow` красные («form-auto.ts is missing»), `crew-answer-config` — 7 красных ячеек, `crew-answer-docs` — 3.
- Новые тесты: `crew-form-auto.test.mjs` (~121 ячейка), `crew-form-auto-flow.test.mjs` (19, настоящий плагин); дополнены `crew-answer-config`, `crew-answer-docs`.
- Исполнитель: затронутые 24 файла — 0 красных; полный набор (130 запусков, до 4 процессов) — красный только снимок справки `crew-answer-golden`, перезаписан; стражи ок 8, FAIL 0.
- Независимая проверка оркестратора: полный набор на свежем `origin/main` — результат в `log.md`.

## 4. Расхождения с заданием

- Исключение «сессия приёмки» снято только для форм; в текстовом пути (`classify`) осталось, чтобы не менять золотые тесты 007 → задача по слову «заводи».
- Добавлены условия: в форме один вопрос без множественного выбора, нет цикла 078, во вкладке идёт ход (иначе вопрос потерян и его ведёт повтор 040).
- Запись `forms/` хранит 200 знаков: добавлены необязательные поля `full`, `optDesc`, `nq`, `multi`, `born`.

## 5. Замер по журналу ответов за 2026-10-18

Файлов-ответов 36 (30 применено, 6 отказано: ход не прерван). Из 30 применённых: 23 — вариант «(Recommended)», 7 — другое. Прогон `judgeForm` по 23: плагин закрыл бы 7 (30 %), владельцу ушло бы 16 (accept 3, approval 3, gates 2, release 2, push 2, merge 2, answer-keys 1, delete 1). По видимому тексту из 16: настоящих ворот 5, пограничный 1, срабатывание на слово из описания положения 10 («на main красный», «при сдаче 103», имя стража со словом gate). Это нижняя граница: в письмах вопрос хранится в 200 знаках. Время ожидания форм замерить нельзя: оно в журнал не попало, его даст `forms/auto/`.

## 6. Что дальше

- Слишком широкий закрытый список: около 60 % уходов к владельцу из-за слов в описании положения, а не из-за настоящих ворот → задача 097.
- Исключение «сессия приёмки» в текстовом пути → задача 097.
- Живая проверка после «обновляй» и перезапуска (строка «owner answer auto-… applied» в журнале, счётчики `/crew`, `forms/auto/`) → задача 097.
