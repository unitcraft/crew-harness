# Разбор 065: единый образец задания task/message.md

Задание — `task/message.md`.

## 1. Разбор

Источник: задания расходились. Плагин собирал из полей `crew_spawn` разделы «Цель / Критерии приёмки / Границы / Открытые вопросы»
(цель — сплошным текстом, пример — 061); быстрый путь оркестратора (063, 064) — «Чего хочет владелец / Что нужно / Результат и куда он
попадает / Границы». Методика формы не задаёт: `task-sessions.md` (коммит `78ed758`), «Порядок», п. 2 — «текст сообщения и ссылки —
файлом task/message.md», п. 7 — раздел «Связи» перед границами, когда задач несколько.

### Место образца в Каноне

Раздел «Задание task/message.md» в `doc/canon/process.md`, а не отдельный файл. Довод: process.md — место отличий и дополнений к
методике, однотипные нормы («Результат и куда он попадает», «Открытые вопросы», «Задача, сессия, подзадача») — разделы этого файла;
отдельный файл добавил бы часть Канона ради одного образца (владелец, 2026-10-10: «наша задача — уменьшить нашу часть канона»).
Ссылка из входа — строка «Задание задачи» в таблице «Параметры для раннера» `doc/canon/README.md`. Отличие от методики — строка таблицы
«Отличия» и ADR-0011. Отличие по сути одно: форма задана (методика её не задаёт) и раздел «Связи» есть всегда — без связей «нет:
<почему>», это тоже сведение для С3 о порядке слияния.

### Поля crew_spawn и совместимость

Новые поля (`crew_spawn`, `crew_task assign`; общий набор `taskInput`): `owner_words` — слова владельца дословно с датой и источником;
`result` — результат и куда он попадает; `links` — связи по методике. В запись задачи попадают только непустые; id запрещены для
полей проекта (`RESERVED_FIELD_IDS`).

Задание из полей: заголовок, шапка (заказчик — роль автора, репозиторий — проект и целевая ветка, дата, источник — ссылка на раздел
слов владельца), разделы по порядку; `goal` — пунктами «Что нужно» (абзац или строка «- …» — пункт; уже нумерованная цель остаётся как
есть); `open_questions` — разделом после «Границ».

Совместимость прежних вызовов — выбран отказ, а не раздел «нет: поле не передано»:
- `owner_words` (с датой ГГГГ-ММ-ДД) и `result` обязательны там, где плагин пишет задание: новая задача с папкой, подзадача, `assign` в
  проекте с папками. Без них — отказ до выдачи номера и коммита папки, ответ называет поле и даёт пример. Довод: это нормы (AGENTS.md,
  п. 2; методика, «Результат и куда он попадает»), заглушка «нет: не передано» пропустила бы задание без слов владельца молча, а страж
  такую строку принял бы; цена отказа — один повторный вызов.
- `links` и `boundaries` — по желанию: их отсутствие законно, раздел пишется «нет: интегратор … не назвал (поле … не передано)».
- `message` (свой текст) — без новых полей, но проверяется теми же правилами, что у стража; не по образцу — отказ со списком нарушений.
- Без изменений: проект без папок задач (`#N`), сессия существующей задачи, задача-план, заказ (`order`).

### Страж и дата введения

`check-task-docs.py`: правила `message-title` (заголовок «# Задание: …» до первого раздела), `message-section` (все шесть разделов
второго уровня, по порядку, не пустые, «нет:» с причиной), `message-owner` (дата ГГГГ-ММ-ДД в заголовке или теле раздела слов
владельца, если раздел не «нет: …»). Судятся задачи, заведённые не раньше `MESSAGE_FROM` = 2026-10-17 01:00 (первая запись `log.md` с
датой и временем). 063 (2026-10-16 21:07), 064 (2026-10-17 00:23) и сама 065 (00:42) заведены раньше и не судятся; названия их разделов
совпадают с образцом, поэтому по п. 4 задания они не правились; недостающие у них «Критерии приёмки» и «Связи» пришлось бы сочинять —
это смена смысла.
