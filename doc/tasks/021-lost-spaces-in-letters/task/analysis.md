# Разбор: потеря пробелов в письмах (задача 021)

## Механизм

Пробелы теряет не плагин и не доставка, а модель-отправитель: в строковых литералах внутри кода инструмента `execute`
(`tools.crew_send({text:'...'})`) она пишет длинные русско-английские строки слитно. Плагин (`crew_send`, `core.ts`) делает только `trim`;
текст в файле письма и в параметрах вызова в записи сессии отправителя одинаков.

## Статистика по моделям (разведка)

- семейство openai gpt-6.1-sol: около 18% длинных входов;
- gpt-6-astra: около 1%;
- luna, claude, kimi: 0.

Признак — слитные куски из смешанных алфавитов (кириллица и латиница без пробела).

## Проверка (`opencode-plugin/glued.ts`, `gluedText`)

- кусок: `(?:[A-Za-z]+[А-Яа-яЁё]+|[А-Яа-яЁё]+[A-Za-z]+)[A-Za-zА-Яа-яЁё]*` длиной не менее 20 знаков;
- не считаются: блоки ``` и инлайн-код, ссылки, слова с «/» или «\» без кириллицы (пути), хеши из 7–64 шестнадцатеричных знаков;
  куски без кириллицы не срабатывают вовсе;
- отказ, если кусков не меньше двух, либо длина больше 150, доля пробелов меньше 0,06 и есть хотя бы один кусок;
- `crew_reply` в плагине нет: все письма, в том числе ответы (`reply_to`), идут через `crew_send`, проверка стоит в нём.

## Прогон на реальных письмах (2026-10-11)

Корпус: 4713 писем с полем `text` из ящика плагина.

- сработало: 165 (162 по правилу «два и более куска», 3 по правилу «длинное и редкие пробелы»);
- 25 случайных сработавших просмотрены глазами (дважды по 25 при подборе правила путей): ложных 0 из 25 (везде склейка вида
  «приёмкаиprobePASSEDконкретно…»);
- пороги оставлены как в задании (20 знаков, два куска, 150 знаков и 0,06 пробелов): ужесточать не пришлось.

Замечание: первая версия исключала «путь» по шаблону с `\w`, не знающему кириллицу, и разрезала склейку «…countedOpen/inflight,…»;
исключение теперь по слову целиком и только без кириллицы (число срабатываний 162 → 165).

## Обход

Короткое письмо; подробности — файлом и ссылкой на него. Справка `crew_help` и README плагина это говорят.
