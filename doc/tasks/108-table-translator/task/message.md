# Задание: переводчик таблиц на русском в машину-данные — файл машины формата 2.5 превращается в JSON `machine/2`, и интерпретатор доведён до версии 2.5

Заказчик: владелец репозитория `unitcraft/crew-harness` (он же принимает результат).
Репозиторий: `unitcraft/crew-harness`, ветка `main`. Дата задания: 2026-10-19.
Эпик: [001-crew-service](../../001-crew-service/); продолжает [106](../../106-expr-evaluator/) (ядро: значение, вычислитель, реестр примитивов) и [107](../../107-table-machine/) (JSON-схема `machine/2`, `TableMachine`, прогонщик сценариев, равенство с машиной чата); план переноса — [105](../../105-plugin-capability-map/plan.md), этап Э0.
Источник: слова владельца в чате оркестратора, 2026-10-19: «цель: все возможности текущие (плагин crew-harness под opencode) + стейт-машины из методики должны быть написаны на таких стейт-машинах внутри голого продукта CrewHarness»; «задача — детерминированное повторение шагов, возможность вызвать из др. стейт-машины и др. требования остаются, но без необходимости писать код на Нова»; «по рекомендации» (порядок: обновить основную копию, затем переводчик таблиц, затем первая беседа с моделью).

Задача полная: разбор, реализация, сдача. Быстрый путь. Основа — свежий `origin/main` (после 107). Код — новый юнит `src/machine_text/` (английские идентификаторы), тесты рядом; в `src/machine*`, `src/engine` правки допустимы только те, что нужны для версии 2.5 и обоснованы в `analysis.md`; `src/chat`, `src/acp`, `src/server`, плагин не менять.

## Чего хочет владелец (его слова, 2026-10-19, чат оркестратора)

- «все возможности текущие … + стейт-машины из методики должны быть написаны на таких стейт-машинах внутри голого продукта CrewHarness»: машина — файл-таблица на русском, один общий интерпретатор на Нове, пользователь кода на Нове не пишет.
- Нотация как в Нове: без двоеточия перед типом; закрытый набор значений — `"a" | "b"`; идентификатор — тип `ид` (UUID).
- Продукт пишется на Нове и собирается Oracle 0.1.0.

## Что нужно

1. **Источники (читать, чужой репозиторий методики — только чтение):** нормативный формат `state-machines/state-machine-table-format.md` (версия 2.5, 2026-10-19; разделы 0–14, образцы определений с хешем), словарь английских имён `state-machine-glossary.md` (версия 9: `новый_ид` → `new_id`), журнал `state-machine-journal.md`, правила `state-machine-spec.md`; выписки пилотов Методики (`pilot-agent-step-v21/agent-step.table.v21.md`, `pilot-meeting-v21/`: счётчики, определения цикла, разметка 80 функций; пути — в промпте исполнителя, в файлах репозитория писать словами); `src/machine/README.md`, `src/machine_table/` (разбор `machine/2` и проверки), `src/machine_run/`, `src/machine_chat/`, `src/machine/schema/`.
2. **Доведение до 2.5 (первый коммит, при необходимости отдельный):** 107 реализует версию 2.2. Посчитать дельту 2.3, 2.4, 2.5 по разделам «Что изменилось» формата и истории файла методики и привести схему `machine/2`, разбор, проверки и интерпретатор к 2.5 в объёме, который нужен переводчику и машинам-образцам: набор литералов `"a" | "b"` (проверка значения при записи), встроенный тип `ид` (проверка формата UUID при загрузке данных и разборе входа), примитив `new_id` (латинское имя; русское `новый_ид` остаётся в таблицах; reading; допустим только в «При входе» операции; значение фиксируется в событии `сразу`; реализация хозяина — `Uuid.v7()` из `std.identifiers.uuid`, значение данных машины в JSON — текст 8-4-4-4-12 строчными hex; в реестре примитивов 106 — строка с типами и классом), `format: 2.5` в шапке. То, что 107 пометила «не реализовано» в формате (вложенные машины, `Правит`, профиль стороны, `Предел запросов`, `Возвратов формы`, `передать`) — не делать; переводчик должен отвечать понятной ошибкой «не поддержано в этой версии» с номером строки, а не молчать.
3. **Переводчик `src/machine_text/`:** функция `translate(file_text) -> Result[MachineJson, []TranslateError]` и командная обвязка в юните (`nova run`-пример или библиотека + пример запуска): разбор Markdown-файла машины, разделы по порядку формата: шапка (`format`, имя, латинское имя, сторона, версия), «Данные» (таблица: имя, тип, начальное значение, `не убывает`, `пишет`), типы и определения, состояния четырёх видов (обращение, операция, развилка, конец) со строками `| № | Событие | Условие | Действия | Куда |`, «При приёме», «При входе», общие события и фрагмент «Пауза», «Концы», параметры и константы, файл определений (отдельный документ формата), сценарии (`scenario/0`) в таблице. Выражения — грамматика раздела 3 (русские имена функций, `есть`, `обязательно`, `??`, лямбды, `для каждого`, `пусть`, записи с изменённым полем, операции, сравнения); действия — раздел 5 (`поле = выр`, `+=`, `поле[ключ] = выр`, `журнал(код, …)`, `вызвать(примитив)`, `ошибка_машины`, `отменить_открытые`); типы — раздел 2 (`?T`, `[]T`, `словарь[K, V]`, кортеж, `число≥n`, перечисление, вариант, набор литералов, `ид`). Русские имена полей, слов и функций переводятся в латинские по словарю методики (таблица соответствий — данные в `src/machine_text/`, источник — словарь, версия 9; неизвестное слово — ошибка с «файл:строка:столбец» и подсказкой ближайшего). Результат — JSON, который принимает `parse_machine` и `check_machine` из 107 без правок; ошибки перечисляются все сразу (не первая), с координатами и цитатой строки.
4. **Обратное направление для проверки (минимальное):** функция `render_summary(machine_json) -> text` — сводка машины (состояния, строки, число действий) для сравнения переводов; полный «JSON → таблицы» не нужен.
5. **Машины-образцы и равенство:** (а) записать машину чата как таблицу `src/machine/machines/chat.table.md` (русский текст по формату 2.5) и доказать, что перевод даёт JSON, который на всех 39 сценариях чата из 107 исполняется так же, как рукописный `chat.machine.json` (состояние, журнал, данные, очередь); рукописный JSON остаётся эталоном до приёмки, затем заменяется переводом, если владелец скажет; (б) перевести все примеры из разделов 2–9 формата методики, которые он помечает как целые машины или фрагменты (образец определений по хешу из формата; каждый фрагмент переводится и проходит проверки загрузки); (в) пилот «Шаг агента» (выписка v2.1 приведена к 2.5 вами по правкам формата): перевести, пройти проверки загрузки; перечень мест, которые не перевелись, с причиной и строкой выписки — в `analysis.md` (это входная ведомость следующей задачи — переноса «Шага агента»; критерий — не менее 95 % строк таблицы переводятся без оговорок, остальное — в ведомости, а не молча); (г) пилот «Совещание» — только перевод определений цикла и разметки функций, счётчик; полная машина — не в этой задаче.
6. **Проверки:** красная проба до кода (заглушки переводчика с теми же сигнатурами — красные тесты); не менее 250 новых проверок (разбор шапки и таблиц, каждый вид состояния и событий, каждая конструкция выражений и действий, типы, определения, сценарии, русские имена по словарю, ошибки: неизвестное слово, лишняя строка, неисчерпанные концы, чтение вне «Входа», недопустимый класс примитива, `новый_ид` вне «При входе», не поддержанные конструкции; детерминизм: два перевода дают тот же JSON; перевод ↔ эталон на 39 сценариях чата); `nova test src --jobs 4` и `--strict-effects` зелёные (на временном контейнере PostgreSQL по необходимости: `src/pg/testdb.ps1`, `-Stop` после); стражи 8 и больше, FAIL 0; коммит по правилам AGENTS.md (английское сообщение, `-s`, без трейлеров и без `#число`, файлы перечнем).
7. **README** `src/machine_text/README.md` (английский): как запустить перевод, формат ошибок, таблица имён, что не поддержано; новые ограничения Oracle — воспроизведения в `spikes/env/repro_*` и в отчёт; в `src/machine/README.md` — ссылка и версия 2.5.

## Критерии приёмки

- Таблица машины чата на русском переводится в JSON, равный по поведению эталону на 39 сценариях; все примеры формата и пилот «Шаг агента» (не менее 95 % строк без оговорок, остальное в ведомости) проходят проверки загрузки; ошибки перевода — списком с «файл:строка:столбец».
- Версия 2.5 в схеме, проверках и интерпретаторе: набор литералов, `ид`, `new_id`; красные пробы на нарушениях.
- `nova test src --jobs 4` зелёный (и `--strict-effects`); не менее 250 новых проверок; красная проба показана; стражи 8 и больше, FAIL 0.
