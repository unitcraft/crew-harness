## Что нужно

1. **Источники (только чтение).** Методика: `task-runner-session-states.md`, `task-runner-session-automaton.md` (таблица, данные, типы, контракт, «Решения при переводе»), `state-machine-pause-states.md` (фрагмент «Пауза»), `state-machine-call-protocol.md`, `state-machine-agent-step.portolan.md` и спецификация Портолана 2.11 (русский нормативен); у нас — `src/machine/machines/` (agent_step, dialog, chat), `src/machine_run/`, `src/machine_text/`, `src/portolan_cli/`, итоги задачи 119 (`analysis.md`, `src/machine/README.md`), план 105 (`matrix.md`, строки Э2: A13 C05 L01 L02 L03 L06 L07 P10), тесты плагина `crew-flow`, `crew-push`, `crew-hung-turn`, `crew-restart`, `crew-step-yield` (описывают поведение, которое должно сохраниться). Пути к методике — в промпте исполнителя; в файлах репозитория писать словами.
2. **Разбор (в `analysis.md` первой частью, до кода).** Состояния и переходы машины по таблице; какие данные, примитивы и внешние объекты она читает и пишет; где вызывает «Шаг агента» (сторона вида `machine`), как принимает «стоп», «продолжить», «отмена»; что из таблицы не ложится на возможности интерпретатора (список, номера строк); как проверяется равенство с методикой.
3. **Реализация.** (а) `src/machine/machines/session_start.portolan.md` (русский вид) и `.portolan.json` (перевод командой `portolan compile`), английский вид — командой `portolan convert`; круг `compile → render → compile` равен; (б) запись в реестре вызываемых машин: «Шаг агента» и «Запуск сессии» (вызов из «Раннера» подготовлен, сам «Раннер» — задача 123); (в) примитивы, нужные таблице (чтение задания, файловые операции сессии), — как данные реестра с тестовым исполнителем (`ScriptedHost`); боевые файловые исполнители в эту задачу не входят; (г) сценарии `src/machine/scenarios/session-*.scenario.test.json`: по строке на каждую строку таблицы и сквозные (запуск, объём, сессия с агентом, разбор итога, пауза, остановка, ошибка, перезапуск посреди вызова, ответ вложенной машины после отмены).
4. **Равенство с методикой.** Журнальные коды и параметры на сценариях сверяются с таблицей журнала методики (`state-machine-journal.md`) и с рукописным автоматом методики, если он есть; расхождения — в `analysis.md` и письмом Методике через оркестратора.
5. **Проверки.** Красная проба до кода (число красных в `log.md`); не менее 100 новых проверок; `nova test src --jobs 4 --timeout 600` и `--strict-effects` зелёные (при необходимости на временном контейнере PostgreSQL: `src/pg/testdb.ps1`, затем `-Stop`); стражи `sh scripts/guards/run-all.sh` ок и больше, FAIL 0; `portolan check/compile/render/run/test` принимает машину; коммиты по правилам AGENTS.md (по темам); метки `// ORACLE-WORKAROUND(N): …` на обходах Oracle, новые пункты README — со следующего свободного номера, согласованного с задачей 119 (119 берёт с 60, эта задача — с 70).
6. **README** `src/machine/README.md`: машина, сценарии, что не поддержано.
