# Задание: устаревший вопросник закрывается, когда вкладка задала новый

Заказчик: владелец репозитория `unitcraft/crew-harness` (он же отвечает на вопросы и принимает результат).
Репозиторий: `unitcraft/crew-harness`, ветка `main`. Дата задания: 2026-10-17.
Источник: 2026-10-17 после перезапуска окон владелец ответил на пять накопившихся вопросов через `crew-answer`. Для двух из них ответ
«не применён: the turn was not interrupted»: вкладка уже кончила ход и потом задала тот же вопрос новой формой с новым id (вкладки
повторяют вопрос по `form-wait.ts`: до трёх раз, потом «без ответа, нужен владелец»). Старые формы остаются открытыми в списке
(`crew-answer`, панель, «Ждут вас»): `frm_14734c69…` у сессии проверки задачи 061 (частичный отчёт интегратор уже получил),
`frm_1482d8f1…` у интегратора crew-harness (тот же вопрос задан заново формой `frm_14981877…`). Ответ на такую форму никуда не идёт, а
владелец видит дубль и не знает, который из них настоящий.

Задача полная: разбор, реализация, сдача. Быстрый путь. Основа — свежий `origin/main`.

## Чего хочет владелец

- «по рекомендации» (владелец, 2026-10-17, чат оркестратора) — на предложение оркестратора: закрывать форму, если вкладка уже задала
  новую, чтобы устаревшие дубли не копились; решено вынести в отдельную задачу 071, потому что 070 уже собрана в пакет.

## Что нужно

1. **Разбор:** жизненный цикл формы в `form-wait.ts` и связанных местах (`forms/<id>.json`, статусы, повтор до трёх раз, «без ответа
   после повторов», `crew-answer`, `ownerAnswer`): когда форма остаётся открытой после того, как вкладка задала новую; чем отличается
   «вкладка повторила тот же вопрос новой формой» (старая устарела) от «вкладка задала второй, другой вопрос» (обе действуют);
   как узнать, что новая форма — тот же вопрос (текст вопроса и варианты совпадают; не угадывать по близости).
2. **Правка:** у одной вкладки одновременно не больше одной открытой формы с одним и тем же вопросом: когда вкладка задала форму с
   тем же текстом и вариантами, старая форма закрывается со статусом «заменена новой» (запись в `forms/` остаётся для истории), не
   показывается в списке открытых, в «Ждут вас», в панели и не считается ожиданием владельца; ответ на неё — понятный отказ «вопрос
   задан заново формой `<id>`, ответьте на неё». Форма вкладки, чей ход давно кончился и которая не повторена, остаётся (вопрос
   действует) — такой случай не затрагивать.
3. **Уже накопленные дубли** закрываются тем же правилом при первом проходе после обновления (по записям `forms/`, без ручных
   правок файлов).
4. **Тесты:** красная проба до кода (вкладка задаёт тот же вопрос новой формой → старая «заменена», в списке одна; другой вопрос —
   обе действуют; неповторённая форма остаётся; ответ на замененную — отказ с подсказкой); полный `npm test` по 4 файла, упавшие по
   одному ([AGENTS.md](../../../../AGENTS.md), пп. 8–9); golden — только изменившиеся ключи.
5. README плагина — абзац.

## Критерии приёмки

- Красная проба до кода падает на источник (две формы с одним вопросом у одной вкладки обе в списке открытых) и проходит после правки.
- На живых данных (только чтение) правило назвало бы устаревшими `frm_14734c69…` и `frm_1482d8f1…`, а действующими — их повторы.
- Полный `npm test`: упавшие при параллельном прогоне проходят по одному; стражи — 8, FAIL 0.
