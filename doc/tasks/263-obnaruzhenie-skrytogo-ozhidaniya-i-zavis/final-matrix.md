## Границы гарантий

- После timeout/restart исходный HTTP/tool call умер. Stale recovery — не его результат и не новое согласие владельца.
  Для текущих ворот требуется новое действительное решение. Старая запись не будит агента и не меняет его задачу/ход.
- Долговечность recovery опирается на существующий journal append движка: answer + признак recovery — один input.
  Ack чтения тоже журналируется. Транзакционное exactly-once получение HTTP-ответа `crew_inbox` клиентом не обещается:
  при обрыве после durable read-marker ответ остаётся в журнале, но новый вызов/команда агента не создаётся.
- Плагин отвечает одним полем q0; многовопросные формы отказываются в окно, неподдержанный сервером ответ не подменяется.
  409 не доказывает, какой ответ выиграл; transport/5xx — unknown без автоповтора. Новая auth-система не добавлялась.
- Диагноз ограничен проверенными источниками и последними 20 assistant-сообщениями. Нет данных — неизвестно.
  `busy/running` не является самостоятельным доказательством работы; PID из файла — не проверка процесса ОС.
- Реальная q0-проба не затронула question 258 или решения владельца; модель использовала только question.
  Две fixture-сессии помечены тестовыми и не назначены пользователю/задачам.
- Код 260 сохранён: Hub.handle, Hub.watch_agent, Rig.page и Rig.page_id байт-в-байт совпадают с целевой базой.
  Проверки обоих сигналов message_delivery/mcp_recovery_read сохранены; словарь содержит 22 сигнала. 264 route сохранён.
- Shared live target exe не использовались. Порты/preview Crew не поднимались; процессы чужих preview/live не трогались.
