# Задание: Канон — догнать актуальную версию методики после pin a449bd2e

Заказчик: владелец репозитория `unitcraft/crew-harness` (он же принимает результат).
Репозиторий: `unitcraft/crew-harness`, ветка `main`. Дата задания: 2026-10-19.
Источник: слова владельца в чате оркестратора, 2026-10-19: «догони методику сейчас»; ранее владелец (2026-10-16): на каждый push методики считать дельту и править Канон; после задачи [061](../../061-kanon-i-aktualnaya-metodika/) Канон стоит на pin `a449bd2e`, а методика ушла вперёд (305 коммитов, папка `state-machines/`, новые машины и правила).

Задача полная: разбор, реализация, сдача. Быстрый путь. Основа — свежий `origin/main`. Правки только `doc/canon/` и папка задачи.

## Чего хочет владелец (его слова, 2026-10-19, чат оркестратора)

- «догони методику сейчас» — Канон должен следовать актуальной версии методики.
- Правило владельца (2026-10-16): «на каждый push методики считать дельту и править Канон»; методика — основа Канона (ADR-0012, `doc/canon/README.md`).

## Что нужно

1. **Дельта.** Репозиторий методики `unitcraft/ai-dev-methodology` (чужой, только чтение: `gh api` или клон на машине): `git diff a449bd2e origin/main` для корневых файлов (`methodology.md`, `task-sessions.md`, `task-runner.md`, `completeness-check.md`, `AGENTS.md`, `README.md`) и `state-machines/README.md` (индекс); сами файлы `state-machines/` (код автоматов, протокол вызова, словарь) в Канон не копируются, на них дают ссылки. Таблица дельты `doc/tasks/103-canon-methodology-sync/delta.md`: каждое изменение методики с коммитом-источником, влиянием на Канон («меняет правило / нет / только справочно») и решением.
2. **Правка Канона** по таблице: `doc/canon/README.md` (строка версии методики и ссылки на `state-machines/` по новым путям), `process.md` (чем проект отличается от методики; новые правила — «вратарь»/усиленный вратарь с разрешением владельца, «предположение вместо ожидания», «потолок доказательства» K=3 и упрощённые ворота alpha — ТОЛЬКО как отсылки к нормам методики с датой и источником слова владельца; если норма в методике ещё «предложение», так и писать), ADR о версии методики (новый ADR или дополнение к ADR-0012: новый pin, дата, причина). Только то, что следует из дельты; новых правил от себя не вводить; слово владельца — дословно с датой и источником.
3. **Pin.** Новый pin — коммит методики на момент сдачи (хеш полный, дата); проверка: `gh api` подтверждает, что коммит есть в `main` методики. Хеш и дату пишет задача, оркестратор подтверждает свежесть перед пушем.
4. **Проверки:** стражи 8 и больше, FAIL 0 (`sh scripts/guards/run-all.sh --index`; ссылки на файлы методики — только на публичный репозиторий `unitcraft/ai-dev-methodology`; страж ссылок не должен краснеть); красная проба — не нужна, документальная задача; независимое чтение: каждое утверждение Канона о методике сверено с её текстом (список сверок в `analysis.md`); коммит по правилам AGENTS.md (английское сообщение, `-s`, без трейлеров и без `#число`, файлы перечнем).

## Критерии приёмки

- `doc/canon/README.md` указывает новый pin; `process.md` и ADR отражают влияние дельты, без выдуманных правил; слова владельца дословно с датой.
