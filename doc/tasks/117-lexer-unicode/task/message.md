## Что нужно

1. **Что выяснено оркестратором на Oracle 0.1.0 (проверено программой).**
   - Срез `str[a..b]` — по БАЙТАМ: `"приветA"[0..2]` даёт «п», `[0..3]` падает паникой «slice splits a UTF-8 codepoint». `s.len()` снят (`E_STR_NO_LEN`): есть `byte_len()` и `chars().count()`.
   - `std.unicode` собирается и работает, если импорт идёт по модулю: `import std.unicode.{is_alphabetic, is_uppercase}` и методы `char @is_alphabetic()`, `@is_uppercase()`, `@is_lowercase()`, `@is_whitespace()`, `@is_numeric()`, `@general_category()`, `@to_lowercase()`; проверка на строке `"приветA7_δ数 "` даёт 9 букв и 1 заглавную (верно). Импорт по файлу (`std.unicode.category.{…}`) не собирается (`decode_at` — функция соседнего файла модуля): это неверная форма импорта, а не ошибка стандартной библиотеки.
   - Лексер сейчас: `tx_chars(s)` строит `[]str` по строке на символ (`"${c}"` в цикле), `tx_slice(items, from, to)` склеивает куски; `tx_is_letter` (Latin и кириллический блок U+0400–04FF), `tx_is_upper`, `tx_is_lower`, `tx_is_space` — вручную. Это 34 вхождения в `src/machine_text/*.nv`. Недостатки: имена на других алфавитах не принимаются (дефект), лишние выделения (образец «Шага агента» переводится около 1 с).
2. **Источники:** `src/machine_text/lex.nv` (и все файлы, где встречаются `tx_chars`, `tx_slice`, `tx_is_letter`, `tx_is_upper`, `tx_is_lower`, `tx_is_space`, `tx_is_digit`: grep по `src/machine_text*`), `src/machine_text/README.md`, тесты `src/machine_text*/…_test.nv` (ожидаемые строки и столбцы ошибок), стандартная библиотека Нова — `std/src/unicode/category.nv`, `graphemes.nv`, `ranges.nv`, `cp_utils.nv` (в установленном Oracle: каталог `std/src/unicode/` рядом с `nova.exe`), `spikes/env/README.md` (пп. 1–44), `doc/tasks/113-portolan-bilingual/analysis.md`.
3. **Лексер на байтовых смещениях.** Убрать `tx_chars` и `tx_slice`; позиции в строке — байтовые смещения; столбцы в сообщениях об ошибках остаются СТОЛБЦАМИ СИМВОЛОВ (как сейчас: для кириллицы и 4-байтных букв значения прежние, все существующие тесты с ожидаемыми `файл:строка:столбец` зелёные без правки ожиданий), столбец считается по `chars()` от начала строки до смещения, а не копированием строк; срезы — `s[from..to]` только на границах символов (смещения берутся от итерации по символам, например по накапливаемой длине в байтах символа).
4. **Буквы по Юникоду.** `tx_is_letter`, `tx_is_upper`, `tx_is_lower`, `tx_is_space` — на `std.unicode` (`is_alphabetic`, `is_uppercase`, `is_lowercase`, `is_whitespace`) плюс `_`; имена данных, типов, состояний и параметров принимают любые буквы Юникода (и цифры после первой), проверка регистра для различения типа и константы работает для любого алфавита, где есть регистр (греческий, кириллица, латиница с умлаутами); алфавиты без регистра (китайский) — как «ни верхний, ни нижний»; запись такого имени в JSON и обратно (`render`) без потерь, круг `md → JSON → md → JSON` на имени с умлаутом и греческом равен.
