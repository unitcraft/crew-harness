Заказчик: владелец репозитория `unitcraft/crew-harness` (он же отвечает на вопросы и принимает результат).
Репозиторий: `unitcraft/crew-harness`, ветка `main`. Дата задания: 2026-10-17.
Источник: 2026-10-17 ~01:12 интегратор Новы задал владельцу вопрос (`question`, вопросник в окне). Владелец, не отвечая, открыл
`/crew-sets use kimi`; окно плагина показало ответ, владелец закрыл его клавишей Esc, и тот же Esc отменил вопрос под ним:
в записи сессии вызов `question` кончился ошибкой, вопрос исчез. Владелец заметил по тому, что вопрос «отменился на фоне» и

   сразу обоим; есть ли в API плагина способ поглотить клавишу или поставить обработчик перед вопросником (слой `keymap`,
   `api.keymap.registerLayer`, приоритет, `stopPropagation`, флаг модального окна). Не угадывать: подтвердить пробой на живом

   открыто поверх вопроса, вопрос остаётся открытым и виден после закрытия.
3. **Запасной вариант, если поглотить Esc нельзя:** пока под окном плагина открыт вопрос владельцу (запись `forms/` вкладки

   отменённый без ответа (запись `forms/` открыта, вызов `question` кончился ошибкой), плагин возвращает вкладке сразу, а не по
   таймеру задачи 040 (письмо «задай вопрос заново» уже есть — проверить, что срабатывает быстро и вопрос не теряется).
4. **Тесты:** красная проба до кода на выбранный путь; полный `npm test` параллельно по 2–4 файла (машина загружена),
