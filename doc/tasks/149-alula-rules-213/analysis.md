## 0. Решение

1. Принимается одна форма: формат 2.14 по правилам 2.13. Синтаксис 2.12 под строкой `format: 2.14` (`Вход:`, `слово(…)`, столбец «слова ворот», Unicode-операторы, раздел «Раскрытие фрагмента», `HashMap[K, V]`, параметр `слово_остановки`, русское имя без JSON-имени в скобках) не читается: переводчик называет прежнее написание и новое; декодер дерева отвергает `words`, событие `word`, ключ `words` у перечисления. Переходного периода нет (слово владельца, 2026-10-20).
2. Таблица слов — файл методики `alula-keywords.tsv` как есть (216 строк); слой продукта `keywords_product.tsv` приведён к ней (параметр фрагмента `сигнал_остановки` / `halt_signal`).
3. Словарь методики (`names.tsv`, версия 10) переводчик больше не читает (AL-46: «словарь — только источник предлагаемых имён, разбор его не читает»). Остаётся то, что принадлежит продукту, а не словарю: имена вложенных машин реестра хозяина (`шаг_агента` → `agent_step`) и имена сигналов протокола фрагмента «Пауза».
4. Не делаем (названо Методикой открытым): ворота человека как событие без запроса, сигнал стороны без строки в текущем состоянии, две записи `Находка`, общий файл типов вызова (раздел 14 спецификации); формат 2.15 и позже.

## 3. Расхождения со спецификацией и вопросы Методике

1. **Имя вложенной машины.** В образце «Совещание» сторона `machine шаг_агента(…)` и параметр `вложенные: [шаг_агента]` называют машину по-русски без JSON-имени; правило AL-46 такого имени в перечне выходящих из машины не называет. Решение: имя берётся из реестра хозяина (у нас — таблица `names_host.tsv`: `шаг_агента` → `agent_step`, `совещание` → `meeting`, `проверка_цикла` → `review`, `запуск_сессии` → `session_start`, `раннер` → `runner`); латинское имя читается само. Вопрос: как нелатинское имя вложенной машины получает JSON-имя в реестре.
2. **Поле с двумя JSON-именами.** Образец «Совещание» пишет `утверждение (statement)` и `утверждение (claim)` в разных типах, `находки (findings)` и `находки (lens_findings)`. Переводчик не знает типов выражений: поле ищется по владельцу там, где он назван (литерал `Тип { поле: … }`, образец `Случай(поле)`, сигнал `имя(поле: …)`), а ссылка без владельца (`x.поле`, строка таблицы запроса) на поле с двумя именами — ошибка «объявлено в машине с разными JSON-именами». Следствие: «Совещание» читается целиком, кроме двух мест с `находки` без владельца. Вопрос: как Методика называет владельца в таких ссылках.
3. **Поля запроса.** Имя поля запроса (`| ход | … |`) не входит в перечень AL-46; берётся из полей типов, иначе из данных (как до сих пор), иначе латинское само.
4. **Фрагмент «Пауза».** Состояния и сторона фрагмента названы в его тексте по JSON-имени (`Halted`, `Pause`, сторона по `id` `enhanced`), чтобы фрагмент находил их при любом написании машины; сигналы протокола и их поля (`стоп человека` → `human_stop`) задаёт таблица продукта вместо файла фрагмента (Я-35 открыт).
5. **Пустые значения.** Спецификация говорит «не пишутся»; чтение отвергает `Запрос: нет`, `Читает: —`, `Срок тишины: —`, `При входе: —` с понятным сообщением (иначе файл 2.12 читался бы молча).

6. **Заглушки в «Совещании».** Четыре параметра образца имеют значение `0 (заглушка источника)`; это не значение выражения. Тест убирает примечание в скобках; вопрос Методике: допускается ли примечание в ячейке «по умолчанию».
7. **Поле остатка транспорта.** Образец Методики пишет `transport_usage`, сценарии и движок продукта — `usage`; таблица продукта `agent_step` — образец плюс `расход (usage)` в пяти типах ответа. Вопрос: общее имя поля для продукта и Методики.
8. **`ScEvent.party`.** Запись события сценария получила поле `party` (API пакета 0.3.0); потребители (`machine_chat`, `machine_dialog_eq` продукта) дописали `party: ""`.
