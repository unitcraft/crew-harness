# Задание: проект без настроек моделей — отказ с вопросом владельцу вместо молчаливого выбора по умолчанию

Заказчик и владелец: владелец репозитория `unitcraft/crew-harness` (он же отвечает на вопросы и принимает результат).
Репозиторий кода: `unitcraft/crew-harness` (https://github.com/unitcraft/crew-harness, ветка `main`). Дата задания: 2026-10-12.
Источник: наблюдение 2026-10-12 в проекте методологии: интегратор завёл задачу, она запустилась на ступени `heavy` с моделью Claude Opus, потому что в `.opencode/crew-harness.json` проекта не было ни `profile_set`, ни `model_profiles`, ни `tier_max`; плагин молча взял значения по умолчанию и расходовал лимит Claude.

Задача полная: разбор, план, реализация, сдача.

## Чего хочет владелец (его слова, 2026-10-12)

- «ты не думаешь, что если модель для воркеров не задана, то должна быть ошибка при попытке создать воркер? либо: у вас проект не настроен, выберите модель для запуска воркера? либо: проект не настроен, перейти к настройке проекта? (и запускать гид)»
- «либо если модель не задана, то в варианте вопросника модель из интегратора; в целом я с тобой согласен, что будешь делать?» — владелец согласен с отказом и гидом и добавляет вариант: модель интегратора (текущей сессии) предлагается среди вариантов вопроса.

## Что есть сейчас

- Проект без настроек моделей при создании задачи (`crew_spawn`, поручение интегратора) получает модель по значениям плагина по умолчанию (ступень `heavy` — Opus и т. д.), без предупреждения. Ни `crew_doctor`, ни `/crew` не сообщают, что у проекта нет настроек моделей.
- Проекты, где настройки есть (`profile_set`, `tier_max`, `model_profiles`), этой проблемы не имеют; настройки читаются с целевой ветки.

## Что нужно

- **Отказ при создании задачи**, если для проекта нельзя определить модель ни из настроек проекта (`profile_set`/`model_profiles`/`profile_sets`, `tier_max`), ни из явного параметра вызова (`model`). Текст отказа: что именно не задано, и **что делать**: интегратору — спросить владельца инструментом `question` с вариантами: (1) применить стандартный набор (рекомендация: `codex`, потолок `light`); (2) использовать модель текущей сессии интегратора для воркеров (в тексте названа модель сессии, вызывающую `crew_spawn`; применяется явным параметром `model` или записью в настройки по выбору владельца); (3) выбрать иное. Затем `crew_config` записывает настройки, задачу можно создавать.
- **Шаблон в `crew_config`:** действие «применить стандартный шаблон» (профили и наборы как в настройках crew-harness: `claude`, `codex`, `kimi`; `profile_set: codex`; `tier_max: light`; шаблоны ветки и дерева) в файл настроек проекта с напоминанием, что файл должен быть закоммичен в целевую ветку (иначе действует прежнее состояние).
- **Видимость заранее:** `crew_doctor` и сводка `/crew` показывают «проект X не настроен: модели» для каждого зарегистрированного проекта без настроек моделей.
- **Явное разрешение прежнего поведения:** ключ настроек проекта (рабочее имя `allow_default_models: true`), для осознанного использования значений по умолчанию; по умолчанию выключен.
- Тесты по одному, с паузами ([AGENTS.md](../../../../AGENTS.md)); красная проверка до правки; существующие тесты, создающие задачи без настроек, получают настройки в тестовом проекте или явное разрешение (не ослабляя проверку).

## Что надо выяснить в разборе

- Где в коде выбирается модель по ступени и профилю (`profiles.ts`, `profile-layer.ts`, `core.ts`, `crew_spawn`, поручение интегратора), что считать «модель определена» (есть набор профилей и выбранная ступень не выше потолка; либо явный `model`).
- Как плагин узнаёт модель текущей сессии интегратора (карточка, `model.request`, база).
- Какие тесты опираются на значения по умолчанию и как их перевести.
