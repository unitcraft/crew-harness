# Задание: CrewHarness как свой продукт — сервис координации агентов, драйверы агентов, пульт в браузере

Заказчик и владелец: владелец репозитория `unitcraft/crew-harness` (он же отвечает на вопросы и принимает результат).
Репозиторий кода: `unitcraft/crew-harness` (https://github.com/unitcraft/crew-harness, ветка `main`; локальная копия у исполнителя). Дата задания: 2026-10-07.

Этой задачей получаем **утверждённый план** работ (spec.md и plan.md по методике); реализация — отдельно, после
утверждения.

## Что есть сейчас

- `opencode-plugin/` — рабочий плагин OpenCode V2 (TypeScript): задачи с приоритетами и очередью, отдельный
  приёмщик с шагами приёмки, замок вливания (одно вливание за раз), письма между сессиями агентов, вопросы с ответом,
  обязательства и напоминания, наблюдения за долгими командами (`crew_watch`), очередь машины для тяжёлых команд
  (`machine_slots`, `heavy_commands`), планы (перепроверка раундами, согласование владельцем, шаги → задачи),
  уборка веток и деревьев, сводка «кто чего ждёт», боковая панель окна, MCP-сервер `crew` для вкладок Claude Code.
  Логика в `opencode-plugin/core.ts` и соседних модулях; MCP — `opencode-plugin/mcp.ts`.
- Плагин живёт внутри одного процесса сервера OpenCode; этот сервер держит все сессии в одном процессе и под
  нагрузкой (≈ 8 параллельных задач, несколько тяжёлых прогонов на машине) зависает и перезапускается — подробности в
  `research-many-agents.md`.
- `doc/plans/` — прежние планы плагина (001–014 закрыты), `doc/research/` — исследование альтернатив.
- Проект-пользователь: nova (язык программирования Нова, https://github.com/nv-lang/nova) — интегратор, исполнители, приёмщики
  работают через плагин; второй проект — claude-limits.

## Что нужно получить (результат продукта, не этой задачи)

1. Сервис координации вне OpenCode: всё, что сейчас умеет плагин (список выше), плюс ведение задачи по циклу
   `task-runner.md` (фазы, ворота, заходы, прогресс, state.json, логи).
2. Драйверы агентов: запуск агента в дереве задачи, продолжение сессии, состояние «работает / ждёт / закончил»,
   остановка, передача картинки; правила хуками агента, где хуки есть.
3. Пульт владельца в браузере: доска задач, ворота (утверждения, ответы, решения), живой терминал агента, чат с
   агентом, вставка картинок.
4. Переезд проектов с плагина OpenCode на продукт без потери задач и писем.
5. Путь переноса сервиса на язык Нова.

## Ограничения и известное

- Подписки, а не ключи API: каждый агент — официальный CLI своего вендора на подписке владельца; для Claude —
  только немодифицированный Claude Code (см. `research-many-agents.md`).
- Windows (машина владельца), без WSL.
- Машина перегружается тяжёлыми прогонами; очередь машины обязательна.
- Плагин OpenCode используется каждый день (проект nova): ничего в нём не ломать до переезда.
- Язык Нова: факты — в `nova-facts.md` (выписка из спецификации репозитория nova).
- Возможности CLI агентов — в `agents-capabilities.md` (из сторонних обзоров, официально не сверено).
- `draft-plan-previous.md` — прежний черновик плана исполнителя, до решения работать по методике; справка, не
  требование.
- **Приватное не в публичное (владелец 2026-10-07):** репозиторий crew-harness публичный; в spec, plan и всё, что
  уйдёт в репозиторий, — без локальных путей машины владельца и приватных репозиториев; Нова — только
  https://github.com/nv-lang/nova.
