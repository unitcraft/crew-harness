# Разбор: тишина в живых ходах и пороги «завис»

Замер 2026-10-13 по базе OpenCode (только чтение), строки `session_message` за 7 дней: assistant 17169, user 4017, idle 3782,
synthetic 1150, system 204, model-switched 31, compaction 27, location-switched 24, agent-switched 9.

## Замер

Тишина = время от последней активности (максимум `time_updated` предыдущей строки) до создания следующей строки внутри хода
(между строкой `user` и ближайшей `idle`), только закрытые ходы; `agent-switched` и `user` пропущены. 11917 разрывов:

| медиана | 95-й | 99-й | 99,9-й | максимум |
|---|---|---|---|---|
| 0,05 с | 1,8 с | 62 с | 194 с | 81 мин (один ход: строка synthetic после долгого инструмента) |

Остальные разрывы короче 5 мин. Строка `assistant` обновляется до 160 мин после создания (долгая одиночная генерация), поэтому
активность считается по `time_updated`, а не по `time_created`.

## Решения

- Активность модели: обновление строк `assistant` (вызовы инструментов лежат частями в ней) и `compaction`. Не активность: `user`,
  `synthetic` (письма плагина), `agent-switched`, `model-switched`, `location-switched`, `system`, `idle`.
- Окно открытого хода `OPEN_TURN_MAX_MS` = 45 мин (было 4 ч); порог «завис» `HUNG_MS` = 15 мин. Нормальная тишина — до 5 мин;
  единственный случай дольше (81 мин) — долгий инструмент, он закрыт проверкой: идущее наблюдение `crew_watch` или часть `tool`
  в состоянии running/pending в последней строке ответа — не «завис».
- Переопределение для тестов: `CREW_HARNESS_OPEN_TURN_MAX_MS`, `CREW_HARNESS_HUNG_MS`.
- Связь с существующим: `hungTurn` (core.ts) стоит рядом со `staleBusy`; зависший ход — вкладка занята по окну, `staleBusy` = 0
  (база хода не видит иначе, чем «открыт»), строки idle после ответа нет. Статус — «owner» с уведомлением один раз (общий путь
  `since`), журнал — `hung turn:` / `hung turn cleared:`.
