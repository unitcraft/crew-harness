# Задание: Честная загрузка проектов и сессий в пульте Crew

Заказчик: crew-harness.integrator; задание собрано плагином из полей crew_spawn.
Репозиторий: проект crew-harness, ветка main. Дата задания: 2026-10-30.
Источник: слова владельца с датой — раздел «Чего хочет владелец».

## Чего хочет владелец

«пункты 1-5 - согласовано, супер быстро» (владелец, 2026-10-30, текущий чат).

## Что нужно

1. Реализовать согласованные пять улучшений загрузки пульта Crew в отдельной новой сессии/дереве от свежего origin/main. 1. При первом открытии скелетоны строк проектов/сессий и «Загружаем проекты и сессии…», не показывать ложное «нет данных» до успешного ответа. 2. Независимые состояния загрузки проектов и сессий, готовые данные показывать сразу. 3. Статус различает установление соединения, соединение с продолжающейся загрузкой и готовность; один открытый WebSocket не означает готовность данных. 4. При долгой загрузке неблокирующее сообщение; при ошибке понятная ошибка и рабочая кнопка «Повторить», не ложный пустой список. 5. При переподключении сохранять уже полученные данные, пометка «Обновляем…», без исчезновения списка. Только эти пять пунктов; широкую оптимизацию скорости серверной загрузки владелец отдельно не поручал. Сначала красные тесты, затем минимальное исправление. Не менять пользовательские сессии.

## Критерии приёмки

1. Тесты воспроизводят delayed initial response без ложных empty states. 2. Проекты и сессии могут завершаться в любом порядке, независимо ошибаться и повторяться; успешный пустой ответ отличается от pending/error. 3. Медленная загрузка и ошибка отображаются корректно; retry действительно повторяет нужный запрос, дубли и устаревшие ответы не портят состояние. 4. Reconnect сохраняет данные и выбранную сессию, корректно завершает обновление, не смешивает старые данные разных проектов. 5. Ненавязчивые skeleton/status, доступные подписи/aria-live без спама, таймеры очищаются. 6. Полный web набор и стражи через machine queue, если затронут backend — соответствующие тесты; независимая приёмка, signed-off коммиты точным списком. Отчёт SHA/команды/результаты и необходимость перезапуска.

## Результат и куда он попадает

Изолированное исправление UI/state загрузки в CrewHarness, тесты и отчёт для независимой приёмки, затем согласованная доставка.
