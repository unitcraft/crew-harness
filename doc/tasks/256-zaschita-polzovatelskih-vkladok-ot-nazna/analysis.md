# Причина и защита

## Плагин

`crew_task assign` в `opencode-plugin/core.ts` принимал id существующей карточки,
проверял проект и занятость, затем записывал `target.task` и отправлял письмо с
обязательством. Происхождение сессии и разрешение на использование беседы не
проверялись. Свободная worker-вкладка могла стать исполнителем чужой задачи.

В записи инцидента назначение задачи Методики 010 имеет `kind: assign`, а
карточка исполнителя — `auto: true`, без `spawned`. В истории сессии до назначения
есть разговор владельца. Это подтверждает путь захвата плагином, а не доказывает
ошибку OpenCode. Исходную сессию, её заголовок и историю расследование не изменяло.

Красная проба `crew-user-tab-guard.test.mjs` воспроизвела два захвата:
явный assign без разрешения и автоматический выбор свободного приёмщика.
После фикса оба запрещены. Отдельные проверки защищают от обхода через
`crew_role`: этот инструмент сбрасывает `auto`, но не подтверждает согласие
владельца. Поэтому граница — программное происхождение `spawned`, а не роль,
простой или `auto`.

Назначение пользовательской вкладке запрещено. В API нет доверенного подтверждения
владельца для конкретной пары «сессия + назначение»; произвольное `owner_words`
с id и датой агент может выдать себе сам. Это не разрешение. То же относится
к `allow_self_assign`. Отказ стоит до создания записи, номера, папки, письма и
обязательства. Он общий для инструментов плагина и MCP (`makeTools` в `core.ts`).
Первый вариант с проверкой текста разрешения отклонён интегратором при проверке
границы доверия; окончательный вариант не имеет текстового обхода.

Автоматический выбор приёмщика допускает только карточки с `spawned`;
пользовательская беседа с любой ролью не кандидат. Если выделенной свободной
сессии нет, создаётся новая штатным путём. Существующие проверки проекта, модели,
занятости, автора, исполнителя и предыдущих раундов сохранены.

Повторное использование программно созданного приёмщика требует сохранить его
жизненный цикл: новое назначение возвращает `spawned.status: running`, а завершение
старой задачи не закрывает сессию, уже занятую другой открытой задачей. Это проверяет
отдельная ячейка регрессии; существующие тесты приёмки сохраняют повторные раунды
и доставку отчёта о доработке.

`reassign` и запуск дополнительных сессий создают новые id, не выбирают свободную
беседу. Регрессия проверяет штатную передачу, новое программное происхождение и
сохранение заголовка и происхождения прежней пользовательской карточки.

## Заголовок инцидента

Единственный писатель заголовков плагина `syncTitles` уже пропускает карточки без
`spawned`. Assign не ставит `spawned`. Регрессионный тест проверяет отсутствие
`session.update` для пользовательской вкладки с прежней записью назначения.

Автор наблюдавшегося заголовка «010 исп …» не установлен. В доступной истории
инструментального вызова переименования не найдено. Известный алгоритм автозаголовка
OpenCode 2.0.26 не объясняет этот заголовок; доказательств, позволяющих приписать
переименование конкретному компоненту, нет. Отсутствие атрибуции переименования не
отменяет доказанного захвата через assign.

## Продукт Crew

В `src/server/crew_tools_hub.nv`, обработчик `ctl_task`, assign/order/reassign
и другие действия управления агенту недоступны: ответ «в продукте этого действия
нет — … делает владелец кнопками». Инструмент `crew_role` роль не назначает.
`crew_spawn` предлагает карточку владельцу, а после подтверждения создаёт дочернюю
сессию; не ищет свободную беседу по роли. Заголовок меняет обработчик действия
владельца `rename` с событием `session_renamed`.

В `scenario_crew_tools` добавлен тест явного отказа assign, рядом с существующим
тестом отказа присвоения роли. Код продукта менять для закрытия пути не требуется:
соответствующей операции у агента нет.

## Совместимость и доставка

Новые исполнители и штатная передача сохраняются. Намеренное изменение: прежние
сторонние вкладки, даже после `crew_role`, больше не выбираются автоматически для
приёмки; assign им запрещён, пока нет доверенного механизма подтверждения владельца.
Прежние записи assign остаются поддержаны тестовыми историческими фикстурами,
но создание таких записей новым вызовом запрещено. Письма `crew_send` не являются
назначением задачи и этой правкой не запрещаются.

Живая основная копия и сервис не менялись. Изменений API OpenCode, переносов файлов
и кода провайдера нет; специальной технической необходимости перезапуска для этих
правок нет (плагин подгружается на лету), применение к живой системе — только в
штатном порядке интегратором по разрешению владельца. Самостоятельного обновления
main, пуша и перезапуска не было.

## Проверено

- Красная проба до исправления: назначение пользовательской сессии и автоматическая
  приёмка воспроизводились. Затем дополнительно закрыты обходы через роль и
  поддельное `owner_words`, включая точный id с датой.
- Одиночная перепроверка первоначально красных файлов и регрессии: 7/7, 199 с.
- Финальный полный набор плагина: `node test/stable.mjs --all --runs 1 --jobs 2` —
  146/146 файлов зелёные, 848 с, через очередь машины.
- Полный набор `nova test src/server_crew_live --jobs 2 --timeout 600` единым
  комплектом Oracle 0.1.0 — PASS 1, FAIL 0, через очередь машины.
- Стражи: `sh scripts/guards/run-all.sh` — 10/10, FAIL 0 после полного прогона.
- `git diff --check` — чисто.

Независимая приёмка не выполнена исполнителем: результат передаётся интегратору.
SHA — в инструментальном отчёте сдачи после коммита этих файлов.
