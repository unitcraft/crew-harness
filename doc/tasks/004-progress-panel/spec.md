## Спецификация

### goal

Владелец видит в боковой панели окна OpenCode (и по команде окна), что сейчас делают фоновые сессии методики по каждой идущей
задаче — какая сессия, шаг «k из N», что делает, когда была последняя весть — и сразу видит, когда вестей давно нет;
для этого сессии пишут журнал `progress.log` одним закреплённым в Каноне форматом, а плагин читает его из всех рабочих
деревьев репозитория без заметной нагрузки на машину.

### current_state

- Панель — блок «Crew» (`sidebar.tsx`), строки строит `sidebarLines` (`status.ts:298`) из `status/<сессия>.json`, которые
  служба плагина пишет раз в 15 с (`index.ts:688`); панель перечитывает файлы раз в 2 с (`sidebar.tsx:9`). Фоновые сессии
  методики — не вкладки OpenCode и в `status/` не попадают (msg M-11). Команды окна: `/crew`, `/crew-config`, `/plans`,
  `/crew-doctor` (`tui.ts:173–177`).
- Журнал `progress.log` в папке каждой задачи сессии пишут сами; ничто в плагине его не читает (поиск по `opencode-plugin/*.ts`
  слова `progress.log` — 0 совпадений, Р-01).
- Плагин знает деревья только задач плагина: `worktrees` и `worktree_name` в настройках проекта (`core.ts:259–260`,
  `taskPlace` — `core.ts:542`) и поле `Task.worktree` (`tasks.ts:67`). У этого репозитория файла настроек проекта нет
  (`.opencode/` отсутствует, Р-02); дерево задачи 002 лежит рядом с репозиторием, вне его корня, и создано не плагином.
- Свежий журнал задачи 002 лежит в связанном дереве (573 строки, закоммичен в ветке), в основной копии — его начало
  (559 строк) (Р-01). Журналы задач 003 и 004 — в основной копии, не закоммичены (Р-01).

### expected_state

- Блок «Ход работ» в боковой панели под блоком «Crew» (решение владельца О-01): по каждой идущей задаче — номер и название,
  сессия словами, шаг «k из N», последняя подпись, время последней вести; при тишине дольше порога — пометка «давно нет вестей»;
  законченные и давно брошенные задачи исчезают.
- Команда окна `/crew-progress` показывает то же полнее: все идущие задачи репозитория вкладки, несколько последних строк
  журнала каждой сессии.
- Обновление само; чтение журналов без запуска процессов; все деревья репозитория находятся без настройки.
- Формат строки журнала закреплён в Каноне (process.md) и проверяется стражем (О-05).

### requirements

Все — обязательные (желательных после ответов владельца нет). «выведено» — сформулировано Сессией С1, а не взято из материалов.

REQ-01 Показ хода: для каждой задачи, у которой есть `progress.log` и показываемая запись (REQ-03) не скрыта по REQ-05 (сессия не завершена либо завершилась
  недавно), показываются: номер и название задачи, сессия словами (REQ-08), шаг «k из N», подпись последней строки,
  время последней вести. Источник: msg M-05, M-06, M-11, M-13, M-15.
REQ-02 Поиск журналов по всем рабочим деревьям репозитория вкладки — основной копии и связанным деревьям git, где бы они ни
  лежали (в том числе вне корня проекта), без настройки `worktrees`: список деревьев берётся у самого git
  (реестр `.git/worktrees/*/gitdir`: основная копия и записи с существующей папкой), а не из настроек плагина. Репозиторий — тот, в котором открыта вкладка на экране
  (`card.directory`, в том числе когда вкладка сама сидит в связанном дереве или в подкаталоге репозитория: корень находится без процессов
  подъёмом по родителям каталога вкладки до `.git` — каталог `.git` значит основную копию, файл `gitdir: …` значит связанное дерево, и общий `.git`
  берётся по `commondir`; путь в `gitdir` и `commondir`, не начинающийся с корня или буквы диска (git в режиме относительных путей), разрешается
  относительно каталога файла, где он записан). Источник: msg M-12, M-19; способ — выведено
  (Р-01, Р-02, Р-06).
REQ-03 Выбор копии — **по каждой сессии**, а не по задаче целиком. Деревья задачи: основная копия и записи реестра `.git/worktrees`, папка которых существует (REQ-02).
  Сессия — блок строк журнала с одним кодом, начатый строкой `k = 0` (Д-03). Сессию в разных копиях опознаёт ключ (код, порядковый номер среди **начатых** сессий этого кода от начала
  журнала копии). Строка запуска (REQ-14) принадлежит сессии того же кода, строка которой идёт следом в той же копии (`старт` или, если «старт» пропущен, строка с `k > 0`; N берётся из
  строки сессии); если следом нет строки того же кода, это запись «запуск без старта» с ключом (код, число начатых сессий этого кода **в этой копии** + 1). Запись «запуск без старта»,
  ключ которой совпал с ключом начатой сессии другой копии, — та же сессия, запуск лишь дополняет её (призрака «запущена, шагов нет» у идущей или законченной сессии нет); новая сессия того же кода
  начинается только по строке запуска, идущей в **той же копии** после предыдущей сессии этого кода (ключ получает следующий номер). Если порядок определить нельзя (без времени, в разных
  копиях), это одна сессия. Две записи «запуск без старта» одного ключа в разных копиях сводятся в одну — более поздняя строка запуска (по времени строки, без времени — из копии с более
  поздним временем изменения файла по REQ-04). Список сессий задачи — объединение сессий всех копий. Для каждой сессии берётся копия, где у неё больше строк (не считая строк запуска),
  при условии, что строки в другой копии — её начало; при равенстве (в том числе копии одинаковы целиком) — основная копия (время вести равных копий — по REQ-04); если ни одна не начало другой
  (разные строки одной и той же сессии) — копия с более поздним временем последней строки сессии, а при равном времени или если время есть не у обеих — копия дерева; запись помечена `≠`
  («журналы расходятся»). Выбор для каждой сессии определён всегда. Время изменения файла для выбора копии сессии не используется.
  **Вытесненная сессия** — такая, после которой в копии, выбранной для её ключа, началась другая сессия (любого кода): так устаревший снимок журнала в другом дереве не возвращает вытесненные
  сессии в кандидаты; кроме того вытеснен кандидат **без** времени, который не самый свежий (его «давно нет вестей» и скрытие от времени файла были бы ложными). **Кандидаты** — остальные
  сессии (последняя сессия копии и брошенный запуск без старта). **Показываемая запись** — кандидат с самой свежей вестью: сначала сессии хвостов (присутствующие в одной копии или различающиеся),
  затем сессии общего начала (они старше любой сессии хвоста); внутри группы — по моменту вести (время последней строки по REQ-04 с датой дня файла выбранной копии, а без времени — время
  изменения файла выбранной копии со знаком «≈»), при равенстве — более поздняя по порядку. Состояние задачи для порядка показа и группы «внимание» (REQ-07) — состояние **показываемой записи**.

REQ-04 Время вести и состояние последней сессии считаются при каждом показе от текущего времени (REQ-10). **Время в строке** —
  необязательное поле в начале подписи, ровно в форме `[ЧЧ:ММ]` и пробел: квадратные скобки буквальны, часы `00`–`23`, минуты `00`–`59`,

  в Python (страж): `^\[(?:[01][0-9]|2[0-3]):[0-5][0-9]\] ` (скобки экранированы обратной косой чертой; запись `[[]…[]]` в JavaScript

- Д-05 В панель помещается не больше 14 строк блока (заголовок, 3 задачи по 4 строки и нижняя строка); подробности — в команде (REQ-07, Н-01).

  для включения не нужно (DNC-07).

  неоконченной (приняты владельцем, О-02); переопределение — необязательными переменными окружения процесса окна (имена — решение плана); ключей
  настроек проекта нет (REQ-10, В-11).

  разных сессий — не расхождение: сессии объединяются (REQ-03).
- Д-10 Подпись последней строки — «последнее сделанное», а не «делает сейчас»: строка пишется по завершении единицы (`run`,
  «Протокол прогресса»); панель так и подписывает.
- Д-11 Регулярное выражение строки — одинаковое в JavaScript и в Python, только ASCII-цифры: `^([^ \t]+) ([0-9]+)/([0-9]+) ([^\n]+)$` (код — любые знаки кроме пробела и
  табуляции, цифры — `[0-9]`, остаток — любые знаки кроме перевода строки); файл читается как байты (UTF-8, недопустимые последовательности заменяются знаком U+FFFD, как в стражах задачи 002; граница слова у ключевых слов — по REQ-04) и делится по `LF` (не текстовым режимом и не `splitlines`: одиночный `CR` и U+2028 внутри строки её не делят), затем в конце строки снимается `CR`. Записи
  с классами `\S`, `\d` и точкой в Python и JavaScript ведут себя по-разному (цифры других письменностей, пробелы Unicode, Р-15). Строка без пробела и текста
  после N (обрезанная) не разбирается.
