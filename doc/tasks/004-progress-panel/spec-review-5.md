## Существенные находки

1. Таблица «куда пишется строка запуска» (REQ-14) вместе с правилом расхождения копий (REQ-03) делает невидимыми сессии, которые по таблице работают в основной копии при существующем дереве.
   - Что не так: REQ-14 отправляет С1, С1п, С2, С3, С3п, С4, **С7, С7п, С8, С9** в основную копию, а свои строки сессия пишет «в журнал того дерева, где работает» (текст для Канона).
     Источника места работы С7–С9 нет ни в spec.md, ни в материалах; зато в Р-01 «`result.md` есть только в дереве» — С7 читает `result.md`, значит работает в дереве, а правило канона
     (process.md, «Отличия», первая строка) говорит, что на воротах папка задачи коммитится в `main` — то есть работа С7–С9 в основной копии допустима тем же Каноном. Как только в дереве есть
     строки С5/С6, а в основной копии появляются строки С7 (или С3п/С4 после ветвления), ни одна копия не начало другой, и REQ-03 берёт копию дерева: строки С7 невидимы, а
     строка запуска из основной копии (код С7 в дереве не встречается, случай (а)) держит «запущена, шагов нет» до порога и «давно нет вестей» до 24 часов, хотя сессия идёт и пишет.
     Модель правила на синтетических копиях (проба 5, случай S1): основная копия = общее начало + `С7 0/0 запуск`, `С7 0/3 старт`, `С7 1/3 …`; дерево = общее начало + `С5 …`, `С6 4/4 готово`
     — выбрано дерево, показано последнее `С6 4/4 готово`, строки С7 в показ не попадают. Это ровно желание владельца «видеть ход фоновых сессий» для сдачи и проверки сдачи, и ни один AC этого не ловит
     (AC-24 берёт запуск `С6` в основную копию, хотя REQ-14 отправляет С6 в дерево).
   - Вторая сторона того же правила (случай S2 пробы 5): запуск из невыбранной копии с кодом, которого в выбранной нет, действует по (а) без сравнения с **самой поздней** строкой выбранной копии. Брошенный
     запуск (сессия не стартовала, оркестратор пошёл дальше) `С7 0/0 [10:00] запуск` в основной копии перекрывает идущую в дереве `С5п 1/3 [12:30] …`: показано «запущена, шагов нет», затем «давно нет вестей»,
     хотя вести свежие. Время есть у обеих строк, но сравнивается только со строкой того же кода (б). Оговорка REQ-20 («остаётся в панели до 24 часов») говорит о самой брошенной сессии, а не о том, что она заслоняет живую.
   - Цитата: «для остальных (С1, С1п, С2, С3, С3п, С4, С7, С7п, С8, С9) — в основную копию» (REQ-14); «(а) в выбранной копии нет ни одной строки с кодом запуска» (REQ-03); «берёт копию связанного дерева (там идёт работа)» (REQ-03).
   - Место: spec.md, REQ-14 (таблица мест), REQ-03 (правило запуска и расхождение), текст для Канона, AC-24.
   - Предложение: определить место записи не по коду, а по факту — после создания дерева все строки задачи (запуск и ход любой сессии, кроме тех, что работают до ветвления) пишутся в журнал того дерева, где лежат
     рабочие файлы сессии, источник места назвать; для запуска из невыбранной копии с временем сравнивать его с последней строкой выбранной копии любого кода, а при расхождении копий не отбрасывать
     строки основной копии, написанные после общего начала (показывать самую позднюю сессию по времени, без времени — по правилу, названному явно); добавить в AC-24 случаи «С7 работает в основной копии при дереве со строками С5/С6»
     и «брошенный запуск другого кода при идущей сессии в выбранной копии».
   - критичность: существенная (допустимый по тексту вход — сессия С7–С9 по таблице REQ-14 — приводит к тому, что ход сессии не виден, а на экране ложное состояние; сценарии приёмки этого не ловят)
   - уровень: требования

2. Выбор между равными по содержимому копиями не определён, а от него зависит, действует ли строка запуска, лежащая в одной из них, — результат расходится, и сценарий нельзя проверить однозначно.
   - Что не так: REQ-03 исключает строки запуска из сравнения, поэтому дерево, созданное С5 после записи запуска в основную копию (общее начало без новых строк), и основная копия равны: «одна и та же копия». Правило запуска (а)/(б) работает «из невыбранной
     копии» — какая из двух равных выбрана, не сказано (проба 5, случай S3: `chosen = null`). Если выбрана основная копия, запуск в ней обычная строка и виден всегда; если дерево — запуск в основной копии при уже использованном
     в дереве коде без времени не действует и остаётся видна прошлая сессия. Это ровно момент запуска С5д/С5п/С6 — самый частый для строки запуска.
   - Цитата: «Копии с равным числом строк и равным содержимым — одна и та же копия» (REQ-03); «Строка запуска в самой выбранной копии — обычная строка по порядку» (REQ-03).
   - Место: spec.md, REQ-03, AC-24.
   - Предложение: сказать явно, что при равных копиях выбранной считается копия дерева (как при расхождении), а запуск из основной копии при равных копиях действует по (а)/(б) так же; AC-24 дополнить этим случаем.
   - критичность: существенная (одно и то же входное состояние даёт разное состояние в панели в зависимости от выбора, не заданного текстом; по тексту нельзя написать проверяемый сценарий)
   - уровень: требования
