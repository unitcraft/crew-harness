1. Правило REQ-03 «запуск без старта, ключ которого совпал с законченной сессией другой копии, — новая сессия» противоречит AC-24 «Без времени» и ломает нормальный путь С5: после окончания сессии в дереве запуск в основной копии становится призраком.

Пока сессия идёт, REQ-03 сводит их по ключу (S0). Но как только сессия в дереве закончена (последняя строка `готово` или `стоп:`),
     ключ запуска в основной копии «совпал бы с законченной сессией другой копии», и по REQ-03 это новая сессия `С5#2` — «запущена, шагов нет». Кандидатами становятся обе: законченная `С5#1` из дерева и призрак `С5#2` из основной копии (последняя сессия своей копии). Те же входные данные в AC-24 «Без времени» читаются наоборот:
     «основная копия заканчивается `С5 0/0 запуск` при `С5 0/14 старт … С5 14/14 готово` в дереве — это та же сессия, показано «готово»; то же при `С5 13/14 стоп: ворота — …` — «остановилась: ворота»». Различить «первый запуск законченной сессии» (AC-24 «Без времени», Р-16) и «повторный запуск того же кода» (AC-24 S4) по двум спискам без порядка нельзя: ни номер (в основной копии законченной сессии нет, номер запуска тот же), ни время (у строк без времени его нет), ни другая копия.
   - Проба 3 (модель REQ-03, дословное прочтение): основная копия = общее начало + `С5 0/0 запуск`; дерево = общее начало + `С5 0/2 старт`, `С5 1/2 …`, `С5 2/2 готово`.      Для сессии, идущей (не законченной), выходит одна запись `С5#1` — S0 верен. Следствие по тексту: на всё время работы после первой С5 (С6, С5п, повторные проверки в дереве) в основной копии висит призрак; со временем в строках он не вытесняется (кандидат со временем оценивается по своему времени, REQ-03), в строке 2 стоит «+1»,
