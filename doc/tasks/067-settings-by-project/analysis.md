## 1. Разбор: где проект и папка настроек ищутся по папке вкладки

Единственный источник — `projectFor(dir, projects)` (`settings.ts`): проект — самый длинный корень, являющийся префиксом `dir`.
Рабочее дерево задачи лежит вне корня, проект не находился, и дальше по цепочке:

| Место | Что делало с `dir` вкладки | Последствие вне корня |
|---|---|---|
| `settings.ts` `projectFor` | префикс корня | проекта нет |
| `settings.ts` `rawSettingsFor` | `p?.dir` или `legacyWalk(dir)` | прежняя форма: поиск файла вверх от дерева находит копию файла ветки задачи, а не основной папки |

Чтение и запись должны идти в основную папку проекта: рабочая копия файла в основной папке — то, что правит `use` и что читает
служба; копия файла в ветке задачи — другое состояние (в пробе она нарочно называет другой набор).

## 2. Как рабочее дерево сопоставляется проекту

Порядок в `projectFor(dir, projects, name?)`:

1. **Имя проекта из карточки вкладки** (`cards/<сессия>.json`, поле `project`), если оно названо и есть среди проектов плагина. Карточку
   плагин ведёт сам; у вкладки задачи или приёмки это проект задачи, где бы ни лежало дерево. Имя не совпало ни с одним проектом
   (запасное имя по репозиторию) — шаг пропускается.
2. **Корень** — самый длинный корень-префикс папки, как раньше (вложенный проект побеждает объемлющий).
3. **Основная папка репозитория дерева**: `git -C <папка> rev-parse --git-common-dir` указывает на `.git` основной рабочей папки; её
   родитель сопоставляется с корнями проектов тем же правилом. У основной папки результат — она сама, шаг ничего не меняет.

Выбор способа и довод:
- **Имя в карточке — главное** (слово владельца, 2026-10-17: «по рекомендации» — настройки ищутся по проекту, имя в карточке, а не по
  папке). Но одного имени мало: карточку метит `projectOf(card.directory)` при каждом касании, а у вкладки, переехавшей в дерево
  `session_move`, это имя оставалось запасным по репозиторию; кроме того, поиск идёт и без карточки (`loadConfig(dir)`, задачи,
  `crew_spawn`) — нужен надёжный путь по папке.
- **`git rev-parse --git-common-dir`** — ссылку «дерево → репозиторий» хранит сам git, она не зависит от имени папки дерева и от места,
  где дерево лежит. Один процесс git в папке самой вкладки; ответ не меняется — кэшируется навсегда (промах «не репозиторий»
  перепроверяется через 30 с).
- **`git worktree list` основного репозитория** отвергнут: нужно сначала знать основной репозиторий (то, что мы и ищем), разбирать
  текстовый вывод, а список включает убранные деревья, которые папкой вкладки быть не могут.
- **Угадывание по имени папки** отвергнуто заданием: ломается при любом другом шаблоне.
- Голый репозиторий и подмодуль (`--git-common-dir` не заканчивается на `.git`) проектом не бывают — результата нет.

Прежняя форма опций (имя → корень): файл ищется вверх от корня проекта, если вкладка стоит вне корня.
