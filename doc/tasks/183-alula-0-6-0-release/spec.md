## Спецификация

### goal

Пакет `alula` 0.6.0 с форматом 2.24 опубликован по слову владельца; машины продукта и таблицы методики переведены на него.

### current_state

- FACT: на дату постановки пакет `alula` опубликован как 0.5.0 (Алула 2.23, `machine/2`); продукт зависит от 0.5 (задача 172).
- FACT: правки набора 2.24 нарезаны на задачи 173–181 по правилу «одна постановка — одна задача»; тексты 2.24 приходят от Методики и кладутся первой задачей 182.
- FACT: перевод продукта и методики на новый пакет делается отдельными задачами после публикации (после 2.23 — задача 172).

### requirements

REQ-1. Текст версии 2.24 записан в пакете: спецификации (ru, en), журналы изменений, перечень слов и два инструмента проверки лежат без изменений от Методики. (дочерняя 182).

REQ-2. Имя функции `непустое` (en `non_empty`) заменено на `обязательно_непустое` (`require_non_empty`), по старому имени — отказ с подсказкой (AL-128). (дочерняя 173).

REQ-3. Приоритеты операторов — по Нове D49, с ошибками со скобками (два сравнения подряд, `не` над сравнением); ни одна существующая таблица не меняет смысл молча (AL-132). (дочерняя 174).

REQ-4. Раздел `## Внешние функции` вместо `## Примитивы`; вызов `имя(арг)` без `вызвать`; старые формы — ошибка с подсказкой (AL-123). (дочерняя 175).

REQ-5. Объявление внешней функции в файле сверяется с реестром хозяина при загрузке; расхождение — ошибка с именем функции (AL-123). (дочерняя 176).

REQ-6. Дерево T1 хранит полную запись внешней функции (имя, параметры, результат, класс); рендер дерево → текст пишет раздел один в один (AL-123). (дочерняя 177).

REQ-7. Хвост параметров `...имя` у внешних функций и пары в вызове (AL-129). (дочерняя 178).

REQ-8. Контракт хозяина `bind_pure`, `bind_volatile`, `bind_acting` со стражем и тест-хостом; непроверяемое типами записано честно (AL-130). (дочерняя 179).

REQ-9. Три функции по роли (`parse_witness_reply`, `parse_author_reply`, `parse_lens_reply`) вместо `parse_agent_reply`; таблица «по роли» из реестра уходит (AL-131). (дочерняя 180).

REQ-10. Формат 2.24, хеши образцов, версия пакета 0.6.0, запись в историю, ни одной заглушки `AL-2xx`; пакет опубликован по слову владельца (метка `v0.6.0`). (дочерняя 181).

REQ-11. Машины продукта и методики в `machines/` переведены на 2.24, деревья пересобраны, продукт зависит от пакета 0.6.0. (дочерняя 184).

REQ-12. Набор таблиц Методики переведён на 2.24 тем же скриптом и передан Методике; репозиторий Методики не правится. (дочерняя 185).

Критерии эпика — команды; у каждой дочерней задачи свой критерий-команда, здесь только цель эпика.

AC-1. `alula version` печатает `alula 0.6.0 (Alula 2.24, machine/2)`.

AC-2. `alula test examples` зелёный.

AC-3. `python tools/check-alula-translation.py` и `python tools/check-alula-keywords.py --glossary …` — 0 расхождений.

AC-4. `nova test` всех папок пакета зелёные.

AC-5. Сценарии эпика на влитом коде в отдельном дереве: `alula test machines/methodology` и `alula test machines/product` (продукт) и `alula test alula-machines --registry … --journal …` (набор Методики) на 0.6.0 зелёные.

### Результат и куда он попадает

Результат: опубликованный пакет `alula` 0.6.0 (метка `v0.6.0`); продукт на 0.6.0 в `main`; набор таблиц Методики на 2.24 для Методики. Действующее место: пакет — его репозиторий, продукт — `machines/` и `nova.toml`, набор Методики — у Методики. Переносится шагами плана: слияние дочерних задач, публикация по слову владельца, задачи 184 и 185. Отдельного текущего описания (`current.md`) не нужно: действует то, что записано в пакете и в `machines/README.md`.
