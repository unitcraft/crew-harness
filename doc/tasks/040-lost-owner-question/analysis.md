# Разбор задачи 040: вопрос владельцу не пропадает молча

Дата: 2026-10-14. Разбор написан по отчёту исполнителя и проверке оркестратора.

## 1. Как узнать, что вопроса в окне уже нет

События шины (`form.created`, `form.replied`, `form.cancelled`) доходят не всегда: в журнале плагина стоит «form wait: event.subscribe unavailable … trying session.hook». Опираться только на них нельзя. Надёжный признак — ход вкладки: инструмент `question` ждёт ответа, пока ход идёт, значит вопрос на экране только у вкладки с идущим ходом. «Ход идёт» складывается из:

- `busy` окна (для открытой вкладки) или визитки (для сессии под задачу);
- `staleBusy` из базы: строка `idle` старше 10 минут и открытого хода нет — окно «залипло», вкладка считается не занятой;
- `pendingTool` (`core.ts`): в последнем ответе хода, начатого в этом процессе, есть инструмент в состоянии `running` или `pending`, строки `idle` после него нет — вопрос на экране, вкладка занята;
- `openTurn` для вкладки без окна.

Занятая вкладка не трогается, закрытая не будится (письмо только ждало бы). Запись о вопросе открыта, а хода нет непрерывно 20 секунд — вкладка получает служебное письмо.

## 2. Перезапуск

Запись, созданная до старта процесса (`at < PROCESS_START`), первые `FORM_RESTART_GRACE_MS` = 3 минуты не трогается: окна успевают восстановиться. Память «вкладка не занята с такого-то момента» после перезапуска тоже начинается заново, поэтому службе нужно увидеть вкладку свободной непрерывно, а не унаследовать старый отсчёт.

## 3. Когда запись закрывается

| Событие | Результат |
|---|---|
| `form.replied` | запись закрыта |
| `form.cancelled` | запись остаётся, помечена; первый повтор идёт сразу, как вкладка свободна |
| новый запрос модели вкладки после вопроса (хук `context`, не раньше 3 с после вопроса) | запись закрыта; исключение — запись, уже ушедшая в повтор: её закрывает только слово владельца |
| успешный конец хода после вопроса (`idle` с `outcome` не `interrupted` и не `failed`) | запись закрыта |
| слово владельца во вкладке | запись закрыта |
| `FORM_TTL_MS` = 12 часов | страховка |

## 4. Идемпотентность

Один цикл прохода на процесс; копии событий сводятся по id формы; письмо побудки с фиксированным id `form-repeat-<id первой формы>-<номер>` и проверкой `letterExistsFor`; номер повтора пишется в запись до отправки; новая форма с тем же текстом в той же сессии наследует счётчик старой записи, поэтому бесконечного цикла нет. Предел — 3 повтора, интервал не меньше 2 минут, затем «без ответа, нужен владелец» и новых побудок нет.

## 5. Связь с 032 и 036

- 032 (устаревшие вопросы `expect_reply`) — другая сущность, не тронута.
- 036 (`hungTurn`) не считает ход зависшим при работающем инструменте; `pendingTool` использует то же условие.
- Найденное по ходу: `staleBusy` через 45 минут признавал вкладку с честно висящим вопросом «залипшей» и заслонял «ждёт вас». Теперь для вкладки с открытой записью он не вызывается, пока `pendingTool` показывает работающий инструмент.

## 6. Видимость

- `Ждут вас: N, старейший ЧЧ:ММ` (`waitingLine`, по всем проектам) — первая строка в `/crew` и в блоке «Crew» боковой панели.
- Команда окна `/ask` (`tui.ts`, `askText`): проект, роль и вкладка, сколько ждёт, состояние, текст вопроса, варианты.
- Уведомление окна (`notices/` + `toast.show`) при появлении вопроса и раз в 30 минут, пока он открыт; общий повтор `owner_reminder_min` для вопросов вопросника отключён, чтобы не было двух потоков.
- Системное уведомление Windows (`toast-win.ts`): встроенный PowerShell 5.1 и Windows Runtime, без зависимостей и прав; текст идёт через переменные окружения, а не через командную строку, и экранируется как XML; настройка проекта `owner_system_notify`, по умолчанию выключена, в `.opencode/crew-harness.json` включена. Пробный запуск завершился с кодом 0; показ на экране глазами не проверен. Риск: антивирус может счесть скрытый запуск PowerShell из процесса службы подозрительным.

## 7. Что не проверено

- Реальные события `form.*` после перезапуска и вид уведомления на экране.
- Какой `outcome` остаётся у хода, оборванного именно перезапуском службы: правило осторожное — неизвестный `outcome` считается ответом, а `interrupted`, `failed` и отсутствие `idle` — «пропал».
- Хук `context` может срабатывать и на служебные запросы модели (названия, сжатие): тогда запись без повтора могла бы закрыться лишним запросом, пока вопрос на экране; защита — 3 секунды после вопроса. Если наблюдение это покажет, хук надо сузить по `kind`.
- Закрытое окно не будится: вопрос виден в `/ask` и уведомлениях, повтор начнётся, когда вкладку откроют.
- В `AGENTS.md` п. 7 число «37 файлов» устарело (в цепочке `npm test` теперь 95).
