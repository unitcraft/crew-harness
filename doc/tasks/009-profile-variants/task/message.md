## Чего хочет владелец (его слова, 2026-10-08)

- «effort у моделей задается в профилях?» — сейчас нет: ячейка профиля хранит `model`, `context`, `output`, необязательный `input`.
- Предложил два равноправных способа записи, например для лёгкой ступени Kimi:
  `"model": "kimi-code-plan-global/k3-256k#low"` и `"variant": "low"` (поле `variant` в ячейке, `"high"` и т. п.).
- «оформи задачу #009 без запуска» — материал готовит оркестратор, сессию С1 запускает владелец.

## Что есть сейчас

- Проверка профилей сравнивает модели без части после `#` (`normModel` в `opencode-plugin/profiles.ts`), поэтому запись `…#low`
  проходит `check`.
- Запуск сессии режет строку модели только по `/` (`index.ts`, `ctx.session.create`: `providerID`, `id`) и вариант не передаёт:
  с `#low` в `id` попадёт `k3-256k#low`, то есть несуществующая модель, и сессия не запустится.
- Открытые вкладки плагин сопоставляет с профилем без варианта (`openai/gpt-5.5#high` подходит профилю `openai/gpt-5.5`).
- Хук `model.request` OpenCode отдаёт вариант отдельным полем `variant`.

## Что нужно

В ячейке профиля задаётся вариант модели (усилие) любым из двух способов: суффикс `#вариант` в строке `model` или поле
`variant` в ячейке; оба вместе допустимы только при совпадении. При запуске сессии (исполнитель, приёмщик, план) плагин
передаёт `{providerID, id, variant}`; `/crew-profiles`, `/crew-sets` (таблица, `show`, `check`) показывают вариант
(например «k3-256k · low»); `crew_config set` принимает оба способа; запись без варианта работает как раньше.

- Как вариант участвует в сопоставлении открытой вкладки с профилем (приёмщик в другой семье, REQ про открытые вкладки роли
  в задаче 003) и в проверке «одно окно на модель и папку».
