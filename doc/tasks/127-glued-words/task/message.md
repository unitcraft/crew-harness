## Что нужно

1. **Источники.** `opencode-plugin/glued.ts` (признак: `MIXED` — кириллица рядом с латиницей, `MIN_RUN` 20, `gluedText`, `gluedRefusal`), `opencode-plugin/core.ts` (применение: `crew_send` около строки 2000; текст помощи плагина про слипшиеся слова), `opencode-plugin/index.ts` (хуки инструментов: `tool.execute.before`, `tool.execute.after`, инструмент `question`, форма `PendingForm`), `opencode-plugin/test/crew-glued.test.mjs`, `package.json`, README плагина, `test/stable.mjs`; для проверки на ложные срабатывания — все `*.md`, `*.portolan.md`, `*.tsv` в `doc/`, `src/` и `scripts/` репозитория.
2. **Разбор (в `analysis.md` первой частью, до кода).** По скриншотам и по файлам: какие виды склейки бывают (кириллица+цифры: «потолок092»; слово+время: «передано16:27»; цифры+кириллица: «решён15:21» после числа без пробела; кириллица+латиница короткие), в каких инструментах модель их пишет (записи файлов `edit`/`write`/`apply_patch`, текст вопросника `question`, `crew_send`, ответы в окне), что хук плагина может перехватить (`tool.execute.before` с отказом, текст результата) и чего не может (обычный ответ модели в окне плагин не правит). Измерить на корпусе репозитория (все `*.md`, `*.portolan.md`, `*.tsv`): сколько мест срабатывает признак; ложные срабатывания записать списком.
3. **Реализация.** (а) Признак: к существующему признаку добавить склейку русского слова из 3 и более букв с цифрами («потолок092»), слова с временем («передано16:27») и цифр с русским словом из 4 и более букв («15:21принять»); не считать склейкой допустимые в проекте записи: имена с одной-двумя буквами и цифрой («С6», «Э0», «В14», «Ш.2», «Я-30», «С7п»), единицы («10мс», «5с», «2-я»), ссылки, пути, хеши, блоки кода и инлайн-код (как сейчас); список допустимых форм — в `analysis.md` и в тесте. (б) Применение: `crew_send` (как сейчас, плюс новый признак); текст вопросника `question` (вызов отклоняется с понятным сообщением: «в тексте слиплись слова …, перепиши с пробелами», модель переписывает); записи текстовых файлов (`edit`, `write`, `apply_patch` и их аналоги в OpenCode) — для файлов `.md`, `.txt`, `.tsv`, `.portolan.md` и подобных текстовых; в коде (`.nv`, `.ts`, `.mjs`, `.json`) признак не применять (идентификаторы). Порог срабатывания выбрать по измерению на корпусе: нулевое число ложных срабатываний на файлах репозитория; одиночная склейка в длинном тексте — тоже отказ (в отличие от смешанных алфавитов). (в) Сообщение отказа называет первые склейки и просит переписать; после отказа плагин не зацикливает: при втором подряд отказе того же вызова пишет в журнал плагина и пропускает (чтобы не блокировать вкладку), с пометкой. (г) Ключ схемы настроек не вводить, если не нужен; включено всегда; исключение — для вкладок, у которых модель не из перечня известных моделей-потеряшек, правило не отключать (дёшево и безопасно).
4. **Проверки.** Красная проба до кода: тесты на фразы со скриншотов (не менее 12 фраз: «потолок092 решён15:21», «interrupted question15:24», «передано16:27», «Разрешение110 round5», «запрос13:34», «готовность0.3», «задача081», «Нова110», «HOLD110», и допустимые «С6», «Э0», «В14», «Ш.2», «Я-30», «10мс», «MSVC 0.3», «2-я», «0.3 не заявляем») красные на `origin/main`; не менее 40 новых проверок; весь набор тестов плагина (`npm test` из `opencode-plugin/`; параллельно `npm run test:parallel -- --jobs 2`, потому что идут другие работы; устойчивость затронутых файлов `npm run test:stable`); стражи `sh scripts/guards/run-all.sh` ок и больше, FAIL 0; коммиты по правилам AGENTS.md (по темам).
