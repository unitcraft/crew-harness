## 1. Что сделано

Страница `src/web/` открывается по адресу сервера, сессия создаётся, разговор идёт с агентом по ACP, хранилище — файлы или PostgreSQL по настройке, службу можно перезапустить посреди сессии.

- **Две программы, а не одна** (расхождение с заданием, см. п. 2): `crew-harness` — фронт на Polaris (`src/crew_harness.nv`, `src/server/front/`): страницы с CSP, `/health`, WebSocket `/ws`; `crew-hub` — хаб (`src/crew_hub.nv`, `src/server/`): сессии, движки, агенты, хранилище. Фронт запускает хаб дочерним процессом, строки по трубам: `open|close|msg <conn> ...` туда, `<conn> <сообщение>` обратно. Хаб заканчивает, когда закрыт его stdin: после остановки фронта процессов хаба и агентов нет.
- **Хаб** (`hub.nv`): на сессию свой `Engine` с многооборотной машиной `dialog_session`, обработчиками `Journal` и `Store` по настройке (файлы или PostgreSQL) и обработчиком агента на ACP-клиенте. `pump` по таймеру; события движка уходят странице через `page_event`: `id` = `<сессия>/<id движка>`, `trace` = сессия, код хода (`turn`) = id события `user_message`. При старте хаб находит сессии по хранилищу и продолжает через `resume_engine`; агент запускается только для сессии с открытым запросом (он кончается `Timeout`) или по первому сообщению.
- **Настройки** (`settings.nv`, `front/front_settings.nv`): файл JSON (аргумент или `CREW_SERVER_CONFIG`) и переменные `CREW_SERVER_*`, `CREW_PG_*`; порт, агенты (по умолчанию `opencode acp`), режим `files`/`pg`, папка данных, параметры PostgreSQL, срок бездействия хода; пароль нигде не печатается; пример — `server.example.json`.
- **Многооборотная машина** (`src/chat/chat.nv`): поле `multi` и `dialog_session(idle_term)`: после ответа, отказа, срока или отмены хода машина возвращается в `Idle`; отмена хода не закрывает сессию. Одноходовая `chat_session()` не изменилась.
- **Движок** (`src/engine/`): вход события — параметр `input` события журнала `event_accepted` (только если не пусто; журнал остаётся структурным: код и параметры, русских строк нет, старый журнал читается), `Engine.take_events()` (принятые события со штампом), `Engine.history()` (те же события из журнала для восстановления после перезапуска, без `reply_discarded` и без строк несфиксированного шага), `EventKind.parse`.
- **Проекция** (`src/acp/project.nv`): `page_event` знает `session_created`.
- **Хранилище:** `list_sessions` (файлы), `crew.list_sessions()` и `pg_list` (PostgreSQL), право роли приложения.
- **Страница** `src/web/`: код не менялся (`transport.js` без `?mock=1` уже подключался к `/ws`); правки только в `src/web/README.md`.
- **Защита сокета:** `/ws` отвечает 403 на запрос с чужим `Origin`.

## 2. Решения исполнителя и расхождения с заданием

- **Две программы вместо сервера на Polaris с движком внутри:** драйвер PostgreSQL и Polaris в одной программе не собираются (вариант `Message` драйвера против типа `Message` Polaris; п. 30 `spikes/env/README.md`); режим `pg` и Polaris оба обязательны, поэтому фронт на Polaris, хаб на драйвере, связь строками по трубам.
- **Переименованы типы движка:** `Request` → `PartyRequest`, `Response` → `PartyResponse` (пакет `http` Polaris называет свои типы так же, п. 29); запись хаба — `Dialog` (у драйвера свой `Session`).
- **Журнал хранит вход события, и есть приёмник событий** (задание допускало один из двух): живые события — через `take_events`, история после перезапуска — из журнала.
- **Код хода — сервера, а не страницы:** id события `user_message` движка выводится из журнала, значит после перезапуска тот же.
- **Агент стартует при создании сессии**; при перезапуске лениво; мёртвый агент заменяется при следующем сообщении, контекст беседы теряется (`session/load` не используется).
- **Входная точка `crew-harness` без `serve` печатает справку** (иначе `nova test src` запускал бы сервер).
- **Чтение stdin хабом — `#blocking fn` и буфер в один байт** (п. 31); WebSocket читается и пишется двумя владельцами сокета через `share()`.
- **Список агентов страницы фиксирован (`opencode`):** страница менялась только для подключения.

## 3а. Перенос на свежий `origin/main` (задачи 100–103; слово оркестратора)

Ветка стояла на старом `main`; в `main` слиты 102 (словарь методики v6: `Event`→`Incoming`, `Agent`→`Link`, `accept`→`on_arrival`, `acp_agent`→`acp_link`, типизированное состояние, структурный журнал, `Machine.step` → `Transition` + `Environment`, `StepOutput`/`StepResult`/`LogNote` убраны), 100, 101, 103. - **Механика**: `node doc/tasks/102-align-glossary/rename.mjs src --skip engine` (сначала `--dry-run`) изменил `src/server/hub.nv` и `dialog_test.nv`; остальное руками по `rename-map.json`: аргументы типов `start_engine[ChatState, ChatSession]`, `decode_snapshot[ChatState, ChatSession](machine, ...)`.

Вход события — параметр `input` события `event_accepted` рядом с `kind`, `name`, `source`; `Engine.fresh`, `take_events`, `history` (строки `event_accepted` без `reply_discarded` и без несфиксированного шага), `EventKind.parse`. `Request[T]` и `Response[R]` остались и в `main`, снова конфликтуют с `http` — переименованы в `PartyRequest` и `PartyResponse`. ## 4. Новые ограничения Oracle 0.1.0 (воспроизведения в `spikes/env/`, `spikes/env/README.md`, п. 29–32)

- (п. 29) Таблица имён типов одна на программу, зависимости включены: `Request[T]` против `http.Request`, `Session` против `Session` драйвера.
- (п. 30) Драйвер nova-postgres и Polaris в одной программе не собираются.
- (п. 31) `Stdin.read` держит рабочий поток волокна (при полном буфере): 282 из 300 против 300 с `#blocking fn`.
- (п. 32) `import std.text` в одном модуле меняет смысл переменной `text` в другом.
- Без воспроизведения: переменные `a`, `b` и метод `entries` из тестовых файлов импортируемого модуля ломают C; `println` — «undefined identifier» при `import std.text`; поток хука `upgrade` Polaris разделён (`into_split()` падает); `detach` и `blocking` — ключевые слова.
