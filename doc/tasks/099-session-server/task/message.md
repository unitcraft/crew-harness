Заказчик: владелец репозитория `unitcraft/crew-harness` (он же принимает результат).
Репозиторий: `unitcraft/crew-harness`, ветка `main`. Дата задания: 2026-10-19.
Эпик: [001-crew-service](../../001-crew-service/); седьмая дочерняя задача этапа «продукт на Нове»: собирает готовое — [091](../../091-product-engine/) (движок), [093](../../093-console-skeleton/) и [094](../../094-console-claude-layout/) (страница `src/web/`), [095](../../095-acp-client/) (ACP-клиент и файловые обработчики), [098](../../098-pg-storage/) (хранилище в PostgreSQL).
Источник: слова владельца в чате оркестратора, 2026-10-18/19: «в браузере иметь возможность открыть сессии и поговорить с агентом» (первый срез MVP); «по рекомендации» на завод `src/server/`; «используй БД pg» (2026-10-19).

Задача полная: разбор, реализация, сдача. Быстрый путь. Основа — свежий `origin/main`. Код под `src/server/` (английские идентификаторы), правки `src/web/` — только то, что нужно для подключения к серверу.

## Чего хочет владелец (его слова, 2026-10-19, чат оркестратора)

- «в браузере иметь возможность открыть сессии и поговорить с агентом» — первый срез MVP: открыть страницу, создать сессию, говорить с настоящим агентом через ACP.
- «используй БД pg, у нас есть драйвер для pg, но нет универсального слоя для БД» — хранилище и журнал на PostgreSQL; пока у владельца нет настроенной базы продукта — запасной вариант на файлах (обработчики 095), выбор настройкой.
- Продукт пишется на Нове и собирается Oracle 0.1.0.

## Что нужно

1. **Образцы и источники:** `src/engine/README.md`, `src/acp/README.md` (проекция ACP → событие → страница, `page_event`, подтверждение `ack`, `decide_event`), `src/pg/README.md`, `src/storage/`, `src/web/README.md` (формат событий страницы, `transport.js`, режим `/ws`, `?mock=1`), `spikes/env/` (Polaris: `ws_echo/`, ограничения Oracle, п. 8–25), `doc/tasks/093-console-skeleton/analysis.md` (раздел 3: проекция 091 → страница на сервере).
2. **`src/server/`:** HTTP-сервер на Polaris на `127.0.0.1` (порт настраивается): отдаёт `src/web/` целиком (CSP `default-src 'self'`, как `serve.mjs`), `/ws` — WebSocket страницы. Сессии: создать (выбор агента из настроек, по умолчанию `opencode acp`), список, отправить сообщение, отмена хода, решение по запросу разрешения. На каждую сессию — свой `Engine` с машиной чата 091, обработчиком `Agent` из 095 (`acp_agent`) и хранилищем по настройке: файлы (095) или PostgreSQL (098). `pump` по таймеру; события движка уходят странице строкой формата 093/094 (`page_event`, штамп движка `id`, `step`, `time`; если журнал хранит только `<вид>/<имя>` — приёмник событий движка или поле `input` в журнале, обосновать).
3. **Перезапуск службы:** при старте сервер находит сессии по хранилищу и продолжает через `resume_engine`; открытый запрос после перезапуска честно кончается `Timeout` (продолжение хода `session/load` не в этой задаче).
4. **Многооборотный чат:** машина 091 однооборотная и отмена завершает сессию (отчёт 095). Нужна многооборотная сессия: после ответа сессия остаётся открытой и принимает следующее сообщение; отмена хода не закрывает сессию. Правки машины чата допустимы, с тестами (смерть между изменениями; другая сторона в окне — правила 13 и 34(е) методики).
5. **Настройки:** файл JSON (аргумент или `CREW_SERVER_CONFIG`) и переменные: порт, команда агента, режим хранилища (`files`/`pg`), папка данных, параметры PG (как `src/pgconf/`); пароль не логировать; в репозитории только примеры с тестовыми значениями. Запуск сервера пользователем из обычного окна с консолью (НЕ через `crew_watch`: подпроцессы из скрытого запуска без консоли падают, задача 100).
6. **Страница:** `src/web/transport.js` подключается к `/ws` без `?mock=1`; список сессий и создание сессии приходят от сервера; запрос разрешения показывается диалогом и решение уходит серверу; прежний режим `?mock=1` не ломается (тесты 093/094 зелёные).
7. **Проверки:** `nova test src --jobs 4` (на PostgreSQL — временный контейнер `src/pg/testdb.ps1`, на файлах без базы); красная проба до кода; тесты сервера на подставном ACP-агенте (`src/acp/testdata/fake_agent.mjs`): создать сессию, ответ кусками, запрос разрешения и решение, отмена хода без закрытия сессии, второй ход в той же сессии, перезапуск сервера посреди сессии (resume), падение агента, два клиента страницы на одной сессии; тест «смерть между изменениями». Проверка из браузера: запустить сервер, открыть страницу во встроенном браузере, создать сессию с подставным агентом и поговорить (описать по дереву страницы), затем с реальным `opencode acp` только `initialize` и `session/new` (без вызова модели, без ключей), результат в `analysis.md`.
8. **README `src/server/README.md`** (английский): протокол `/ws` (сообщения страницы и сервера, примеры), настройки, как запустить, что не вошло; новые ограничения Oracle — в `spikes/env/repro_*` и в отчёт.

## Критерии приёмки

- Сервер запускается, страница открывается по его адресу, сессия создаётся и разговор идёт с подставным агентом; с реальным агентом (по слову владельца, ключи у него) — отдельный шаг после сдачи.
- Многооборотная сессия: после ответа можно писать дальше; отмена хода не закрывает сессию; перезапуск сервера не теряет сессию.
- Хранилище по настройке: файлы и PostgreSQL дают те же результаты на тестовых сценариях.
- `nova test src --jobs 4` зелёный (и `--strict-effects`); тесты страницы 093/094 зелёные; красная проба до кода показана; стражи 8 и больше, FAIL 0; коммит по правилам AGENTS.md.
