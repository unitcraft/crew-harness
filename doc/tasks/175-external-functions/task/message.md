Касается нормы или формата: да (раздел таблицы, вид вызова, проверка при загрузке, схема `machine-2.schema.json`, поле вызова; имя формата дерева `machine/2` остаётся)

Слова владельца, 2026-10-25 (чат оркестратора): нарезка релиза 0.6.0 — четыре задачи вместо десяти (оптимум по данным — 2–5 ч агента на задачу; две параллельные ветки); эта задача — объединение прежних 175, 176, 177, 178 в один поток по общему парсеру (AL-123, AL-129). Формулировка передана исполнителю оформления оркестратором (пересказ); дословная цитата владельца лежит в чате и вносится в журнал при приёмке постановки.

Слова владельца, 2026-10-25 (чат Методики и оркестратора, из прежних постановок): раздел «Внешние функции» вместо «Примитивов» и вызов без слова `вызвать` (AL-123); расхождение объявления с реестром хозяина — ошибка при загрузке (AL-123); дерево хранит полную запись внешней функции (вариант Т1), имя формата `machine/2` не меняется; хвост параметров `...имя` только для внешних функций (AL-129).

## Что нужно

Цель одной фразой: объявлять внешние функции в разделе `## Внешние функции` / `## External functions` и вызывать их как обычные, сверять объявление с реестром, хранить полную запись в дереве и принимать хвост параметров; `## Примитивы` и `вызвать(…)` отвергать с подсказкой.

**Часть А. Раздел и вызов (AL-123).**

1. Раздел `## Внешние функции` (en `## External functions`) вместо `## Примитивы`; число разделов таблицы прежнее — 11.
2. Объявление: `внешняя функция имя(арг тип, …) <класс> [-> тип]`, без тела (`<класс>` — слово класса чистая/изменчивая/действующая; en — `external function name(arg type, …) <class> [-> type]`).
3. Вызов: `имя(арг)` — в выражении и оператором. `вызвать(…)` и заголовок `## Примитивы` — ошибка с подсказкой нового способа (AL-123).
4. `время_сейчас` и `новый_ид` объявлены заранее (в таблице их объявлять не нужно). В файле функций внешние функции запрещены (ошибка).
5. Миграция данных пакета: образцы, `cases`, `examples`, встроенные таблицы тестов — около 92 вызовов и 12 файлов с разделом (оценка по поиску оркестратора; точные числа — первой записью журнала).

**Часть Б. Сверка с реестром хозяина (AL-123).**

6. Любое расхождение подписи в файле (имя, параметры, результат, класс) с реестром — ошибка при загрузке с именем функции и расхождением; образец: «функция записать_статус: параметр 2 в файле число, в реестре строка». Функция есть в файле, но нет в реестре — ошибка. Лишние функции в реестре допустимы. Признаки `читает`/`пишет` и роли берутся из реестра, не из файла.
7. Корпус: загрузка каждой таблицы методики и продукта с её `registry.md` (файлы берутся из выкладок рядом, только чтение) даёт 0 расхождений. Для таблиц продукта это достигается правкой реестров продукта (+1–2 ч, отдельный коммит в репозитории продукта с номером 175), для таблиц методики — списком исправлений реестра в виде текста письма Методике (реестр методики здесь не правится).

**Часть В. Дерево T1 (AL-123).**

8. Узел `primitives` дерева хранит для каждой внешней функции `{name, params:[{name,type}], result, class}`; имя формата `machine/2` остаётся, схема `machine-2.schema.json` обновляется; рендер дерево → текст пишет раздел `## Внешние функции` один в один. Деревья образцов пакета пересобираются командой `alula compile`; сопровождающая проза версии — не здесь (181).

**Часть Г. Хвост параметров (AL-129).**

9. Объявление `...параметры: строка` — последний параметр внешней функции; внутри тела хвоста тип — `словарь[строка,строка]`. У вызова — поле дерева `named:[{name,value}]`; точный вид пар в тексте — как в разделе AL-129 спецификации (здесь не пересказывается). У функции автора хвост — ошибка; повтор ключа в вызове — ошибка. Рендер дерево → текст сохраняет хвост и пары один в один; схема обновляется.

Порядок коммитов: первой записью журнала — красная проба (AC-1) и точные числа миграции; затем А, затем В (дерево нужно хвосту), затем Г, затем Б (сверка идёт по полной записи в дереве); у каждой части свои тесты.

## Критерии приёмки

AC-1. Красная проба до кода: команда AC-2 на прежнем коде (после слияния 182, но до этой задачи) красная; красный вывод и номера разделов спецификации (AL-123, AL-129) записываются в журнал первой записью работы, после работы та же команда зелёная.
AC-2. Одна команда-критерий: `sh scripts/accept-175.sh` (скрипт `scripts/accept-175.sh` пакета пишет исполнитель первым шагом, он красный до работы). Она запускает:

   - набор проб по разделам спецификации: таблица с `вызвать(x)` → `alula check` даёт ошибку с подсказкой нового способа и кодом AL-123; проба с заголовком `## Примитивы` — то же; функция внешняя в файле функций — ошибка; хвост у функции автора — ошибка; повтор ключа в вызове — ошибка; объявление с хвостом и вызов с парами — чисто;
   - `alula test examples` — 66 из 66; `nova test` затронутых папок зелёные;
   - `grep -rn "вызвать(" examples spec/samples src/machine_agent/cases` — пусто; `grep -rn "^## Примитивы\|^## Primitives"` по тем же местам — пусто;
   - круг текст → дерево → текст на всех образцах пакета и в `examples` даёт текст, идентичный исходному (побайтно, концы строк по правилу пакета); каждое дерево валидно по `machine-2.schema.json`;
   - деревья мигрированных таблиц равны деревьям до миграции (разбор JSON), с точностью до узла `primitives` и поля `named` (их полная запись — часть В и Г);
   - тесты на каждый вид расхождения сверки: имя, число параметров, тип параметра, результат, класс, отсутствие в реестре, лишнее в реестре (ожидается «ок») — 7 из 7; скрипт корпуса: загрузка каждой таблицы методики и продукта с её `registry.md` — расхождений 0.

   Ожидаемый вывод последней строкой: `ПРИНЯТО 175: пробы старых форм AL-123; хвост: 5 проб из 5; examples 66 из 66; вызвать( 0; Примитивы 0; круг N из N; схема N из N; деревьев равных N из N; сверка: видов 7 из 7, таблиц N, расхождений 0 (исправлений реестров продукта K, письмо Методике: M строк); nova test N из N`.
AC-3. Приёмка — ОДИН перепрогон команды AC-2 чистым заходом (этапных ревью нет).

## Оценка

Число запусков и часов до результата: 16 запусков, 6–10 ч агента (по оценке оркестратора; сумма оценок частей — А 6 запусков, 3–5 ч; Б 4 запуска, 1,5–2,5 ч плюс 1–2 ч на правку реестров продукта; В 3 запуска, 0,5–1 ч; Г 3 запуска, 1,5–2,5 ч, то есть 6,5–11 ч без правки реестров).
