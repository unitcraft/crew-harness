## Что нужно

1. Подключить Kimi Code как второго настоящего ACP-агента standalone веб-пульта CrewHarness на Nova, рядом с существующим OpenCode, без подмены существующих сессий/агента. Сейчас backend допускает agents в server settings, но live UI берёт AGENTS из mock.js (opencode + disabled second). Дать минимальный поддержанный механизм показа и выбора НАСТРОЕННЫХ агентов при создании новой сессии, не hardcode Kimi вместо OpenCode. Существующую сессию не переключать на другого агента.
   Факт проверки интегратора: установлен Kimi Code CLI 2.1.1, команда kimi.cmd acp; штатная spikes/env/acp/acp_initialize.mjs выполнила только initialize в пустой временной папке: protocolVersion1, agentInfo name Kimi Code CLI/version2.1.1, loadSession=true, authMethods login; PASS. Модельный prompt/login не выполнялись. Это handshake, не доказательство авторизованного разговора. Для Windows использовать корректный запуск npm shim либо существующий node entry, без auto/yolo.
   Работа fast: короткий разбор, полный brief, RED→GREEN, минимум3различающие пробы, независимая приёмка; не С1–С4. Если нужен full — только вопрос владельцу. Сначала читать Канон/AGENTS, закрепить pin. Новых задач/подагентов не создавать.

## Критерии приёмки

1. В живом режиме UI показывает реальные настроенные agent id/label (OpenCode и Kimi), а не disabled mock second. Источник списка — серверная конфигурация, без передачи executable path/args/секретов в браузер. Mock-режим остаётся работоспособным.
2. При создании сессии выбранный Kimi id доходит до hub и запускает kimi ACP; существующие OpenCode-сессии/история не меняются. Неверный/неизвестный agent id безопасно отклоняется.
3. Протокольная совместимость подтверждена fake ACP тестами и реальным initialize без prompt; если требуется login, UI явно показывает необходимость входа, не просит/не сохраняет токен и не запускает интерактивную авторизацию сам. Проверку реального разговора проводить только в явно изолированном каталоге; не выдавать initialize за conversation PASS.
4. Позитив OpenCode/Kimi registry, неизвестный id и отказ/недоступность агента покрыты тестами; минимум3 различающие пробы. Полный набор затронутых web/server/ACP частей, штатная сборка Nova и независимая приёмка обязательны, тяжёлые команды через очередь машины.
5. Не менять Docker/схему/БД/историю, настройки OpenCode/модели/подписки; не включать auto/yolo. Без потери CSP/textContent, безопасности и существующих функций.
6. Совместимость с130 (дизайн) и131 (показ модели): согласовать пересечения UI напрямую, не возвращать fake model-selector. Код показа модели не дублировать в этой задаче.
Ветка: собственная ветка задачи, назначенная crew_spawn от origin/main; не live main/дерево114.
