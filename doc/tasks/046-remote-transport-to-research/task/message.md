## Что нужно

1. **Перенести прототип в исследование:** `doc/research/remote-transport/` — код (`ntfy.ts`, `github.ts`, `tailnet.ts`, `remote.ts`), его тесты и `ntfy-latency.mjs` как есть (история через `git mv`), плюс `README.md` исследования: что это, что исследовано и измерено (задержки ntfy и т. п., если есть в документах или тестах), что работает, что не доделано, как запустить тесты вручную из этой папки, ссылки на ADR-0004 и исследование «много агентов». Код в папке исследования не должен подключаться к плагину и не входит в `npm test`.
2. **Отключить от плагина:** убрать импорт и создание моста из `index.ts`, ветку «другая машина» и `queueRemote`/`remoteRoute` из `core.ts`, все остальные ветки «если мост/remote» в плагине; поведение плагина без `remote.json` не меняется (это и есть рабочее поведение у владельца). Если в описаниях инструментов, `crew_help`, README плагина или настройках упоминается связь машин — убрать или пометить «исследование, не в плагине» со ссылкой.
3. **Не путать:** настройка `cleanup: "local+remote"` и уборка удалённых веток git (`origin`) — это не транспорт писем, их не трогать.
4. **Тесты:** убранные тесты выходят из `npm test`; весь оставшийся набор зелёный; новый маленький тест (или клетка в существующем), что плагин не импортирует ничего из `doc/research/` и не создаёт мост (красная проба — на коде основы он красный). Тесты по одному, с паузой 15 с ([AGENTS.md](../../../../AGENTS.md), п. 9).
5. **Стражи** зелёные (`sh scripts/guards/run-all.sh`): перенос кода в `doc/` может задеть стражи текстов (гигиена, ссылки) — исправлять текст, а не обходить страж.
