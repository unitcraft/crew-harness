# Задание: агенты, которых запускает продукт CrewHarness, работают без плагина crew-harness (и без лишних плагинов)

Заказчик: владелец репозитория `unitcraft/crew-harness` (он же принимает результат).
Репозиторий: `unitcraft/crew-harness`, ветка `main`. Части: сервер и хаб продукта (`src/server/`, `src/acp/`), плагин `opencode-plugin/` (живая система: правки только в рабочем дереве, AGENTS.md пп. 11–12). Дата задания: 2026-10-23.
Эпик: [001-crew-service](../../001-crew-service/); цель владельца «все возможности плагина — в продукте на машинах-данных» ([105](../../105-plugin-capability-map/task/message.md)); связано с [135](../../135-instrumenty-crewharness-v-pulte-epik-per/) (инструменты CrewHarness в веб-интерфейсе) и [157](../../157-branch-guard/task/message.md).
Источник: слова владельца в чате оркестратора, 2026-10-23: «opencode сейчас запускается с нашим плагином crew-harness, а у нас задача — перенести весь функционал плагина в продукт CrewHarness, соответственно надо выключать плагин crew-harness при запуске агентов в opencode, возможно выключать некоторые плагины или все — что скажешь?».

Задача полная: разбор, реализация, сдача. Быстрый маршрут. Основа — свежий `origin/main`. Исполнитель ничего не публикует и не пушит.

## Признаки маршрута

Цель: агент, которого запускает хаб продукта (`opencode acp` и другие), не загружает плагин crew-harness и не запускает его фоновые циклы; набор остальных плагинов у такого агента задаётся явно.
Источников: 3 (конфигурация OpenCode владельца, код плагина, код хаба/ACP-клиента).
Частей системы: 2 (плагин, настройки сервера и запуск агента).
Риск: средний (живая система; двойная работа плагина — в окне владельца и в каждом агенте продукта)
Необратимо: нет
Причина известна: да (по фактам: `opencode acp` не имеет флага отключения плагинов — только `--login` и общие флаги; плагины берутся из глобального `opencode.jsonc`, ключ `plugins`, где стоят `opencode-windows-env`, `opencode-claude-guards`, модели `opencode-claude-code-provider` и пакет `crew-harness`; у плагина нет переключателя выключения, только интервалы `CREW_HARNESS_*`; настройки агента сервера `agents[]` содержат `id`, `label`, `program`, `args` и не содержат окружения)
Касается нормы или формата: нет

Ветка: task-160-agents-without-plugin

## Чего хочет владелец

- «надо выключать плагин crew-harness при запуске агентов в opencode, возможно выключать некоторые плагины или все — что скажешь?» (2026-10-23, чат оркестратора).
- Цель: функционал плагина переезжает в продукт; два одновременных исполнителя одной логики недопустимы.

## Что нужно

1. **Разбор (в `analysis.md` первой частью, до кода).** Как OpenCode выбирает плагины и конфигурацию (глобальный `opencode.jsonc`, проектные файлы, переменные окружения, рабочий каталог), что делает каждый из плагинов владельца (`opencode-windows-env`, `opencode-claude-guards`, `opencode-claude-code-provider/models`, `crew-harness`), какие из них нужны агенту продукта (окружение процессов на Windows, защита, модели провайдера), что происходит, когда в окне агента загружается плагин crew-harness (фоновые циклы, чтение настроек проекта, запись статусов, инструменты `crew_*` в разговоре агента). Проверить на реальном `opencode acp` без отправки подсказок: запустить с `--print-logs` и посмотреть, какие плагины инициализируются (результаты — в `log.md`). Решить и записать способ изоляции из вариантов: (а) переменная окружения, которую читает плагин при старте и ничего не регистрирует (рекомендация разбора: самый малый и безопасный шаг); (б) отдельная конфигурация для агентов продукта (отдельный каталог конфигурации через окружение процесса, со своим списком плагинов и входом в аккаунт); (в) оба.
2. **Плагин.** Переменная `CREW_HARNESS_OFF=1` (имя можно изменить в разборе): при старте плагин не регистрирует хуки, инструменты и циклы и пишет одну строку в журнал OpenCode «плагин выключен переменной»; без переменной поведение прежнее. Тесты: выключен, включён, переменная не равна `1`, плагин не пишет в файлы проекта при выключении.
3. **Настройки сервера.** В `agents[]` ключ `env` (объект «имя → строка») и, если решено в разборе (б), ключ для каталога конфигурации агента; значения передаются запускаемому процессу агента, секреты в журнал и ошибки не попадают; для агента `opencode` в примере настроек `CREW_HARNESS_OFF=1`; проверка значений (имена переменных — латиница и подчёркивание). Тесты разбора настроек, передачи окружения фальшивому агенту (`src/acp/testdata/fake_agent.mjs` печатает, что получил).
4. **Политика остальных плагинов.** Таблица в `log.md`: плагин → нужен агенту продукта (да/нет/по агенту) → как отключается; решение по умолчанию (оставить `opencode-windows-env` и модели провайдера, если нужны для запуска; `opencode-claude-guards` — решить; `crew-harness` — выключен). Для агентов не на OpenCode (`kimi`, `codex-acp`, `claude-agent-acp`) плагины OpenCode не применимы: записать.
5. **Проверки.** Красная проба до кода. Затронутые наборы плагина (`npm test` по файлам из `package.json`, не больше 4 одновременно, паузы) и продукта (`nova test src/server`, `src/acp`, `src/acp_live`, затем полный по правилам AGENTS.md п. 9 с временным PostgreSQL), `--strict-effects`, стражи. Реальный `opencode acp` — только запуск и закрытие без подсказок; проверка по журналу, что плагин crew-harness не инициализировался, а остальные — по таблице.
6. **Документация:** `src/server/README.md` (ключ `env`), `opencode-plugin/README.md` (переменная выключения), `doc/canon` — строка в процессе, если разбор покажет необходимость; развёртывание и откат в `log.md`.

## Критерии приёмки

AC-1. Агент `opencode`, запущенный хабом продукта с настройками по умолчанию из примера, не загружает crew-harness (подтверждено журналом реального запуска без подсказок); окно владельца и служба работают как прежде (без переменной поведение плагина не изменилось: тесты).
AC-2. `agents[].env` читается, проверяется и передаётся процессу агента; секреты не попадают в журнал и ошибки.
AC-3. Таблица политики плагинов в `log.md` с решением по каждому; решение владельцу по спорным (`opencode-claude-guards`) вынесено текстом.
AC-4. Не менее 12 новых тестов, красная проба, затронутые и полные наборы зелёные; стражи зелёные.
AC-5. В `log.md` — решения, числа, развёртывание (обновление основной копии по слову «обновляй» и без перезапуска службы, если разбор подтвердит) и откат. Ничего не опубликовано и не запушено.
