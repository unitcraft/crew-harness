# Разбор 089: ключ опций «папки настроек проектов» называется `project_settings`, старое имя `projects` остаётся синонимом

Задание — `task/message.md`. Источник: слова владельца в чате оркестратора, 2026-10-18: «почему "projects", если это папка настроек, а не сам проект?» и «project_settings делаешь? что по рекомендации?».
Причина: ключ `projects` в опциях плагина (`opencode.jsonc`) перечисляет не проекты, а папки репозиториев настроек; имя и корень проекта берутся из файла `.opencode/crew-harness.json` в такой папке (`"project"`, `"root"` от папки).

## 1. Где ключ читается или называется

- `settings.ts`, `parseProjects`: раньше читал `opt?.projects`; теперь `projectsOption(opt)` — `project_settings`, а если он не задан, то `projects`. Новые функции `optionKeyLines`, `settingsNotes` и константы ключей; строки для врача запоминаются при разборе опций.
- `settings.ts`, `settingsProblems`: в начало добавлены проблемы по ключам; совет врача для прежней формы «имя → корень» называет `"project_settings": [...]`.
- `core.ts`: `saveProjects` пишет в `projects.json` ящика оба ключа как заданы; `loadProjects` (для MCP-сервера) читает любой из них; переменная `OPENCODE_CREW_PROJECTS` теперь значение `project_settings` и отменяет `projects`; два отказа `crew_config` «задан прежней формой… записать некуда» называют `project_settings`; `crew_doctor` после вердикта дописывает блок «К сведению:» с заметками.
- `index.ts`: самопроверка пишет `notes` в `doctor.json`; `status.ts` (`doctorText`) и `tui.ts` показывают их в окне `/crew-doctor` под вердиктом. `profile-layer.ts`: текст отказа `/crew-sets use` для прежней формы называет ключ `project_settings`.
- Менять не пришлось: `cmd-ops.ts`, `profile-cmd.ts`, остальной `profile-layer.ts`, `open-questions.ts` — их `projects` внутренний список `Project` из `settingsContext()`, а не ключ опций. `crew_help`, `doc/canon/`, `AGENTS.md` ключ не называют.
- README плагина: пример опций, раздел про репозиторий настроек, абзац про MCP — с фразой о синониме.

## 2. Правило

| Опции | Действует | `crew_doctor` |
|---|---|---|
| только `project_settings` | он | молчит |
| только `projects` (список папок) | он (синоним) | вердикт зелёный; «К сведению: ключ projects переименован в project_settings; прежнее имя работает» |
| оба, записи совпадают | `project_settings` | заметка «убери projects» |
| оба, записи расходятся | `project_settings` | проблема (красит вердикт): какие записи только в одном ключе |
| `projects` в прежней форме «имя → корень» | как раньше | совет с названием `project_settings` |

Формат файла `.opencode/crew-harness.json`, выбор проекта по корню, чтение закоммиченной ветки, соседние ключи (`local`, `retention_days`) не менялись.

## 3. Проверка и оговорки

- Красная проба до кода — `test/crew-project-settings-key.test.mjs` (33 проверки) на копии исходного кода: падали «project_settings даёт проекты» (получается `[]`), «оба ключа — действует project_settings», обе проверки строки врача, далее `TypeError: settings.settingsNotes is not a function`; после правки зелёные.
  Тест покрывает: тот же набор проектов под обоими именами; оба ключа (расходятся и совпадают); только `projects` списком; прежнюю форму под `projects`; ящик и `OPENCODE_CREW_PROJECTS`; через `index.ts` чтение закоммиченного файла, `crew_config set`, `crew_config show`, `/crew-sets use`, `crew_doctor`; текст окна `/crew-doctor`.
- Старые тесты менять не пришлось (они используют `projects`, оставшийся синонимом); golden не менялись.
- Полный набор исполнителя: 0 красных из 127 запусков, 4 одновременно; стражи: ок 8, FAIL 0.
- Решения исполнителя: расхождение при двух заданных ключах — проблема (красит вердикт), потому что игнорируемый ключ с другим списком может молча терять проекты; совпадающие записи — только заметка. Прежняя форма «имя → корень» под ключом `project_settings` тоже читается (чтобы не терять проекты молча), но врач ставит проблему: она живёт только под `projects`.
- Строки врача о ключах хранятся в состоянии модуля и обновляются при каждом `parseProjects` — так `settingsProblems(parseProjects(opts))` работает без нового параметра.
- Для владельца: в `opencode.jsonc` вместо `"projects": [...]` можно поставить `"project_settings": [...]` с теми же папками; пока ключ не заменён, всё работает, а `crew_doctor` и `/crew-doctor` показывают заметку. Перезапуск службы нужен, чтобы плагин перечитал опции.
