# Задание: ключ опций плагина «папки настроек проектов» называется `project_settings`, старое имя `projects` остаётся синонимом

Заказчик: владелец репозитория `unitcraft/crew-harness` (он же принимает результат).
Репозиторий: `unitcraft/crew-harness`, ветка `main`. Дата задания: 2026-10-18.
Источник: слова владельца в чате оркестратора, 2026-10-18: «почему "projects", если это папка настроек, а не сам проект?» и «project_settings делаешь? что по рекомендации?» — на рекомендацию оркестратора: назвать ключ `project_settings`
(«папки настроек проектов»), а старое имя `projects` оставить рабочим синонимом на переходный период.
Причина: в опциях плагина (`opencode.jsonc`, `"options": { "projects": [...] }`) ключ `projects` перечисляет не проекты, а папки репозиториев настроек; имя и корень проекта берутся из файла `.opencode/crew-harness.json` в этой папке (`"project"`, `"root"` относительно папки).
Для четырёх проектов папка настроек совпадает с корнем, для Nova — нет (`nova-opencode` против `nv-lang`), и название вводит в заблуждение.

Задача полная: разбор, реализация, сдача. Быстрый путь. Основа — свежий `origin/main`.

## Чего хочет владелец

- «project_settings делаешь? что по рекомендации?» (владелец, 2026-10-18, чат оркестратора): сделать ключ `project_settings`, старый `projects` оставить синонимом.

## Что нужно

1. **Разбор:** все места, где плагин читает или называет ключ опций `projects`: `settings.ts` (около разбора `opt?.projects`, `settingsContext`), `core.ts` (запись контекста для сервера около `opt?.projects`), `cmd-ops.ts`, `profile-layer.ts`, тексты `crew_doctor` и отказов («проект … задан прежней формой опций: … новая — список папок настроек …»), `crew_config`, `/crew-sets`, README плагина, `doc/canon/`, справка `crew_help`, `AGENTS.md`;
   форма значения: новая — список папок; прежняя — объект «имя → корень» (`{ "nova": "C:/work/nova" }`), он остаётся только под старым именем `projects`.
2. **Правило:**
   - основной ключ — `project_settings` (список папок настроек); `projects` читается как синоним, если `project_settings` не задан;
   - заданы оба: действует `project_settings`, `projects` игнорируется, а `crew_doctor` говорит об этом одной строкой (какие записи расходятся);
   - только `projects` (список папок): работает как раньше; `crew_doctor` — одна строка низкой важности «ключ projects переименован в project_settings; прежнее имя работает» (не ошибка, не предупреждение, мешающее зелёному вердикту);
   - только `projects` в прежней форме «имя → корень»: как раньше, с прежним советом врача, в котором новая форма называется `project_settings`;
   - значения и правила разбора записей (путь папки, чтение закоммиченного файла, `local`, `retention_days` и прочие соседние ключи) не меняются;
   - файл `opencode.jsonc` владельца плагин не правит (только читает).
3. **Тексты:** README плагина (раздел про репозиторий настроек, пример опций), справка `crew_help`, описания `crew_config`/отказов, `doc/canon/` — где названо `projects` как ключ, привести к `project_settings` с одной фразой о синониме. Прежние упоминания в `log.md` и `analysis.md` других задач не править (история).
4. **Тесты:** красная проба до кода (источник: опции с `project_settings` дают тот же набор проектов, что `projects`; оба ключа — `project_settings` главный; только `projects` — работает и врач молчит о проблеме, говорит одну строку низкой важности; прежняя форма «имя → корень» — как раньше;
   переименование не меняет чтение закоммиченного файла, запись настроек `/crew-sets use` и `crew_config set` в проекте, заданном через `project_settings`); обновить ожидания старых тестов (`crew-project`, `crew-config`, `crew-settings`, `crew-profiles-*`, golden — только изменившиеся ключи);
   полный `npm test` не больше чем по 4 параллельно ([AGENTS.md](../../../../AGENTS.md), п. 9).
5. В сообщениях коммитов номер задачи пишется тремя цифрами без решётки.

## Критерии приёмки

- Красная проба до кода падает на источнике и проходит после правки.
- `opencode.jsonc` с `project_settings` и с `projects` (список) даёт одинаковый набор проектов; прежняя форма «имя → корень» работает как раньше; `crew_doctor` для каждого случая говорит ровно то, что записано в правиле.
