# Задание: точность закрытого списка автоответа — слова ворот по смыслу, а не по вхождению; приёмщики в текстовом пути

Заказчик: владелец репозитория `unitcraft/crew-harness` (он же принимает результат).
Репозиторий: `unitcraft/crew-harness`, ветка `main`. Дата задания: 2026-10-19.
Источник: слова владельца в чате оркестратора, 2026-10-19: «не задавайте и не тормозите»; «answer_mode: recommendations … надо доделать»; «по рекомендации, с учетом выше сказанного тут». Продолжает [096-form-autoanswer](../../096-form-autoanswer/) (замер: закрытый список уводит владельцу около 70 % вопросов, из них около двух третей по слову из описания положения).

Задача полная: разбор, реализация, сдача. Быстрый путь. Основа — ветка задачи 096 (в `origin/main` её ещё нет): модуль `opencode-plugin/form-auto.ts` и тесты лежат в рабочем дереве. Правки только `opencode-plugin/`, дополнение ADR-0010 и папка задачи.

## Чего хочет владелец (его слова, 2026-10-19, чат оркестратора)

- «не задавайте и не тормозите» — вопросы о технических фактах и проверяемых вещах владельцу не задаются; ждать его только по закрытому списку (tag, выпуск, удаление, пуш в `main`, расширение прав).
- «answer_mode: recommendations … надо доделать» — автоответ на вопросы по рекомендации должен реально работать.

## Что нужно

1. **Закрытый список по смыслу.** Сейчас `CLOSED_LIST` ищет слова во всём тексте вопроса и описаниях вариантов (замер 096: 10 из 16 уходов к владельцу — слово из описания положения: «на main красный», «при сдаче 103», имя стража со словом gate). Переделать на проверку действия: закрытым считается вопрос, ПРЕДЛАГАЮЩИЙ действие из списка (глагол + объект: «запушить/пушь/push в main», «слить/merge», «удалить/убрать ветку/дерево/файл», «поставить tag», «выпустить/опубликовать релиз/asset/pin», «перезапустить службу», «утвердить спецификацию/план», «разрешить … вне границ», пароль/ключ/токен/оплата, изменение ключей answer_*), либо рекомендованный вариант сам содержит такое действие. Слово из описания положения без предлагаемого действия закрытым НЕ делает. Форма таблицы в коде: на каждую строку — образцы (шаблоны) и «не закрывает» примеры; расширяется без правки логики.
2. **Замер до и после** на журнале ответов за 2026-10-18 (то же, что в 096): сколько из 23 ответов по рекомендации закрыл бы плагин было (7 из 23) и стало; все настоящие ворота из 16 (accept, approval, gates, release, push, merge, answer-keys, delete) должны по-прежнему уходить владельцу; регрессии по безопасности — красная проба: тест на каждый настоящий случай из журнала (обезличенный текст в тесте, без путей машины владельца).
3. **Приёмщики в текстовом пути.** Снять исключение «сессия приёмки» и в текстовом пути (`classify`, `answer-parse.ts`), как уже снято для форм (слово владельца 2026-10-19); золотые тесты 007 обновить осознанно (список изменённых ячеек в `analysis.md`).
4. **Живая проверка** после «обновляй» и перезапуска (отдельный шаг, не в этой задаче): записать в `analysis.md` точный список того, что смотреть (строка в журнале плагина, счётчики `/crew`, записи `forms/auto/`, `crew_doctor`).
5. **Проверки:** `npm test` из `opencode-plugin/` (до 4 файлов параллельно), красная проба до кода, `node test/stable.mjs`-прогон затронутых; стражи 8 и больше, FAIL 0; коммит по правилам AGENTS.md (английское сообщение, `-s`, без трейлеров и без `#число`, файлы перечнем).

## Критерии приёмки

- На замере 2026-10-18 доля закрываемых плагином ответов по рекомендации выросла минимум до 60 % (было 30 %), настоящие ворота уходят владельцу все; тест на каждый из 16 случаев.
- Закрытый список — таблица «действие → шаблоны + не-закрывающие примеры», тест на каждую строку и на каждый не-закрывающий пример.
- Исключение «сессия приёмки» снято в текстовом пути, золотые тесты обновлены с перечнем.
- Полный набор тестов плагина зелёный; стражи 8 и больше, FAIL 0.

## Результат и куда он попадает

нет: результат — код плагина, тесты, дополнение ADR-0010; основную копию `main` не править; обновление и перезапуск — по слову владельца.
