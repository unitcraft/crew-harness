# Задание: понятный вывод /crew-sets show

Заказчик и владелец: владелец репозитория `unitcraft/crew-harness` (он же отвечает на вопросы и принимает результат).
Репозиторий кода: `unitcraft/crew-harness` (https://github.com/unitcraft/crew-harness, ветка `main`). Дата задания: 2026-10-17.
Источник: 2026-10-17 владелец открыл `/crew-sets show` в окне crew-harness и написал «в этой каше ничего не понять». Вывод — по
абзацу на каждый из восьми этапов (разработка, приёмка, планирование, приёмка плана, разбор, приёмка разбора, сдача, приёмка
сдачи), в каждом — «codex/task — по ступени задачи: heavy → openai/gpt-6-luna (срез границами ступеней), medium → …, light → …»,
строка контекста профиля («контекст 525К · ввод 461К · вывод до 128К», с путём к файлу настроек) и пометки наследования; на деле
у всех этапов и ступеней одна модель, а единственная важная вещь — заметка в конце о том, что приёмка на той же семье моделей,
что разработка.

Задача полная: разбор, реализация, сдача. Быстрый путь. Основа — `main` (`e4e6f42`).

## Чего хочет владелец (его слова, 2026-10-17, чат оркестратора)

- «в этой каше ничего не понять»
- «по рекомендации» — на предложение оркестратора: короткая таблица «этап × ступень» с короткими именами моделей и одной
  строкой-расшифровкой внизу; одинаковое схлопнуто (все этапы одинаковы — одна строка; унаследованный этап — «как «…»»);
  предупреждения (приёмка той же семьи, что разработка) — отдельной строкой со знаком ⚠; подробности (наследование, срезы,
  откуда взят контекст) — только по `/crew-sets show <этап>`.

## Что нужно

1. **Вид по умолчанию** (`opencode-plugin/profile-cmd.ts`, где собирается `show`): заголовок «Набор «<имя>» — включён/выключен»;
   таблица: строка — этап, колонки — heavy, medium, light; в ячейке — короткое имя модели (`luna`, `sol`, `opus` …; правило
   сокращения — в разборе, без потери различимости: две разные модели не получают одно имя); унаследованный без отличий этап —
   «как «<этап>»»; если все этапы совпадают — одна строка «все этапы: heavy/medium/light → <модели>». Под таблицей — расшифровка
   коротких имён: полное имя, контекст, вывод (по разу на модель, без пути к файлу настроек). Затем предупреждения ⚠ — каждое одной
   строкой (та же семья у приёмки и разработки; модель недоступна; и прочие, что уже считает `show`). Ширина — окно `/crew`
   (`DIALOG_WIDTH`), строки не переносятся.
2. **Подробный вид** — `/crew-sets show <этап>` (и `show all`, если нужен прежний полный текст): всё, что выводится сейчас, для
   одного этапа, без потери сведений. Подсказка о нём — последней строкой краткого вида.
3. **Ничего не теряется:** каждое сведение прежнего вывода есть либо в кратком, либо в подробном виде — перечислить в разборе
   соответствие «было → где теперь».
4. **Тесты:** красная проба до кода (снимок краткого вида на наборе, где все этапы одинаковы, и на наборе с разными моделями и
   наследованием; подробный вид этапа; предупреждение семьи); полный `npm test` параллельно до 4, упавшие — отдельно
   ([AGENTS.md](../../../../AGENTS.md), пп. 8–9); golden — только изменившиеся ключи.
5. README плагина — абзац о кратком и подробном виде.
6. **Тот же приём для остальных ответов `/crew-sets`** (дополнение, владелец, 2026-10-17, чат оркестратора: после
   `/crew-sets use kimi` — «это тоже не читаемо»). Ответ `use` сейчас — сплошной абзац: «Включён набор «kimi» (записано в
   profile_set файла проекта, без коммита; было «codex»). Перезапуск не нужен. Этапы: … Контекст сессий в рабочих деревьях задач
   (было → стало), применится на следующем ходу каждой сессии: … Приёмка и приёмка плана: контекст профиля здесь не применяется
   (приёмка идёт в основной папке): … Файлы окон: записано 2, снято 0; задач с рабочим деревом сейчас 2…». Нужно: первой строкой
   одно предложение «Набор «kimi» включён (был «codex»); новые сессии пойдут на нём, перезапуск не нужен»; ниже короткий список
   «что изменилось» — этапы и модели (одинаковое схлопнуто), окна контекста «было → стало» (если не менялись — одна строка «окна
   прежние»), затем ⚠ и предупреждения; пояснения про основную папку и файлы окон — одной короткой строкой или по запросу
   (`/crew-sets show`). Проверить так же остальные подкоманды (`set`, `unset`, `new`, `rename`, `delete`, `check`) и привести их
   ответы к тому же виду: первая строка — итог, дальше только изменившееся. Красная проба на снимках ответов; ничего из
   сведений не теряется (соответствие «было → где теперь» в разборе).
7. **Одно слово «show»; слово «view» — убрать** (дополнение, владелец, 2026-10-17, чат оркестратора: «во всех командах /crew*
   оставить show, там где был view - удалить, обновить тексты»; прежнее решение владельца о слове `view` этим снято). Во всех
   командах окна `/crew*` и во всех инструментах агентов (`crew_task`, `crew_config` и прочие, где есть `view`) единственное слово
   для «показать» — `show`. Из схем инструментов (enum `action`), подсказок (`core.ts`: строки справки, описания инструментов,
   тексты ответов вроде «crew_task {action: "view", n}»), README плагина и тестов `view` удалить; тексты обновить. Вызов `view`
   — не молчаливый синоним, а понятный отказ: «Команды view больше нет, используй show» (как у уже снятых глаголов,
   `GONE_VERBS`), чтобы уже идущие сессии агентов, помнящие `view`, получили подсказку, а не сломались. Список мест — в разборе
   (поиск по всему `opencode-plugin/` и `doc/canon/`; журналы и разборы прошлых задач не переписывать).
8. **`/crew-sets ls` и `/crew-profiles ls`** (дополнение, владелец, 2026-10-17: «/crew-sets ls — отметить в таблице, какой набор
   включён, и показать модели»; «/crew-profiles ls»). Глагол `ls` — список; команда без слов делает то же самое; `list` принимается
   как синоним. В таблице набора включённый помечен `●`, в ячейках — модели (короткие имена по п. 1, расшифровка под таблицей), а
   не «семья/режим». `/crew-profiles ls` — тот же вид для справочника: семья, ступень → модель, окно.
9. **Интерактивный выбор вместо ввода текста** (дополнение, владелец, 2026-10-17: «интерактивно переключить сет с этого экрана
   можно?» и «в меню выбора набора (use, show, rename, delete) показывать список реальных наборов с моделями вместо поля для
   набора текста. Стрелками выбрали kimi — Enter, ничего вводить не надо»). Окно `ls` открывается как выбор (`dialog.select`):
   строка — набор, `●` у включённого, в подписи модели; Enter на строке включает набор (`use`) и показывает короткий итог по
   п. 6. Меню глаголов `use`, `show`, `rename`, `delete`, `set`, `unset`, `check` (где аргумент — имя набора) сначала открывает тот же
   список наборов; ввод текста остаётся только там, где нужно новое имя или ячейка (`new`, `rename` — второе имя, `set` — этап и
   семья/ступень). Для `/crew-profiles` — список семей. Полная таблица по этапам — `show`. Разбор: что даёт `dialog.select` окна
   OpenCode (поля `title`, `value`, `description`, `footer`, `current`, `onSelect`, `category`) и чего не даёт (автодополнение
   набираемого слова в самой строке `/` — нет: хука нет); текст в `showText` не интерактивен, поэтому `ls` — выбор, а не таблица.

## Критерии приёмки

1. `/crew-sets show` на наборе, где все этапы одинаковы, и на наборе с разными моделями и наследованием даёт короткий вид по
   пункту 1 «Что нужно»; подробности — по `/crew-sets show <этап>`, ничего из прежнего вывода не потеряно (соответствие «было → где
   теперь» в разборе).
2. Ответы `use`, `set`, `unset`, `new`, `rename`, `delete`, `check` начинаются строкой-итогом, дальше только изменившееся.
3. Красные пробы написаны до кода; полный `npm test` зелёный (упавшие при параллельном прогоне перепроверены отдельно); README
   плагина описывает краткий и подробный виды.
4. Слово `view` удалено из схем, справки, README и тестов (вызов даёт отказ «используй show»); `ls` и окно выбора набора
   работают по пунктам 8–9 «Что нужно».
