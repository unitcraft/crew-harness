## Что нужно (этап «ядро»: не зависит от окончательного синтаксиса таблиц)

1. **Образец и источники:** черновик формата v1 и итоги пилотов (папки на диске: `draft-format-v1.md` рядом с папкой задачи 104 в рабочем дереве `crew-harness-104-machine-table-format`; выписки Методики: `pilot-agent-step-v1/`, `pilot-meeting-v1/`; разметка 80 функций совещания `functions-markup.md`; все только чтение), `src/engine/README.md`, `GLOSSARY.md`, ограничения Oracle 0.1.0 (`spikes/env/README.md`, п. 1–29: обобщённые типы с протоколами ломают C, пишите динамическое значение вместо обобщений).
2. **Значение `Value`** (одно перечисление с данными, без обобщений): `Null`, `Bool`, `Int`, `Float`, `Text`, `List`, `Dict`, `Record(name, fields)`, `Variant(type, name, fields)`; кодирование в JSON и разбор из JSON (на `std.encoding.json`); равенство, порядок, текст по правилам v1 (`текст(x)`: целое — десятичная запись; дробное — кратчайшая; перечисление — слово кода; `пусто` — `none`).
3. **Дерево выражений** (узлы JSON, как в черновике: `lit`, `name`, `field`, `index`, `call`, `lambda`, `match`, `let`, `if`, `record`, `with_field` («запись с изменённым полем»), `list`, `dict`, операции `+ - * / %`, сравнения, `and or not`, `??`) и **вычислитель**: чистая функция `eval(expr, scope) -> Result[Value, EvalError]`; `if`, `and`, `or`, `??` ленивы; `match` исчерпывающий с охраной и привязкой полей варианта; макросы `filter`, `map`, `any`, `all`, `count`, `first_where`, `fold`, `range(a, b)` (пуст при `b <= a`), `keys`, `values`, `length`, `has` (`есть`), `require` (`обязательно`: отсутствие значения — ошибка машины), склейка списков `+`, `remove(list, item)`, `without_key(dict, key)`; индекс словаря по отсутствующему ключу — `Null`; переполнение `Int` — ошибка; ошибки типов — `EvalError` с путём в дереве. Тотальность: нет циклов и рекурсии, глубина дерева ограничена.
4. **Реестр примитивов хозяина:** тип `Primitive { name, params: []ParamSpec, result: TypeSpec, class: Pure | Reading | Writing | Irreversible }`, регистрация, проверка допустимости класса в позиции вызова (`Pure` везде; `Reading` только в «При входе» и «Вход»; `Writing` и `Irreversible` только в действиях и «При входе» операций и концов), вызов по имени из вычислителя через переданный обработчик (никаких побочных эффектов внутри ядра). Заполнить реестр заглушками по разметке методики: 17 примитивов совещания (reading 8, writing 6, irreversible 3) и примитивы «Шага агента» (`reply_validation`, `close_agent_turn`, `check_cache`, время и др.), с типами входа и выхода.
5. **Типы:** `TypeSpec` (int, float, text, bool, optional T, list T, dict K V, record name, variant name) и проверка значения по типу (для данных машины и параметров примитивов).
6. **Проверки (`nova test src --jobs 4`, `--strict-effects`):** красная проба до кода; тесты вычислителя на каждую конструкцию и на крайние случаи (ленивость: правая часть `??`, `and`, `or`, `if` не вычисляется; `range` пустой; переполнение; отсутствующий ключ; исчерпанность `match`; охрана; склейка списков; `fold` с накоплением; `text` для целого, дробного, перечисления, `none`; ошибки с путём); кодирование и разбор JSON туда и обратно без потерь (кириллица, 4-байтные буквы); детерминизм (два прогона дают то же); реестр: проверка класса в позиции; не менее 150 проверок; стражи 8 и больше, FAIL 0; коммит по правилам AGENTS.md (английское сообщение, `-s`, без трейлеров и без `#число`, файлы перечнем).
7. **README** `src/machine/README.md` (английский): значение, дерево, список макросов и их семантика, реестр, ограничения Oracle и обходы; новые ограничения Oracle — воспроизведения в `spikes/env/repro_*` и в отчёт.
