Задание — `task/message.md`. Источник: слова владельца в чате оркестратора, 2026-10-19: «цель: все возможности текущие (плагин crew-harness под opencode) + стейт-машины из методики должны быть написаны на таких стейт-машинах внутри голого продукта CrewHarness»; «по рекомендации» (строить ядро, когда формат подтверждён пилотами). Язык выражений взят из формата версии 2 (`state-machines/state-machine-table-format.md` методики, опытный), а не из черновика версии 1, на который ссылается задание: версия 2 вышла в ходе работы, оркестратор велел следовать ей там, где она отличается.

## 1. Что сделано

Код — `src/machine/`, один модуль `crew_harness.machine`, README — `src/machine/README.md`.

- **Значение `Value`** (`value.nv`): `Null`, `Bool`, `Int`, `Float`, `Text`, `List`, `Dict`, `Record`, `Variant`; без обобщений; равенство и общий порядок; `text(x)` по формату 2; кортеж — анонимная запись с полями `1`, `2`, …; кодирование в JSON и разбор без потерь (целое и дробное различаются, кириллица и четырёхбайтные буквы).
- **Типы** (`types.nv`): `TypeSpec` (целое, `число≥n`, дробное, текст, закрытый набор текста, да/нет, `?T`, список, словарь, кортеж, запись, вариант), `check_value` с путём первого несовпадения.
- **Дерево выражений** (`expr.nv`): узлы `lit`, `name`, `field`, `index`, `call`, `lambda`, `primitive_call`, `match`, `let`, `if`, `record`, `with_field`, `variant`, `list`, `tuple`, `dict`, операторы; чтение и запись JSON с ошибкой и путём; предел глубины 64.
- **Вычислитель** (`eval.nv`): `eval(expr, scope)` и `eval_with(expr, scope, host)`; ленивы `if`, `and`, `or`, `??`; `match` исчерпывающий с охраной и привязкой полей; макросы и функции каталога формата 2 (`filter`, `map`, `any`, `all`, `count`, `first_where`, `fold`, `dict`, `range`, `keys`, `values`, `length`, `has`, `require`, `remove`, `without_key`, `text`, `float`, `int`, `max`, `min`, `journal_event`); ошибки значением `EvalError { kind, message, path }`; пределы глубины, числа узлов и длины списка; вызов примитива — только через переданный `PrimitiveHost`.
- **Реестр** (`registry.nv`): 21 примитив (17 совещания: reading 8, writing 6, irreversible 3; 4 шага агента), проверка класса в позиции вызова по формату 2 (восемь позиций), проверка аргументов и результата по типам, списки `reads` и `writes`.

## 2. Расхождения с заданием и решения исполнителя

- Индекс списка вне границ и индекс словаря по отсутствующему ключу — `Null` (формат 2).
- `require(x)` на `Null` — дефект `Unreachable`, а не «ошибка машины» (формат 2, Ш18).
- `remove` убирает все равные; словарь хранит порядок вставки; `+` над текстами и списками; `dict(…)` и литерал словаря с повтором ключа — `DuplicateKey`.
- `int(x)` отбрасывает дробную часть к нулю; `text(дробное)` по правилу владельца: кратчайшая обратимая запись, `.0` у целых значений, без показателя при 1e-4 ≤ |x| < 1e16.
- Деление и остаток целых — к нулю; `<` и подобные только на числах; `==` целого и дробного — ложь.
- Один модуль и один юнит вместо трёх: модуль во вложенной папке Oracle 0.1.0 не принимает (п. 25); 163 теста с короткими именами укладываются в 4096 байт вывода (3351).
- `check_cache` записан как writing-примитив шага агента (в коде автомата его нет, пилот называет его первоисточником).

## 4. Новые ограничения Oracle 0.1.0 (воспроизведения — `spikes/env/repro_engine/src/`, `spikes/env/README.md`, п. 33–35)

33. `for_in_enum_literal`: `for c in [Pure, Writing]` по литералу списка из значений перечисления не собирается.
34. `option_enum_named_variants`: перечисление с вариантом с именованными полями и запись с полем `Option[ЭтоПеречисление]`, объявленная ДО перечисления, ломают C.
