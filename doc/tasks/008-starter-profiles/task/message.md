# Задание: стартовый справочник профилей и наборов по явному пункту меню

Заказчик и владелец: владелец репозитория `unitcraft/crew-harness` (он же отвечает на вопросы и принимает результат).
Репозиторий кода: `unitcraft/crew-harness` (https://github.com/unitcraft/crew-harness, ветка `main`). Дата задания: 2026-10-08.
Источник: [спецификация задачи 003](../../003-model-profiles/spec.md) (REQ-01, REQ-03, REQ-26, AC-30, Д-03) и замечание владельца по живому окну.

Задача полная: разбор, план, реализация, сдача.

## Чего хочет владелец (его слова, 2026-10-08)

- «см ридми - это не о чем, надо хотя бы ссылка кликабельная, а лучше заполнять стартовыми профилями и сетами автоматически»
  (про ответ «Справочник пуст. Пример файла — в README плагина» команды `/crew-profiles` в проекте без справочника).
- «по рекомендациям» на предложение: ссылку сделать сразу (правка текста без изменения спецификации), а стартовое
  заполнение оформить отдельной задачей с правкой требований задачи 003.

## Что есть сейчас

- Справочник профилей (семья, ступень → модель, контекст) и наборы лежат в файле проекта (`.opencode/crew-harness.json`);
  пустой справочник — тупик: команды советуют смотреть README.
- Спецификация задачи 003 запрещает плагину самому писать наборы (REQ-26), вшивать образцы наборов и семьи моделей в код
  (REQ-03, REQ-01) и брать контексты окон из каталога моделей (REQ-01, Д-03).

## Что нужно

По явному пункту меню окна («Создать стартовый справочник и наборы», одно подтверждение) плагин добавляет в файл проекта
недостающее стартовое содержимое: профили семей claude, kimi, codex со ступенями heavy, medium, light и стартовые наборы
(например `claude-all`, `cross-kimi`, `cross-codex`); существующие записи не перезаписываются; после записи показывается,
что создано, и выполняется `check`. Стартовое содержимое хранится одним файлом рядом с README плагина, из которого берут и
README-пример, и меню, и проверка. Требования задачи 003 (REQ-26, REQ-03, REQ-01, AC-30, Д-03) правятся этой задачей.
