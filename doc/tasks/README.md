# Задачи

Одна задача — одна папка `NNN-<slug>/`, устроенная по методике
([`task-sessions.md`](https://github.com/unitcraft/ai-dev-methodology/blob/main/task-sessions.md), раздел «Подготовка»).
Чем у нас отличается — [doc/canon/process.md](../canon/process.md): папка в репозитории, коммитится на воротах, без приватных данных.

Список задач — сами папки этой директории; руками он не ведётся (статус задачи — в её `log.md`).

## Журнал хода `progress.log`

Сессии пишут ход в `progress.log` папки задачи строкой `<код сессии> <k>/<N> [ЧЧ:ММ] <что сделано>`; формат, слова `запуск`, `старт`,
`готово`, `стоп:` и правила записи — в Каноне ([doc/canon/process.md](../canon/process.md), «Журнал хода»). Формат проверяет страж
[`scripts/guards/check-task-docs.py`](../../scripts/guards/check-task-docs.py): строка не по форме или с путём машины красная, адрес —
«файл:строка». Предел подписи в 80 знаков страж проверяет только у добавленных строк журнала, который уже есть в `HEAD`, и только в
хуке `pre-commit` (`run-all.sh --index`); в `pre-push` и в CI (`run-all.sh --ci`) предела нет — там проверяется дерево целиком и добавленных
строк нет, поэтому длинную подпись в уже закоммиченном журнале они не найдут (это судится приёмкой). Старые строки журналов не переписываются.
Панель окна читает те же журналы всех рабочих деревьев репозитория ([README плагина](../../opencode-plugin/README.md), «Progress of background sessions»).

## Постановка быстрого маршрута

Быстрый маршрут — по методике ([`task-runner.md`](https://github.com/unitcraft/ai-dev-methodology/blob/main/task-runner.md), «Маршрут», ворота В14; запись в
Каноне — [process.md](../canon/process.md), «Маршрут задачи»): постановка `task/message.md` заменяет `spec.md`, плана нет, проверка реализации — один чистый заход.
Чтобы задача шла быстрым маршрутом, постановка содержит (иначе она идёт на полный):

- пронумерованные критерии приёмки — строки, начинающиеся с `AC-1`, `AC-2`, … (не меньше одной); по ним пишется красный тест;
- строку `Ветка: <имя>` (плана нет, ветку берут из постановки);
- раздел «Признаки маршрута» со строками `Цель: …`, `Источников: <число>`, `Частей системы: <число>`, `Риск: низкий|средний|высокий`,
  `Необратимо: да|нет`, `Причина известна: да|нет`, `Касается нормы или формата: да|нет`;
- слово владельца «заводи <номер>» (с датой и источником) — запись о быстром маршруте; в нашей практике его заменяет слово «по рекомендации» на
  предложение завести задачу, и тогда в «Источнике» постановки цитируется это слово.

Образец раздела (из задания 110):

```text
## Признаки маршрута

Цель: формат 2.7 «Портолан» в переводчике и интерпретаторе, образец методики переводится без правки.
Источников: 3
Частей системы: 4
Риск: средний
Необратимо: нет
Причина известна: да
Касается нормы или формата: да

Ветка: task-110-format-27

## Критерии приёмки

AC-1. Образец методики формата 2.7 переводится без правки, проходит проверки загрузки; расхождения с продуктовой таблицей — в отчёте.
AC-2. Метки П-1…П-9 реализованы и покрыты красными пробами; старые файлы 2.5 и 2.6 читаются.
AC-3. `nova test src --jobs 4` зелёный (и `--strict-effects`); не менее 150 новых проверок; стражи 8 и больше, FAIL 0.
```

Задания 106–109 сделаны до этого правила: критерии в них идут обычным разделом без `AC-N`; переписывать их задним числом не нужно.
