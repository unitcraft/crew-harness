# Разбор 086: все задачи всех проектов подписываются тремя цифрами без «#»; «#N» закреплено за issue GitHub

Задание — `task/message.md` (вторая редакция; первая — «#N» везде — заменена тем же днём). Источник: слова владельца в чате оркестратора, 2026-10-18: «разве задачи мы не называем через # ?», «а где унификация?»; затем, увидев issue Nova с чужими коммитами
(скриншот: «added 11 commits that reference this issue» — коммиты про задачу, а не про issue), решение: «все задачи всех проектов подписываются тремя цифрами без # (022, 061, 081, 094) … количество цифр может быть и больше 3; закрепить #{N} за номером issue на github,
поэтому по стражу подумай». Причина: GitHub превращает любое «#N» в сообщении коммита, описании и комментарии в ссылку на issue или PR; перекрёстные ссылки засоряют чужие issue и рассылают уведомления.

## 1. Как места идут к подписи

- `taskNo` в `tasks.ts` — единственное место, где номер задачи строится: три цифры с нулями слева, длиннее — как есть (`1000`), без «#», для любого проекта, с папкой и без; параметры `project` и `folder` в типе остались и игнорируются. `taskRef`, `sessionRef` идут через него.
- Через него же: сводка `statusOf` (`ref`), панель, `/crew`, «Ждут вас» (`refOf`, `tabOf`, `tabRef` в `status.ts`), `idle-tab.ts`, `review.ts` (`lockWaitLine`), `precheck.ts`, `core.ts` (`sessionLabel`, письма, отказы по лимитам), `index.ts` (`syncTitles`, заголовок при создании сессии),
  `task-folders.ts` (`sessionTitleRef`), `profile-cmd.ts` (там была ветка «`ref` из сводки, иначе `taskNo`» — теперь всегда `taskNo`).
- Читается подпись одним местом: `TAB_RE` в `status.ts` (экспортирован) принимает «#33 исп» и «045 С4-3»; `tabOf` показывает обе формы по-новому («033 исп»); `syncTitles` строит новый заголовок и сравнивает с `titleShown`, поэтому вкладки со старым заголовком переименовываются сами (лимит 3 за проход и порог в сутки сохранены).
- Других разборов заголовка по `#\d+` в `scripts/` и `opencode-plugin/` нет. Остальные «#» с числом — не подпись и не менялись: ключ `проект#N` в `index.ts` и `tui.ts` и адрес заказа (`parent: "проект#N"`, разбор в `core.ts`), суффикс модели «#вариант», счётчик nudge, заголовки Markdown, цвета.
- Номера на диске остались тремя цифрами: `pad3` в `task-numbers.ts`, подстановка `{n}` в имена папок и веток (`index.ts`, `review.ts`).
- Тексты для агентов и людей приведены к трём цифрам: `crew_help`, описания `crew_spawn`/`crew_task`/`crew_list` в `core.ts`, подсказка в `mcp.ts`, системная подсказка в `index.ts`, README плагина, `doc/canon/process.md` (с причиной — автоссылки GitHub), `AGENTS.md` п. 4. Прежние «#31» в `log.md` и `analysis.md` других задач не правились (история).

## 2. Страж сообщения коммита

Новое правило R8 в `scripts/guards/guard-commit-message.py` (метка `task-hash`): «#число» допускается только как ссылка на issue или PR GitHub — после слов fix, close, resolve (в любых формах), ref/refs, see, issue, pr, pull request, без учёта регистра; допустимы списки вида «Closes: #4, #5 and #6». Не судятся: строки цитаты на «>»,
«&#31;», «owner/repo#3», «file#12», «#cfg(…)», «#123abc» (цвет), комментарии редактора. Диагностика: «номер задачи пишется тремя цифрами без #; #N закреплено за номером issue GitHub» с номером строки. Работает в хуке commit-msg, перед пушем (`--commit`) и в CI; проверяются только новые коммиты (диапазон пуша), история не переписывается.
Самотесты: `test-guard-commit-message.py` (52 пробы, 9 из 17 новых были красными на неизменённом страже), `test-commit-msg.py` (`-m`, `-F`, комментарий редактора), `test-pre-push.py` (красный и зелёный коммит).
