Репозиторий: `unitcraft/crew-harness`, ветка `main`. Дата задания: 2026-10-18 (первая редакция — «все через #N», заменена тем же днём).
Источник: слова владельца в чате оркестратора, 2026-10-18: «разве задачи мы не называем через # ?» и «а где унификация?» (первая редакция задания: «#N» везде); затем, увидев issue Nova с

Задача полная: разбор, реализация, сдача. Быстрый путь. Основа — ветка задачи (в ней первая редакция: `taskNo` пишет «#N»; её надо переделать), свежий `origin/main` — база.

## Что нужно

   (`1000`). Подпись сессии — `061 С4-3`, `061 исп`, `061 прм`. Один `taskNo` на все места; параметры `project` и `folder` подписи не меняют. «#N» нигде не пишется для задач: ни в панели, `/crew`,
   заголовках вкладок, письмах, сообщениях плагина, ни в текстах справки, README, Каноне.
2. **Чтение старых заголовков:** вкладки, названные ранее, читаются в обеих формах — «#33 исп» (первая редакция 083 и прежний Nova-вид) и «045 С4-3»; `syncTitles` переименовывает их в новую форму
   (лимит 3 за проход, порог в сутки — как сейчас). `TAB_RE` принимает обе.
3. **Страж сообщения коммита (механизм вместо слов):** в `scripts/guards/guard-commit-message.py` новое правило (R8): «#<число>» в сообщении коммита допускается только как ссылка на issue или PR GitHub —
   сразу после слов `Fixes`, `Closes`, `Resolves`, `Refs`, `See`, `issue`, `PR`, `pull` (без учёта регистра, в одной строке); иначе красный с текстом «номер задачи пишется тремя цифрами без #; #N
   закреплено за номером issue GitHub» и указанием строки. Строки-комментарии git (на «#» при редакторе) и строки цитаты на «>» не считаются; шестнадцатеричные цвета («#ff00ff», «#123abc») — не
   номер. Самотест в `scripts/guards/selftest/test-guard-commit-message.py`: красное (голое «#31», «task #94», «(#31 «title»)»), зелёное («Fixes #12», «Refs #3», «see PR #7», «#cfg(target_os)» — не число, цвет), и
   что правило работает в хуке commit-msg, pre-push (`--commit`) и в CI. Только новые коммиты: проверка диапазона пуша, история не проверяется.
