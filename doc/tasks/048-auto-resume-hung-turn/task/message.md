# Задание: зависший ход вкладки плагин снимает и продолжает сам

Заказчик и владелец: владелец репозитория `unitcraft/crew-harness` (он же отвечает на вопросы и принимает результат).
Репозиторий кода: `unitcraft/crew-harness` (https://github.com/unitcraft/crew-harness, ветка `main`). Дата задания: 2026-10-15.
Источник: 2026-10-15 15:24 ход интегратора crew-harness завис (вызов инструмента остался в состоянии `streaming` с пустым вводом); задача 036 верно подняла «ход завис с 15:24 (15 мин): нажмите Esc в окне и напишите «продолжай»».

Задача полная: разбор, план, реализация, сдача. Быстрый путь. **Основа — ветка `waiting-line`** (ещё не влита в `main`: сводная строка «Ждут вас» и снятие «застряла» рабочим ходом).

## Что есть сейчас

- Задача 036 (`hungTurn` в `core.ts`, `noteHung` в `index.ts`): вкладка, которую окно считает занятой, без активности модели дольше 15 минут и без работающего инструмента или наблюдения — «завис»; владельцу строка и уведомление «нажмите Esc и напишите «продолжай»».
- В OpenCode 2.0.26 есть прерывание хода: команда окна `session.interrupt` (клавиша Esc) и метод сервера `POST /api/session/:sessionID/interrupt` (запрос `resume`, ответ `{interrupted}` — «прерывает активное выполнение, принадлежащее этому процессу OpenCode»). Сервер требует аутентификации (снаружи процесса — 401); плагин живёт внутри процесса службы.
- В контексте плагина сейчас используются `ctx.session.get / prompt / synthetic / create / update / hook`; есть ли `ctx.session.interrupt` (или иной способ из процесса) — не проверено.
- Плагин умеет будить вкладку письмом (`postLetter` + доставка), в том числе в сессию без окна (`session.prompt` с `resume`).

## Что нужно

1. **Выяснить способ прервать ход из плагина** без учётных данных и без обхода защиты: метод контекста (`ctx.session.interrupt` или подобный), внутренний клиент SDK в контексте плагина, событие шины; проверить на живой службе нельзя (её перезапускает владелец) — проба через `crew_doctor`/журнал: плагин при загрузке пишет в журнал, какие методы прерывания доступны. Если способа нет — в `analysis.md` записать это с доказательствами и предложить запасной путь (например, письмо вкладке с просьбой прервать свой инструмент сама, если это вообще осуществимо), не делать вид, что работает.
2. **Самовосстановление зависшего хода:** когда `hungTurn` признал ход зависшим, плагин сам прерывает ход и будит вкладку письмом «Ход завис и прерван плагином в ЧЧ:ММ; продолжай с того места, где остановился» (по-русски, как остальные служебные письма). Пределы: одна попытка на зависание, не больше 2 попыток на сессию за час; после неуспеха (снова завис) — прежнее уведомление владельцу «нажмите Esc…» и запись в журнале. Работающий инструмент, наблюдение (`crew_watch`) и вопрос к владельцу (вопросник, задача 040) зависанием не считаются — как в 036.
3. **Тексты:** уведомление владельцу «ход завис…» остаётся только для случая, когда автоматика не смогла; при успешном самовосстановлении — запись в истории задачи (если есть) и строка в журнале плагина, владельцу ничего делать не нужно.
4. **Тесты:** красная проба — ход зависший дольше порога → прерывание вызвано и письмо «продолжай» ушло; второй раз в пределах часа — не больше 2; неуспех → уведомление владельцу; работающий инструмент и вопрос владельцу — без прерывания. Тесты по одному с паузой 15 с ([AGENTS.md](../../../../AGENTS.md), п. 9).
