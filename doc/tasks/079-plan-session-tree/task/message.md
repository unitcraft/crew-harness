# Задание: сессия плана с рабочим деревом подхватывается, а не создаёт второе дерево

Заказчик: владелец репозитория `unitcraft/crew-harness` (он же отвечает на вопросы и принимает результат).
Репозиторий: `unitcraft/crew-harness`, ветка `main`. Дата задания: 2026-10-17.
Источник: 2026-10-17 интегратор crew-harness по задаче 061 «Канон и актуальная методика» (спецификация утверждена, идёт план) спросил
владельца: плагин не запускает уже записанную сессию плана (С3п) — пытается создать второе рабочее дерево на ветке, которая уже занята
деревом, подготовленным интегратором вручную (`crew_task track` записал ветку и путь дерева, затем `crew_spawn {task: 61, session: С3п,
place: task}`). Предложенный обход: точечно править служебную запись задачи 061 (путь дерева) с резервной копией. Владелец ответил «Исправить
путь» («проверь сессии opencode, … ответь по своей рекомендации», 2026-10-17), но причина — дефект плагина: путь дерева записи задачи и
дерево сессии не согласуются, и ручная правка записи понадобится снова.

Задача полная: разбор, реализация, сдача. Быстрый путь. Основа — свежий `origin/main`.

## Чего хочет владелец

- «по рекомендации» (владелец, 2026-10-17, чат оркестратора) — на предложение оркестратора завести задачу, чтобы ручная правка записи не
  понадобилась в следующий раз.

## Что нужно

1. **Разбор:** где плагин решает, какое дерево у сессии задачи с папкой (`core.ts`/`index.ts`: `spawnInFolder`, `startSession`, `track`,
   `session_move`, `worktree_ready`, `task-folders.ts`): что записывает `crew_task track` (ветка, дерево), что делает `crew_spawn {task, session,
   place: task}` для уже зарегистрированной сессии и почему идёт к созданию второго дерева на занятой ветке (проверка занятости ветки, `git
   worktree add` против существующего дерева, запись `tree`/`worktree` в записи задачи и в записи сессии). Воспроизвести на одноразовом
   репозитории в тесте: задача с папкой, дерево создано вручную на ветке задачи, `track` его записал, сессия плана зарегистрирована
   (`planned`), запуск.
2. **Исправление:** если дерево сессии уже существует (запись `track` или дерево на этой ветке по `git worktree list` — основной репозиторий
   проекта) — использовать его, не создавать второе; запись задачи и сессии согласуются по одному пути; ветка занята другим деревом, не
   принадлежащим задаче, — понятный отказ с путём этого дерева, а не попытка `worktree add`. Файлы и ветки не переносить и не удалять.
3. **Ничего не ломать:** обычный запуск (дерево создаётся плагином) — как прежде; удалённое дерево (путь записан, папки нет) — плагин
   пересоздаёт или отказывает понятно (по разбору).
4. **Тесты:** красная проба до кода (источник: дерево создано вручную и записано `track`, затем запуск сессии → второе дерево не создаётся,
   сессия идёт в существующем; границы: дерево создаёт плагин; ветка занята чужим деревом → отказ; путь записан, папки нет); полный `npm test` по
   8 параллельно ([AGENTS.md](../../../../AGENTS.md), п. 9); golden — только изменившиеся ключи.
5. README плагина — абзац.

## Критерии приёмки

- Красная проба до кода падает на источнике и проходит после правки.
- На одноразовом репозитории воспроизведён сценарий 061 (дерево вручную + track + запуск сессии плана) и закончился запуском сессии в
  существующем дереве без второго `worktree add`.
