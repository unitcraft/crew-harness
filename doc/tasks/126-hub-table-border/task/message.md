## Что нужно

1. **Источники.** `src/server/hub.nv` (`Hub.is_awaiting`, `Hub.say`, `@handle`), `src/server/dialog_test.nv`, `src/server/portolan.nv`, `src/machine_run/machine.nv`, `step.nv`, `chain.nv` (`PortolanMachine`, выбор строки, `hit_of`, общие события), `src/machine/machines/dialog.portolan.md` и `.json`, `chat.portolan.md` и `.json` (то же поле `текст текст`), `src/acp/project.nv` (`project_update`, `stop_event`, `page_event`), `doc/tasks/114-portolan-server/` (как устроено подключение), `src/server/README.md`, `src/machine/README.md`.
2. **Хаб не знает имён состояний (п. 2 списка).** Заменить сравнение `state_name == "Awaiting"` вопросом к машине: интерпретатор получает метод «принимает ли состояние это слово» (проверка общих событий и строк состояния по виду события, имени слова и, если нужно, условию с пустыми привязками; точная форма — решение исполнителя, записать в `analysis.md`); `Hub.say` игнорирует сообщение, если состояние слова не принимает, как раньше (строка в журнал хаба «a message to ... while a turn is open: ignored»). Поведение для пользователя не меняется. После правки таблицу можно переименовать (имя состояния) без правки хаба: тест это доказывает на изменённой копии таблицы.
3. **Поле слов названо по смыслу.** В `dialog.portolan.md` и `chat.portolan.md` слова `сообщение_пользователя(текст текст)` и часть `кусок_ответа(текст текст)` получают поле `содержание текст` (имя по смыслу), строки таблицы ссылаются на него (`сообщение_пользователя(содержание: сообщение)`, `кусок_ответа(содержание: кусок)`); перевод `.json` и английский вид пересобираются `portolan compile` / `portolan convert`; круг `compile → render → compile` равен; сценарии `dialog-*` и `chat-*` остаются зелёными (у слов с одним полем имя в сценариях не пишется; если пишется — правка генератора, не руками); вшитый JSON хаба обновляется.
4. **Словарь общих слов записан (п. 1, 3, 4 списка).** В `src/server/README.md` (или в `src/machine/README.md`, решение исполнителя; одно место) раздел «Граница таблицы и кода»: (а) список слов, которые код подаёт машине (`user_message`, `cancel`, `permission_decision`, `session_created`: поля и кто подаёт), и слов, которые приходят от агента (`agent_chunk`, `agent_done`, отказ с кодом, `acp_note`, срок), с указанием, где слово объявлено в коде; (б) что `session_created` намеренно подаётся машине как слово, которого таблица не знает (запись `event_unknown` в журнале); (в) сопоставление `stopReason` агента с исходами (`end_turn` — ответ; `max_tokens`, `max_turn_requests`, `refusal`, `cancelled`, прочее — отказ с кодом из `FailCode`) в `stop_event` клиента ACP; (г) что в таблице, а что в коде (схема границы — в разборе). Тест, который ловит расхождение словаря: каждое слово, которое подаёт код, объявлено в таблице диалога или названо в списке «таблице не известно».
5. **Проверки.** Красная проба до кода: тест на изменённую копию таблицы диалога с переименованным состоянием и тест на `принимает ли состояние слово` красные на `origin/main`; не менее 25 новых проверок; затронутые юниты (`server`, `machine_run`, `machine`, `portolan_eq`, `portolan_scenarios`, `server_live`, `server_pg`) и полный набор `nova test src --jobs 4 --timeout 600`, `--strict-effects` зелёные (программы со stdin — с закрытым stdin; PostgreSQL — временный контейнер `src/pg/testdb.ps1`, затем `-Stop`; Docker запускает владелец, сам не запускай); стражи `sh scripts/guards/run-all.sh` ок и больше, FAIL 0; коммиты по правилам AGENTS.md (по темам); метки `// ORACLE-WORKAROUND(N): …` на обходах Oracle, новые пункты README Oracle — с номера 120.
