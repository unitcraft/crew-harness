# Разбор 078: вкладка зациклилась на вопросе после ответа владельца

Задание — `task/message.md`. Источник: владелец, 2026-10-17 («по рекомендации», чат оркестратора — на предложение завести задачу).
Живые данные читались только на чтение: записи `forms/`, ящики `inbox/` и `read/` вкладки, ответы `answers/`, база сообщений OpenCode
(`session_message`, `session_inbox`). Вкладка — `nova.worker`, задача #94; формы называются по короткому виду.

## 1. Разбор

### Что видит вкладка: пакет доставки

Ожидание задания: «письмо-напоминание и письмо-ответ приходят в одном пакете, вкладка не читает письмо с ответом». **По базе это не так.**
Вкладка получает не пакет, а **по одному старому сообщению очереди сервера за ход**; письма с ответом владельца лежат в хвосте очереди и до
модели **ни разу не дошли**.

- Сообщения `user`, которые модель видела в ходах с 17:23: семь служебных сообщений плагина, ни в одном нет слов «Ответ владельца».

  | ход (время записи) | сообщение, которое видела модель | создано плагином |
  |---|---|---|
  | 17:23 | «Ваш вопрос не получил ответа… (Повтор 1 из 3)» | 16:07 |
  | 18:24 | то же, повтор 2 из 3 | 16:09 |
  | 19:24 | то же, повтор 3 из 3 | 16:11 |
  | 19:39 | «Не завершено: задача #94… Продолжай работу… Ход без работы 2 из 3» | 16:22 |
  | 19:40 | «Не завершено: задача #94…» | 17:23 |
  | 20:39 | то же | 18:24 |
  | 20:45 | то же | 19:24 |

- Очередь входящих (`session_inbox`, доставка `queue`) вкладки: **четыре строки**, поставленные плагином в 19:39:59, 19:40:54, 20:39:16 и
  20:45:12. Каждая — один пакет из писем плагина. Ни одна не стала сообщением в `session_message` (по идентификатору — 0 строк): модель их не
  получала. Порядок внутри пакета — по имени файла письма, поэтому письмо с ответом `owner-answer-…` всегда **последнее**: напоминание
  «Не завершено», повтор «задайте вопрос заново» и последним — «Ответ владельца на ваш вопрос … не задавайте этот вопрос снова, продолжайте с этим
  ответом». Пакеты 19:40:54, 20:39:16 и 20:45:12 устроены так же; в пакет 20:39 вошли письма интегратора и приёмщика («Phase 1 РАЗРЕШЕНА»), в
  пакет 20:45 — письмо оркестратора «ты зациклился».

### Причина цикла

1. **Служебные сообщения копятся в очереди сервера за ожидающим вопросом.** Ход с вызовом `question` держит сервер: инструмент ждёт ответа
   (в этой сессии каждый такой ход кончился ровно через час, `idle` с исходом `interrupted`). Пока вопрос ждал, плагин поставил в очередь три
   повтора «задайте вопрос заново» (16:07, 16:09, 16:11), а после каждого конца хода — напоминание «Не завершено». Очередь сервера отдаёт
   модели **одно сообщение за ход**, самое старое.
2. **В каждом ходе модель видит только старое «задай заново» или «продолжай» и свой оборванный вопрос** — и вызывает `question` снова.
3. **Каждый ответ владельца только подкармливает цикл.** Ответ через `crew-answer` прерывает ход (так задумано, задача 059); конец хода — повод
   для нового напоминания, и пакет «напоминание + ответ» встаёт **в хвост**. Хвост не сокращается: на каждый ход одно новое сообщение.
4. **Что плагин считает «доставлено».** Письмо уходит в `session.prompt(delivery: "queue")`; сервер принял — письмо переносится в `read/`. Плагин
   не видит, что принятое стоит за другими, поэтому «письмо с ответом доставлено» верно, а «модель его прочитала» — нет.

Следствие для вопроса задания «можно ли исправить текстом»: порядок внутри пакета (ответ первым) цикла не остановил бы, потому что модель
пакетов не получала. Запрет напоминания «пока ответ в пути» остановил бы только рост хвоста, не опустошил бы стоящий. Поэтому нужен отдельный
признак цикла (п. 2 задания): он перестаёт множить сообщения и сразу показывает владельцу тупик с выходом.

### Число повторов вопроса

В сессии с 15:21 — **9 вызовов `question`**, каждый — своя форма; из них **4 ответа владельца** через `crew-answer` (19:39:55, 19:40:46, 20:39:11,
20:45:07), все применены. Четыре вопроса до первого ответа — повторы по часовому таймеру; четыре вопроса после ответов — «вопрос → ответ → тот же
вопрос». Между вопросами после ответов нет ни одного вызова инструмента, кроме `question`. Тексты форм различаются (модель переписывала вопрос),
варианты почти те же: у четвёртой формы подпись «Разрешить (Recommended)» вместо «Разрешить Phase 1 (Recommended)» — строгое правило 071/073
на этой форме оборвало бы цепочку (учтено в п. 2).

## 2. Признак цикла

Звено цепочки — форма вкладки, которая (а) создана после того, как письмо с ответом владельца было передано вкладке (сервер принял), (б) без
рабочего хода между доставкой и вопросом (вызов инструмента, кроме `question`) и (в) задаёт тот же вопрос. **Третье звено подряд открывает цикл**
(`LOOP_AFTER = 3`). Ответ, который не дошёл; рабочий ход между вопросами; другие вопросы; всего две формы после ответов — не цикл.

«Тот же вопрос» (`sameAsk`): одинаковое число вариантов с теми же подписями в том же порядке; подпись может быть целословным префиксом другой,
пометка `(Recommended)` не считается; текст при вариантах не сравнивается. Без вариантов — тот же текст.

Пока цикл открыт: напоминание «Не завершено» и повтор потерянного вопроса не уходят (ответы владельца вкладке доставляются); владелец видит
одну строку (состояние «ждёт вас», значок `↻`, «вкладка зациклилась на вопросе: … (ответ дан N раз); переназначьте задачу (crew_task reassign)
или напишите вкладке прямо») в панели, `/crew` (счётчик `loop: N` в строке проекта) и `/ask`; автору задачи — одно письмо с выходом и строка в
истории задачи. Цикл снимается рабочим ходом вкладки, словом владельца во вкладке, сменой или закрытием задачи, закрытием вкладки.
