# Задание: хранилище и журнал движка продукта в PostgreSQL (обработчики Store и Journal на драйвере nova-postgres)

Заказчик: владелец репозитория `unitcraft/crew-harness` (он же принимает результат).
Репозиторий: `unitcraft/crew-harness`, ветка `main`. Дата задания: 2026-10-19.
Эпик: [001-crew-service](../../001-crew-service/); шестая дочерняя задача этапа «продукт на Нове», продолжает [091-product-engine](../../091-product-engine/) (эффекты `Journal` и `Store`, `src/engine/effects.nv`, обработчики в памяти `memory.nv`) и идёт рядом с задачей 095 (ACP-клиент и файловые обработчики; в `origin/main` её ещё нет).
Источник: слова владельца в чате оркестратора, 2026-10-19: «используй БД pg, у нас есть драйвер для pg, но нет универсального слоя для БД»; до этого Методика прислала набросок хранилища в PostgreSQL (владелец: «по рекомендации»).

Задача полная: разбор, реализация, сдача. Быстрый путь. Основа — свежий `origin/main`. Код пишется ТОЛЬКО под `src/` (английские идентификаторы), тесты — рядом.

## Чего хочет владелец (его слова, 2026-10-19, чат оркестратора)

- «используй БД pg, у нас есть драйвер для pg, но нет универсального слоя для БД» — хранилище и журнал продукта в PostgreSQL; пишем обработчики эффектов прямо на драйвере `nova-postgres`, универсальный слой над базами НЕ делаем и не ждём.
- Набросок Методики (2026-10-19): таблицы `machine_snapshot(id, step, snapshot jsonb, saved_at)` и `machine_journal(id, step, seq, entry jsonb)`, функции `save_step` и `load`; рекомендации (приняты): шаг должен быть равен текущему (повтор) или текущему плюс один, иначе ошибка записи; журнал машин только в базе, `log.md` задачи остаётся файлом; одна роль приложения с правом только на `save_step` и `load`, без прямого доступа к таблицам; PostgREST — позже и только под этой ролью.

## Что нужно

1. **Образец и источники.** `src/engine/README.md`, `effects.nv`, `memory.nv`, `engine.nv` (порядок фиксации: журнал → снимок → отправка; правило 13), `src/engine/GLOSSARY.md`; драйвер `nova-postgres` (чужой репозиторий, ТОЛЬКО чтение: `README.md`, `src/`, `examples/smoke`, `examples/session-check`, `examples/live`; статус «work in progress»: протокол, сессия, адаптер `pgnet`, простые и расширенные запросы, значения `Row` сырые `[]ParamValue`, кодеков типов и фасада `Db` нет — их не ждать, читать значения сырыми и кодировать параметры текстом); ограничения Oracle 0.1.0 и обходы — `spikes/env/README.md` (в частности: пакет из git, типы стороннего пакета не переходят границу модуля — как подключать, посмотреть в README драйвера и в `examples/live`).
2. **`src/storage/` (или `src/pg/`, обосновать):** обработчики эффектов `Store` (`save`, `load`) и `Journal` (`write`, `read_all`) на PostgreSQL. SQL — по наброску Методики: `save_step` одной транзакцией пишет снимок и строки журнала шага; повтор того же шага безвреден (`on conflict`), откат на меньший номер и пропуск номера — ошибка записи (`step` равен текущему или текущему плюс один); `load` возвращает последний снимок. Схема и функции — файл миграции `src/storage/schema.sql` (в репозитории, без секретов); роль приложения: только `execute` на `save_step` и `load`, прямого доступа к таблицам нет.
3. **Подключение:** параметры (хост, порт, база, пользователь, пароль) — из файла настроек и переменных окружения; в репозитории ни паролей, ни путей машины владельца; пароль не пишется в журналы и ошибки; без TLS на `localhost` (TLS — отдельной задачей). Ошибка записи — не значение, а остановка процесса (как в `effects.nv`: шаг не зафиксирован, правило 13).
4. **Проверки (`nova test src`, `--strict-effects`):** красная проба до кода (заглушки); тесты на настоящем PostgreSQL: временная база или контейнер Docker с тестовыми учётными данными (допустимо: локальный хост, значения тестовые, созданные задачей, записанные в тестовый seed или пример-конфиг; Docker на машине есть; если Docker не запущен — сказать, не обходить). Проверки: сохранить и загрузить снимок; повтор шага без дубля строк журнала; шаг +1 проходит, пропуск и откат — ошибка; `read_all` в порядке записи и `seq`; кириллица в журнале и снимке; смерть между записью журнала и снимком — функция одной транзакцией: либо оба, либо ни одного (правило 13/34(е): тест «смерть между изменениями»); роль приложения не может выполнить `select` из таблиц напрямую; повторный запуск миграции безвреден. Движок из `src/engine/` работает на этих обработчиках поверх машины чата (сценарий из `chat_engine_test.nv`) — те же результаты, что на обработчиках в памяти.
5. **README `src/storage/README.md`** (английский, как `src/engine/README.md`): таблицы, функции, правила шага, роль, как запустить базу для тестов (команда Docker с тестовым паролем), что не вошло; новые ограничения Oracle — в `spikes/env/repro_*` и в отчёт.

## Критерии приёмки

- `nova test src` зелёный на настоящем PostgreSQL (и `--strict-effects`); красная проба до кода показана; движок с машиной чата даёт те же результаты на PG и на памяти.
- Шаг пишется одной транзакцией; пропуск номера и откат — ошибка записи; повтор безвреден; роль приложения не читает таблицы напрямую.
- В репозитории нет паролей, путей машины владельца и приватных имён; пример-конфиг только с тестовыми значениями.
- В коммите только `src/`, `spikes/env/` (если нужны воспроизведения ошибок Oracle) и `doc/tasks/098-pg-storage/`; стражи — 8 и больше, FAIL 0; коммит по правилам AGENTS.md (английское сообщение, `-s`, без трейлеров и без `#число`, файлы перечнем).

## Границы

Без универсального слоя над базами, без TLS, без PostgREST, без изменения движка и машины чата (кроме подключения обработчиков в тестах), без вызова модели. Чужие репозитории — только чтение; ошибки Oracle не обходить молча — воспроизведение в `spikes/env/repro_*`. Основную копию `main` не править: работа в этом рабочем дереве. Пароль владельца или его рабочей базы не использовать и не просить: только тестовая база. В сообщениях коммитов номер задачи — три цифры без решётки.
