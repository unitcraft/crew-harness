# Разбор 098: хранилище и журнал движка продукта в PostgreSQL

Задание — `task/message.md`. Источник: слова владельца в чате оркестратора, 2026-10-19: «используй БД pg, у нас есть драйвер для pg, но нет универсального слоя для БД»; набросок Методики (таблицы `machine_snapshot`, `machine_journal`, функции `save_step` и `load`) принят «по рекомендации» (2026-10-19). Быстрый путь. Основа — `origin/main`.

## 1. Что сделано

Обработчики эффектов `Store` (`save`, `load`) и `Journal` (`write`, `read_all`) движка на PostgreSQL, прямо на драйвере nova-postgres, без слоя над базами. Код — три модуля Нова рядом с папкой `src/pg/` (SQL, пример настроек, скрипт базы для тестов, README):

- `src/pg/schema.sql` — миграция: схема `crew`, таблицы `machine_snapshot (id, step, snapshot jsonb, saved_at)` и `machine_journal (id, step, seq, entry jsonb)` (внешний ключ «строка журнала → снимок её шага»), функции `crew.save_step` и `crew.load`, роль `crew_app` без входа. Повторный запуск безвреден.
- `crew.save_step(id, step, snapshot, lines, first_seq)` — одна транзакция: снимок и строки шага вместе. Правило шага: `step` равен текущему (повтор) или текущему плюс один; новая сессия начинается с 1; пропуск и откат — ошибка `CH001`, ничего не пишется. Повтор с тем же снимком и теми же строками безвреден; повтор с другим снимком или другой строкой на занятом номере — ошибка `CH002`. Блокировка `pg_advisory_xact_lock` по сессии.
- `crew.load(id)` — последний снимок и весь журнал сессии одним запросом.
- Роль приложения: `execute` только на `save_step` и `load`; прямой доступ к таблицам и право создавать в схеме отняты; функции `security definer` с фиксированным `search_path`.
- `src/pgdb/` — `PgConfig` (проверка: локальный хост, порт, имена, пароль), вызовы `pg_save_step`, `pg_load`, `pg_migrate`, `pg_rows`, цикл по сокету `wire.nv`, поддержка тестов `testkit.nv`.
- `src/pgconf/` — настройки из файла JSON (аргумент или `CREW_PG_CONFIG`) и переменных `CREW_PG_HOST/PORT/DATABASE/USER/PASSWORD` поверх файла.
- `src/pgstore/` — `PgWorld`, `pg_store`, `pg_journal`: строки шага ждут в `PgWorld` и уходят вместе со снимком одним `save_step` (порядок правила 13 не меняется: журнал, потом снимок). Сбой записи — не значение: обработчик останавливает процесс (`panic`), в тексте нет пароля.

## 2. Решения исполнителя и расхождения с заданием

- **Папка не `src/storage/`, а три папки `src/pgdb`, `src/pgconf`, `src/pgstore`:** `src/storage/` занята файловыми обработчиками задачи 095; два ограничения Oracle (раздел 4) требуют отдельных модулей.
- **В коммит вошли `nova.toml` и `nova.lock.toml` корня** (зависимость `postgres` из git, версия 0.1.0): без них `nova test src` не собирается.
- **Драйвер: не `postgres.pgnet`, а чистое ядро `postgres.Session` и свой цикл по сокету** (`wire.nv`, около 60 строк): файл `listener.nv` драйвера в одной программе с движком читается как запись типа `Event` движка.
- **Роль видит только `save_step` и `load`**: метки диспетчера идут через `save_step` без снимка; `load` возвращает снимок и журнал.
- **Хранится история снимков** (по строке на шаг), а не последний; чистка — позже.
- **Одно соединение на вызов**, пула нет (md5 около 10 мс, SCRAM около 0,25 с на неоптимизированной сборке).
- **Нет `target/pg-test.json` — красный тест с сообщением, не пропуск:** зелёный прогон должен значить настоящий PostgreSQL. Запуск и остановка базы — `src/pg/testdb.ps1` (Docker, образ `postgres:16-alpine`, порт случайный на `127.0.0.1`, случайные пароли в `target/pg-test.json` вне репозитория).
- **Логины тестов — md5**, чтобы уложиться в предел 60 с на модуль; один тест проверяет вход со SCRAM.
- **Пароли тестов случайные:** страж секретов остановил первый коммит с фиксированными паролями.

## 4. Новые ограничения Oracle 0.1.0 (воспроизведения в `spikes/env/repro_engine/src/`, `repro_pg_event/`; `spikes/env/README.md`, п. 14–18)

14. `std.os` и пользовательский `Output` движка в одной программе путаются (095 переименовала тип в `StepOutput`).
15. Запись `Event` движка и файл драйвера `pgnet/listener.nv` в одной программе: конструктор варианта `ListenerMsg.Event` читается как запись.
16. Тело операции обработчика эффекта — только `panic(...)`: C возвращает `(nova_int)0`.
17. `return []T.new()` в операции обработчика: `use of undeclared identifier 'cap'`.
18. Модуль на два уровня вглубь `src/` отвергается (E_D78_MODULE_PATH_MISMATCH).

Без воспроизведения: `nova test` убивает модуль дольше 60 с и печатает только `TIMEOUT`.

## 5. Границы и что дальше

- TLS → не нужно в этой задаче, потому что граница задания; настройки отвергают нелокальный хост, пока нет TLS.
- Сервер сессий `src/server/` (один `PgWorld` на сессию, перезапуск по `resume_engine`) → следующая задача эпика 001.
- Подключение настроек к программе с движком и слияние `pgconf` в `pgdb` → задача 095 (переименование `Output` в `StepOutput` уже в её ветке), после её слияния.
- Пул соединений, повтор при обрыве, чистка старых снимков → не нужно сейчас, потому что сбой записи останавливает процесс, а перезапуск находит последний зафиксированный шаг.
- PostgREST и создание логина приложения → не нужно в этой задаче, потому что граница задания.
- Тест двух одновременных писателей → не нужно сейчас, потому что без потоков в тесте он ничего не покажет; прогон двух процессов — при появлении сервера сессий.
- Файловые обработчики 095 остаются запасным вариантом: те же эффекты, склейки не требуется.
