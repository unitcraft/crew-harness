## Что нужно

1. **Источники:** `src/pg/README.md`, `src/pg/schema.sql`, `src/pg/testdb.ps1` (образец: временный контейнер на случайном порту, пароли случайные, файл настроек `target/pg-test.json`, работа только через Docker), `src/pg/pg.example.json`, `src/pgconf/settings.nv` (настройки из файла и среды: `CREW_PG_HOST`, `_PORT`, `_DATABASE`, `_USER`, `_PASSWORD`), `src/server/README.md` (раздел настроек: `store`, `pg`, пароль — в среде или в файле вне репозитория), `src/server/settings.nv`, `src/server/test/e2e.mjs`. Docker на машине владельца есть (Docker Desktop); чужие контейнеры других проектов не трогать никогда (ни остановка, ни удаление, ни имена).
2. **Скрипт управления** `src/pg/db.ps1` (PowerShell; параметры по образцу `testdb.ps1`; команды): `up` — создать контейнер `crew-harness-pg` (образ `postgres:16-alpine`, именованный том `crew-harness-pg-data`, порт на `127.0.0.1` по умолчанию 15432, настраивается `-Port`), при первом запуске сгенерировать случайные пароли администратора и логина `crew_service` (член `crew_app`), записать их в файл вне репозитория (`~/.config/crew-harness/pg.json`, права только владельцу; путь переопределяется `-Config`), дождаться готовности, создать базу `crew`, применить `schema.sql` (безопасно повторно), создать/обновить логин; повторный `up` ничего не ломает и не меняет пароли; `status` — состояние контейнера, порт, хватает ли тома, версия схемы (число таблиц/функций); `down` — остановить контейнер, том оставить; `psql` — открыть `psql` внутри контейнера под администратором; `backup <файл>` — `pg_dump` в файл; `restore <файл>` — восстановить (с предупреждением); `reset -Force` — удалить контейнер и ТОМ (необратимо: без `-Force` отказ с пояснением); `env` — напечатать, какие переменные среды задать серверу (без пароля в выводе по умолчанию, `-ShowPassword` — с паролем); `serve-config` — записать пример настроек сервера с `store: pg` и блоком `pg` без пароля (файл вне репозитория, путь по умолчанию `~/.config/crew-harness/server-pg.json`). Скрипт работает только с контейнером `crew-harness-pg` и томом `crew-harness-pg-data`; не использует службу PostgreSQL машины; если Docker не запущен — понятное сообщение и код возврата 1.
3. **Запуск сервера на PostgreSQL.** Скрипт `src/server/run-pg.ps1` (или команда `db.ps1 serve`): убедиться, что база поднята (`up`), что программы собраны (`target/crew-hub.exe`, `target/crew-harness.exe`; нет — подсказать две команды `nova build`), задать пароль в среде процесса из файла вне репозитория (в журнал и вывод пароль не попадает) и запустить `crew-harness serve` с настройками `store: pg`. Запуск — из окна с консолью, не скрытый.
4. **Проверка.** `node src/server/test/e2e.mjs --pg` (или отдельный `e2e-pg.mjs`): на подставном агенте создаёт сессии при `store: pg` на временной базе (контейнер `testdb.ps1`), разговор, ПЕРЕЗАПУСК сервера посреди сессии, сессия продолжается; затем та же проверка на постоянной базе через `db.ps1` (контейнер `crew-harness-pg`, своя тестовая база или схема, данные владельца не затрагивать: проверка идёт на отдельной базе `crew_e2e`, которая создаётся и удаляется скриптом); `down`, `up` — данные тома на месте (проверить по списку сессий). Все проверки снять с контейнера после себя (`-Stop`/`down`), кроме постоянного контейнера, если владелец его не просил удалить: в конце оставить постоянную базу поднятой и пустой (без тестовых сессий) либо остановленной — решение записать в `log.md`.
5. **README и документы.** `src/pg/README.md`: раздел «Постоянная база в Docker» (команды, где лежат пароли, как сделать резервную копию и восстановить, как сбросить, что не затрагивается); `src/server/README.md`: как запустить сервер на PostgreSQL одной командой; `src/server/server.example.json` — вариант с `store: pg` (без реального пароля). В репозитории только примеры с тестовыми значениями; реальные пароли и пути машины владельца в репозиторий не попадают (страж `guard-secrets`).
6. **Проверки качества:** скрипты проверены на реальном Docker (вывод в `log.md` без паролей), красная проба: тест/проверка `e2e --pg` на отсутствующей базе даёт понятную ошибку (а не зависание); `nova test src --jobs 4` и `--strict-effects` зелёные (на временном контейнере `src/pg/testdb.ps1`, затем `-Stop`), если код Нова не менялся — достаточно юнитов `pgconf`, `pgdb`, `pgstore`, `server`, `server_pg`; стражи 8 и больше, FAIL 0; коммиты по правилам AGENTS.md (английское сообщение, `-s`, без трейлеров и без `#число`, файлы перечнем).
