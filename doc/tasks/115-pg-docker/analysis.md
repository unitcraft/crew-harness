## 4. Решения и расхождения

- **Добавлены команда `dropdb` и ключи `-Database`, `-Sql`:** без них база `crew_e2e` не «создаётся и удаляется скриптом». `dropdb` снимает только базы `crew_<что-то>`, `crew` — никогда.
- **`restore` не требует `-Force`** (задание: «с предупреждением»), но предупреждает и сам делает копию `backups/<база>-before-restore-<время>.dump` рядом с файлом настроек; сбой восстановления оставляет базу прежней (одна транзакция).
- **Контейнер с `--restart unless-stopped`:** база постоянная; остановленная `down` остаётся остановленной.
- **Пример `store: pg` — отдельный файл** `server-pg.example.json`, а не правка `server.example.json`: тест настроек требует, чтобы тот проходил `check()`, а `pg` без пароля не проходит. Для нового примера добавлен тест.
- **`data_dir` — `target/crew-data`:** файлы входящих клиента ACP не попадают в рабочее дерево.
- **Вход SCRAM, а не md5:** для постоянной базы это умолчание PostgreSQL 16; цена — четверть секунды на вызов (одно соединение на вызов); тесты `testdb.ps1` остаются на md5.
- **Сравнение историй в e2e по id и порядку шагов:** страница, подключившаяся во время возобновления сессий, получает событие дважды (живое и в истории); страница сама хранит событие один раз по id.
- **Постоянный контейнер оставлен поднятым и пустым:** база `crew` без сессий, `crew_e2e` снята, порт 15432.

## 5. Находки

- Windows PowerShell 5.1 портит двойные кавычки в аргументах нативных команд: `-Sql` передаётся по stdin, порт читается из `json .HostConfig.PortBindings`.
- Сообщение хаба о несуществующей базе — «the server closed the connection» без причины: драйвер не передаёт причину; `db.ps1 up` и `status` показывают её прямо.
- Дублирование события при подключении страницы во время возобновления сессий — в хабе; страница дедуплицирует по id.
