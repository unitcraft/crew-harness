## Что известно (задача 100, разбор)

- `taskkill /T /F /PID <pid watch>` не убивает `timeout.exe` и `sleep.exe` отменённой команды: их родитель в Windows — мёртвый pid fork-копии Git Bash (msys), а не процесс watch. Отмена гейта или сборки оставляет работу живой (в обоих режимах запуска, до и после задачи 100).
- Сироты держат общую консоль watch, поэтому `conhost` живёт, пока они не закончатся; на машине десятки лишних процессов.
- Значение: «fence» старой сессии (задача 081) упёрся в то же: отмена не останавливает работу под watch.

## Что нужно

1. **Воспроизведение** (красная проба до кода): тест, который запускает через watch долгую команду с дочерними процессами (`sleep`, цепочка `bash -c`, `timeout`), отменяет watch (`dropWatch`/отмена по пределу времени) и проверяет, что через несколько секунд не осталось ни одного процесса из дерева команды (поиск по метке: уникальный аргумент или переменная окружения в команде); на текущем коде красный.
2. **Исправление:** убить всё дерево команды, включая msys-потомков: способ на выбор исполнителя с обоснованием — группа процессов msys (`kill -- -<pgid>`), обход `ps -ef` по цепочке `PPID` внутри Git Bash, метка в окружении (`CREW_WATCH_ID`) и поиск потомков по ней, объект job Windows; свойства watch сохраняются (пишется `.exit`, корректный статус «отменено», тайм-аут, переживает службу). Не убивать чужие процессы: критерий — только процессы с меткой этого watch.

4. **Тесты:** новый тест на отмену дерева, существующие `crew-watch*.test.mjs` зелёные; `npm test` из `opencode-plugin/` (до 4 файлов параллельно); красная проба до кода; стражи 8 и больше, FAIL 0; README плагина — раздел про watch (что делает отмена).
