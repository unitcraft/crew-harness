## Факты по коду

- `src/web/README.md`: обычные HTML/CSS/JS без framework/build/CDN, три колонки, темы system/light/dark, WebSocket `/ws`; история страницы stateless, приходит массивом событий из журнала.
- `src/web/mock.js`, `strings.js`, `app.js`: список моделей и подписи «Базовая/Быстрая/Глубокая» принадлежат mock; реальные транспортные события их не задают. Нельзя называть эти значения фактическими.
- `src/web/state.js`: `session_created` хранит agent/project/folder, но не model; других model-видов нет. Reducer уже дедуплицирует event ID и отбрасывает неизвестную цепочку.
- `src/server/hub.nv`: session_created/history строятся из engine journal, выдача `/ws` — `page_event`. При восстановлении читается metadata session_created. ACP client удерживается в диалоге, но при resume создаётся заново при открытом запросе.
- `src/acp/client.nv`: `initialize` читает только `agentInfo.name`; `session/new` читает `sessionId`; `session/update` переводится через `project_update(update)`. Ни поле текущей модели из initialize/session/new, ни поддержанный model update не обнаружен.
- ACP типы/тесты и серверные сценарии подтверждают поток progress/tool/usage, а не модель. Проверить фактическое сообщение конкретного внешнего агента в данном анализе нельзя; спецификация не должна предполагать его наличие.

### Исходная находка о модели — вне объёма задачи 130

Этот технический разбор сохранён для истории исходной постановки и не является работой или требованием задачи 130; не менять ACP/hub/engine/WebSocket/history ради модели. Интегратор оформит модель отдельной задачей.

На текущем контракте источник фактической модели отсутствует. Конфигурация ACP (`program/args`), mock options и глобальные defaults не доказывают модель выбранной сессии. Предложение для реализации: ACP адаптер извлекает provider/model/variant только из стандартизованного или явно поддержанного агентом session/update metadata; передаёт их как типизированное событие модели через engine accepted event → hub `page_event` → журнал/history и WebSocket → web reducer/UI. Событие обязано включать trace/session и монотонный step/event identity; неизвестные поля/агенты оставляют значение «Модель не сообщена». Если ACP не предоставляет значение, показывать его нельзя — не угадывать по тексту/настройкам. Совместимость: старые журналы и агенты без metadata остаются валидными и отображают unknown. Точный ACP mapping и тестовая фикстура должны быть установлены до реализации; если протокол агента не гарантирует модель, это остаётся явно ограниченным.

## Направление

Спокойный компактный desktop workspace: системная sans-serif, нейтральный фон, один ясный акцент, меньшая плотность рамок/карточек, сильная иерархия заголовка сессии → сообщения → composer; левая навигация сохраняется, чат получает ширину, правая информация становится лёгкой сворачиваемой панелью. Состояния/метаданные показывать небольшими текстовыми бейджами. Composer — простой текстовый ввод и заметная, но не массивная отправка; убрать визуальный шум от неработающих элементов, не скрывая уже работающие действия. Light/dark — один набор семантических токенов. На узком экране — одно основное представление за раз, без бокового горизонтального скролла.
