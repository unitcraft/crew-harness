# Разбор 123: машина «Раннер задачи» как таблица Портолана 2.12

Задание — `task/message.md`. Источник: слова владельца в чате оркестратора, 2026-10-19: «все возможности текущие … + стейт-машины из методики должны быть написаны на таких стейт-машинах внутри голого продукта CrewHarness»; 2026-10-20: «давай все задачи по быстрому пути пускай». Быстрый маршрут, полная задача. Текст составлен оркестратором по отчёту исполнителя и `log.md` (инструмент записи не дал подагенту создать этот файл); числа сверены по `README` и юниту `src/machine_runner`, числа полных прогонов — по логам оркестратора.

## 0. Решение

«Раннер задачи» методики записан одной таблицей Портолана 2.12: `src/machine/machines/task_runner.portolan.md` (русский вид), `task_runner.portolan.json` (перевод `portolan compile`, байт в байт), английский вид — `portolan convert --language en`. В таблице 76 состояний (75 методики и развилка ReviewVerdict) и 251 строка. Машина вызывает вложенные «Запуск сессии» (`session_start`) и «Проверку цикла» (`cycle_check`); «Запуск сессии» в свою очередь вызывает «Шаг агента» — два уровня вложенности, поэтому прогонщик пары (`src/machine_run/nested_scenario.nv`, `nested.nv`) стал рекурсивным. Всё, что у методики «делает исполнитель» (чтение и запись документов, подготовка, блокировка, остановка группы процессов, показ человеку), записано примитивами хозяина (`standard_registry()`, 56 примитивов, из них 29 новых) с тестовым `ScriptedHost`; боевых исполнителей нет, их задание не включало.

Границы: примитивы без боевых исполнителей; хаб сервера не меняется; совещание в Раннер не подключено (задача 124).

## 4. Расхождения с методикой и спецификацией

1. **Вердикт проверки — поле записи, а не условие строки ответа.** Формат допускает условие только в строках сигнала, а вердикт проверки — поле `ИтогПроверки`. Поэтому у каждой из четырёх проверок (AnalysisReview, PlanReview, ImplementationReview, DeliveryReview) две строки (`answer`, `failure`), а 18 строк методики «ответ: clean / requirements / question / plan / restart» — строки новой развилки ReviewVerdict (19 вместе с «иначе»). Отсюда 76 состояний вместо 75.
2. **Одно имя слова с разным составом данных.** У слов ворот «продолжить» и «реализация» в первоисточнике в разных строках разный состав. Записаны с одним составом: слово человека с автором и источником.
3. **Метка «FACT:».** Определение `дописать_как_факт` дописывает ответ в документ с литеральной меткой `FACT:`; формат строки первоисточник не уточняет, меняется одно определение.
4. **Хозяин отвечает по имени примитива.** Чтение статуса документа, стоп-слова и признаков идёт примитивами `specification`, `task_plan`, `implementation_report` (по правилу Я-29 чтение только через `пусть`); у `ScriptedHost` ответ выбирается по имени примитива, по одному на документ.
5. **Коды сессий латиницей.** `s1`, `s1_fix`, … — коды рукописного автомата; метки продолжения и слова остановки — наборы литералов его слов.
6. **Подготовка при возобновлении.** `возврат_подготовки` — действие исполнителя до входа в сохранённое состояние, данное `preparation_return` пишет только оно; поэтому строку PreparationOutcome 2 не берёт ни одна последовательность событий, а проба `prep_test.nv` берёт данное из входа пробной машины.
7. **22 строки, которых не берёт ни один сценарий.** Защитные «иначе» (там, где типы уже исключают ветку), PreparationOutcome 2, PhaseSwitch 6, общее событие 6. Названы тестом `cover_test.nv`.

## 5. Находки

- Внешний объект «утверждения[документ]» — словарь данных; пишут ЗАПИСЬ_УТВЕРЖДЕНИЯ и КОПИЯ_ПОСТАНОВКИ, снимают операции «снятие»; утверждение действует, если хеш записи равен хешу документа сейчас.
- Ответ, пришедший на паузе, удерживается по правилу 14 в скрытом данном `$held` (журнал `answer_held`), запрос остаётся среди открытых, возврат «продолжить» ничего не шлёт и берёт сохранённый исход (журнал `answer_replayed`); сценарий `cycle-flow-pause-answer-held`. Ответ на запрос, которого машина не держит открытым, отбрасывается как раньше.
- `check_registry` проверяет каждый уровень; машина, которую зовёт машина ниже первого уровня и которой нет в реестре, — пробел, который называет `registry_gaps` (сегодня: `meeting`, задача 124). `product_registry()` содержит `agent_step`, `session_start`, `cycle_check`.
- Новые метки `ORACLE-WORKAROUND(32)` стоят в 7 файлах нового юнита `machine_runner` (`import std.text` нужен `nova build` для `[]str.join`); новых пунктов README Oracle задача не открыла, индекс `spikes/env/workarounds.md` обновлён (меток пункта 32 стало на 7 больше).

## 6. Предложения Методике

1. Дать вердикту проверки место, чтобы строка ответа могла иметь условие по полю результата (п. 4.1), или записать в формате, что развилка по результату — штатный приём.
2. Закрепить в первоисточнике состав данных слов ворот «продолжить» и «реализация» (п. 4.2).
3. Записать в первоисточнике формат строки, которой ответ дописывается в документ (п. 4.3).
4. Решить, чьи коды сессий — латинские (`s1`, `s1_fix`) или русские; сейчас таблица следует рукописному автомату (п. 4.5).
