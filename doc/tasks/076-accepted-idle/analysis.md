# Разбор 076: принятая задача без уборки поднимает автору простой после последнего напоминания

Задание — `task/message.md`. Основа — правила простоя 063 ([разбор](../063-idle-between-sessions/analysis.md)) и 070 ([разбор](../070-idle-by-status/analysis.md),
раздел «Пробел: принята, приёмщик ждёт cleanup»). Решение владельца: «6 — по рекомендации» (владелец, 2026-10-17, чат оркестратора) — на
вопрос #6 в `doc/open-questions.md`.

## 1. Разбор

### Где считается «идёт» для `accepted`

- `idle-tab.ts`, константа `GOING`: `starting`, `running`, `rework`, `submitted`, `reviewing`, `accepted`, `approval`. Задача из `GOING`
  вкладку не простаивающей не делает (`going = true` в `idleBlockers`). С 070 для `starting/running/rework` перед этим вызывается
  `standing`; для `accepted` проверки не было — статус «идёт» всегда.
- `index.ts`: `idleStep` берёт открытые задачи вкладки-автора (состояние `tasks`, вкладка открыта, порог включён); `runCtx` собирает
  факты о сессиях и передаёт в `idleBlockers` четвёртым аргументом.
- Напоминания об уборке (задача 043) — проход сторожа потока в `index.ts`: каждые `accepted_reminder_min` (30) письмо приёмщику и автору,
  не больше `ACCEPTED_REMINDERS_MAX` (5) на приёмку. `tasks.ts`: `acceptedAt`, `acceptedReminderId`, `acceptedReminders`, `letterTime`.
- После пятого письма плагин молчит (остаётся строка «принята и не убрана N ч» в `/crew`); для вкладки автора задача по-прежнему «идёт».

### Что значит «приёмщик не ведёт уборку»

Данные — сводка приёмщика из `status/` (прошлый проход), база ходов, наблюдения, письма.

| Состояние приёмщика | Ведёт? | Довод |
|---|---|---|
| `working` | да | работает над уборкой (в том числе ход, начатый напоминанием) |
| `owner` | да | ждёт слова владельца законно |
| `reply` | да | законное ожидание ответа |
| `question` | да | это «сессия ждёт указаний автора» (063): `waitsOn` срабатывает раньше |
| `watch`, начато меньше `idle_tab_minutes` назад | да | свежее ожидание |
| `watch`, старше порога, хода и изменений задачи нет | НЕТ | ждёт без прогресса (Нова #91: «отдельный cleanup plan», девять часов) |
| `task`, `tasks`, `idle` | НЕТ | молчит |
| сводки нет, карточка не будится, или приёмщика нет | НЕТ | убирать некому |
| сводки нет, карточка живая | да | служба только поднялась |

Молчание считается от самого позднего: конец последнего хода, непрочитанное письмо в ящике, начало наблюдения (только `watch`).

### Правило

`accepted` в `idleBlockers` стоит, когда: (1) автору ушли все 5 писем; (2) приёмщик уборку не ведёт; (3) прошло больше
`idle_tab_minutes` с самого позднего из: последнее письмо (`lastAcceptedReminder`; письма убраны — приёмка плюс 4 интервала
`accepted_reminder_min`), молчание приёмщика, `updated` задачи. Нового ключа нет. Стоящую принятую не оправдывает соседняя идущая
задача (как «мёртвую» в 070). Очищенная вне правила. Остальное — по 063/070: условия вкладки, одно письмо на эпизод, эпизод кончают
рабочий ход вкладки, слово владельца, очистка, изменение стоящей задачи или хода приёмщика, другое состояние вкладки.

Отметка и `/crew`: `#91 принята, уборка ждёт приёмщика с 15:52` (время приёмки). Письмо автору называет задачу, пять ушедших напоминаний
и шаги: `crew_send` приёмщику, либо убрать самому и вызвать `crew_task cleanup`, либо спросить владельца.

### Граница с законной уборкой

Без отметки: приёмщик работает; `crew_watch` начат меньше порога назад; последнее письмо моложе порога; задача менялась меньше порога
назад; приёмщик замолчал меньше порога назад; писем меньше пяти (напоминает плагин); нет фактов уборки в `RunCtx` (прежнее поведение).
Вне правила: очищенная.

Известное ограничение: честное длинное наблюдение приёмщика по уборке (сборка, гейт) после порога и пяти писем без хода и без изменения
задачи названо ожиданием без прогресса; цена — одно письмо автору и ход. Различить заметку наблюдения без ложных срабатываний нельзя
(как #94 в 070).
