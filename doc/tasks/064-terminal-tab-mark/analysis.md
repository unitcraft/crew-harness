# Разбор 064: «?» в заголовке вкладки терминала; задача на панели — названием

Задание — `task/message.md` (пп. 1–5 — заголовок вкладки; пп. 6–8 — дополнения владельца о панели «Crew»).

## 1. Разбор возможности (п. 1)

**Кто задаёт заголовок.** OpenCode (проверено на установленной сборке 2.0.26) сам ставит заголовок терминала: «OpenCode» на
домашнем экране, «OC | <название сессии>» на вкладке сессии; эффект перезапускается при смене вкладки и названия сессии, при выходе
заголовок очищается. Выключается настройкой окна OpenCode `terminal.title` (команда палитры «Disable terminal title»), по умолчанию
включён; в настройках окна владельца он не выключен. Профили Windows Terminal владельца не задают ни `tabTitle`, ни
`suppressApplicationTitle`.

**Может ли окно сменить заголовок.** Да: у плагина окна есть `api.renderer` (`CliRenderer` из `@opentui/core`), его метод
`setTerminalTitle(title)` — тот же, которым пользуется сам OpenCode. Последовательность заголовка пишет нативный отрисовщик, а не
плагин в `stdout`, поэтому с кадрами она не перемешивается; отрисовку это не ломает. Прочитать текущий заголовок нельзя (геттера нет,
запрос OSC 21 Windows Terminal не поддерживает), поэтому исходное имя — проект окна (`project` вкладок окна), как и разрешает задание.

**Что делает терминал владельца.** Заголовок консоли процессов окон сейчас — «OC | <сессия>» (OpenCode его ставит), а вкладка Windows
Terminal подписана именем проекта. Значит, для вкладок окон проектов заголовок приложения подавлен (вкладка запущена с фиксированным
заголовком и подавлением или переименована вручную): терминал принимает последовательность, но вкладку не переименовывает. Так же он
поступит и с заголовком плагина: «?» в заголовке вкладки владелец не увидит, пока подавление включено. Скрипты запуска окон и профили —
вне репозитория, задание их править не разрешает.

Вывод: сменить заголовок изнутри окна технически можно, но при нынешнем запуске окон владельца это ничего не покажет. По заданию код
пп. 2–5 не пишется до решения владельца; вопрос с вариантами — ниже.

### Вопрос владельцу (варианты)

1. **Рекомендация.** Окна проектов запускаются без подавления заголовка приложения (без `--suppressApplicationTitle`, вкладка не
   переименовывается вручную), собственный заголовок OpenCode выключается один раз (палитра, «Disable terminal title»), заголовок
   ставит плагин: имя проекта, `? имя` пока в окне ждут владельца (`owner`, в том числе ворота 062). Довод: единственный вариант, при
   котором значок виден, имя проекта остаётся; без выключения заголовка OpenCode тот при каждом переключении вкладки пишет
   «OC | <сессия>» поверх. Настройка плагина — ключ `tab_title_mark` (включено по умолчанию).
2. Подавление снимается, заголовок OpenCode не выключается: плагин переписывает заголовок каждую секунду. Довод против: после
   переключения вкладки до секунды виден «OC | …» — мигание, которое задание запрещает.
3. Ничего не менять в запуске окон: заголовок недоступен; сигнал остаётся прежним — строка «Ждут вас» с проектом и вкладкой на панели
   каждого окна (055), системное уведомление, когда окно не в фокусе, и ясная панель пп. 6–8. Значок прогресса во вкладке (OSC 9;4)
   Windows Terminal показал бы и при подавлении, но безопасного пути писать сырые последовательности у плагина нет (`writeOut`
   отрисовщика закрыт, запись в `stdout` мимо него рвёт кадр) — не предлагается.

Значки в заголовке: только `?` (ждут владельца, включая ворота `⚠` и фразу ожидания `‖` у вкладки владельца). `▶` и `◷` — нет: они не
ждут владельца, а заголовок отвечает на один вопрос «куда переключиться».

## 2. Задача на панели (пп. 6–8)

- **Название первой строкой (п. 6).** Вкладка задачи: значок, номер и название (`‖ #85 Accept Oracle evaluation`), перенос по словам не
  больше двух строк, дальше «…»; роль и состояние — строкой ниже (`  прм  ждёт указаний`); вопрос или фраза ожидания и шаги — как
  прежде, ниже. Заголовок задачи с папкой — так же, без значка (значки — у её сессий). `/crew` — название целиком, без «».
- **Виды сессий и шаги (п. 7).** Перечень видов методики — один: `SESSION_WORDS` в `progress.ts` (его уже читала панель «Ход работ»,
  теперь и `status.ts` `sessionKind`); он совпадает со списком кодов `task-runner.md` методики (С1 … С9, С1п, С3п, С5д, С5п, С7п).
  Код вне перечня (С2м и подобные) берёт короткое название из цели сессии в записи задачи; нет цели — только код. Сессия методики на
  панели: `?  ↳ С2-5 проверка разбора`, состояние — строкой ниже. Шаг приёмки: `проверка 3/12: sabotage — подсунь негодное` (короткое
  название — текст шага до первого «:», «;», «.», « — », «(»), перенос по словам; строка «↳ текст шага» под ним больше не нужна.
- **Задача один раз, законченное свёрнуто (п. 8).** Вкладки одной задачи без папки — под одним заголовком, значок слева — самой важной
  вкладки (по порядку состояний); приёмщик на доработке — `↻ ждёт доработки`. У задачи с папкой сданные, переданные и закрытые сессии
  (не ждут владельца и не работают) — одной строкой `✓ сдано N сессий` под живыми; в счёт девяти строк панели они не идут, освободившиеся
  места получают живые вкладки. `/crew` перечисляет все сессии, задачу без папки — тоже одним заголовком.

## 2а. Устаревшая привязка и ожидание владельца без вопроса (пп. 9–10)

- **Устаревшая привязка (п. 9).** Источник: карточка интегратора Новы с `task: {n: 73}` — задача отменена, привязка осталась; панель и
  «Ждут вас» звали вкладку «#73 исп» (`tabOf` и `who` берут номер из задачи сводки). Правило: задача входит в сводку вкладки, только
  если она открыта и вкладка — не интегратор; вкладка закрытой задачи (влита, отменена) и вкладка интегратора показываются по роли.
  Состояние не меняется: закрытая задача и прежде не давала состояния «task», интегратор с открытой задачей по-прежнему «стоит между
  ходами» — меняется только подпись. Привязку снимает проход `finishTasks`: у вкладки владельца (не сессии задачи) с задачей или приёмкой
  в статусе `done`/`cancelled` поле убирается из карточки. Сессиям задач привязка оставлена: по ней окно закрывает их вкладки.
- **Ожидание владельца текстом (п. 10).** Источник: интегратор Новы ответил «#85 ждёт отдельного решения владельца о возобновлении…»
  без инструмента question; плагин узнал фразу ожидания (`‖`, «ждёт вас»), но владельцу не на что было ответить, а вкладке никто не
  сказал задать вопрос. Правило: на проходе сводок (`gateStep`) ход вкладки владельца кончился фразой ожидания (`endOfTurn` с `wait`),
  слово владельца после хода не написано, вопросника вкладки нет, фраза не называет другую вкладку (интегратор, исполнитель, приёмщик,
  приёмка, воркер, сессия) — плагин записывает остановку вида `wait` в `gates/` (время — конец хода, текст — фраза). Дальше как у
  ворот 062: одно письмо `WAIT_LETTER` («Ты ждёшь решения владельца, но вопроса нет: задай его сейчас инструментом question — вопрос,
  рекомендация, довод»), состояние `owner` с отметкой `⚠`, подпись «ждёт вашего решения, вопроса нет (с ЧЧ:ММ): <фраза>», на панели
  «решение, вопроса нет». Снимают: вопросник, «?» в конце следующего хода, слово владельца, ход с вызовом инструмента после фразы
  (`workedAfter`). Пустой ход («понял») отметку держит без нового письма; эпизод — от фразы до снятия, письмо — одно на эпизод.
- **Граница с вопросом текстом (`?`).** Ход, кончившийся «?» к владельцу, — вопрос: владелец видит его в «Ждут вас» с текстом и отвечает
  словом в вкладке; письма нет, отметка `?`. Фраза ожидания — не вопрос: в ней нет того, на что отвечать («ждёт решения» — какого?),
  поэтому вкладка обязана задать вопрос инструментом (правило 062). Сессия задачи (`spawned`) не судится: её фраза ожидания адресована
  интегратору и уходит ему подталкиванием (задача 056).
