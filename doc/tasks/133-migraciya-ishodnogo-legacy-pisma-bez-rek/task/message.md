## Критерии приёмки

1. До исправления сохранённый legacy формат воспроизводимо RED, после — штатный migrate распознаёт критерии и ветку, не меняя исходный text и его digest. Публичная fixture — явно переносимая производная с provenance, не raw «исходник» с подменённым hash.
2. Legacy разрешён только для подходящей существующей folderless-записи и проверенного формата исходного письма; должны совпадать task/project/номер и ветка с существующей задачей. Произвольный текст, пустые/отсутствующие критерии, отсутствующая/другая ветка, чужая задача и неполная форма безопасно отказывают до записи.
3. Точный отдельный owner word с тем же номером/датой, открытый статус, запрет повтора и все проверки 129 сохранены. Современный planRoute/briefFaults новых задач не ослаблены.
4. Identity, sessions/IDs, attempts, rounds, история, branch/worktree, FAIL/stale/precheck/lock и evidence не теряются/не превращаются в GREEN; нет дубликата 092. Исходный message сохраняет точные bytes/hash, не генерируется по карточке/памяти.
5. Минимум3различающие пробы, реальные format-derived regression tests плюс прежние route/help/tool texts; полный набор плагина через очередь, guards, независимая приёмка и exact-SHA precheck/merge gates обязательны.
6. README содержит точную read-only процедуру получения saved original text и команду migrate для legacy-письма; не требует вручную менять metadata/заголовки/ветку. Если source недоступен — явный отказ.
Ветка: собственная task-ветка, назначенная плагином от origin/main, не живая main.
