# Задание: сводка при сжатии контекста — коротко и по образцу

Заказчик: владелец репозитория `unitcraft/crew-harness` (он же отвечает на вопросы и принимает результат).
Репозиторий: `unitcraft/crew-harness`, ветка `main`. Дата задания: 2026-10-17.
Источник: 2026-10-17 владелец показал скриншот «Important Context» — сводку, которую OpenCode пишет при автоматическом сжатии
контекста вкладки (у интегратора crew-harness контекст дошёл до 79%) — и спросил «нужно ли нам такое». В сводке: хеши коммитов и
файлов, номера карточек запуска и сессий, процессные оговорки проверяющих, часть строк описывает состояние, которое владелец уже
изменил (031 и 045 сняты). Плагин в этот текст не вмешивается; слово `compaction` в коде встречается только при подсчёте времени
активности (`core.ts`). Сжатие нужно (без него вкладка упирается в лимит), вид сводки — нет.

Задача полная: разбор, реализация, сдача. Быстрый путь. Основа — свежий `origin/main`.

## Чего хочет владелец

- «нужно ли такое» (владелец, 2026-10-17, чат оркестратора, скриншот блока «Important Context» из сводки вкладки интегратора)
- «по рекомендации» (владелец, 2026-10-17, чат оркестратора) — на предложение оркестратора завести задачу: сначала выяснить, есть ли у
  плагина хук на сжатие; если нет — запасной путь через подсказку вкладок.

## Что нужно

1. **Разбор:** есть ли в сборке OpenCode 2.0.26 способ для плагина влиять на сводку при сжатии контекста — хук серверного плагина
   (например, `experimental.session.compacting` или подобный) или настройка (`compaction.*` в `opencode.jsonc`, уже встречается
   `compaction.reserved`); где задаётся промпт сжатия; можно ли дополнить или заменить его. Источник — собранный JS окна и сервера
   (внутри исполняемого файла `opencode`, читается как текст) и типы `@opencode-ai/plugin`; не угадывать. Показать, какой текст промпта
   сжатия действует сейчас.
2. **Образец сводки** (текст, который плагин потребует от вкладки): по разделам — «Что решил владелец» (слова дословно, с датой и
   источником), «Открытые вопросы владельцу», «Что идёт и что ждёт» (задачи с названием, сессии с видом, кто чего ждёт), «Где лежат
   документы» (пути, не хеши), «Что нельзя делать» (запреты владельца и границы). Хеши коммитов и файлов, номера карточек и сессий,
   процессные оговорки — только если без них нельзя продолжить, иначе ссылкой на файл. Длина: порядок 1–1,5 тысячи знаков на раздел,
   всего до 6 тысяч.
3. **Реализация по результату разбора:** если хук есть — плагин добавляет образец в промпт сжатия (настройка включения в
   `config-schema.ts`, по умолчанию включено; не для вкладок Claude Code); если хука нет — одно короткое правило в подсказку вкладок
   (`index.ts`, хук `context`, в пределе TT-1e) и описание в README; решение за исполнителем по разбору, обоснованное доказательством.
4. **Тесты:** красная проба до кода на выбранный путь; полный `npm test` по 2–4 файла, упавшие по одному
   ([AGENTS.md](../../../../AGENTS.md), пп. 8–9); golden — только изменившиеся ключи.
5. README плагина — абзац о сводке при сжатии.

## Критерии приёмки

- Разбор называет, влияет ли плагин на сводку, с доказательством (код сборки или типы), и показывает действующий промпт сжатия.
- Красная проба до кода падает на выбранный путь и проходит после правки.
- Образец сводки лежит в одном месте (в Каноне `doc/canon/process.md` — раздел о сводке при сжатии, или в README плагина — решить в
  разборе), плагин ссылается на него.
