## Сводка консенсуса (это задание)

1. Файл `doc/open-questions.md` — вне Канона; ссылки из `doc/canon/README.md` и `doc/canon/process.md`. В шапке —
   ссылка на правила методики (с хешем коммита); отличия проекта — в `process.md`.
2. Порог входа: в файл — только то, что требует решения владельца или другой стороны; остальное автор разбора делает
   сам или отклоняет.
3. У каждого пункта «Не сделано» в разборе (`analysis.md`) ровно одна пометка: «→ open-questions #N», «→ задача NNN»
   или «не нужно, потому что …»; ставит автор разбора в той же сессии.
4. Страж (`scripts/guards/`, новый или правило `check-task-docs.py`): пометки в разборах, начатых после даты введения
   (дата — константа в коде стража); форма пунктов файла — вопрос, адресат, решение по умолчанию, срок датой, дата и
   источник; закрытие — строкой «закрыто: <ссылка на норму или слово владельца>, <дата>»; не больше двух продлений,
   второе — с причиной. Самотест стража, подключение стража (`check-wiring.py`).
5. Истёк срок — применяется умолчание: строка «применено умолчание: … (дата)» в файле и отдельный пункт в ближайшем
   докладе владельцу.
6. Каждый запрос оркестратора «пушь …» несёт строку «просрочено: N» (и при N = 0), при N > 0 — список с выбором
   «решить / продлить до даты / закрыть». Число считает код стража (скрипт с выводом числа и списка); `crew_doctor`
   показывает то же число, вызывая тот же код или его перенос — без второго счётчика (обосновать способ).
7. Старые хвосты: один проход по разборам от 039 до разборов, начатых до даты введения стража, — без пересказа,
   перенос со ссылкой на источник и пометки в самих разборах (дописка, не переписывание). Разборы 001–038 — только по
   слову владельца или при найденной на них ссылке.
