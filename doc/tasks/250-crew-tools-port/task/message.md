# Задание: инструменты crew_* плагина работают в самом продукте

Заказчик: оркестратор окна CrewHarness (пульт). Репозиторий: проект crew-harness, ветка `task/192.10-crew-tools-port` (от `task/192-ready`). Дата задания: 2026-10-28.
Источник: слова владельца с датой — раздел «Чего хочет владелец».

## Чего хочет владелец

- «инструменты crew_* должны работать в самом продукте Крю; плагин OpenCode в этом никак не участвует, он только для обкатки идей; я говорю о ВСЕХ инструментах crew_*, которые есть в плагине» (владелец, 2026-10-28, чат оркестратора)
- «инструменты, которые работают с КОНФИГАМИ (crew_config и всё, что читает/пишет конфигурацию плагина или продукта), СЕЙЧАС НЕ переносить: структуру конфигов мы будем отдельно обсуждать» (владелец, 2026-10-28, чат оркестратора, поправка в ходе работы)

## Что нужно

1. Инвентарь всех инструментов crew_* плагина (`inventory.md`): назначение, аргументы, результат, на что опираются, как ложатся на сущности хаба, решение «переносим / переносим с изменением смысла / отложено / не нужен».
2. Реализация перенесённых инструментов в MCP-сервере хаба под теми же именами и совместимыми аргументами (`src/server/crew_tools.nv`, `crew_tools_hub.nv`), с адаптацией к хабу: опасное — через карточки владельца и лимит `route_max_active`, каждый вызов — в журнал сессии и в панель «Машины».
3. Имена без конфликта: `crew_task` плагина и `crew_task` хаба — один инструмент; вызов без `action` остаётся прежним предложением задачи, `crew_task_list` остаётся.
4. Инструкции и Канон: справка `crew_help`, таблица инструментов в `src/server/README.md`, ADR-0015.
5. Тесты (чистые и сценарий на фейковом агенте) и живая проверка на своём экземпляре с настоящим Claude Code.

## Критерии приёмки

1. `inventory.md` перечисляет каждый инструмент плагина (14 `crew_*`) с решением и причиной. 2. Каждый перенесённый инструмент вызывается через `tools/call` хаба и даёт ожидаемый результат или отказ (сценарий `scenario_crew_tools`). 3. Старые `crew_task` без `action` и `crew_task_list` работают как прежде. 4. `crew_config` не реализован и не показывается доступным. 5. Новый исполнитель (`crew_spawn`) появляется только после «да» владельца и под лимитом. 6. Стражи `sh scripts/guards/run-all.sh` зелёные; тесты `src/server` зелёные. 7. Живая проверка: агент-оркестратор вызывает `crew_list`, `crew_spawn`, `crew_send`, `crew_wait`, `crew_doctor`.

## Результат и куда он попадает

код: `src/server/` (`crew_tools.nv`, `crew_tools_hub.nv`, `crew_tools_kit.nv`, тесты), `src/acp/testdata/fake_agent.mjs`; документы: `src/server/README.md`, ADR-0015, `doc/routes/*.md`; ветка задачи `task/192.10-crew-tools-port`, без пуша.

## Связи

нет: связи не названы; пересекается по файлам с `task/192.9-crew-tools` (видимость инструментов у семей агентов: `crew_task_hub.nv`, `signals.nv`) — конфликт разбирает оркестратор.
