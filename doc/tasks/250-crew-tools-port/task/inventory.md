# Инвентарь: инструменты crew_* плагина OpenCode и их место в продукте

Источник: `opencode-plugin/core.ts` (`makeTools`, 14 инструментов, возвращаются одним списком в конце функции), `index.ts` (регистрация в OpenCode), `mcp.ts` (тот же список для окон `claude-code`). Слово владельца: «инструменты crew_* должны работать в самом продукте Крю; плагин OpenCode в этом никак не участвует, он только для обкатки идей; я говорю о ВСЕХ инструментах crew_*» (владелец, 2026-10-28). Поправка того же дня: инструменты, работающие с конфигами, сейчас не переносить — структуру конфигов обсуждают отдельно.

Журналы задачи (`journal.ts`, `progress.ts`, регистрируются отдельно: `progress_line`, `log_line`, `usage_line`) — ещё три инструмента агента; слово владельца, 2026-10-29: перенести под **новыми именами** `crew_progress_line`, `crew_log_line`, `crew_usage_line`, алиасов старых имён не делать. Они входят в инвентарь ниже.

## Итог

| Решение | Сколько | Инструменты |
|---|---|---|
| Перенесён как есть (смысл тот же) | 6 | `crew_list`, `crew_send`, `crew_inbox`, `crew_wait`, `crew_timer`, `crew_help` |
| Перенесён с изменением смысла | 7 | `crew_role`, `crew_spawn`, `crew_task`, `crew_watch`, `crew_doctor`, `crew_step_note`, `crew_branch_note` |
| Перенесён под новым именем | 3 | `progress_line` → `crew_progress_line`, `log_line` → `crew_log_line`, `usage_line` → `crew_usage_line` |
| Отложено: структура конфигов обсуждается с владельцем | 1 | `crew_config` |
| Не нужен в продукте | 0 целиком | (отдельные действия `crew_task` и поля инструментов не переносятся — таблицы ниже) |

Всего 17 инструментов плагина (14 `crew_*` и 3 журнала): перенесено 16, отложен 1. Старые инструменты хаба `crew_task` (предложение задачи) и `crew_task_list` (список распознанных работ) сохранены.

## Сущности плагина и хаба

| Плагин | Хаб |
|---|---|
| вкладка OpenCode (сессия, `Card`, визитка) | сессия хаба (`Dialog`), её журнал и агент ACP |
| роль (`worker`, `integrator`, `acceptor`, замок исключительной роли) | роль по режиму и дереву: оркестратор (у сессии есть дочерние или она эпик), исполнитель (задача или дочерняя), приёмщик (идёт независимая проверка), работник (без задачи); не назначается |
| проект (`projectOf`, `projects.json`) | проект сессии (`project_id`) |
| письма в ящиках `nova-peers` (`read/`, `pending/`) | письма в памяти хаба (`CtlLetter`): ждущее письмо идёт служебным ходом агента, когда он свободен; живут, пока работает хаб |
| `crew_spawn` — новая сессия задачи у интегратора | предложение работы: карточка владельцу, дочерняя сессия (ADR-0014) после «да» |
| `crew_task` — журнал `tasks.ts`, статусы, приёмка, замок слияния | задачи хаба: папка `doc/tasks/NNN`, ветка, дерево, `children.md`; приёмка и слияние — кнопки владельца |
| журнал `journal` плагина, панель `/crew` | журнал сессии (`route_note`) и панель «Машины» (служебные подсказки) |
| наблюдатель `watch.ts` (команда в фоне) | подписка на событие хаба (`crew_watch`), таймер (`crew_timer`) |
| лимиты `spawn_limits`, `inflight_limit` | лимит `route_max_active` на всё число работ хаба |

## Таблица инструментов

### crew_list — перенесён как есть

- Назначение: вкладки своего проекта (адрес, открыта/закрыта, занята/свободна, модель, ждущие письма) и открытые задачи.
- Аргументы: `all?` (все проекты).
- Результат: строки; звёздочка у вызывающего.
- Опирается на: визитки вкладок, окна, задачи `tasks.ts`.
- В хабе: сессии проекта (id, название, роль, занята/свободна, агент, задача, эпик, родитель), открытые задачи, «в работе N из route_max_active». Аргументы те же.

### crew_role — с изменением смысла

- Назначение: сменить роль вкладки (`worker`, `integrator`, …); исключительная роль — один держатель, `force` отнимает.
- Аргументы: `role`, `force?`.
- Опирается на: визитку, замок роли, `exclusive_roles` из файла настроек проекта.
- В хабе: роль выводится из режима и дерева (оркестратор / исполнитель / приёмщик / работник), назначить её вызовом нельзя. `crew_role {}` возвращает роль, оркестратора сессии и число дочерних; `role`, не совпавшая с выведенной, — отказ с причиной; `force` не используется. Часть про `exclusive_roles` из файла настроек не перенесена (конфиг отложен).

### crew_send — как есть

- Назначение: письмо другой вкладке; `wake`, `expect_reply` (qid), `reply_to`, `tier`.
- Аргументы: `to`, `text`, `wake?`, `expect_reply?`, `reply_to?`, `tier?`.
- Опирается на: ящики, живые окна, роли, правила `inbound` проектов, страж слипшихся слов.
- В хабе: адрес — id сессии, номер задачи, `parent` / `orchestrator`, `children`; `wake: true` (по умолчанию) — служебный ход получателя, как только его агент свободен (метка в ленте «[crew] Письмо от …» с началом текста — владелец читает письмо); `wake: false` — ждёт в `crew_inbox` и присоединяется к следующему письму с пробуждением; `expect_reply` даёт qid; `reply_to` без `to` — ответ тому, кто спросил. Не перенесены: `tier` (выбор вкладки по ступени модели — в хабе новая работа идёт только через `crew_spawn`), адреса `проект.роль` и `all` (письма между проектами и рассылка всем — не нужны: у сессии есть родитель и дети), правило `inbound`, страж слипшихся слов (он про конкретные модели OpenCode). Письмо без текста и пустое «принято» не отправляются: длина до 8000 байт.

### crew_inbox — как есть

- Назначение: письма вкладки; ждущие выдаются здесь же.
- Аргументы: `limit?`. Результат: «НОВЫЕ ПИСЬМА» и прочитанные.
- В хабе: то же над письмами в памяти хаба; выданное считается прочитанным.

### crew_wait — как есть, шире по целям

- Назначение: ждать ответа на вопрос (qid) в этом же ходе, до 300 с.
- Аргументы: `qid`, `seconds?`.
- В хабе: `target` (синоним `qid`): qid вопроса; номер, id или название дочерней сессии — ждёт, пока она «готово» или «слита» (предложенная, но ещё не принятая владельцем работа ждётся: дочерняя появится после «да»); `children` — все дочерние; пусто — любое письмо. Результат — ответ, состояние дочерней и её последние слова, либо «за N с нет». Отмена хода владельцем прерывает ожидание.

### crew_timer — как есть

- Назначение: письмо разбудит вкладку через N минут, не держа ход.
- Аргументы: `minutes`, `note?`; в хабе добавлен `seconds` (дробные минуты — секундами); до 719 минут, не больше 20 таймеров и наблюдений на сессию.
- Опирается на: в плагине — наблюдение `sleep N`, переживает перезапуск сервера; в хабе — ожидание в памяти, **перезапуск хаба таймеры забывает** (записано в описании инструмента).

### crew_watch — с изменением смысла

- Назначение: долгое ожидание без удержания хода: плагин запускает команду в фоне и будит письмом с кодом выхода и хвостом вывода; очередь машины (`machine`); список; `cancel`.
- Аргументы: `command`, `note`, `minutes`, `machine`, `action`, `id`.
- В хабе: **команды хаб не запускает** (они шли бы мимо прав агента, плагин для этого сверял `permissions.deny`; у агентов продукта есть свои фоновые инструменты) — `command` отвечает отказом с причиной. Вместо этого подписка на событие хаба: `on: child | children | reply | idle` (+ `target`), письмо будит сессию, когда событие наступило; без `on` — список; `action: cancel` + `id` — снять. `machine` / очередь машины не перенесены (в продукте тесты и гейты запускает агент своими средствами; очередь машины — отдельная часть плагина).

### crew_spawn — с изменением смысла

- Назначение: интегратор запускает задачу в новой сессии (папка задачи, ветка, дерево, `goal`, `criteria`, `route`, `tier`, `model`, `part_of`, шаблон `message.md`).
- В хабе: предложение работы **новому исполнителю** (ADR-0014): `goal` и `criteria` становятся текстом `message.md`; если у вызывающего есть открытая задача — дочерняя (он становится эпиком), иначе самостоятельная; владельцу показывается карточка, дочерняя сессия, ветка и дерево создаются **только после его «да»** (кнопка или кодовое слово), под лимитом `route_max_active` (над лимитом — очередь или слово «сверх»). Результат называет, как ждать: `crew_wait {target: название}`. Аргументы: `goal` (обязательно), `criteria`, `title`, `touches`, `kind` (`child` / `new`), `agent`. Не перенесены: `route fast/small`, `tier`/`model` (семью агента выбирает владелец в карточке или `agent`), `part_of`, `kind: plan`, `parent` (приказы другим проектам) — это устройство задач плагина; в хабе способы оформления выбирает владелец в таблице кандидатов.

### crew_task — одно имя, два смысла объединены

- Плагин: задачи по номеру — `list`, `show`, `assign`, `order`, `push`, `reassign`, `cancel`, `backlog`, `resume`, `priority`, `route`, `deliver`, `review`, `check`, `round`, `precheck`, `merge`, `unlock`, `rework`, `accept`, `cleanup`, `track`, `contour`, `migrate`, `plan_decide`, `submit`.
- Хаб (прежде): `crew_task` — предложение задачи владельцу карточкой (`kind`, `title`, `summary`, `touches`, `confidence`), без `action`.
- Решение по именам (требование «старые имена остаются»): **один инструмент `crew_task`**. Без `action` (или `action: propose`) — прежнее предложение, байт в байт; с `action` — работа с задачами хаба. Перенесены: `list` (открытые задачи, `all`), `show` (`n`: сессия, состояние, ветка, дерево, дочерние), `submit` (исполнитель сдаёт отчёт оркестратору письмом), `push` (`n`, `text`: разбудить сессию задачи письмом). Остальные действия плагина — это приёмка, слияние и устройство журнала `tasks.ts`: в хабе они кнопки владельца (карточки, шаги режима, «Слить в main» / «Влить в ветку эпика», закрытие сессии) — вызов отвечает отказом с этим объяснением; ничего не пропадает молча. `crew_task_list` (список распознанных работ) — другое имя, смысл не менялся, не переименован.

### crew_config — отложено

- Плагин: `guide`, `show`, `set`, `apply_template` над файлом настроек проекта.
- **Отложено: структура конфигов обсуждается с владельцем** (2026-10-28). В хабе не реализован, в `tools/list` и `crew_help` не показывается; вызов отвечает отказом «not available yet». Файлов настроек хаб при этом не читает и не пишет.

### crew_doctor — с изменением смысла

- Плагин: самопроверка (возможности OpenCode, плагин окна, ящик, настройки, профили, ветки окон).
- В хабе: самопроверка хаба и сессии: папка сессии и дерево задачи на месте, ветка каталога и ветка задачи, папка задачи, лимит работ, дочерние в очереди, непрочитанные письма, число ожиданий. Проблемы — отдельным списком, справка — «К сведению». Настройки не читаются.

### crew_step_note — с изменением смысла

- Плагин: ответ на письмо «Шаг стоит N мин, срок вышел» (причина, продление, `done`), решение владельца (`decide`, `hold`, `release`) на таймере шагов `idle-watch.ts`.
- В хабе: заметка шага режима в журнал сессии (`reason`, `minutes`, `done`, `n`). Срока шага и тревоги нет, поэтому `decide`, `hold`, `release`, `who`, `project` не перенесены (упираются в машину сроков плагина и в настройки `step_*`).

### crew_branch_note — с изменением смысла

- Плагин: причина смены каталога или ветки; без неё `branch-guard.ts` отклоняет команды git.
- В хабе: запись причины (`what`, `why`, `who`, `directory?`, `branch?`) в журнал сессии вместе с каталогом и веткой, которые хаб знает; хаб команды не блокирует (механизм охраны — только плагина), запись читает приёмка (AGENTS.md, п. 6а).

### crew_help — как есть

- Справка по инструментам. В хабе: короткая справка по перенесённым инструментам; `crew_config` не показывается.

### progress_line → crew_progress_line — перенесён под новым именем

- Плагин: строка журнала хода `progress.log` (`<код> k/N [ГГГГ-ММ-ДД ЧЧ:ММ] <подпись>`): агент называет вид (`start`, `step`, `done`, `stop`, `correction`; `launch` пишет только запускающий) и числа, инструмент ставит слово, номер захода, вид остановки, дату и время и сверяет с прежними строками той же сессии.
- Аргументы: `code`, `kind?`, `k?`, `n?`, `pass?`, `stop?`, `text?`, `to?`, `unit?`; `file` необязателен.
- В хабе (`crew_journal.nv`, `crew_journal_hub.nv`): правила те же — старт первой строкой и один на сессию, шаги по единице без пропусков, k не уменьшается и не повторяется, `done` не раньше последней единицы и не при k меньше N из строки старт («N завышено: …» как у плагина), `stop: вопрос|план|ревизия|требования|ворота`, после итоговой строки — только её повтор, поправка `correction` с `to` (10–30 знаков), подпись не длиннее 80 знаков, у проверяющих кодов С2/С4/С6 обязателен `pass`; строку запуска агент не пишет. Отказ называет правило и пример вызова `crew_progress_line {…}`.
- Куда пишет: в `progress.log` **папки задачи этой сессии** (`rt.task_dir`: `doc/tasks/NNN-слаг/task/` в дереве или папка в data_dir, как для `message.md`), имя файла фиксировано, только дозапись, файл создаёт строка `start`. `file` — необязательный довесок для совместимости: принимается только путь к этому же файлу своей задачи (`progress.log`, `task/progress.log` или `doc/tasks/<своя папка>/progress.log`); путь с `..`, другое имя и чужая папка задач — отказ «вне папки задачи». Сессия без задачи — отказ «задачи нет». Агент ребёнка пишет в журнал **своей** задачи, не эпика.
- Время — **местное время машины**, ставит хаб (`Time.local_offset_sec`); агент времени не пишет.
- Согласование с чек-листом режима (`progress.md`, решение задачи 246): журнал единиц и чек-лист шагов режима — один прогресс сессии. Шаг `k` при `n`, равном числу пунктов `progress.md`, отмечает и k-й пункт чек-листа (`- [x]`), если он ещё не отмечен; ответ называет отмеченный пункт. Шаги режима, которые отмечает сам хаб по ходу режима, остаются как были; `done` и `stop` чек-лист не трогают. Различное `n` (журнал ведёт свои единицы) — чек-лист не трогается.
- Не перенесено: `launch` (запускающий — это оркестратор плагина; в продукте записи запуска нет), чтение номеров запусков из `log.md`, шлюз «ворота» плагина (`gate-stop`).

### log_line → crew_log_line — перенесён под новым именем

- Плагин: запись `log.md` `ГГГГ-ММ-ДД ЧЧ:ММ <вид>: <текст>`, вид — из закрытого списка Канона (`решение владельца`, `заседание`, `ворота`, `документ`, `пуск`, `слияние`, `находка`), одна строка до 2000 знаков; запись о запуске агент не пишет.
- Аргументы: `kind`, `text`, `file?`. В хабе то же, в `log.md` папки задачи этой сессии; папка должна существовать; время местное, ставит хаб; те же правила `file`, «задачи нет». Не перенесён отдельный ответ шлюза для вида `ворота` (запись принимается как любая).

### usage_line → crew_usage_line — перенесён под новым именем

- Плагин: одна строка JSON с учётом сессии в `usage.log` рядом с `progress.log` (поле версии `v: 1`, модель, токены, цена из карточки OpenCode, задержка цикла службы).
- Аргументы: `code`, `result` (до 200 знаков), `file?`. В хабе: строка JSON `{v:1, code, at, session, agent, started_ms, seconds, commit, result}` — токены, цена и задержка плагина в хабе не измеряются и не выдуманы (полей нет); `commit` — `git rev-parse HEAD` дерева задачи. Пишется только рядом с существующим `progress.log` своей задачи.

## Имена: пересечение с инструментами хаба

| Имя | Что было в хабе | Что в плагине | Решение |
|---|---|---|---|
| `crew_task` | предложить задачу владельцу | работа с задачами по номеру | один инструмент: без `action` — прежнее, с `action` — плагинное; `action: propose` — явное прежнее |
| `crew_task_list` | список распознанных работ | нет | без изменений |
| `ask_user_question` | вопрос владельцу | нет | без изменений |
| `progress_line`, `log_line`, `usage_line` | нет | журналы задачи | под новыми именами `crew_progress_line`, `crew_log_line`, `crew_usage_line`; старые имена не алиасы (слово владельца, 2026-10-29) |

Поле `action` необязательно в схеме `crew_task`, поэтому прежние вызовы (в том числе агенты, которым описание выдали раньше) не ломаются; описание сказано так, чтобы новые агенты видели оба смысла.

## Права, лимиты, подтверждения

- Новая работа (`crew_spawn`) — только карточка и «да» владельца; лимит `route_max_active` считает ту же функцию, что кнопка «В работу».
- Изменяющих настройки инструментов нет (`crew_config` отложен).
- Письма не обходят очередь агента: служебный ход начинается, когда агент свободен; закрытый и ждущий очереди ребёнок письмом не будится.
- Каждый вызов — строка `▸ crew_… ` в журнале сессии (видна в ленте) и запись в панели «Машины» («Служебные подсказки»: аргументы и результат).
- Все инструменты (кроме `crew_task`/`crew_task_list`, у которых свой набор) идут во всех наборах, кроме прежнего «только вопрос» (`ask_user_question` без остального); видимость у семей агентов — задача 192.9.
