## Находки

1. Заглушки `GATE:recount` и `GATE:once` нельзя получить заменой одного выражения: после правила «существующая запись решает» ни одна одиночная замена не краснит названные ячейки, и шаг 12 («прогоны 7 и 11, `answer-red ok`») неисполним для них как записан.

   Что не так. Раздел «Доказательство красного» требует: «заменяется ровно одно выражение по маркеру `GATE:<имя>` (счёт совпадений 1)». Заглушка 11 описана двумя действиями сразу: «счёт предела включает записи этого же хода **и** проверка «запись уже есть» стоит после классификации»; заглушка 7 (`GATE:once`) — тремя: запись перезаписывается (нет `linkSync`), письмо без `letterExists` и (после правки захода 4, молча) ранний возврат по существующей записи. Правило «существующая запись решает» и правило счёта «только прежние ходы и меньшие номера» дублируют друг друга: каждое в одиночку делает второй проход идемпотентным, поэтому снятие одного из них решения не меняет. Так же `GATE:once`: ранний возврат стоит раньше `createRecord` и `letterExists`, второй проход до них не доходит, и снятие защит записи и письма ничего не краснит. Названные ячейки (`AC-17 повтор при пределе`, `AC-14 пакет повтор`, `AC-02 второй проход` при 11; `AC-17 повтор прохода`, `AC-17 второй процесс` при 7) поэтому не покраснеют ни при какой замене одного выражения, а исправление существенной находки захода 4 останется без доказательства того, что ячейки ловят дефект. Отдельно: в `AC-02 второй проход` проверяется только отсутствие «ждёт вас» и прибавки записей; если при снятом ранней проверке второй проход заново закрывает вопрос (`handled` истина), ячейка зелёная и при дефекте. Кроме того, маркер `/* GATE:x */` стоит «сразу после выражения», но где выражение начинается, правило подстановки не говорит (скрипту нужен либо разбор, либо договорённость вроде скобок или пары маркеров).

   Чем доказано: проба 1 — имитация текста плана (`answer_max=2`, пакет из двух, проходы 1 и 2 с разным `now`):
   `plan text                    closed,closed | exist,exist | a: 2 r: 0`
   `stub: exists off only        closed,closed | closed,closed | a: 2 r: 0`
   `stub: count-all only         closed,closed | exist,exist | a: 2 r: 0`
   `stub: both                   closed,closed | rest,rest | a: 2 r: 1`
   то есть красный проход 2 (`rest`, лишний `r`) получается только при снятии обоих мест. Проба 3 — порядок «поиск записи → запись → письмо»:
   `план как есть (раннее решение + защиты)        писем: 1 answeredAt: 10`
   `GATE:once (link и letterExists сняты)          писем: 1 answeredAt: 10`
   `только раннее решение снято                    писем: 1 answeredAt: 10`
   `раннее решение + link + letterExists сняты     писем: 2 answeredAt: 20`
   Строки плана 412, 416, 420 (раздел «Доказательство красного»).

   критичность: существенная — причина: проверка, ради которой введены ячейки существенной находки захода 4 (повторный проход не переворачивает решение и не шлёт второго письма — REQ-21, REQ-06, AC-17), при исполнении плана не выполнится: шаг 12 упадёт на заглушках 7 и 11 либо исполнитель подменит заглушку своей, и тогда «красное» уже не следует из плана. Доказательство красного в этом плане — часть DoD уровня F, поэтому по шкале это непроверяемость, а не формулировка.

   Что сделать: (а) разрешить заглушке быть набором маркеров с общим счётом (`GATE:recount` = `GATE:recount-exists` + `GATE:recount-count`; `GATE:once` = `GATE:once-early` + `GATE:once-link` + `GATE:once-letter`), по одному совпадению на каждый маркер, таблица «маркер → замена» — по маркерам; (б) для границы выражения: либо парные маркеры `/* GATE:x< */ … /* GATE:x> */`, либо выражение в скобках, начало которых скрипт находит от маркера назад по балансу скобок; (в) в `AC-02 второй проход` добавить проверку, что второй проход при снятом ранней проверке меняет что-то видимое (например, при `answer_max` равном числу ответов уведомление остатка), либо вывести ячейку из списка красных при 11.

   уровень: план

2. «Ряд записей сессии» для предела не определён для записей остатка `r-…`: при прямом чтении остаток обрывает «подряд», и предел обходится после первого же остатка по пределу; ни одна ячейка этого не ловит.

   Что не так. Предел (строка 58): «счёт — число записей `дан` подряд в конце ряда записей сессии по времени ответа; запись `владелец вмешался` ряд обрывает». Записи остатка `r-…` лежат в той же папке `answers/` под той же сессией (строка 53), у них есть `answeredAt`, и «ряд записей сессии» при чтении папки включает их. Тогда при `answer_max=2`: ход 1 — два ответа, ход 2 — остаток «предел автоответов» (запись `r`), ход 3 — в конце ряда стоит `r`, `дан` подряд = 0, вопрос закрывается автоответом. REQ-10 говорит иначе: «возвраты владельцу не считаются», «после `answer_max` ответов подряд … следующий её вопрос идёт владельцу», счёт обнуляет «слово владельца … написанное после её последнего автоответа» — единственный сброс; REQ-07 про пометку остатка: «в счёт предела не идёт». Дословный исполнитель получает цикл «вопрос — ответ по рекомендации — вопрос», которого предел должен не допускать (REQ-10, «источник»: цикл не должен обойти потолок заходов). Ячейка `AC-14 счёт` проверяет «два ответа, третий — предел, слово владельца обнуляет» и четвёртый ход после остатка без слова владельца не рассматривает; `AC-14 пакет повтор` и `AC-17 повтор при пределе` — один ход.

   Чем доказано: проба 2 — имитация плана с двумя чтениями ряда (`max=2`, три хода подряд, владелец не пишет):
   `rInRow=false closed,closed | rest | rest`
   `rInRow=true closed,closed | rest | closed`
   (второе чтение даёт автоответ третьему ходу после остатка по пределу). Строки плана 53, 58; spec.md REQ-10, REQ-07, AC-14.

   критичность: существенная — причина: реализация, точно следующая тексту плана в одном из двух естественных чтений, проходит весь DoD и нарушает REQ-10 в сторону автоответа — сторону, которую принцип «закрыто по умолчанию» запрещает; проверить это по плану нечем (число и сценарий, поэтому поверхностной быть не может).

   Что сделать: записать, что ряд составляют только записи вида `a` (состояния `дан` и `владелец вмешался`), записи `r-…` в ряд не входят, счёт не обрывают и не сбрасывают, обнуляет его только `владелец вмешался`; добавить ячейку `AC-14 после остатка` (`answer_max=2`: два ответа, остаток по пределу, четвёртый ход без слова владельца — снова «предел автоответов»; после слова владельца — ответ) и пометить её красной при `GATE:limit`.

   уровень: план
