Заказчик: владелец репозитория `unitcraft/crew-harness` (он же принимает результат).
Репозиторий: `unitcraft/crew-harness`, ветка `main`. Дата задания: 2026-10-18.
Эпик: [001-crew-service](../../001-crew-service/); вторая дочерняя задача этапа «продукт на Нове» (первая — [090-product-env-spike](../../090-product-env-spike/): разведка среды, результат в `product/spike-env/`).
Источник: слова владельца в чате оркестратора, 2026-10-18: «ядро концепции — всё сделано на движке стейт-машин, события должны быть самодостаточными и обрабатывать вход и генерить выход»; «пишем на Нова, для MVP компилируем Оракулом до тех пор, пока Карина не будет готова»;
«пушь 090, заводи 2». Русские идентификаторы Нова пока не поддерживает (владелец, 2026-10-18): весь код — английскими идентификаторами; методика описывает движок русскими.

Задача полная: разбор, реализация, сдача. Быстрый путь. Основа — свежий `origin/main` (в нём `product/spike-env/`).

## Чего хочет владелец (его слова, 2026-10-18, чат оркестратора)

- Ядро продукта — движок стейт-машин; событие самодостаточно: несёт всё нужное, обрабатывает вход и порождает выход.
- Первый срез продукта (эта задача — основа): каркас движка на Нове, собираемый Oracle 0.1.0, с тестами.

## Что нужно

1. **Источник.** Движок уже описан в методике кодом на Нове с русскими именами: `state-machine-engine-automaton.md` и нормы `state-machine-spec.md` (правила 12–25, 31, 35), контракт «шаг агента» — `task-runner-session-states.md`, `task-runner-meeting-states.md` («Типы на Нове»);
   читать точные файлы из `unitcraft/ai-dev-methodology` (`gh api`, ветка `main`, на момент старта записать коммит; локальный клон методики не использовать и не менять). Задача — не перепечатка, а ПОДМНОЖЕСТВО для MVP «сессия чата с агентом» (ниже) и перевод имён на английский со словарём.
2. **Каталог `product/engine/`** (пакет Нова, `nova.toml`; сборка — `product/spike-env/README.md`, Oracle 0.1.0, Clang; Oracle ставить так же, как в 090: скачанное вне репозитория или уже лежащий каталог из 090 — указать, что использовано). Английские идентификаторы; русские термины методики — в `product/engine/GLOSSARY.md` (термин → идентификатор → где в методике).
3. **Типы (подмножество MVP):**
   - `Event` — самодостаточное событие: идентификатор, трасса, номер шага, вид, вход (данные), время; ничего не берётся «из окружения»;
   - `Request[Input]`, `Outcome[Result]` (результат или отказ), `FailCode` (закрытый список: `NoResult`, `ModelRefused`, `ConnectionLost`, `FormNotFixed`, `Timeout`, `Cancelled`, `StoppedByHuman`, `CeilingReached`, `MaxTokens`, `MaxTurnRequests`) — по методике («Типы на Нове»), с английскими именами;
   - `Machine` — протокол машины: начальное состояние, `step(state, event) -> StepResult` (новое состояние плюс список выходов), чистая функция без ввода-вывода;
   - выход `Output` — команды движку: отправить запрос, записать в журнал, сохранить снимок, завершить.
4. **Движок (`Engine`).** Цикл: принять событие → `step` → применить выходы через эффекты (`Journal.write(entry)`, `Store.save(id, snapshot)` / `Store.load(id)`, `Agent.send(request)`/`Agent.receive() -> Option[Event]`, `Time.now`); журнал событий (дозапись, формат строкой JSON с конвертом: трасса, номер шага, вид, идентификатор запроса, время);
   перезапуск повторным входом: из снимка и журнала восстановить состояние и продолжить без повторной отправки уже открытых запросов (правила 12, 22 спецификации); «один запрос — один ответ» (правило 15): повторный ответ на закрытый запрос отбрасывается и журналируется; отмена запроса отдельным событием.
   Обработчики эффектов для тестов — «в памяти»; боевые (файл, ACP) — следующими задачами.
5. **Демонстрационная машина — сессия чата** (`ChatSession`): состояния `Idle`, `Awaiting` (запрос агенту открыт), `Done`/`Failed`; события `UserMessage(text)`, `AgentChunk(text)`, `AgentDone`, `AgentRefused`, `Cancel`, `Timeout`; выходы: отправить запрос агенту, записать в журнал, сохранить снимок. На ней показываются все свойства движка.
6. **Тесты (`nova test`, красная проба до кода):** `step` чистая и детерминированная (два вызова — тот же результат); события самодостаточны (машина не читает ничего вне события и состояния); один запрос — один ответ (дубль отбрасывается, журнал помнит); перезапуск повторным входом (остановить в `Awaiting`, восстановить, ответ приходит — результат тот же, второй отправки нет);
   отмена; срок бездействия; закрытый список отказов; журнал — строки разбираются, трасса и номера шагов сходятся; ограничение: кириллица в тексте сообщений проходит без искажений (UTF-8 в снимке и журнале).
7. **README `product/engine/README.md`:** как собрать и запустить тесты на Windows (команды из `product/spike-env/README.md` плюс то, что нужно), устройство, словарь, что не вошло (по правилу: список «не вошло в MVP»), где продолжение.

## Критерии приёмки

- `nova test` в `product/engine` зелёный на Oracle 0.1.0 (Clang), числом проверок не меньше перечисленных в п. 6; красная проба до кода (первый тест красный на пустом каркасе) показана в отчёте.
- Код без русских идентификаторов; нет ввода-вывода внутри `step`; `Event` несёт всё нужное (проверка тестом «машина не читает ничего вне события и состояния»: прогон на копии состояния даёт тот же результат).
- Перезапуск повторным входом проверен тестом (два варианта: после открытия запроса и после ответа); один запрос — один ответ проверен тестом.
- Только `product/engine/` и `doc/tasks/091-product-engine/` в коммите; без бинарников (`target/` в `.gitignore`), без скачанного, без ключей и абсолютных путей машины владельца (пути вида `C:/work/...`); стражи — 8 и больше, FAIL 0; коммит по правилам AGENTS.md.
- Отчёт: что собрал Oracle 0.1.0 без обходов, что потребовало обходов или упёрлось в ограничение Oracle (минимальные воспроизведения для интегратора Nova), время сборки и тестов; соответствие подмножества методике (какие правила покрыты, какие нет); порядок следующих задач (ACP-клиент, сервер сессий).
