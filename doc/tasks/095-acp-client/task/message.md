Эпик: [001-crew-service](../../001-crew-service/); пятая дочерняя задача этапа «продукт на Нове»: продолжает [090-product-env-spike](../../090-product-env-spike/) (среда, ACP `initialize` работает), [091-product-engine](../../091-product-engine/) (движок и машина чата, `src/engine/`, `src/chat/`) и [093-console-skeleton](../../093-console-skeleton/) / [094-console-claude-layout](../../094-console-claude-layout/) (формат событий страницы).
Источник: слова владельца в чате оркестратора, 2026-10-18: «определить, кто и что делает» по ACP — ACP-клиент это продукт CrewHarness; «пишем на Нова, для MVP компилируем Оракулом»; первый срез — «в браузере открыть сессию и поговорить с агентом»; «по рекомендации» (2026-10-18) на предложение завести `src/acp/` и `src/server/` по порядку: сначала `src/acp/`.

Задача полная: разбор, реализация, сдача. Быстрый путь. Основа — свежий `origin/main`. Код пишется ТОЛЬКО под `src/` (корневой `nova.toml` из 091), только английские идентификаторы.

## Чего хочет владелец (его слова, 2026-10-18, чат оркестратора)

- ACP-клиент — часть продукта CrewHarness (не плагина); продукт на Нове, MVP собирается Oracle 0.1.0.
- Ядро — движок событий: событие самодостаточное; агент, журнал и хранилище — внешний мир движка (эффекты `Agent`, `Journal`, `Store` из 091).
- Первый срез — разговор с агентом в браузере: этой задачей ставится нижний слой (общение с агентом и файлы), сервер и страница — следующими задачами.

## Что нужно

1. **Образец и источники.** Прочитать `src/engine/README.md` и `src/engine/effects.nv` (эффекты и «что не вошло»), `src/chat/chat.nv` (машина чата), `spikes/env/` (README п. «Proc», `child_echo`, `acp/acp_initialize.mjs`, найденные ограничения Oracle 0.1.0 и обходы) и машину «Шаг агента» методики (папка `state-machines/` репозитория методики, файлы `state-machine-agent-step-*`; только чтение: типизированные запрос и ответ агента, коды отказов, запись использования). Спецификацию ACP читать из публичных источников (ACP initialize/session/new/session/prompt/session/update/session/cancel/session/request_permission); не угадывать формат.
2. **`src/acp/` — клиент ACP поверх stdio.** Запуск дочернего процесса агента через эффект `Proc` (по умолчанию `opencode acp`, команда настраивается), JSON-RPC 2.0 с разбором строк (по одному сообщению на строку), чтение и запись без блокировки друг друга: `initialize`, `session/new`, `session/prompt`, `session/cancel`; входящие `session/update` (куски ответа, вызовы инструментов, планы, использование), запросы агента `session/request_permission` (ответ владельца приходит событием, не решается клиентом сам), `fs/*` и терминал агента — отказ «не поддерживается» (в `initialize` не объявлять). Закрытие, падение процесса и таймаут — события-отказы с кодами из закрытого списка `FailCode` (091), а не исключения.
3. **Обработчик эффекта `Agent`** на основе этого клиента: `send` (запрос → `session/prompt`), `receive` (следующее входящее событие без ожидания; `None` — нет), `cancel`. **Событие из `receive` подтверждается только после фиксации** (в 091 это отмечено как открытое: событие, взятое из `receive` и не зафиксированное, пропадало вместе с процессом) — предусмотреть и покрыть тестом, либо описать в README, почему нельзя, и как это решается (например, очередь с подтверждением `ack`).
4. **Проекция «ACP → событие движка».** Таблица соответствия: `session/update` и ответы ACP → `Event` 091 (виды, `name`, `input`) и дальше → события страницы (`agent_chunk`, `tool_call`, `tool_call_update`, `usage_update`, `permission_request` и др. из 093/094). Проекцию 091 → страница, рекомендованную в `doc/tasks/093-console-skeleton/analysis.md` (раздел 3), реализовать здесь как чистые функции (`name → kind`, `at → time`, `input` — в объект); неизвестные виды ACP пропускаются без ошибки, но журналируются.
5. **Файловые обработчики `Journal` и `Store`** (`src/engine/` или `src/storage/` — на выбор исполнителя, обосновать): журнал — один файл на сессию, дописывание строк (формат строки из 091 `codec.nv`), снимок — файл на сессию, запись во временный файл и переименование (замена целиком); путь папки данных — параметр. Файлы только в папке данных (создаётся при запуске), права и пути без выхода из неё (имя сессии проверяется: без `..`, без разделителей).
6. **Проверки.** `nova test src` (один юнит на модуль, как в 091): разбор и сборка JSON-RPC (в том числе кириллица, строка без перевода строки на конце, два сообщения в одном чтении, сообщение, разорванное на два чтения); проекция ACP → событие → страница; обработчик `Agent` на **поддельном ACP-агенте** — небольшой скрипт на Node в `spikes/env/` или `src/acp/testdata/` (читает JSON-RPC со stdin, отвечает на `initialize`, `session/new`, `session/prompt` потоком `session/update`, умеет запрос разрешения, отмену, падение, молчание); файловые `Journal` и `Store` (в том числе смерть между записью журнала и снимком — правило 13/34(е) методики: тест «смерть между изменениями»);
   красная проба до кода (заглушки). Реальный `opencode acp`: только `initialize` и `session/new` без вызова модели (без ключей и входа), результат — в `analysis.md`; вызов модели не делать.
7. **Описание.** `src/acp/README.md` (английский, как `src/engine/README.md`): что вошло, таблица проекции, как подтверждается событие, ограничения Oracle 0.1.0 и обходы (новые — в `spikes/env/repro_*` и в отчёт, их передаёт интегратору Nova оркестратор).

## Критерии приёмки

- `nova test src` зелёный (и `--strict-effects`); красная проба до кода показана; обработчик `Agent` проходит сценарии поддельного агента: обычный ответ кусками, запрос разрешения и решение, отмена хода, падение процесса, молчание по сроку, дубль события.
- Событие из `receive` подтверждается после фиксации (тест) либо решение описано; смерть между записью журнала и снимком покрыта тестом.
- Проекция «ACP → событие → страница» — чистые функции с таблицей в README; неизвестное пропускается и журналируется.
- Реальный `opencode acp` отвечает на `initialize` и `session/new` через клиент на Нове (если машина позволяет); иначе описано, что мешает.
- В коммите только `src/`, `spikes/env/` (если нужны подставной агент или воспроизведения) и `doc/tasks/095-acp-client/`; стражи — 8 и больше, FAIL 0; коммит по правилам AGENTS.md (английское сообщение, `-s`, без трейлеров и без `#число`).
