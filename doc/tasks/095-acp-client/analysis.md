# Разбор 095: ACP-клиент продукта на Нове, боевой обработчик агента, файловые журнал и снимок

Задание — `task/message.md`. Источник: слова владельца в чате оркестратора, 2026-10-18: ACP-клиент — часть продукта CrewHarness; «пишем на Нова, для MVP компилируем Оракулом»; первый срез — «в браузере открыть сессию и поговорить с агентом»; «по рекомендации» (2026-10-18) на предложение завести `src/acp/` и `src/server/` по порядку, сначала `src/acp/`.

## 1. Что сделано

- `src/acp/` — клиент ACP поверх stdio и обработчик эффекта `Agent`: `jsonrpc.nv` (разбор и сборка JSON-RPC, `LineSplitter`: байты → строки), `project.nv` (проекция ACP → событие движка → страница, чистые функции), `link.nv` (дочерний процесс агента и фибры вокруг него), `client.nv` (рукопожатие, очередь запросов, разрешения, входящая очередь с подтверждением, `acp_agent`), `testdata/fake_agent.mjs` (подставной ACP-агент на Node), `README.md` (английский: таблица проекции, подтверждение, ограничения Oracle).
- `src/acp_live/` — проверки с живыми процессами (подставной агент, подтверждение, движок плюс файлы плюс ACP, реальный агент).
- `src/storage/files.nv` — файловые `Journal` (`<сессия>.journal`, дописывание строк) и `Store` (`<сессия>.snapshot`, временный файл и переименование), проверка имени сессии, папка данных создаётся при запуске.
- Правки движка 091 (нужны для подтверждения): четвёртая операция эффекта `Agent` — `ack(source)`; ключ источника входящего события — в `Event.id` (`Event.from_source`), движок кладёт его в строку журнала (`src=<ключ>`); `pump` зовёт `ack` после фиксации шага; перезапуск собирает ключи зафиксированных событий и повторяет `ack`; тип `Output` переименован в `StepOutput`; в `chat.nv` текстом ответа считается только `agent_chunk`.
- `spikes/env/repro_acp/` (6 воспроизведений) и `spikes/env/repro_child_pipes/` (программа) — ошибки Oracle для интегратора Нова; `spikes/env/README.md`, п. 14–20.
- 159 проверок в 6 юнитах: 13 (типы, кодек) + 50 (машина и движок с памятью) + 14 (файлы и движок над файлами) + 45 (`src/acp`: JSON-RPC 18, проекция 27) + 37 (`src/acp_live`: обработчик над подставным агентом 26, подтверждение 4, движок плюс файлы плюс ACP 6, реальный агент 1).

## 2. Решения (с причинами)

1. **Файловые обработчики — в `src/storage/`, а не в `src/engine/`:** движок знает эффекты и обработчики в памяти, `std.fs` в него не тянется; те же помощники нужны входящей очереди клиента.
2. **Подтверждение события — `Agent.ack(ключ)` после фиксации плюс файл входящих.** Событие, отданное `receive`, хранится в «взятых»; после фиксации шага движок зовёт `ack`; без `ack` после перезапуска событие отдаётся заново первым. Запись события в файл — до выдачи. Если процесс умер между фиксацией и `ack`, перезапуск повторяет `ack` для зафиксированных ключей. Итог — событие берётся ровно один раз.
3. **Закрыта дыра перезапуска 091:** строки умершего шага стояли перед строкой перезапуска и после второго перезапуска считались зафиксированными; теперь строки перед строкой перезапуска с её номером или большим не считаются (`overtaken_lines`), тест есть.
4. **Молчание агента решает движок** (срок бездействия → `Expired` → `Timeout` → `cancel`); любое событие агента продлевает срок; падение процесса — `ConnectionLost`, отказ рукопожатия — `NoResult`.
5. **Решение владельца о разрешении клиент не принимает сам:** `session/request_permission` — событие `permission_request` с ключом; ответ придёт событием `permission_decision`. Отмена хода отвечает на открытые запросы исходом `cancelled`.
6. **`fs/*`, терминал и неизвестный метод агента** — ошибка −32601 и заметка `acp_note`; в `initialize` файлы и терминал объявлены как `false`.
7. **Неизвестные виды ACP не теряются:** событие `acp_skipped` (журналируется, странице ничего не уходит).
8. **Проекция на страницу — чистая `page_event(event, turn)`** (`name → kind`, `at → time`, `input` → объект).
9. **Фибры вокруг процесса:** читатели stdout и stderr, писатель stdin и наблюдатель общаются с программой каналами; все фибры клиента — в одной области `supervised` отсоединённой фибры-хранителя, писатель — в своей отменяемой области, `close()` ждёт конца фибр. Первый вариант (четыре отдельных `detach`) давал зависание бинарника раз в 5–20 прогонов под нагрузкой.
10. **Тесты в двух юнитах с короткими именами:** бинарник блокируется, если его строки вывода вместе больше 4096 байт, а `nova test src` трубу не читал; каждый юнит держит вывод ниже 4 КБ (`chat` 3,7 КБ — запас небольшой).

## 3. Расхождения с заданием и методикой

- Эффект `Agent` получил операцию `ack` (задание допускало «очередь с подтверждением»); в строку журнала добавлен хвост ` src=<ключ>`.
- Тип `Output` переименован в `StepOutput` (обновлены `GLOSSARY.md` и `README.md` движка): в Oracle тип пользователя с этим именем ломает C, как только подключён `std.os`.
- Машина чата берёт текстом ответа только `agent_chunk`.
- Перезапуск службы не продолжает ход: открытый запрос после перезапуска кончается `Timeout` (`session/load` не сделан).
- Реальный `opencode acp` идёт в тесте только при `CREW_REAL_ACP=1`.

## 4. Ограничения Oracle 0.1.0 (воспроизведения — `spikes/env/repro_acp/`, `repro_child_pipes/`; `spikes/env/README.md`, п. 14–20)

14. Тип пользователя `Output` плюс `import std.os` — несовместимые `Nova_Output` в C.
15. Однознаковый строковый литерал там, где ждётся `char`, для переменной цикла `for part in text.split(...)`: проверка молчит, C не собирается.
16. Результат «плавного» сеттера значимого типа нельзя присвоить обратно.
17. `AtomicInt` в записи — копия переменной; общее значение между фиброй и держателем записи — только канал.
18. Имя захваченного `consume`-значения — макрос C; поле с тем же именем в теле фибры не собирается.
19. Зависания труб дочернего процесса (воспроизведение нестабильное): запись в stdin потомка не возвращается ни при смерти потомка, ни по таймауту; запущенная `detach`-фибра не стартует; бинарник, закончивший тесты, не выходит. После схемы из п. 2.9 — 100 прогонов подряд без зависаний, полностью не исключено.
20. Бинарник юнита, чьи строки вывода больше 4096 байт, блокируется, если трубу не читают.

## 5. Проверки

- Красная проба до кода: `src/acp` 5 из 82 зелёные, `src/chat` 45 из 49, `src/storage` 1 из 14; итого 94 красных из 145; первый красный — «cannot start the fake agent: stub: not implemented».
- Доказательство красного после реализации: восемь временных поломок реализации (движок не зовёт `ack`; перезапуск не повторяет `ack`; перезапуск не учитывает перекрытые строки; клиент не пишет `ack` в файл; клиент не пишет события в файл; читатель не отдаёт последнюю строку без перевода строки; клиент не шлёт `session/cancel`; запись журнала без перевода строки после обрыва) — каждая ловится красными тестами.
- Исполнитель: `nova test src` — PASS 6 юнитов, 159 проверок; `--strict-effects` зелёный; 18 прогонов подряд зелёные (38–43 с); стражи ок 8, FAIL 0; реальный `opencode acp` v2.0.26 ответил на `initialize` и `session/new` через клиент на Нове (запроса к модели не было).
- Независимая проверка оркестратора: ветка перенесена на свежий `origin/main`, `nova test src` — PASS 6 юнитов, FAIL 0, 39 с.

## 6. Что дальше

- Сервер сессий и страница на Polaris (`src/server/`): `Engine` на сессию с `Journal` и `Store` и `acp_agent`, `pump` по таймеру, `/ws` с `page_event`, приём `permission_decision`, список сессий, перезапуск службы через `resume_engine` → следующая задача этапа «продукт на Нове».
- Страница должна получать события со штампом движка, а строка журнала хранит только `<вид>/<имя>` → задача сервера `src/server/`.
- Продолжение хода после перезапуска службы (`session/load`) → не нужно сейчас, потому что открытый запрос после перезапуска честно кончается `Timeout`, а `loadSession` агент может не объявить.
- Отмена хода владельцем сама завершает чат-сессию (машина 091 однооборотная): многооборотная машина → задача сервера `src/server/`.
- Ворота человека для разрешений (правила 19–21) → не нужно сейчас, потому что на время ожидания хватит длинного срока бездействия машины.
- Сжатие файла входящих при работе → не нужно, потому что файл растёт на строку за событие и сжимается при каждом старте.
- Передать интегратору Нова воспроизведения `repro_acp` и `repro_child_pipes` → не нужно как отдельная задача, потому что их отправляет оркестратор письмом.
