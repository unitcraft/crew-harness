# Реестр примитивов хозяина

Задача 105. Список эффектов и чистых разборов, которые понадобятся машинам продукта — и машинам методики, и новым машинам проекта ([matrix.md](matrix.md)). Правило владельца, 2026-10-18: машины на Нове не пишутся; примитивы хозяина пишутся на Нове один раз. Здесь — их перечень с классом, входом, выходом, готовностью в `src/` и оценкой работы.

**Что называется примитивом.** Формат машины (черновик v0 задачи 104) допускает в выражениях только закрытый чистый язык: без цикла, времени, ввода-вывода. Всё, что читает или меняет мир, и всё, что разбирает текст по сложным правилам, вызывается как примитив из реестра: имя, входы, результат, класс. Чистые функции над данными (сравнения, выбор модели по таблице, ступень, порядок) пишутся в самой машине как определения и сюда **не** входят; в реестр попали только разборы текста и сопоставления, которые в языке без циклов не записать.

**Классы** (из методики): `pure` — не читает мир; `reading` — читает файл, git, процесс, хранилище; `writing` — пишет или запускает, обратимо; `irreversible` — необратимо. Класс определяет, где вызов допустим. Предложение, которое ждёт решения методики (оговорка Р3 пилота): `pure` и `reading` — в условии, в действии и в «При входе»; `writing` и `irreversible` — только в действии и в «При входе».

**Имена** — латиницей, по классу: `pure_*`, `rd_*`, `wr_*`, `ir_*`; в формате они пойдут в английской форме словаря методики. Колонка «методика» в разделе 3 называет машины методики, которым примитив нужен независимо от плагина (функции `Objects` и `Irreversible` автоматов раннера, сессии, совещания и шага агента).

## 4. Сколько на Нове

Всего 61 примитивов, около 4407 строк кода на Нове (без тестов). Оценка по строке — это строки соответствующего кода плагина с поправкой: разбор текста и сопоставление переносятся примерно 1 к 1,3 (на Нове больше явных типов и ветвей); обёртки над git и файлами — по числу команд, а не по строкам TypeScript; процессы Windows — с запасом, потому что цепочка скрытой консоли (задача 100) и удар по дереву по метке (задача 101) на Нове не писались. Тесты каждого примитива — вектор «вход, ожидаемый результат», снятый с плагина (оракул, [plan.md](plan.md), «Проверка равенства»): строк тестов примерно столько же, сколько кода.

Калибровка по сделанным задачам продукта: ACP-клиент и файловые обработчики (095) — около 1 700 строк кода и 2 000 строк тестов за одну задачу; хранилище PostgreSQL (098) — около 520 строк кода и 1 300 строк тестов за одну задачу. Одна задача вмещает 1 800–3 700 строк кода вместе с тестами. Для 4407 строк кода и столько же тестов это **4–6 задач** с запасом на то, что не известно заранее: в стандартной библиотеке Новы есть `text.regex`, `os` (процессы `Command.new`), `fs`, `encoding.json` (выписка фактов о Нове, 2026-10-07), но проверенных в этом репозитории среди них только `std.os` и JSON.

## 5. Что уже есть в `src/` и чего нет

- Есть: эффекты `Journal`, `Store`, `Agent` (отправка, приём, отмена, подтверждение) и `Time` движка (`src/engine/effects.nv`, с задачи 144 — в пакете `alula`); файловые обработчики журнала и снимков ([src/storage/files.nv](../../../src/storage/files.nv)); обработчики PostgreSQL ([src/pgstore/handlers.nv](../../../src/pgstore/handlers.nv)); ACP-клиент с открытием сессии, отправкой, отменой и подтверждением входящих ([src/acp/client.nv](../../../src/acp/client.nv)); проекция событий страницы `page_event` ([src/acp/project.nv](../../../src/acp/project.nv)).
- Нет: всё остальное. Чтение и запись файлов проекта, git, процессы, настройки проекта, разборы текста, хранилище проекта с атомарным «сравнить и записать».
- Нет в движке (не примитив, а возможность движка): таймеры (`wr_timer`), вызов машины из машины, общие события «стоп человека» и «продолжить», ворота человека, множество сторон ([plan.md](plan.md), «Зазоры движка и формата»).

## 6. Ограничения Oracle 0.1.0, которые уже известны и касаются примитивов

Из README движка и разборов задач 095 и 098: обобщённый вариант со строкой не собирается; модуль на два уровня вглубь `src/` отвергается; тело операции обработчика, состоящее только из `panic(...)`, и `return []T.new()` в обработчике дают ошибки C; `std.os` и тип `Output` движка путаются (поэтому тип назван `StepOutput`); файл `listener.nv` драйвера PostgreSQL и запись `Event` в одной программе не собираются; `nova test` убивает модуль дольше 60 секунд; тестовый бинарь, печатающий больше 4 096 байт, блокируется на Windows при параллельном запуске модулей. Для примитивов отсюда следует: каждый примитив — отдельный маленький модуль с короткими именами тестов; процессные примитивы (`wr_proc_start`, `wr_proc_run`, `ir_proc_kill`) — отдельная папка и воспроизведение на Windows первым делом; тесты, запускающие `git`, делают это во временных репозиториях и укладываются в 60 секунд на модуль.
