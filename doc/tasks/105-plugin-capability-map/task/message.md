# Задание: инвентарь возможностей плагина crew-harness и матрица переноса в продукт CrewHarness на машинах-данных

Заказчик: владелец репозитория `unitcraft/crew-harness` (он же принимает результат).
Репозиторий: `unitcraft/crew-harness`, ветка `main`. Дата задания: 2026-10-19.
Эпик: [001-crew-service](../../001-crew-service/); продолжает этап «продукт на Нове» ([091](../../091-product-engine/), [095](../../095-acp-client/), [098](../../098-pg-storage/)); связано с 104 (папка пока не в main) (формат машины как данных, черновик).
Источник: слова владельца в чате оркестратора, 2026-10-19: «цель: все возможности текущие (плагин crew-harness под opencode) + стейт-машины из методики должны быть написан на таких стейт-машинах внутри голого продукта CrewHarness».

Задача документальная (исследование): без изменений кода. Быстрый путь. Основа — свежий `origin/main`. Правки только папка задачи.

## Чего хочет владелец (его слова, 2026-10-19, чат оркестратора)

- «все возможности текущие (плагин crew-harness под opencode) + стейт-машины из методики должны быть написаны на таких стейт-машинах внутри голого продукта CrewHarness» — продукт без OpenCode и без плагина: те же возможности, реализованные машинами-данными (формат v0) на движке `src/engine`.
- Ограничение владельца (2026-10-18): без написания машин на Нове; примитивы хозяина (эффекты) — на Нове один раз.

## Что нужно

1. **Образцы и источники:** `opencode-plugin/` (все `*.ts`, README, `test/README.md`, тесты как описание поведения), `doc/canon/` (процесс, ADR), `doc/tasks/*/analysis.md` задач плагина (007, 012, 059, 078, 092, 096, 097, 100, 101 и другие), `src/engine/README.md`, `doc/tasks/104-machine-table-format/draft-format-v0.md`, машины методики (`state-machines/`, чужой репозиторий, только чтение: `task-runner-*`, `state-machine-agent-step-*`).
2. **Инвентарь возможностей** (`inventory.md`): ВСЕ возможности плагина по группам — инструменты `crew_*` (названия и что делают), панель и статусы, формы и ответы (в том числе автоответы), задачи и их жизненный цикл (создание, исполнитель, приёмка, доработка, слияние, уборка), рабочие деревья и ветки, очередь тяжёлых команд (`crew_watch`, слоты), письма и ящики между окнами, роли и профили моделей, ворота и маршрут задачи, настройки проекта и конфиг, диагностика (`crew_doctor`), стражи и хуки; для каждой: где в коде (файл), какое состояние хранит (файлы данных), какие внешние эффекты использует (git, файловая система, процессы, GitHub, OpenCode API), с какими другими возможностями связана. Объём: счёт возможностей (число строк таблицы) и размер кода по группам.
3. **Матрица переноса** (`matrix.md`): для каждой возможности — как она выражается в продукте: (а) МАШИНА (состояния и события; какие машины; какая из машин методики её покрывает: «Шаг агента», «Запуск сессии», «Проверка цикла», «Совещание», «Раннер»); (б) ПРИМИТИВ хозяина (эффект, класс pure/reading/writing/irreversible: например git, файлы, процессы, очередь машины, GitHub, ACP); (в) ИНТЕРФЕЙС пульта (экран, форма, команда страницы); (г) НЕ ПЕРЕНОСИТЬ (с причиной: относилось только к OpenCode, заменено стражем, устарело). Для каждой: сложность (малая, средняя, высокая), риск, зависимости, порядок.
4. **Реестр примитивов продукта** (`primitives.md`): сводный список уникальных эффектов хозяина, которые понадобятся машинам (имя, вход, выход, класс, где применяется, есть ли готовый обработчик в `src/`), с оценкой «сколько на Нове».
5. **План переноса** (`plan.md`): порядок этапов (что переносится раньше), для каждого этапа критерий готовности, проверка равенства с плагином (сценарии: события → ожидаемые журнал и данные; сравнение по структурным данным), риски и вопросы владельцу (с рекомендацией); оценка работы в числе задач; что можно сделать в продукте уже сейчас, независимо от интерпретатора.
6. **Проверки:** каждая возможность в инвентаре имеет ссылку на файл и строку; независимая сверка 10 случайных возможностей по коду; сумма по группам сходится с общим числом; стражи 8 и больше, FAIL 0; коммит по правилам AGENTS.md (английское сообщение, `-s`, без трейлеров и без `#число`, файлы перечнем).

## Критерии приёмки

- `inventory.md` покрывает все `crew_*` инструменты, статусы панели, виды форм, жизненный цикл задач, очередь, письма, профили, ворота, настройки, диагностику, стражи; в каждой строке ссылка на код и состояние.
- `matrix.md`: у каждой возможности указан способ переноса (машина, примитив, интерфейс или не переносить) и порядок.
- `primitives.md` и `plan.md` написаны; в плане вопросы владельцу с рекомендацией.
- Сверка 10 случайных возможностей зелёная; стражи 8 и больше, FAIL 0.

## Результат и куда он попадает

нет: результат — документы в папке задачи; на их основе оркестратор заводит задачи переноса (машины, примитивы, интерфейс).
