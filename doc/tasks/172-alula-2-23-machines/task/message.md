# Задание: перевод машин продукта на Алулу 2.23 (пакет `alula` 0.5.0)

Заказчик: владелец репозитория `unitcraft/crew-harness` (он же принимает результат).
Репозиторий: продукт `unitcraft/crew-harness`. Дата задания: 2026-10-25.
Источник: решение владельца и Методики о выпуске `alula` 0.5.0 (Алула 2.23), 2026-10-25 (чат Методики: «по рекомендации»; о классах — «принимаю три класса: чистая, изменчивая, действующая»).

Задача механическая, объёмная по числу правок. Исполнитель ничего не публикует и не пушит.

## Признаки маршрута

Цель: таблицы машин продукта и методики в `machines/` записаны в формате 2.23, деревья `*.alula.json` пересобраны программой `alula` 0.5.0, продукт зависит от пакета `alula` 0.5.
Источников: 3 (таблицы `machines/`, встроенные тексты машин в `src/`, зависимость в `nova.toml` и `nova.lock.toml`).
Частей системы: 2 (продукт; плагин `opencode-plugin` только проверяется по чтению, не правится).
Риск: средний (много правок в таблицах; поведение ловят 595 сценариев и тесты «таблица равна дереву»).
Необратимо: нет
Причина известна: да (пакет 0.5.0 читает только формат 2.23, переходного периода нет, старые формы — ошибка с названием нового способа)
Касается нормы или формата: да (формат таблиц машин 2.22 → 2.23; сам формат задан пакетом, продукт его только принимает)

Ветка: task-172-alula-2-23-machines (от `origin/main`)

## Чего хочет владелец

Слова владельца и Методики, 2026-10-25 (чат Методики): выпуск Алулы 2.23 одним релизом `alula` 0.5.0 без переходного периода; машины продукта и методики, живущие в этом репозитории, переводятся на новую запись. Отдельно владелец Методики ждёт от продукта перегенерированные таблицы `agent_step`, `session_start`, `cycle_check`, `task_runner` и `registry.md`/`journal.md` для переноса в методику.

## Что нужно

1. Инвентаризация вхождений старых форм до правки (числа — в `log.md`).
2. Миграция скриптом (скрипт вне репозитория): `format: 2.22` → `2.23`; столбец `пишет`: `строки` → `действия` (AL-122); код журнала в кавычках `журнал("код", …)` (AL-115); классы внешних функций `reading` → `изменчивая`, `writing` и `irreversible` → `действующая` (AL-116); хеш образца файла функций `642e1f78f0f7` → `ebb7658048b2`; образец `agent-step-sample.txt` — если содержит старые формы. Деревья `*.alula.json` пересобираются программой 0.5.0.
3. Зависимость от пакета: `nova.toml` — версия `0.5`, `nova.lock.toml` — тег `v0.5.0`, коммит `9fd413a9bf94ed696b8d0d4584d66ee263c4cd30`. Тесты, утверждающие версию формата, приводятся к 2.23.
4. Проверки: `alula test` обоих наборов, тесты папок `src/` с машинами, стражи.
5. Выходные файлы для Методики — вне репозитория (пути в отчёте).

## Чего не меняется

- Поведение машин, сценарии (число и содержимое по существу), журнальные коды — прежние; меняется только запись.
- Плагин `opencode-plugin` — не правится (только отчёт, не читает ли он деревья или формат 2.22).
- Исторические документы `doc/tasks/*` не правятся.

## Критерии приёмки

- AC-1. В `machines/` нет `format: 2.22`, `журнал(` без кавычек у кода, слов `reading`/`writing`/`irreversible`, значения `строки` в столбце `пишет`, хеша `642e1f78f0f7`; деревья имеют `alula_version: "2.23"`.
- AC-2. Деревья равны сборке программой 0.5.0 (разбор JSON; завершающего перевода строки нет, как раньше); при сравнении «до/после» меняются только ожидаемые ключи.
- AC-3. `alula test machines/methodology` и `alula test machines/product` — все сценарии зелёные (число прежнее; сценарии `dialog_steps` лежат здесь).
- AC-4. Тесты папок `src/` с машинами зелёные на пакете 0.5.0.
- AC-5. `sh scripts/guards/run-all.sh` зелёный.
