## Что нужно

1. **Разбор:** где в плагине создаётся и хранится задача (`tasks.ts` — тип `Task`, `crew_spawn` в `core.ts`, запись `tasks/<проект>/<N>.json`, `crew_task`), как задача показывается (`status.ts`, `/crew`, панель), как читается `task/message.md` (`task-folders.ts`, `crew_task show`); какие поля методики из списка ниже уже есть в записи; какие из «Проверок реализации» (тесты 1–23 методики) относятся к данным и проверке постановки, а какие — к раннеру (не делать).
2. **Данные маршрута в записи задачи** (имена на английском, соответствие терминам методики — таблицей в README): `route` (`full` | `fast`, по умолчанию `full`), `route_basis` (текст), `route_source` (`rule` | `helper` | `human`), `route_proposal` (`full` | `fast`), `route_word` (дословная цитата слова владельца «заводи N» с датой и источником), `route_word_date`, `clean_runs`, `ceiling`, `probes`, `delivery_compressed` (bool), `sources_list` (перечень источников из постановки, список строк).
   Запись неизвестна старым задачам: отсутствие поля читается как `route: full`, значения по умолчанию — полный путь (4 потолок, 2 чистых, 3 проб); быстрый — 2, 1, 3; минимумы методики (1 чистый заход, 3 пробы) не ослабляются (значение ниже минимума отвергается). Параметры проекта (`.opencode/crew-harness.json`): `route_defaults` с числами по маршрутам и порогами выбора; отсутствие — значения методики.
3. **`crew_spawn` / создание задачи:** необязательный параметр `route` (`fast`) и поля п. 2; при `fast` — проверка постановки: `task/message.md` существует, содержит нумерованные критерии приёмки (раздел «Критерии приёмки» с не менее чем одним пунктом) и строку с веткой; `route_word` не пустое и содержит «заводи»; иначе отказ с понятным текстом «быстрый путь требует: …» (маршрут остаётся `full`, задача не создаётся без явного решения).
   Расхождение с методикой «Ветка:»: формат постановки проекта — «Репозиторий: …, ветка …» — принимается проверкой так же; записать в README.
4. **Решение 51 как правило данных:** изменение `task/message.md` после слова завода при `route: fast` помечает запись `route_word_stale` (возврат на ворота В5 нужен) и при следующем `crew_task` шаге или показе выводит предупреждение «постановка изменена после слова завода: нужно новое слово владельца»; смена маршрута на `full` — только записью `route` и `route_word` пустого с причиной; серии чистых заходов обнуляются (поле `clean_runs`), трасса и номера заходов сохраняются.
5. **Показ:** в `/crew` и панели у быстрой задачи значок или слово маршрута (по выбору, коротко), строка предупреждения п. 4; в журнале задачи (`log_line`) — событие «маршрут: быстрый, основание, источник, слово завода».
6. **Тесты:** красная проба до кода (источник: задача `fast` без `message.md`/без критериев/без слова завода — отказ; с ними — создана с полями; старая запись читается как `full`; значение ниже минимума отвергается; изменение `message.md` после слова — предупреждение `route_word_stale`; показ);
   полный `npm test` не больше чем по 4 параллельно ([AGENTS.md](../../../../AGENTS.md), п. 9); golden — только изменившиеся ключи. README плагина — раздел «Маршрут задачи».

## Критерии приёмки

- Красная проба до кода падает на источнике и проходит после правки.
- Старые задачи читаются без изменений (`route: full`); `crew_spawn` с `route: fast` без условий отказывает с текстом; с условиями создаёт задачу с полями.
- Изменение постановки после слова завода даёт предупреждение; показ маршрута виден в `/crew` и панели.
- Полный `npm test` зелёный (красные, нестабильные под нагрузкой, перепроверены по одному — перечень в сдаче); стражи — 8 и больше, FAIL 0.
