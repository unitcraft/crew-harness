# Разбор 059: ответ владельца на вопросник снаружи окна

Основа — `main` `2a0c283`, коммит задания `bf85843`. Проверено на OpenCode 2.0.26 (строки бинаря, только чтение; учётные данные службы не использовались, к службе по HTTP не обращались).

## 1. Осуществимость: нет

У плагина нет способа ответить на вопрос инструмента `question` так, как отвечает окно.

- Вопросник — это форма (`form.created` / `form.replied` / `form.cancelled`, схема `Form.Reply = {answer}`).
- Окно отвечает HTTP-клиентом SDK: `i.session.form.reply({sessionID, formID, answer}, location)` → маршрут `session.form.reply` `/api/session/:sessionID/form/:formID/reply` («Submit an answer to a pending form.»), под промежуточным слоем аутентификации.
- Контекст плагина (`d.setup(Q)`) состоит из ключей `app, location, options, agent, aisdk, command, event, experimental, generate, model, provider, integration, mcp, permission, plugin, reference, rpc, skill, storage, tool, vcs, websearch, worktree, session, shell`. Ключа `form` нет; в `session` (`hook, create, get, remove, switchAgent, switchModel, prompt, generate, command, compact, synthetic, interrupt, update, move, wait, context`) формы нет; `permission.reply` отвечает только на запросы разрешений; `rpc` — методы, которые плагин объявляет сам (`Plugin.Rpc.fromEffect`), а не вызов сервера. HTTP-клиента (`client`, `serverUrl`) в контексте нет.
- Снаружи процесса маршрут требует учётных данных (разбор 048: ответ 401) — задание их запрещает.

По заданию (п. 1) работа была остановлена; затем владелец выбрал путь 2 — см. раздел 4.

## 2. Пути, которые остаются (решение владельца)

1. **Перехват инструмента `question` через `ctx.tool.transform`** (тот же механизм, что уже в `index.ts` и `journal.ts`): обёртка `execute` ждёт либо ответ окна, либо ответ из папки входящих и во втором случае возвращает его модели как итог инструмента, а ожидание формы прерывает сигналом. Ход продолжается с ответом владельца; что станет с формой на экране (снимется как отменённая или повиснет) — не доказано строками, нужна проба на живой службе после перезапуска. Риск — меняется поведение встроенного инструмента у всех вкладок.
2. **Обход вопросника:** `ctx.session.interrupt` (задача 048) снимает ход, затем письмо с ответом владельца через `session.prompt`. Работает средствами контекста, но вопросник закрывается не ответом, а прерыванием; ход начинается заново.
3. **Просьба к OpenCode** добавить `form.reply` в контекст плагина — вне нашего репозитория.

Рекомендация: путь 1 отдельной задачей с пробой на живой службе — он ближе всего к «как нажатие в окне»; путь 2 — запасной.

## 3. Безопасность (для любого пути)

Ответ принимается только из локальной папки данных службы; подделать его может тот, кто пишет в эту папку, — та же граница, что у ящика писем. Сигнал — строка журнала и событие «ответ владельца через оркестратора» в истории задачи.

## 4. Путь 2: что сделано и проверка

Решение владельца (2026-10-15, чат оркестратора): «по рекомендации» — путь 2 основной.

- `opencode-plugin/owner-answer.ts`: папка входящих `<ящик>/answers/`; `resolveAnswer` (форма по id или сессии, вариант по номеру или подписи без «(Recommended)», свой текст; отказ без цитаты, без формы, без варианта; «already answered (answer <id>)», если на эту форму уже применён ответ); `answerTick` — запись `forms/` снимается до прерывания (событие `form.cancelled` от прерывания не начинает повтор 040), `interruptTurn` из 048 с `resume:true`; неудача — запись возвращается, отказ с причиной; удача — письмо «Ответ владельца на ваш вопрос «…»: … (передан через оркестратора по слову владельца: «…»)», событие в истории задачи вкладки, снятие отметки «застряла», побудка вкладки, строка журнала `owner answer <id> applied`. Итог — в самом файле (`status`, `why`, `answer`).
- `index.ts`: вызов `answerTick` в проходе `formWatch` (раз в `CREW_HARNESS_FORM_MS`, 5 с). Места задачи 058 не тронуты.
- `scripts/crew-answer.mjs`: без аргументов — открытые вопросники (проект, вкладка, форма, вопрос, варианты); с аргументами — цель (форма, сессия или `проект.роль`), `--option`/`--text`, `--quote`; ждёт итога до 30 с (`--no-wait` — не ждать).
- README плагина — раздел «Your answer to a question from outside the window».

Проверка: `test/crew-owner-answer.test.mjs` (14 проверок): применение, прерывание с `resume`, запись снята без повтора 040, письмо с ответом и цитатой, история задачи, журнал; неверная форма — отказ с причиной; повтор — «already answered», второго прерывания нет; неудачное прерывание — вопрос остаётся, письма нет. Красная проба до подключения — 9 падений.

Не проверено: поведение живой службы — что прерывание снимает вопросник с экрана окна и что ход после письма идёт с ответом. Проба — после перезапуска владельцем: строка `owner answer … applied` в журнале и вкладка, продолжившая работу.
