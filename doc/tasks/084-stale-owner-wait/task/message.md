# Задание: устаревшее ожидание владельца не висит в «Ждут вас» и «застряла»

Заказчик: владелец репозитория `unitcraft/crew-harness` (он же принимает результат).
Репозиторий: `unitcraft/crew-harness`, ветка `main`. Дата задания: 2026-10-17.
Источник: слово владельца в чате оркестратора, 2026-10-17, к скриншоту панели Crew: панель показывает «Ждут вас: 2 · с 15:22», «? nova #94 прм»,
а нижняя строка — «ждут 0»; у задачи «Реестры контрактов…» (в реестре сдана, обе сессии сданы) висит «⚠ застряла с 10:48»; на рекомендацию оркестратора
(исчерпанная форма не считается ожиданием владельца, как только вкладка после неё снова работала или задала новую форму) — «по рекомендации».
Разбор оркестратора (чтение, 2026-10-17): состояние `owner` вкладке даёт `status.ts` по `pendingForms(session)[0]` — в том числе по форме, исчерпавшей повторы
(«без ответа, нужен владелец»); две такие формы с 15:22 (вкладки nova.integrator и nova.acceptor, вопрос о разрешении Phase 1) лежат до сих пор, хотя
вопрос снят, вкладки работали и задавали новые. Отметка «застряла» берётся из `obligationsOf(session)` (`o.stuck`, задача 043); у сданной задачи она
висит, хотя ждать нечего.

Задача полная: разбор, реализация, сдача. Быстрый путь. Основа — свежий `origin/main`.

## Чего хочет владелец

- «по рекомендации» (владелец, 2026-10-17, чат оркестратора) — на рекомендацию: исчерпанная форма не считается ожиданием владельца, как только вкладка
  после неё снова работала (получила письмо или начала новый ход) или задала новую форму; то же проверить для отметки «застряла» у сданной задачи.

## Что нужно

1. **Разбор (только чтение живых данных):** где состояние `owner` вкладки берётся из формы (`status.ts`, `form-wait.ts`: `pendingForms`, `exhausted`,
   `cancelled`, `repeats`); что сейчас значит «после формы вкладка работала» в записях (`forms/`, `cards/`, `status/`, сообщения сессии в базе — только
   чтение); откуда считаются «Ждут вас» в панели (`waitingRows`, `waitingLine`) и нижняя строка «ждут N» (`ход N · ждут N`) и почему они расходятся;
   откуда «⚠ застряла с 10:48» у задачи «Реестры контрактов…» (`obligationsOf`, `stuckAt`, задача 043): какое обязательство висит и почему не снято у сданной
   задачи. Показать на живых записях: какие формы и обязательства устарели по каждому правилу ниже.
2. **Правила:**
   - исчерпавшая повторы форма перестаёт давать вкладке состояние `owner` (и не входит в счёт «Ждут вас»), если после неё вкладка работала (новый ход
     после `exhausted`, письмо ей доставлено и принято) или у вкладки есть более новая форма; сама запись остаётся в `forms/` (история, `crew-answer`
     её видит как «без ответа после повторов»);
   - форма, ждущая ответа и не исчерпавшая повторы, — как сейчас (живое ожидание);
   - цикл на вопросе (078) — как сейчас;
   - отметка «застряла» у обязательства, чья задача сдана и принята (или обязательство выполнено другим путём), не показывается; что именно считать
     «снято» — по разбору, без догадок;
   - «Ждут вас» и нижняя строка «ждут N» считают одно и то же (один источник числа).
3. **Тесты:** красная проба до кода (источник: вкладка с исчерпанной формой, после которой был новый ход → не `owner`, счёт «Ждут вас» 0; исчерпанная форма без
   дальнейшей работы → остаётся `owner`; форма не исчерпана → остаётся; новая форма вместо старой → одна; сданная задача с висящим обязательством → без
   «застряла»; счёт панели равен нижней строке); полный `npm test` по 8 параллельно ([AGENTS.md](../../../../AGENTS.md), п. 9; если у другой задачи идёт
   полный прогон — суммарно не больше 4); golden — только изменившиеся ключи.
4. README плагина — абзац; пункт в `doc/open-questions.md` не нужен.
