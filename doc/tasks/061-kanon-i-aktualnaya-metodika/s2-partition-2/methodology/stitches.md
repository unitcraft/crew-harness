# Поставка, первый перенос и методическая сторона К1

## М1: самостоятельная трасса по первичному тексту

Источники: current `methodology.md:538–542` (полная :541, пять сегментов), `task-sessions.md:181–199,317–327`, Canon `process.md:175–197`. Предмет: `spec.md:38,52,58,72–90`, `spec-trace.md:125–146`, `analysis.md:30–36`, `method-delta.md:9–19,58–61,83–92`, `031-impact.md:94,120`. Прочитаны целиком указанные строки и соседние условия, не только найденное слово current.

П1. В-01 выбран, upstream проверен, В-02 пока открыт. Первый разрешённый перенос — README/process. По REQ-05 и AC-05 current создаётся в этом же шаге и называет оба раздела. Format не создаётся. **Допустимо**: это буквально разрешённая Canon-first/current-now ветвь, ожидание В-02 не препятствует указателю.

П2. Отличие от П1 только одно: current отсутствует до переноса format. **Недопустимо**: REQ-05 «Первый будущий шаг переноса ЛЮБОГО результата … создаёт current.md», AC-05 отдельно запрещает Canon-first/current-only-at-format. Spec88, trace141–144, analysis32 и impact120 не дают соседнего разрешения отложить указатель.

П3. Первый разрешённый перенос — только новый ADR/реестр/ссылка из входа. **Current нужен сразу**, даже если README-правило pin и format ещё впереди. Его создаёт именно первый фактический перенос, а не заранее выбранный вид результата; trace143 явно включает эту ветвь.

П4. Current уже создан при Canon. После В-02 согласованный format вводится единственным файлом и дополняет current. **Допустимо**, повторного указателя с нормой не возникает. Иначе говоря, format-шаг создаёт current только если сам оказался первым переносом (spec88/trace144).

П5. Не получен ответ по pin/переходу или возник drift, требующий нового решения. **Переноса нет**, текущие задачи и их pins не меняются. REQ-06/AC-06/07/В-01/01а запрещают скрытый автоматический переход. Назвать проверенный a449 «последним сейчас» без новой проверки нельзя; эта проверка использует его как заданный immutable input, не измеряет нынешний remote.

П6. После В-02 исполнитель редактирует approved spec/REQ/AC/trace 031 вместо нового пакета. **Недопустимо при любом варианте ворот**: REQ-05, AC-05/08, DNC-01, spec84/92 и trace135 отделяют новый destination от immutable input.

П7. В-02 ещё открыт, но исполнитель считает `src/runner_core/regulation/format.md` и четыре раздела уже утверждёнными. **Недопустимо**: spec76/84/86 прямо отмечает авторское предложение, точный файл создаётся будущим шагом после отдельного согласования; не выбран ни shape, ни version. Process185 действительно пока называет `opencode-plugin/`. Его адресное уточнение/новый ADR входят в В-02, не уже действующий override.

Это семь самостоятельных осмотренных исполнений внутри одной пробы порядка. Единственная мутация П1→П2 изолирует прежний М1; она не проверка runtime. Источник :192 не подменяется кодовым стражем process194–197: условие guard по наличию result не отменяет обязанности первого переноса.

## К1: методические входы, передаваемые С2к

Сопоставлены все C01–C60 с методическими обязанностями, а не только количество строк. C01–C16 различают номер/code, запись до request, atomic persist, append-only record, offset до launch, два offset после launch, время, именованную группу и время старта, stop-all перед retry/exit, meeting outcomes, result snapshot, tail текущего code, lock/identity cleanup, fallback/log. Ни один из этих атрибутов не исчезает только по причине внешнего mutable state. R89/152/159–160/574/590–608/681 прочитаны первично; существование точных API не установлено.

C17–C28 получают разные нормативные ограничения: целое keyword и знак; единственный start/отдельный launch; correction с текущим k и цитатой; correction не единица/не живость; startN и законное k>N; обоснованное завышенное N; исправление final тем же k/keyword; отсутствие/два start; пять stop kinds; артефакт важнее журнала; длина/инструмент/приоритет хвоста; неизвестный N не ноль. Изолирующая пара новой карты `0/2 → 1/2` не прежняя `0/2 → 1/1`.

C29–C35 различают свежий запуск, обычные две линзы/разделы/счёт/пробы, мнение до рекомендации, default-on/owner-off, другую семью если доступна, отдельный профиль и предел десяти сообщений/факты без мнения/след результата. Helpers-off не отключение opinion. C36–C45 отдельно покрывают порог замысла, его три поля/факты/спорно/след, неравенство согласованию, границу и её проверяемость, доказательство от базы/бремя автора/связь соседей/приватность, четыре поля OQ и сигнал >3, ответ без роста/условия выноса, одна попытка/откат/последний потолок, трассу неисполненной спецификации/следующее подтверждение, таблицу форм/судью/version batch, исключение норм самой проверки на 2–3 прогонах. Не обнаружен пропуск названного обязательного смысла в пользу общего слова «runtime».

C46–C50 покрывают обе части хвоста/инструмент/сессионный приоритет, уточнение перед old message, смысловой override подзадачи, первый current/immutable/одно место, язык принимающего без включения optional режима. C51–C60 сохраняют pin/hash/approval, независимость версий, coverage каждого смысла, owner gates, матрицу outcome, отдельные commit/push/send, recovery, внешний registry/013 и уже принятую Q5. Последние технические типы и ограничения — предмет полного 031-аудита С2к.

Независимый осмотр пяти N-контролей по R91/716: `start 0/2 → 1/2` с правдивой причиной — завершение; без причины — нет; причина с ложным артефактом — нет; `2/2` — завершение; `3/2` — завершение. Эти исходы касаются только названных условий, не всех свойств строки. Методическая трасса подтверждает C21/22; что именно допускает закрытый approved формат, устанавливает С2к по полному оригиналу.

Строгая граница: эта часть не аттестует все поля/типы/closed enums/nullability/domain/availability approved 031, не выводит schemaVersion из semantic conflict и не объявляет совместимость с 013. Полный approved 031 — С2к; собственное чтение здесь не его повтор. Передать сводной нужно именно этот join, не сумму двух complete.
