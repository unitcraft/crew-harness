# ADR-0004. Агенты — сменные драйверы на подписках вендоров

## Контекст

Один процесс OpenCode держит все сессии и зависает примерно на восьми параллельных задачах
([исследование](../../../../../../../publication/originals.zip) (историческая цель: `../../research/2026-10-06-many-agents.md`; точный оригинал — в архиве)). Владелец, 2026-10-07: «а у др ИИ агентов (codex, kim code,
z code и др) что есть, при использовании подписки, чтобы можно было выбрать унифицированное решение». Подписка Claude
разрешена только в немодифицированном Claude Code.

## Варианты

1. **Остаться в OpenCode** как хозяине всех сессий. + работает сейчас. − предел одного процесса.
2. **Свой цикл вызова модели по API.** + полный контроль, кеш, усилие. − платно по API, не подписка.
3. **Официальные CLI агентов, каждый своим процессом в своём дереве, на подписке вендора; наш сервис — координация;
   агенты подключаются к нему по MCP.** + масштаб — процесс на агента; подписки законно; агенты взаимозаменяемы.
   − у CLI разные возможности (хуки, поток событий, продолжение сессии); кешем и усилием на запрос не управлять.
4. **Готовый оркестратор** (Agent Orchestrator) как основа. + доска, драйверы 30+ агентов готовы. − приёмщика, замка
   вливания, очереди машины нет; его модель задач с нашей может спорить.

## Решение

Вариант 3. Драйвер агента умеет: запустить в дереве задачи с ролью и заданием, продолжить сессию, сказать «работает /
ждёт / закончил», остановить, передать картинку. Первыми — Claude Code, Codex CLI, Kimi Code; GLM — через Claude
Code. Идеи у Agent Orchestrator брать можно (владелец, 2026-10-07).

## Последствия

- \+ Сотни задач не упираются в один процесс; можно мешать агентов в одной задаче (исполнитель — один, приёмщик —
  другой).
- − Раздел раннера методики про кеш и усилие исполняется лишь частично (вопрос В-02 задачи 001).
- − Нужна сверка возможностей каждого CLI по официальной документации (этап замеров задачи 001).

## Границы

Учётные данные агентов сервис не хранит и не вводит: вход в агента делает владелец его собственным CLI.

Когда пересмотреть: вендор запретил работу своего CLI на подписке под внешней координацией или убрал безголовый режим;
или расход по API стал для владельца приемлемым.
