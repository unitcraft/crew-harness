# ADR-0012. Версия основы Канона и явный переход активных задач

## Контекст

Владелец, 2026-10-16, question «061 В-01 — версия»: «А: на старте (Recommended)»; question «061 В-01а — дрейф»: «А: сверить заново (Recommended)». Политика выбрана, конкретный пакет и pin активной 061 ещё не приняты. Плавающий main не должен тихо менять основание пройденных ворот.

## Варианты

1. **Плавающая main для всех задач.** + не нужен явный выбор версии. − невоспроизводимость проверок и неуполномоченный переход активных задач; противоречит выбранной политике.
2. **Версия на старте и явный переход.** + история сохраняет основание, полномочие проверяемо. − старые задачи остаются на старых версиях, drift требует сравнения и новых ворот.

## Проект решения

Вариант 2. Политика и полномочия — [process.md](../process.md), «Версия и переход»; конкретная основа Канона — [README](../README.md), «Параметры для раннера». Внешние нормы применяются по своим условиям, не импортируются пересказом. Статус этого проекта не является принятием.

## Последствия

- + Прежние pins, серии, журналы и утверждения сохраняют своё основание.
- − Перед переносом нужно повторно наблюдать upstream и target, сравнивать drift и получать решение по конкретным текстам.
- − Документирование нормы не создаёт её программного исполнения; условные схемы и производный код не являются runtime проекта.

## Границы

Не меняет принятые ADR, включая ADR-0011 и единый образец задания. Не даёт массового перехода задач, полномочия править approved031, возобновлять 045/013 или отменённую приёмку, создавать JSONC/каталог, менять код/config/модели/live. Первый любой перенос сопровождается current тем же шагом; current содержит только адреса. Номер 0012 — кандидат exact patch на наблюдённом target, не резерв: перед переносом проверить реестр, при коллизии остановиться.
