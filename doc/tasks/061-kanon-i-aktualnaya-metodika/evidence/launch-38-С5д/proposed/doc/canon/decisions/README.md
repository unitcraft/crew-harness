# Решения (ADR)

Правила — по методике ([methodology.md](https://github.com/unitcraft/ai-dev-methodology/blob/main/methodology.md), раздел
«Решение (ADR)»): решение пишется до кода; не меньше двух вариантов с плюсами и минусами; минусы в последствиях
обязательны; строка в реестре ниже. Принятое решение не переписывается: дрейф — датированной вставкой
(«**Уточнение, дата (кто).** …»), замена — новым решением со ссылкой, у старого статус «заменено ADR-NNNN».
Исключение — старт проекта: решения 0001–0007 сведены к итоговому виду без уточнений (владелец, 2026-10-07); прежние
редакции — в истории git.

## Шаблон

Файл `ADR-NNNN-<slug>.md`: номер — следующий по реестру, `<slug>` — латиницей. Разделы — по формату MADR, который
называет методика.

```markdown
Статус: принято, ГГГГ-ММ-ДД, кто          ← или «предложено», «заменено ADR-NNNN»

# ADR-NNNN. Решение одной фразой

## Контекст

Что случилось и почему надо выбирать. Слово владельца — цитатой с датой: «владелец, ГГГГ-ММ-ДД: «…»».

## Варианты

1. **Вариант.** + плюс. − минус.
2. **Вариант.** + плюс. − минус.

## Решение

Вариант N — что именно принято, без пересказа вариантов.

## Последствия

- \+ что становится лучше.
- − что теряем или что дороже — и как с этим живём (обязательно).

## Границы

Чего решение не касается и где кончается его действие.

Когда пересмотреть: измеримое событие, при котором решение пересматривается (необязательно).

## Связи

Необязательно; только связи, не перечень всего упомянутого в тексте:

- задача: [NNN — название](../../tasks/NNN-<slug>/);
- заменяет / уточняет / опирается на: [ADR-NNNN](ADR-NNNN-<slug>.md) — чем;
- источник слова владельца, если это не чат.
```

Читаются «Решение» и «Границы»: плюсы отвергнутых вариантов — не решение.
