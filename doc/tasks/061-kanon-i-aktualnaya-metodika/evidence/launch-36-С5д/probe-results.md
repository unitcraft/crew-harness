А/В — выполненные именованные ручные маршруты по первичным условиям; Б — исполнение read-only проверок с отрицательными входами. Cwd всех команд — корень назначенного дерева, не внешний клон.

```
PATH_PROBES 6/6; foreign/old writes 0; content mutant detected
```

Raw с конкретными старыми путями/hash — stdout/probes.json; повторный прогон должен идти в новом назначенном E, а не затирать этот raw output.

B1/B2 отвергли старые before/expected до открытия на запись; прежний SHA сверился. B3 вычислил foreign destination и отказал в памяти, файлов там не создавал. B4 прочитал Canon README: исходный hash совпал с before, мутант `data + '\nMUTANT\n'` дал иной hash при том же nameset; мутация только в памяти. B5 разрешил заранее перечисленный отсутствующий after.json (не создавал его в пробе). B6 отверг повторное использование уже существующего E; собственный ранний before и базовый gate доказывают, что E отсутствовал до первого создания.

Отдельная отрицательная находка реального исполнения: Python importlib до применения -B создал __pycache__/safe_io.cpython-314.pyc вне исходного nameset. Это FAIL чистоты output-контракта, не PASS безопасного ввода-вывода по одной искусственной пробе. Файл не удалялся и не выдаётся за разрешённый output; qualification раскрывает остаток. Последующие Python вызовы идут -B без новых pyc.

Команда: `python -B doc/tasks/061-kanon-i-aktualnaya-metodika/evidence/launch-36-С5д/safe_io.py search`.
Exit: 0. Дословный stdout:

```
SEARCH tracked positive; untracked 0 matches 0 fixture positive; rg False
```

Raw: stdout/search.json. `git grep -n -I` по Канон/current.md/Второе мнение исключил doc/tasks/** и нашёл действующий Canon: положительный контроль tracked состоялся. `git ls-files --others --exclude-standard -z` дал 0 untracked вне doc/tasks: для этого корпуса нет файлов, а не ложное доказательство отсутствия будущих дубликатов. Тот же Python-поиск на изолированном виртуальном корне E/probe-inputs нашёл active-control.md:2; fixture не попал в corpus проекта вне задач.

Реальный вызов `rg` попытались исполнить: FileNotFoundError, executable отсутствует; успешного rg invocation не было. Статус именно проверки через CLI rg: NOT VERIFIED (недоступная программа). Настройки не менялись, установка не выполнялась. Доступный заменяющий поиск — Python по точному untracked nameset с положительным fixture, явно не назван rg. Единственность будущего перенесённого Канона этим не утверждается: переноса ещё нет.
