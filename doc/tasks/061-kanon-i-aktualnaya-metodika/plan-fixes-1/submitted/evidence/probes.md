# Собственные пробы: контракт до запуска

Команда из корня своего дерева: `python doc/tasks/061-kanon-i-aktualnaya-metodika/plan-fixes-1/probe_plan.py`.
Входы: исправленный `plan.md`, raw `plan-before.md`, ранний `baseline.json`, Git HEAD/refs и
существующие notes `NEWs3-1/`. Разрешённый тестовый вывод — только новые `fixtures/` и `probe-results.json`
в этой папке. Скрипт использует exclusive create; повторный запуск не заменяет прежнюю сдачу.
Ожидаемые исходы закреплены в `expected.json` до invocation. Вывод и exit фиксируются отдельно.

P1 — собственная проба D0/override. Проверка реального текста подготовительного шага 3 и переноса 5;
положительный контроль — D0 без override и отсутствие записи Канона на шаге классификации;
отрицательный — буквальная старая команда «Внести проектное правило …» выявляется как дефект.
Дополнительный условный пример обоснованного отличия разрешает лишь будущий перенос после ворот/current.
Это модель планового условия, не нормативный runtime validator. Ручная смысловая проверка ниже обязательна.

P2 — пути и сохранность: реальные exists/hash старых notes, отсутствие старого coverage,
принадлежность всех старых before/expected раннему corpus; пример новых путей двух разных запусков
не совпадает с входными С3 notes и между собой. Реальная exclusive-запись test-only stale fixture и
отказ её перезаписать должны сохранить hash. Негативная модель исключения всего старого evidence
должна быть отвергнута. Будущие реальные `evidence/launch-…` не создаются.

P3 — оболочка плана: фактический Git commit/дата/ветка, первые три строки, разделы План/DoD/Требует утверждения,
семь последовательных пунктов, checkbox DoD; новый план принимается по этим полям, старый и мутация
«нет База» отвергаются. Это лёгкая проверка формы для следующего промпта С5, не запуск С5/runner.

P4 — регрессия: привязка к реальным пунктам 2/5/6, AC-05…08 и owner-decision границе;
проведение плановых условий на положительных и отрицательных входах: current немедленно,
drift независимо от scope, условная shape/три версии, переход после ворот только владельцем.
Именованная ручная проверка читает источник решения, а не доверяет функции модели.

Ни одна проба `s4-2/` не считается собственной. Это новые входы/код/выполнение данной С3п.
Тесты продукта, общий validator, runtime и тяжёлые прогоны не запускаются.

## Повторное воспроизведение без перезаписи

После первого успешного запуска команда с `--replay` повторяет те же assertions и отказ exclusive write
на уже существующей test-only fixture, сверяет actual с сохранённым результатом и ничего не перезаписывает:
`python doc/tasks/061-kanon-i-aktualnaya-metodika/plan-fixes-1/probe_plan.py --replay`.
Expected и результат первого запуска неизменны. Этот режим добавлен после первого прогона для независимого
воспроизведения без очистки/нового рабочего дерева; ожидается тот же stdout и exit 0.
