## REQ

REQ-01. После выбора и фиксации pin применять действующую основу по её собственным условиям, если явный project override/отключение не принят владельцем и не указан с источником. Для каждого изменённого anchor отдельно классифицировать: действующая норма; условия применимости; точный override либо его отсутствие и источник; открытый вопрос; степень доказанности практикой. `partial/not tested/unconfirmed` — квалификация практики/происхождения, сама по себе не отменяет норму. Внешнюю методику в Каноне не пересказывать: фиксировать только точное проектное отличие и причину.

REQ-02. Для каждого затронутого смысла указать old/current path/section/line, состояние нормы по REQ-01, override либо его отсутствие, применимость, evidence практики, точные code callsites либо явную границу отсутствия доказанной реализации и consequence. Отличать подзадачу методики — пункт плана без своих ворот (`task-sessions.md:108–110`) — от project override: отдельная нумеруемая работа со своей приёмкой (`process.md:151–160`); это смысловое отличие, не только расширение счёта. Second opinion, протокол сходимости и таблицу «Кто решает» квалифицировать отдельно от обязательности внешней нормы. Вопрос методики и отсутствие реализации норму не отменяют; отключение помощников не равно отключению second opinion.

REQ-05. После утверждения спецификации, плана и соответствующих ворот переноса внести политику В-01/В-01а в `doc/canon/README.md` («Параметры для раннера», строка версии/источника) и `doc/canon/process.md` («Основа», отдельное правило перехода). В process оставить только обоснованные точные проектные отличия с причиной и источником; принятые границы оформить новым ADR с реестром `doc/canon/decisions/README.md` и входной ссылкой `doc/canon/README.md`. `AGENTS.md` менять лишь при доказанном воздействии на конкретное правило репозитория и отдельном разрешении. Для каждой части delta указать адрес и проверку действующего текста. Первый любой реальный перенос результата 061, даже только README/process/ADR, немедленно тем же шагом создаёт `current.md` этой задачи; каждый последующий перенос дополняет указатель. В current — только адреса уже действующих результатов и пометка об истории, без текста нормы.

REQ-06. «Последнюю» методику проверять относительно явно названного upstream `https://github.com/unitcraft/ai-dev-methodology`, `refs/heads/main`, на момент ворот и непосредственно перед внесением. Записать момент, неизменяемый commit и перечень применимых файлов/хешей. Любой drift после проверки останавливает перенос до нового сравнения и повторных ворот, без условия «если значимый» и без автоматического перехода. Активные задачи переводить лишь по В-01/AC-07 с сохранением их старых pins/журналов/истории; ранее проверенный commit не объявлять последним без свежей проверки.
