## Формат 031: три оси, не runtime PASS

Crosswalk разделяет данные/refs, нормативную семантику REQ/AC/пар и новые поля/shape. Конфликт `готово:` между approved:259/309/540 и current R88 доказан первичными текстами; grammar ref не отменяет прямые REQ/AC. Нужна отдельно утверждаемая семантическая редакция для покрытия current, даже если shape прежняя.

Изолирующая N-пара сохраняет startN и финальную дробь: `0/2 → 1/2` с правдивым обоснованием против той же дроби без него. `0/2 → 1/1` не изолирует исключение. Новый JSON key gap не доказан; это не достаточность или совместимость. Versions/reader проверяются отдельно по В-02; ни автоматического повышения, ни автоматического сохранения schemaVersion нет.

Mutable launches[] находятся снаружи JSONC, но REQ-27/29 approved:325/329 требуют декларации предусмотренных намерений: регистрация до request, offsets/snapshot, stop-all перед retry, process group/start time, lock/cleanup. Поатрибутный маршрут graph/actions/events/routes/typed bindings нельзя заменить общей внешней границей. Для каждой операции неизвестны точные signatures/domain/nullability/availability.

Обычные линзы С2 выражаются через prompt/document, не meeting-only lens.sessionId. ProfileValue имеет ровно tier/effort/reasoning/budget, без family. Свежесть и другая семья требуют декларативной политики и внешнего селектора, а не выдуманного API.

## Блокеры 045 и 013

**Первый блокер: протокол плана 045.** Нужен per-anchor/per-DNC checklist/test. Каждая запись: точный источник/указатель, входы, проверка, target или reason пустого результата, expected, evidence/команда, ответ независимого reviewer `PASS`/`NOT VERIFIED` и причина. План:136–139,156–164 и первичное описание дефекта `plan-review-4.md`:14–16 задают предмет будущей правки 045, не исправление Канона.

Проверить все девять DNC: ворота до артефактов; защищённые inputs/Canon/config/main; отсутствие runtime/validator/git/live/delete/restart; 013 read-only и без новых заказов; отсутствие ложной совместимости; отсутствие выдуманного registry; destination/tools; отсутствие новых дочерних задач; privacy и заявления о live. Для DNC-08 проверяются обе части: история создания/сессий/задач И состав/имена папок. Одно не заменяет другое. 045 этой сессией не правится.

**Второй блокер: содержательная полнота каталога.** Путь В-03/В-05 выбран владельцем: существующая 045 и есть каталог, без новых целей, отдельной задачи или эпика сейчас. Эпик допустим после утверждения плана, если объём не помещается. План:192–212 фиксирует решение, не готовый продукт.

По пересланному ответу Методики от 2026-10-16 она не определяет готовый typed registry. Десять видов имеют только смысловой исходный текст: gate, outcome, document-status, unit, event, profile-stage, profile-value, role, prompt, scenario. Их сначала утверждают по закреплённому commit. Шесть видов predicate, route-trigger, action, effect, grammar, context проектируются в 045 как предложения «проект реализатора, не источник методики»; отдельные ворота владельца — следующие ворота 045. До решения они не включаются в данные, которые читает 013. Unknown блокирует полноту. Старый срок 2026-10-23 снят, open-questions #4 закрыт, поиск готового API не открыт заново. Дословный источник и происхождение ответа — `owner-gate-decisions.md`, В-03/В-05; пересланный отрицательный ответ не собственный повторный аудит и не глобальное доказательство отсутствия каталогов.

По каждому ID будущего комплекта всё ещё требуются version/digest/provenance, predicate args/result/outcomes, unit numerator/denominator, route-trigger gate→outcome, event/action/effect payload/boundary/confirmation/result, prompt source/hash/substitutions, context schema/domain/availability и остальные typed signatures. Выбор пути не утверждает эти данные, десять видов, шесть предложений или план 045 и не исправляет первый блокер. ОТВ-01/02 сохраняются: один комплект в `src/runner_core/regulation/`, 013 read-only без compatibility claim, проверки разовые.

Spec:457–512 требует разработки 14 предметов, версии/hash и отдельного утверждения ДО кода; proposed runner-regulation.md не утверждённый API. Совместимость 013 и полный whitelist не доказаны. Source/status/hashes и глубина чтения названы в описи; унаследованные ranges не присваиваются текущему автору.

## Результат, current и сохранность

Canon README/«Параметры для раннера» и process/«Основа» получают выбранное основание; process/«Отличия» и отдельное правило перехода — согласованные overrides и переход. Новый ADR/реестр/входная ссылка — только решения. AGENTS меняется лишь при доказанном воздействии на правила репозитория.

Первый будущий перенос **любого** результата 061, включая README/process/ADR, создаёт current с этим местом; каждый следующий дополняет его. Ожидание содержательных ворот формата не откладывает указатель внесённого Канона. Canon-first/current сразу → format-later/current дополнить допустим; current только при format недопустим.

Место новой редакции 031 выбрано в В-02: `src/runner_core/regulation/format.md`, разделы «Контракт формата», «Версии и совместимость», «Приёмочные пары», «Источники и покрытие». Будущий шаг «Ввести новую редакцию формата» после содержательных ворот создаёт самодостаточную норму, проверяет пары и дополняет current. Approved 031 не правится ни до, ни после ворот. Process:185 пока называет opencode-plugin; адресное уточнение и новый ADR выбраны как направление, не внесены. Отсутствие reader не разрешает разнести комплект.

Latest проверяется по названному upstream на воротах и перед внесением, с commit/hashes. Drift между проверкой и внесением останавливает перенос, требует нового delta и повторных ворот. Сейчас remote latest не измерялся; прежние pin/review/серии не переписываются. Canon/current/format/JSONC/schema/registry/реализация не создаются. Текущая поставка — авторская актуализация, не утверждение спецификации и не полная сдача задачи.
