Оценка многомерная: в каждой строке указан непустой набор категорий, выделенных жирным в колонке вердикта, с привязкой к конкретным частям требования. «Уже выражается» может сочетаться с «нужны только данные» для формы и наполнения соответственно; это не вывод о достаточности всей строки. «Нужны только данные» не заменяет «семантический конфликт» для одной и той же декларации. «Нужен формат» требует собственного доказательства missing-field gap. Наличие semantic conflict не доказывает shape gap; правила versions/compatibility проверяются отдельно.

## Ограничение вывода

Три независимые оси оценки: новые данные/refs; изменения нормативной семантики/REQ/AC/приёмочных пар (возможны при прежней JSON shape); новые поля/shape. Никакая из этих осей не заменяет две другие. Отсутствие missing-field gap не исключает семантической редакции. Решение о schemaVersion требует отдельной проверки versions/compatibility и ворот, а не следует автоматически из наличия или отсутствия нового поля.

Таблица описывает выражаемость нормативных деклараций и отделяет её от runtime-гарантий. Проверка полей сверена по REQ-11, 12–20, 23–35 approved spec. Обязательный атрибут без поля в обследованных категориях не доказан, но семантическая достаточность не следует из этого: прямые ограничения progress конфликтуют с текущей нормой. Если 031 должен покрыть current, требуется явное предложение изменения REQ/AC и приёмочных пар; смена grammar ref этого не делает. После отдельной оценки может быть достаточно прежней shape, либо понадобится новая shape/version. Применимые правила versioning/compatibility требуется установить до решения; автоматически обещать сохранение или смену `schemaVersion` нельзя. Эта С1 не меняет approved 031 и не создаёт новую действующую схему. Неподтверждённые external contracts — отдельные неизвестности.
