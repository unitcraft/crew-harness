## Нормализация и происхождение хешей

`read_git.py` принимает locator только аргументом, сохраняет commit/path/range/bytes/SHA и момент, **не payload** внешних blobs. Gitshow читает raw LF: CRLF=0 у названных blobs. Разбиение длинных строк на `n.part` — только показ, не новая нумерация источника и не правка bytes. Shell previews усекались по общему размеру, поэтому полные managed outputs дочитаны read по диапазонам; внешние абсолютные locators этих managed файлов не публикуются. Первоначальные read длинных diff M541/M720 имели ограничение2000знаков/строку: полный M541 прочитан wrapped Gitshow530–545, M720 wrapped700–722/653–740. Usages/counts не принимаются за чтение.

Algorithm Git LF:51475bytes, `ff55cf734d3fe816178f7c46718cd4e8322b73cac8d64efdf955b166dc079e96`; искусственная замена LF→CRLF: `8a0004dbfd8b6d8f9889abeb8ee02f3bf87ea9af6309ca2a21b8cfdca9eead8d`. Это два различных представления, не два source commits. Checkout CRLF и Git LF не смешиваются: source-fingerprints — Git; before/after/submitted — raw checkout.
