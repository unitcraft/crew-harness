## 2. Ключ подключений фрагментов в дереве (продуктовый)

Формат от дерева требует одного: чтобы по 1б(м) можно было восстановить строку подключения — имя фрагмента и значения всех параметров. Ключ не нормативен (ответ Методики оркестратору, 2026-10-20: «ключ продуктовый, форму выбираешь ты»; совет: верхний ключ `fragments`, элементы `{name, args}`).

```json
"fragments": [
  { "name": "Pause",
    "args": {
      "halt_word":       { "op": "lit",  "value": "halt" },
      "halt_code":       { "op": "lit",  "value": "pause_halt" },
      "nested":          { "op": "list", "items": [ { "op": "lit", "value": "agent_step" } ] },
      "cancel_requests": { "op": "lit",  "value": "mechanics" },
      "reenter":         { "op": "lit",  "value": "nothing" },
      "write_right":     { "op": "lit",  "value": "сессия ничего не пишет" } } } ]
```

- Верхний ключ `fragments` стоит после `includes`, до `initial`. Порядок элементов — порядок строк раздела «Подключения».
- `name` — ключ фрагмента по таблице слов (`Pause`), на любом языке файла один; ключи `args` — латинские ключи параметров: `halt_word`, `halt_code`, `nested`, `cancel_requests`, `reenter`, `write_right`. Значения — выражения дерева: слово ворот — литерал с латинским именем слова, код и примечание — текстовые литералы, `nested` — список литералов с именами машин реестра, слова поведения — литералы с латинскими ключами таблицы слов (`mechanics`, `without_return_to_send`, `stop_transport_turn`; `nothing`, `requests_from_to_send`).
- Фрагмент в дереве остаётся подставленным: его данные, общие события, состояние `Pause` и сигналы протокола лежат в обычных ключах, интерпретатор не меняется. Обратный генератор по имени фрагмента знает, сколько данных, общих событий, состояний и сигналов он внёс, и не пишет их как собственные.
- Декодер проверяет: имя известно, фрагмент подключён один раз, названы все шесть аргументов и никаких других, слова поведения из перечня.

## 3. Расхождения со спецификацией и вопросы Методике

1. **Ключ `fragments`** — ответ получен: продуктовый; остаётся вопрос, нормативен ли он для круга между продуктами-потребителями.
2. **Текст фрагмента и канонический вид.** Фрагмент «Пауза» зовёт состояние `ОСТАНОВЛЕНО` и сторону `усиленный`; канонический файл пишет заголовок состояния латинским именем без скобок, а сторону без слова словаря — тоже латиницей, поэтому подключённый по строке фрагмент их не находил. Наше решение: синонимы словаря у заголовков состояний и строка `party усиленный enhanced` в `names_format.tsv`. Вопрос: как фрагмент должен называть состояние и сторону машины при каноническом виде (раздел 9 это не говорит).
3. **Таблица кодов журнала продукта и «Машина».** Столбец «Машина» у продукта — перечень машин продукта и «движок продукта»; методика такого значения не задаёт.
4. **Таблица «по роли»** — запись реестра хозяина; типы ролей для `parse_agent_reply` взяты из `standard_types()`.
5. **Поле входа `источник_запуска`** по словарю v10 — `launch_source`; сценарии запуска сессии переведены на этот ключ.
6. **Перевод строки в конце файла дерева.** `portolan compile -o` его дописывает, дерево в репозитории хранится без него (тесты сравнивают байты); после пересборки конец срезан.

## 4. Что ломает прежние файлы

- Каждая машина, фрагмент и файл определений: `format: 2.11` → `2.12`; хеши подключений пересчитаны.
- Машины, вызывающие «Шаг агента»: тип `StepInput` исчезает; в «Входе» обращения — семь полей и профиль столбцом «Стороны».
- Все сценарии «Шага агента» и пар: стартовый `input` — восемь плоских полей вместо записи `agent_request`; ожидаемые данные прежние.
- Код журнала, которого нет ни в таблице методики, ни в таблице продукта, — ошибка проверки (только у реестра, заполненного таблицами).
- Значение разбора не того типа — дефект хозяина, а не возврат формы.
- Обращение без строки `Вход:` или с пустым `Вход:` — ошибка.
