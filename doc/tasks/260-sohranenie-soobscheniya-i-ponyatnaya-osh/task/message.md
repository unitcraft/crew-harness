# Задание: Сохранение сообщения и понятная ошибка прямо в чате Crew

Заказчик: crew-harness.integrator; задание собрано плагином из полей crew_spawn.
Репозиторий: проект crew-harness, ветка main. Дата задания: 2026-10-30.
Источник: слова владельца с датой — раздел «Чего хочет владелец».

## Чего хочет владелец

«делай супер быстро» — согласие на предложенное исправление исчезновения сообщения и показ ошибки прямо в чате (владелец, 2026-10-30, текущий чат).

## Что нужно

1. В отдельной новой сессии/дереве расследовать и исправить инцидент пульта 8100: пользователь отправил сообщение, оно исчезло, у сессии только надпись «ошибка» без причины. Сначала доказательное воспроизведение и красные тесты. Не ограничиваться косметикой. Сохранить сообщение/черновик при ошибке доставки или обработки; показывать непосредственно рядом с ним в чате заметный красный блок с иконкой, понятной причиной и следующим действием. Различать неотправленное сообщение и уже принятое сервером, но не обработанное агентом. Кнопки «Повторить» и «Вернуть в поле ввода» с безопасным поведением; технические детали раскрываются и копируются, без секретов. Ошибка и сообщение сохраняются после reload/reconnect. Причину конкретного инцидента определить по доступным read-only журналам, без повторной отправки сообщения пользователя и без изменения его сессии.

## Критерии приёмки

1. Красные тесты воспроизводят исчезновение сообщения и отсутствие причины; причина подтверждена или неизвестность явно указана. 2. Ошибки сети, HTTP, запуска/ответа агента отображаются в чате с корректной связью с сообщением; серверное принятие не выдаётся за неотправку. 3. Retry не создаёт дубликатов при потерянном подтверждении/двойном клике/reconnect; если невозможно безопасно повторить — честный статус и явное действие владельца. 4. Возврат текста в composer не затирает существующий черновик молча; сообщение и ошибка переживают reload, поздний ответ корректно меняет статус. 5. Красный цвет дополнен иконкой/текстом, доступная индикация; секреты из backend/provider ошибок редактируются, подробности раскрываются/копируются безопасно. 6. Полные наборы затронутых частей и стражи через machine queue, независимая приёмка; отчёт SHA, точные тесты, требования применения/перезапуска.

## Результат и куда он попадает

Изолированное исправление сообщения/ошибки UI и при необходимости backend с регрессионными тестами для независимой приёмки и отдельной согласованной доставки.
