## Находки

1. REQ-38 после правки захода 26 не согласован с REQ-14 по хвосту за строкой-ножницами.
   - Что не так: REQ-14 (317–319) судит хвост за строкой-ножницами при `-F` и `-m` только без режима с diff (при `-v` и
     `commit.verbose` git хвост обрезает — проба 3, пункт D; для `-m` — проба 5 захода 26). REQ-38 (518–519) говорит безусловно: «а также хвост
     за строкой-ножницами при -F»; про `-m` в этой фразе ничего нет. Буквально: `git commit -v -F файл` с именем в хвосте
     REQ-38 краснит, REQ-14 нет. Правка захода 26 («Изменения захода 26», п.2) исправила только REQ-14; в находке 2
     захода 26 REQ-38 был назван вторым местом.
   - Цитата: «а также хвост за строкой-ножницами при `-F`» (REQ-38).
   - Место в spec.md: REQ-38 (518–519).
   - критичность: поверхностная. Причина: REQ-38 открывается оговоркой «ВСЕ строки сообщения в смысле REQ-14 (то, что git
     сохранит в историю)», и именно ей руководствуется С3; расхождение даёт только лишнюю строгость на файле с буквальной
     строкой-ножницами при `-F` (штатные сообщения агента такой строки не содержат), законная команда не отклоняется,
     пропуска нарушения нет, сценарий AC-32 (б) («без режима с diff») верен и от этого оборота не зависит.
   - уровень: требования

2. AC-09 не отсылает к определению «что судится» и буквально шире REQ-14 для не-ASCII.
   - Что не так: AC-09 (772–773): «с не-ASCII вне строк цитаты (по О-05) … хук `commit-msg` отклоняет коммит». Проба с
     кириллицей в строке `#` в режиме редактора по этой фразе красная, по REQ-14 и по AC-32 (946) проходит (git строку
     убирает). Пробы режимов REQ-14 записаны только в AC-32 (сценарий о приватных данных); из AC-09 к ним ссылки нет, а
     по таблице покрытия M-21 ведёт к «REQ-14; ответ О-05 → AC-09».
   - Цитата: «с не-ASCII вне строк цитаты (по О-05)» (AC-09).
   - Место в spec.md: AC-09 (772–780); AC-32 (945–946).
   - критичность: поверхностная. Причина: AC-09 доказывает REQ-13…REQ-15 в целом, а что именно считается сообщением,
     определяет REQ-14 (первая фраза), на который AC-09 опирается («по О-05» и «сообщение коммита»); режимные пробы
     есть и проверяемы в AC-32; ни требование, ни число проб, ни то, что хук отклоняет или пропускает, от оборота не
     меняется.

## Рассмотрено, находкой не считаю

- Признак `-v`, заданный флагом командной строки, при `-F` и `-m` хуку `commit-msg` не виден: окружение хука при обоих
  режимах одно (`GIT_EDITOR=:`), а файл при `-F -v` со строкой-ножницами и при `-F` без `-v` устроен одинаково (проба 3,
  пункты D и E; видна только настройка `commit.verbose`). Поэтому часть обещания REQ-14/AC-32 («при `-F -v` хвост не
  судится») механизм не различит и будет судить хвост строже. Это механизм С3 (Д-11), а не поведение, которое нельзя
  описать; затрагивает только файл с буквальной строкой-ножницами, которого в штатной работе нет. Для редактора
  различать нечего: git кладёт diff в файл только в режиме редактора (проба 3, пункт C — при `-F -v` diff в файл не
  записан).
- `Signed-off-by` при `-v -s -F` и строке-ножницами в файле git ставит перед строкой-ножницами (проба 3, пункт D):
  подпись не пропадает вместе с хвостом, REQ-13 в этом режиме выполним.
- Режим «редактор или нет» хуку доступен через `GIT_EDITOR` (проба 3: `:` при `-F`, `-m` и `--amend --no-edit`, путь к
  редактору при редакторе). Механизм — дело С3; REQ-37 («режим — вход стража») выполнима обёрткой хука.
- REQ-14 судит строки `#` в режиме `-F`, тогда как О-05 говорит «комментарии git». Читаю согласованно: комментарий git —
  то, что git убирает; при `-F` строка `#` остаётся текстом истории (проба 3, пункт A). Сужения слова владельца по сути
  нет: исключение «комментарии» сохранено там, где git их убирает.
- Исключения для `core.commentChar`, `commit.cleanup`, `--cleanup=strip` при `-F` в тексте нет; при общем принципе («то,
  что git сохранит») поведение определено, оборот «при `-F` и `-m` — как есть» ошибается только в сторону строже.
- `pre-push` и CI судят уже сохранённое сообщение целиком (кроме строк `>` для не-ASCII), различать редактор и `-F` им не
  нужно; результат согласован с `commit-msg` (убранное git'ом в историю не попадает).
- Класс законных команд `git commit -v …` (флаги `-v`, `--verbose`) AC-10 строкой не называет, но REQ-16 запрещает только
  перечисленное; `git commit -v -s -F <файл> --only -- <файл>` проходит по тексту (14 строк AC-10 с `git commit`, ни одна
  не ограничивает `-v`). Целого непокрытого класса нет.
- Прочее, отмеченное в заходах 25–26 как «Рассмотрено», не изменилось: AC-03 против REQ-05; форма
  `git commit -s -m "$(cat <<'EOF' … EOF)" --only -- <файл>`; слова из запретов внутри имён веток; сырые правила хука;
  запреты хука, которых нет в AGENTS.md (шортлист владельца и решение В9); незакоммиченные правки задачи 001 и `core.ts`
  в рабочей копии `main` (не предмет DNC-01); имя автора ASCII; таблица «What is here»; уровень F «AC-01…AC-21»;
  пометка «механизм» у п.15.
