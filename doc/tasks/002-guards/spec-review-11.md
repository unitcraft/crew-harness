## Находки

1. Хук `pre-merge-commit` не останавливает коммит слияния. Git сам подсказывает, как его создать, и `pre-push` такой
   коммит не ловит. REQ-17 (строки 363–364): «хук `pre-merge-commit` отказывает в коммите слияния». AC-11 (строка 746):
   «`git merge --no-ff` останавливает хук `pre-merge-commit`». Замер (проба 4), установлены `merge.ff only` и хук,
   который отказывает:
   - `git merge <ветка>` на разошедшихся ветках: git отказывает и советует `git merge --no-ff` или `git rebase`;
   - `git merge --no-ff <ветка>`: хук отказывает, но git оставляет слияние незавершённым и пишет «Not committing
     merge; use 'git commit' to complete the merge.»;
   - `git commit --no-edit`, как советует git: вызывается `pre-commit`, а не `pre-merge-commit`. Создан коммит с двумя
     родителями, код 0.

   Каждый шаг повторяет подсказку самого git: так поступит человек и агент вне Claude Code. Это Codex CLI и Kimi Code,
   для них по Н-09 правило `--ff-only` держат именно хуки git. Хук агента пропускает и `git pull --no-ff`: запрет в
   REQ-16 стоит только на `git merge` без `--ff-only`. Опубликовать такой коммит ничто не мешает:
   - `pre-push` (REQ-18) судит только fast-forward, удаление и создание ветки, а коммит слияния поверх удалённой
     головы — fast-forward;
   - защита ветки (REQ-18, AC-12) — только от силового пуша и удаления;
   - CI (REQ-19, REQ-29) проверяет подпись и стражи, родителей не считает.

   Слов `MERGE_HEAD`, «linear», «двух родителей» в spec.md нет (проба 1). AC-10 (строка 731) прямо пропускает
   «`git commit` при идущем слиянии». Это верно для правила о перечне файлов, но больше ничто в spec.md этот коммит не
   судит. При правиле `--ff-only` идущее слияние появляется только после `--no-ff` или `--no-commit`, то есть законного
   случая для такого коммита в проекте нет.
   - Материал: msg п.4 «слияние только `--ff-only`» (M-23); msg «Решения»: `merge.ff only` (M-33); AG п.3 «в `main` —
     только `git merge --ff-only`»; О-01 (`merge.ff only` на весь репозиторий, ветка обновляется ребейзом); meth §20
     «то же свойство другим синтаксисом — красный».
   - Место в spec.md: REQ-17, строки 363–364; REQ-18, строки 376–387; AC-11, строки 745–747; AC-12, строки 751–758;
     Н-09, строки 231–234.
   - Что сделать. Записать, что коммит слияния запрещён в любой форме:
     - хук `pre-commit` (или `commit-msg`) отказывает, когда идёт слияние (`MERGE_HEAD`);
     - `pre-push` отказывает, если в коммитах пуша есть коммит с двумя и более родителями;
     - по желанию — защита ветки с требованием линейной истории, по слову владельца (О-04, К-09).

     В AC-11 добавить пробу: `git merge --no-ff` → отказ `pre-merge-commit` → `git commit` → отказ. В AC-12 добавить
     пробу: пуш коммита слияния, который сделан с `--no-verify` или в клоне без хуков, — отказ. Прошлые 4 коммита
     слияния (Ф-04) в диапазон пуша не входят (DNC-05).
   - критичность: существенная (требование M-23 и сценарий AC-11; нарушение доходит до публикации)
   - уровень: требования
