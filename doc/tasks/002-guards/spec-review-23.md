## Находки

1. Охват стража текста (REQ-09…REQ-12) определён через «бинарный по содержимому», а git так называет именно файл с байтом
   NUL и файл в UTF-16, то есть самый явный управляющий байт и самый частый след неверной кодировки на Windows выводят
   файл из-под стража.
   - Что не так: REQ-09 (строки 295–301): охват — «все отслеживаемые файлы, которые git считает текстовыми (не бинарные по
     содержимому или атрибуту)»; AC-08 (745–748): «бинарный файл не судится». Для git «бинарный по содержимому» — это
     файл с байтом NUL в начале содержимого (так считает и `diff`, и `git ls-files --eol`); эвристика `eol` дополнительно
     считает бинарным маленький файл с высокой долей непечатаемых байтов. Проба 4 в одноразовом репозитории с `.gitattributes`
     `* text=auto eol=lf`: файл с NUL — `i/-text`, `--numstat` даёт `- -`; тот же результат у файла UTF-16 с BOM
     (так выглядит вывод, перенаправленный в файл в PowerShell 5.1, на котором spec.md сама строит хук — REQ-16, Ф-16);
     маленький файл с одним байтом 0x01 — `i/-text` по `git ls-files --eol`, но «текст» по `--numstat`; большой файл с
     одним ESC — текст. Итог: байт NUL (управляющий байт по REQ-09), UTF-16 с BOM (REQ-11) и, смотря какое из двух
     определений git возьмёт реализация, малый файл-фикстура с управляющим байтом не судятся — зелёный страж на файле,
     который сам называет msg п.3. Донор A сверен: A: guards/check-no-control-chars.sh ищет `[\x00-\x08\x0b\x0c\x0e-\x1f]`
     (проба 5), то есть NUL ловит; перенос с формулировкой «как git» его потерял (заход 3, находка 4 заменил список
     расширений определением git, и это определение оказалось слишком широким). Бинарных файлов в репозитории нет (проба 6:
     108 из 108 `i/lf`), поэтому ничего законного это не защищает.
   - Цитата: «все отслеживаемые файлы, которые git считает текстовыми (не бинарные по содержимому или атрибуту)» (REQ-09);
     «бинарный файл не судится» (AC-08); «управляющие байты, кракозябры, BOM, смешанные концы строк» (msg п.3).
   - Место в spec.md: REQ-09 (295–301), REQ-11 (304), Д-06 (684–687), AC-08 (745–748).
   - Что сделать: бинарным считать только файл с атрибутом `binary`, `-text` или `-diff` (в самотесте атрибут задаёт
     временный репозиторий, `.gitattributes` проекта не меняется, DNC-06); байт NUL и файл UTF-16 с BOM в файле без такого
     атрибута — нарушение (красный); в AC-08 добавить две красные пробы (NUL; UTF-16 с BOM) и одну зелёную (файл с
     атрибутом `-text` не судится).
   - критичность: существенная. Меняет то, что отклоняется и что проходит (требование REQ-09 и сценарий AC-08).
   - уровень: требования
