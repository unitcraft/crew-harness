## Находки

1. Запрет обхода хуков (REQ-16, AC-10) задан перечнем написаний, а git принимает то же свойство в других: сокращение
   длинного флага, слитные короткие флаги, ключ настройки в другом регистре, настройку из переменных окружения. Каждое
   из них в одноразовом репозитории снимает красный хук `pre-commit` (проба 3).
   - Материал: meth §20 «Четыре пробы каждого стража»: «то же свойство другим синтаксисом — красный»; meth §19:
     «Находка стража исправляется переписыванием текста, а не обходом»; msg п.1 и «Что есть сейчас» («История уже
     переписывалась один раз»); spec-review-6, находка 2.
   - Место в spec.md:
     - REQ-16: «`--no-verify` у `git commit`, `git merge`, `git push`; короткий `-n` у `git commit` … запись или снятие
       `core.hooksPath` (`git config`, `git -c core.hooksPath=…`)»;
     - AC-10: пробы только в этих написаниях — `git commit --no-verify …`, `git commit -n …`,
       `git -c core.hooksPath=<путь> commit …`;
     - REQ-26 требует пробу «другим синтаксисом» у каждого стража, но к хуку агента это не применено (см. находку 2).
   - Факт (проба 3, git 2.56): хук снят и коммит прошёл (код 0) при `--no-verif` (сокращение длинного флага —
     git принимает однозначный префикс), `-sn` и `-nm` (слитные короткие флаги), `git -c core.hookspath=…` (ключи
     настройки без учёта регистра), `GIT_CONFIG_COUNT=1 GIT_CONFIG_KEY_0=core.hooksPath GIT_CONFIG_VALUE_0=…` и
     `GIT_CONFIG_PARAMETERS=…` префиксом команды; неоднозначное `--no-ver` — отказ git с кодом 129. В spec.md слов
     «сокращ», `hookspath`, `GIT_CONFIG` — 0 строк (проба 1). Донор A ловит слитные короткие флаги у силового пуша
     (`-[A-Za-z]*f[A-Za-z]*`), но не сокращения длинных (`\s--force(-with-lease|-if-includes)?\b`) — тот же класс у
     правила силового пуша REQ-16 (`--forc` не прогонялось, вывод по разбору опций git).
   - Следствие: агент, у которого коммит покраснел, получает отказ на `--no-verify` и повторяет с `-sn` или
     `--no-verif` — путь машины уходит в ветку, первый пуш делает его публичным до красного CI. Правило, добавленное
     ради закрытия находки 2 захода 6, закрывает только написания из самой находки; самотест по AC-10 будет зелёным
     на хуке, который этот обход пропускает.
   - Что сделать: в REQ-16 задать правило свойством, а не написанием: флаги разбираются как у git — однозначный
     префикс длинного флага (`--no-verify`, `--force`, `--force-with-lease`), короткий флаг внутри слитной группы
     (`-n` у `commit`, `-f` у `push`); ключ `core.hooksPath` и ключ ожидаемого адреса — без учёта регистра; отказ на
     префикс окружения `GIT_CONFIG_COUNT`/`GIT_CONFIG_KEY_*`/`GIT_CONFIG_VALUE_*` и `GIT_CONFIG_PARAMETERS` у команды git.
     В AC-10 — проба на каждую форму (`--no-verif`, `-sn`, `core.hookspath`, оба вида переменных, `--forc`).
   - критичность: существенная
