## Находки

1. REQ-14 и REQ-38 приписывают режиму редактора обрезание по строке-ножницам независимо от `-v`; git так не делает.
   - Что не так: REQ-14 (315–317): «в режиме редактора — сообщение после того, как git убрал комментарии (строки с `#`)
     и хвост за строкой-ножницами (в том числе diff индекса при `git commit -v` или `commit.verbose`)»; REQ-38 (520):
     «в режиме редактора судится сообщение после очистки git». Проба 3 (пункт A): редактор без `-v`, файл содержит строку
     `# ------------------------ >8 ------------------------` и после неё слово-метку — git убрал строки `#`, но
     строку-ножницы с хвостом СОХРАНИЛ (очистка редактора по умолчанию обрезает по ножницам только при `-v`/
     `commit.verbose`, `--cleanup=scissors`). По тексту хвост в редакторе без `-v` не судится, а в истории он есть.
     Правильная формула: хвост за строкой-ножницами не судится только там, где его убирает git (режим с diff — `-v`,
     `commit.verbose`; при `-F` и `-m` это то же условие), иначе судится.
   - Цитата: «в режиме редактора — сообщение после того, как git убрал комментарии (строки с `#`) и хвост за
     строкой-ножницами» (REQ-14).
   - Место в spec.md: REQ-14 (315–317); REQ-38 (520); AC-32 (943, 945) пробы режима редактора от оборота не зависят.
   - критичность: поверхностная. Причина: ошибка возможна только для строки-ножниц, набранной в редакторе руками без
     `-v` (штатные сообщения агента идут через `-F`, ножницы в них не встречаются; в режиме редактора с `-v` перечень
     верен); определение, на которое опираются REQ-13, REQ-15, REQ-38, AC-09, AC-32, — «то, что git сохранит в историю»
     — стоит первым и верно, оборот с режимом редактора лишь пример к нему; законная команда не отклоняется, а
     пропуск — это намеренно набранная строка-ножницы, то есть обход, а не штатная работа; `pre-push` и CI судят уже
     сохранённое сообщение (REQ-18, Д-08) и хвост увидят. Число проб, сценарий и текст наружу не меняются.
   - уровень: требования

## Рассмотрено, находкой не считаю

- Признак `-v`, заданный флагом командной строки, при `-F` и `-m` хуку `commit-msg` не виден (рассмотрено в заходе 27):
  механизм С3 (Д-11); ошибка только в сторону строже, на файле с буквальной строкой-ножницами.
- Режим «редактор или нет» хуку доступен через окружение хука (рассмотрено в заходе 27); REQ-37 выполнима обёрткой.
- `--cleanup=scissors|verbatim|whitespace`, `commit.cleanup`, `commit.commentChar` (`core.commentChar`) в тексте не
  названы: общий принцип «то, что git сохранит» определяет поведение; перечень режимов REQ-14 — пояснение, а не
  закрытый список. Тонкие режимы git оставлены механизму плана.
- REQ-14 судит строки `#` при `-F` и `-m`, тогда как О-05 говорит «комментарии git»: комментарий git — то, что git
  убирает (рассмотрено в заходе 27); сужения слова владельца нет.
- Класс законных команд `git commit -v …` AC-10 строкой не называет, но REQ-16 запрещает только перечисленное;
  `git add -- .claude/settings.json` и подобные пути с точкой в начале имени не совпадают с запретом «`.`» (запрет
  относится к аргументу, равному `.`); целого непокрытого класса нет.
- Прочее, отмеченное в заходах 25–27 как «Рассмотрено», не изменилось: AC-03 против REQ-05; форма
  `git commit -s -m "$(cat <<'EOF' … EOF)" --only -- <файл>`; слова из запретов внутри имён веток; запреты хука, которых
  нет в AGENTS.md (шортлист владельца и решение В9); незакоммиченные правки задачи 001 и `core.ts` в рабочей копии
