## Находки

1. Сценарии приёмки не доведены до нового определения «судится то, что git сохранит»: красная проба AC-32 для строки `#`
   не называет режим и в режиме редактора противоречит REQ-38, а изменённое поведение REQ-14 не имеет ни одного
   сценария.
   - Что не так (а): AC-32 (940): «красные пробы: запрещённое имя … в строке, начинающейся с `#`, и в строке цитаты,
     начинающейся с `>`». Это текст захода 24, до различения режимов. По REQ-38 (517–519) и REQ-14 (315–318) в режиме
     редактора строки `#` git убирает до записи в историю и они не судятся; красными они остаются только при `-F` и `-m`.
     Проверяющий, который прогонит эту пробу через редактор (естественный режим хука `commit-msg`), получит зелёный
     коммит и признает AC-32 невыполненным либо потребует красного там, где REQ-38 его не требует. Файл, который видит
     хук, в пробах (а) и (б) устроен одинаково (строка-ножницы и хвост за ней, проба 6): вердикт различается только
     режимом, а в AC-32 режим назван лишь у (а), у (б) и у проб `#` и `>` не назван. AC-09 (777–779) и REQ-37 (512–514)
     требуют, чтобы режим стража был входом, заданным пробой явно; AC-32 этого не говорит.
   - Что не так (б): прежняя находка 25 состояла из двух следствий — краснело имя в удалённой строке diff (REQ-38) и
     краснела кириллица в добавленной строке diff (REQ-14; законный коммит правки русского документа через `-v`). REQ-14
     правкой захода 25 изменён (314–318), но ни AC-09, ни AC-32 не имеют пробы на изменённое поведение: нет зелёной
     «кириллица только в добавленной строке diff при `-v` — проходит», нет «кириллица в строке `#`: в режиме редактора
     проходит, при `-F` красная», нет «кириллица в самом сообщении при `-v` — красная». AC-32 судит только имена по
     списку и путь машины, то есть REQ-38. Требование, которое правка захода 25 изменила, остаётся без доказательства.
   - Цитата: «красные пробы: запрещённое имя (из выдуманного списка пробы) в строке, начинающейся с `#`, и в строке
     цитаты, начинающейся с `>`; нет списка — красный; (а) коммит в режиме с diff (`-v` или `commit.verbose`) …; (б)
     `-F` со строкой-ножницами и запрещённым именем в хвосте после неё — красный» (AC-32);
     «в режиме редактора — сообщение после того, как git убрал комментарии (строки с `#`) и хвост за строкой-ножницами»
     (REQ-14).
   - Место в spec.md: AC-32 (935–943); AC-09 (771–779); REQ-14 (314–318).
   - Что сделать: в AC-32 назвать режим у каждой пробы (редактор / `-F` / `-m`) и записать пары: строка `#` с именем —
     при `-F` и `-m` красная, в режиме редактора проходит (git её убрал); строка `>` с именем — красная в обоих; в AC-09
     добавить пробы REQ-14: кириллица только в добавленной строке diff при `-v` — проходит, кириллица в сообщении при
     `-v` — красная, кириллица в строке `#` при `-F` — красная, в режиме редактора — проходит.
   - критичность: существенная. Меняет сценарий приёмки и то, что хук отклоняет и пропускает (законный `-v`-коммит
     русского документа); без пробы изменённое требование не доказывается.
   - уровень: требования

2. Перечень режимов в REQ-14 и REQ-38 утверждает про git больше, чем он делает: при `-v` или `commit.verbose` хвост за
   строкой-ножницами git убирает и при `-F`, и при `-m`.
   - Что не так: REQ-14 (317–318): «при `-F` и `-m` — всё как есть, строки с `#` и хвост после строки-ножниц остаются в
     истории»; REQ-38 (518–519): «хвост за строкой-ножницами при `-F`». Проба 5: `git commit -v -F файл` и
     `git -c commit.verbose=true commit -F файл` (и `-m`) обрезают сообщение по строке-ножницам — хвоста в истории нет;
     `-F … --cleanup=strip` и `-F … -e` убирают строки `#`, хвост оставляют. Определение в первой фразе («то, что git
     сохранит») верно, перечень после него — нет.
   - Цитата: «при `-F` и `-m` — всё как есть» (REQ-14).
   - Место в spec.md: REQ-14 (317–318), REQ-38 (518–519), «Изменения захода 25», п.1.
   - Критичность: поверхностная. Перечень ошибается только в сторону строже: лишнее судится сообщение, которое git
     всё равно обрежет, а скрыть приватные данные это не позволяет; законная команда не отклоняется (строка-ножницы с
     хвостом в файле сообщения для `-F` — не штатная форма, diff при `-F` без редактора git не дописывает); главное
     правило («то, что git сохранит») от этого не меняется и именно им руководствуется С3. Требования, сценарий, число и
     текст наружу не меняет.
   - уровень: требования

## Рассмотрено, находкой не считаю

- Режим «редактор или нет» хуку `commit-msg` доступен: файл в обоих режимах устроен одинаково (проба 6), но git
  выставляет в окружении хука `GIT_EDITOR=:` при `-F` и `-m` и настоящий редактор при редакторе (проба 6). Механизм —
  дело С3; отдельный хук или аргумент от обёртки — его выбор. Требование REQ-37 («режим — вход стража, не среда») С3
  выполнит, если обёртка хука превратит признак в аргумент; отсутствие механизма находкой не считаю. Но проверка
  самого признака в самотесте нужна — это в находке 1.
- REQ-14 в режиме `-F` теперь судит и строки `#` на ASCII, тогда как ответ О-05 говорит «комментарии git». Читаю
  согласованно: комментарий git — то, что git убирает; при `-F` строка `#` остаётся текстом истории. Это моя же
  рекомендация захода 25, отклонений от слова владельца по существу нет; сужение исключения касается только `-F`-файла,
  который агент пишет сам и пишет по-английски.
- Два места, где определение «то, что git сохранит» действует без режима: `pre-push` и CI судят уже сохранённое
  сообщение целиком (кроме строк `>`), поэтому для них различать редактор и `-F` не нужно; результат согласован с
  `commit-msg` (в режиме редактора убранное git'ом не попадает в историю, значит и не будет судиться позже).
- Исключения в REQ-14 для `core.commentChar` и `commit.cleanup` в тексте нет; при общем принципе («то, что git
  сохранит») поведение определено, остальное — механизм С3.
- Прочее, что отмечено в заходе 25 как «Рассмотрено», не изменилось: AC-03 против REQ-05; форма
  `git commit -s -m "$(cat <<'EOF' … EOF)" --only -- <файл>` (хук донора A отвечает 0); слова из запретов внутри имён
  веток (поведение определено словом «подкоманда»); сырые правила хука; запреты хука, которых нет в AGENTS.md (шортлист
  владельца и решение В9); незакоммиченные правки задачи 001 и `core.ts` в рабочей копии `main` (не предмет DNC-01);
  имя автора ASCII; таблица «What is here»; уровень F «AC-01…AC-21»; пометка «механизм» у п.15.
