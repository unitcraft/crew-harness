## Находки

1. Стражу сообщения в CI не из чего взять ожидаемый адрес автора: REQ-15 берёт его только из локальной настройки
   git, которую пишет установщик, а REQ-29 и Д-08 гонят страж сообщения в CI по каждому коммиту пуша.
   - Материал: msg п.7 и «Решения»: стражи запускаются «из хуков и из CI»; meth §19: «не выполнилась ≠ пройдена —
     обязательная проверка, не отработавшая, даёт красный».
   - Место в spec.md: REQ-15 («адрес автора совпадает с ожидаемым из локальной настройки git вне репозитория, которую
     пишет установщик»), Д-10, REQ-28; REQ-29 («стражи сообщения … по коммитам … пуша»), Д-08; REQ-35 («В CI
     «пропущено» у обязательного стража — красный прогон»); AC-09 (только хук `commit-msg`), AC-20 («прогон
     зелёный»).
   - Факт (проба 7): в spec.md источник ожидаемого адреса назван только как настройка, которую пишет установщик
     (REQ-15, REQ-28, Д-10, AC-19); о CI — ни слова. В раннере GitHub Actions установщик не запускается.
   - Следствие: в CI правило адреса либо «пропущено» — по REQ-35 красный прогон на каждом пуше, и AC-20 невыполним, —
     либо исполнитель сам выбирает, что делать (молча снять правило в CI, завести адрес секретом, перенести в
     переменную репозитория), — решение без записи. Адрес — личные данные (Д-10), так что «положить в репозиторий» не
     выход.
   - Что сделать: сказать, судится ли адрес автора в CI и чем: например, правило адреса — только локально, в CI —
     «судить нечего: нет настройки установщика» с причиной в шапке; или адрес — секрет репозитория с маскировкой, как
     список REQ-04 (тогда это ещё одно действие на GitHub по К-09 и В-04). Добавить случай в AC-09 или AC-20.
   - критичность: существенная
   - уровень: требования

2. «Доказательство красного» задано заглушкой `exit 0` для любого стража, хотя стражи — на sh и Python (И-01); урок
   донора A о заглушке на языке стража и о самотестах в обоих расширениях выпал.
   - Материал: meth §20: «страж подменяется заглушкой «всегда успех», и самотест обязан упасть»; meth §19: «красное
     может быть дефектом самой проверки — проверяется, почему зелено или красно». Донор A, A: guards/
     check-novac-selftest-proves-red.sh, шапка (проба 6): заглушка пишется на языке стража, иначе подмена не
     исполнится и «доказательство» будет мусором; стражи на Python стояли вне доказательства, пока искались только
     `.sh`; самотест ищется в обоих расширениях и гонится нужным интерпретатором. sur G-20: «взять с правкой: маска
     `check-*`».
   - Место в spec.md: REQ-26 («подменяет страж заглушкой `exit 0`»), AC-17 («подменяет каждый страж заглушкой
     `exit 0`»), И-01 (sh и Python), REQ-25 («есть самотест» — в каком расширении, не сказано).
   - Следствие: страж на Python, подменённый текстом `exit 0`, падает синтаксической ошибкой, его самотест падает уже
     на зелёной пробе — и прогон засчитывает «доказано», не проверив ни одной красной пробы: ложное доказательство
     ровно того вида, от которого донор ушёл. Самотест на Python при поиске только `test-*.sh` даёт «нет самотеста».
   - Что сделать: в REQ-26 и AC-17 — заглушка «всегда успех» на языке стража (для Python — модуль, выходящий с
     кодом 0); самотест ищется и запускается в обоих расширениях; в AC-17 — проба: заглушка, которая не исполняется
     (синтаксическая ошибка), не засчитывается доказательством.
   - критичность: существенная
   - уровень: требования
