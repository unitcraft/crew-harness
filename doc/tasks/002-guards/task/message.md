# Задание: стражи репозитория crew-harness — хуки git, проверки CI, самотесты

Заказчик и владелец: владелец репозитория `unitcraft/crew-harness` (он же отвечает на вопросы и принимает результат).
Репозиторий кода: `unitcraft/crew-harness` (https://github.com/unitcraft/crew-harness, ветка `main`). Дата задания:
2026-10-07.

Задача полная: разбор, план, реализация, сдача.

## Что есть сейчас

- Репозиторий публичный. Правило «без приватных данных» —
  [ADR-0006](../../../canon/decisions/ADR-0006-public-repository.md): держится на ручном поиске перед коммитом; страж
  записан там «кандидатом в задачу». История уже переписывалась один раз из-за попавших в неё приватных данных.
- Правила репозитория — [AGENTS.md](../../../../AGENTS.md): коммиты по-английски, `-s`, файлы по имени, без
  `git add -A`, слияние `--ff-only`, без силового пуша.
- Документы задач — по машинным форматам методики (`task-runner.md`, раздел «Машинные форматы»).
- В репозитории есть `.gitattributes` (`* text=auto eol=lf`); хуков, `scripts/`, `.github/` нет.
- Тесты плагина — `opencode-plugin/test/*.mjs` (node); сервис на Go появится в задаче 001.
- Машина общая и нагруженная: тяжёлые прогоны — по одному ([AGENTS.md](../../../../AGENTS.md)).

## Что нужно (потребности из разбора)

1. Нет приватных данных: пути машины, имена приватных репозиториев и проектов, секреты. **Список запрещённых имён в
   репозитории не хранится**, даже в самом страже: образцы — из файла вне репозитория (локально) и из секрета
   репозитория (CI); нет списка в CI — страж красный, а не зелёный.
2. Нет битых относительных ссылок и якорей в Markdown.
3. Гигиена текста: управляющие байты, кракозябры, BOM, смешанные концы строк.
4. Гигиена коммитов: `Signed-off-by`, сообщение латиницей, без `git add -A`, слияние только `--ff-only`, без силового
   пуша.
5. Машинные форматы документов задач: строка статуса `spec.md`/`plan.md`, первая строка проверки
   `Заход N: существенных K, поверхностных M, проб P`, уникальные REQ/AC.
6. Нет рукописных таблиц статусов, дублирующих правду.
7. Мета: каждый страж подключён (хук и CI), у каждого самотест, который доказывает и красное, и зелёное; страж не
   зелёный на пустом входе.
8. Нет пустых тестов (тест без проверки).

## Исходные решения исполнителя, с которыми владелец согласился

- Подключение: `scripts/githooks/` и установщик (`core.hooksPath`, `merge.ff only`); стражи запускаются по маске из
  хуков и из CI; защита ветки `main` на GitHub от силового пуша.
- Проверки индекса и сообщения коммита — вне общей маски (иначе при общем прогоне они «пропущены» и зелёные).
- Логику стражей брать из разбора, переписывая шапки и комментарии: в публичный репозиторий не попадают имена,
  номера планов и пути чужих проектов.

## Границы

- Стражи кода Go (правила переноса на Нову, [ADR-0003](../../../canon/decisions/ADR-0003-go-first-then-nova.md)) — не
  здесь, вместе с кодом сервиса (эпик 001).
- Машинные форматы при чтении проверяет сам CrewHarness (эпик 001); здесь — страж на коммит, чтобы неверный файл не
  попал в историю.
