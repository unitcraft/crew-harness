  а не барьер (решение владельца В9, заход 11; Н-12). Поведение [Сессия С1п, заход 17; spec-review-17]:
  - правило применяется к каждому отдельному вызову git в команде — по его собственной подкоманде и аргументам, а не к
    строке целиком: команды в цепочке (`&&`, `||`, `;`, `|`, перевод строки) судятся каждая сама по себе; перевод строки после обратной

    внутри;
  - законные команды не отклоняются: чтение, поиск, цитирование команд в тексте и цепочки после разрешённой команды
    проходят (таблица AC-10).

REQ-35 [выведено из meth §19, §20] Вердикт стража — одна из четырёх различимых форм: «ок: осмотрено N <мишень>» (число
  осмотренного и имя мишени); «судить нечего: <причина>» — проверка не применима (пустой индекс при правке только
  сообщения, REQ-27); «пропущено: <причина>» — проверка не выполнена; нарушение — «FAIL» с адресом (файл, строка).
  «Судить нечего» законно и для правила, которое по шапке стража не применимо в среде, — только по явному признаку
  режима, заданного входом стража (сверка ожидаемого адреса автора — в режиме `--ci`, П-08), а не по отсутствию
  предпосылки и не по переменной окружения. «Пропущено» законно только локально и только с причиной из закрытого списка в шапке стража; список может быть пустым — у стражей
  задачи законного пропуска на дату разбора нет: им нужны только git, bash и Python, а отсутствие Python — красный
  (REQ-03); причина вне списка — FAIL. В CI «пропущено» у обязательного стража —
  красный прогон (meth §19: «не выполнилась ≠ пройдена»). Код 0 — у «ок», «судить нечего» и законного локального
  «пропущено»; общий прогон печатает число вердиктов каждого вида.
REQ-36 [выведено из meth §20 «Внешний вызывающий»] Шапка каждого стража: зачем, что проверяет, чего не проверяет, где
  живёт правило (пункт `AGENTS.md` или ADR).
REQ-37 [выведено из meth §20 «Проверка судит предмет, а не среду»] Результат стража не зависит от среды: одинаков в Git
  Bash на Windows и в bash на ubuntu (CI), при любой локали (поиск кириллицы — без классов `grep`, зависящих от
  локали), без абсолютных путей; самотест держит контрольный ввод по строке на каждую форму. Режим работы стража
  (например `--ci`, REQ-15) — это вход стража, заданный аргументом, а не среда: самотест задаёт его явно в каждой
  пробе, и при одинаковом входе вердикт одинаков локально и в CI.
REQ-38 Сообщение коммита не содержит приватных данных [выведено (Сессия С1п); spec-review-23, находка 2; К-06,
  AG п.15, ADR-0006]: страж сообщения прогоняет через определение пути машины (REQ-06) и список запрещённых имён

  (git оставляет их в истории) и с `>` (строки цитаты), а также хвост за строкой-ножницами при `-F` и `-m` без режима с diff (при включённом режиме с diff git обрезает по
  строке-ножницам и там; в режиме редактора судится сообщение после очистки git); diff индекса,
  который редактор показывает при `-v` и который в историю не попадает, не судится; вердикт называет «сообщение коммита, строка» и номер образца и не
  содержит значения (REQ-04). Вызывается из хука `commit-msg`, из `pre-push` и в CI по каждому коммиту пуша; нет
  списка — красный (REQ-03). Прошлые коммиты не судятся (DNC-05). Источник: msg п.1 (M-14…M-17); AG п.15; ADR-0006.

### assumptions

- Д-01 Список запрещённых имён: файл в домашнем каталоге пользователя вне репозитория, путь переопределяется
  переменной окружения; формат — образец на строку, без учёта регистра, строки с `#` — комментарии; в CI — секрет
  репозитория в том же формате; концы строк LF и CRLF читаются одинаково (REQ-03); короткие имена вносятся в путевой
  форме, чтобы не совпадать с частыми словами (meth §19). Имена файла, переменной и секрета выбирает С3. Причина: msg
  задаёт только «вне репозитория» и «секрет».
- Д-02 Нет локального списка — страж красный, как в CI. Причина: молча зелёный страж на новой машине — ровно то, что
  запрещает M-17; все рабочие деревья на одной машине видят один файл.
- Д-03 «Не зелёный» в M-31 читается по meth §20: не «ок» — красный «мишень потеряна» либо «судить нечего: причина»
  (REQ-35). Пустое сообщение — красный (git и сам не делает коммит с пустым сообщением). Пустой индекс — «судить
  нечего: индекс пуст», код 0: это законная правка только сообщения `git commit --amend`, при которой страж
  сообщения работает. Поломка предпосылки (нет git, списка, интерпретатора, локально — настройки установщика) — красный. Причина: красный на пустом
  индексе запретил бы `--amend`, а обход `--no-verify` снял бы и проверку сообщения (П-04).
- Д-04 `Signed-off-by` должен совпадать с автором коммита (имя и адрес), как в доноре A `dco.yml`. Причина: так
  проверяет `git commit -s`. Прошлый коммит `d343557` с несовпадением не судится (REQ-19, DNC-05).
- Д-05 Правило донора «меняющая команда git без `-C`» убирается целиком. Причина: sur G-13 «убрать правило с путём
  машины» — читается как правило, а не только путь.
- Д-06 Стражи гигиены текста смотрят содержимое, которое уходит в историю (отслеживаемые файлы и индекс), все
  кроме явного списка бинарных расширений (REQ-09). Причина:
  `.gitattributes` и так нормализует концы строк при `git add`; страж ловит то, что нормализацию обошло (бинарное
  определение, `-text`). Бинарными считаются только файлы с расширением из явного списка (REQ-09).
- Д-07 Страж формата проверяет `DNC-NN` наравне с `REQ-NN` и `AC-NN` — одна строка формата в `run`.
- Д-08 В CI страж индекса работает в режиме дерева пуша (только правила высокой уверенности: ключ, токен, учётные данные в
  адресе, пути машины), а страж сообщения (в том числе проверка сообщения на приватные данные, REQ-38) — по каждому
  коммиту пуша; коммиты по их добавленным строкам до публикации судит `pre-push` (REQ-18). Причина: в CI нет индекса;
  sur G-03 «идея `--tree`».
- Д-09 Стражи не исключают себя и свои самотесты по пути (meth §20: область не исключается): образцы нарушений
  собираются самотестом во время прогона (К-06), в файлах стражей их литералов нет; где без литерала нельзя —
  пометка с причиной на строке (REQ-09).
- Д-10 Ожидаемый адрес автора (REQ-15) — текущий `user.email` на момент установки; установщик пишет его в локальную
  настройку git и печатает; нет `user.email` — громкий отказ (REQ-28). Причина: адрес — личные данные, в репозиторий
  не пишется; в истории два адреса (Ф-04), выбор текущего — по последним коммитам. В CI (режим `--ci`) сверки с ожидаемым адресом
  нет (П-08); локально без настройки — красный с подсказкой запустить установщик.
- Д-11 Механизм поведения хука агента из REQ-16 (как выделить отдельные вызовы git и литералы) — в плане Сессии С3.

AC-03 [выведено] Когда в отслеживаемом файле (любого расширения, в том числе в папке задачи) есть образец из списка,

  самотест с временным списком, созданным в прогоне; поиск образца в выводе — 0 совпадений.
AC-04 [выведено] Когда списка нет — локально нет файла, в CI нет секрета или он пуст, — или нет рабочего
  интерпретатора, тогда страж красный и говорит, как завести недостающее. Доказательство: самотест (четыре случая);
  прогон CI без секрета на служебной ветке (ссылка) — по слову владельца (К-09).
AC-05 [выведено] Когда стражи приватности прогнаны на рабочем дереве задачи со списком владельца, тогда «ок»: общие

AC-08 [выведено] Когда в отслеживаемом файле управляющий байт (кроме TAB, LF, CR), подпись кракозябр, U+FFFD, BOM или

AC-09 [выведено] Когда сообщение коммита без `Signed-off-by`, с подписью не автора, с не-ASCII вне строк цитаты (что
  судится — по определению «что git сохранит в историю» из REQ-14, режимные пробы — AC-32; по О-05), с `Co-Authored-By` или адрес автора не совпадает с записанным установщиком, тогда хук `commit-msg` отклоняет
  коммит с причиной; правильное сообщение — проходит. Когда тот же страж сообщения прогнан по коммитам пуша с
  аргументом `--ci` (так его зовёт workflow CI), тогда правило адреса печатает «судить нечего: CI, нет настройки
  установщика», а коммит, у которого адрес в `Signed-off-by` не совпадает с адресом автора, — красный. Когда
  страж вызван без `--ci` и настройки установщика нет, тогда он красный с подсказкой «запусти установщик», в том
  числе при `GITHUB_ACTIONS=true` в окружении. Доказательство: самотест (режим задан аргументом в каждой пробе: без
