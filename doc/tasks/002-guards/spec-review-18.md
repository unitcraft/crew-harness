## Находки

1. В AC-10 нет ни одной обычной команды git для инструмента `PowerShell`, в том числе цепочки «коммит, затем пуш». Хук
   стоит на `PowerShell` (REQ-16, строка 318; AC-16). Это основная оболочка агента на машине владельца, Windows
   PowerShell 5.1. В ней нет `&&`, поэтому условная цепочка пишется только так: `A; if ($?) { B }`. Обычный коммит с
   пушем в этой форме донор A отклоняет. Проба 4, код 2:
   - `git commit -s -F m.txt --only -- a.txt; if ($?) { git push -u origin 002-guards }`;
   - то же с сообщением через here-string `@'…'@`;
   - `git commit -s -F m.txt --only -- a.txt; if ($?) { git status -s }`.

   Причина — «флаг после `--`»: диапазон правила проходит через `;` и `{` и ловит `-u` и `-s` следующей команды. Тот
   же коммит без цепочки и `…; if ($?) { git push origin 002-guards }` (без флага) — код 0. В AC-10 цепочки есть
   только для `Bash` (строки 750–753). Строки `PowerShell` (762–763) — только here-string. Поэтому от плана не
   требуется показать, что разбор на вызовы работает и для синтаксиса `PowerShell`: `if ($?) { … }`, блок в фигурных
   скобках. А по Д-11 механизм может быть свой для каждой оболочки (токенизатор `bash` синтаксис PowerShell не знает).
   - Материал:
     - REQ-16, строки 318 и 321–322: хук на `Bash` и `PowerShell`, каждый вызов git судится по своим аргументам;
     - хук донора A (S21), строки 266–267: `[^\n]*?\s--\s[^\n]*?\s-(?:F|m|s|S|u)\b` — до конца строки;
     - meth §20, «Самотест в обе стороны, законное первым»;
     - решение В9: ложные отказы законных команд существенны.
   - Место в spec.md: AC-10, строки 733–763. В таблице нет строк для инструмента `PowerShell` с обычными командами
     git и с цепочкой `; if ($?) { … }`.
   - Что сделать: добавить в таблицу AC-10 строки для инструмента `PowerShell`, ответ «проход»:
     - `git commit -s -F <файл> --only -- <файл>; if ($?) { git push -u origin <ветка> }`;
     - `git add -- <файл>; if ($?) { git commit -s -F <файл> --only -- <файл> }`;
     - коммит с сообщением here-string `@'…'@`, а затем `; if ($?) { git push -u origin <ветка> }`.

     И строку «отказ»: `git commit -s -F <файл> --only -- <файл>; if ($?) { git push --force }`. REQ-16 не меняется:
     его поведение этот случай уже покрывает.
   - критичность: существенная. Меняется сценарий AC-10: добавляются строки проб. По решению В9 это ложный отказ
     законной команды. Это класс штатной работы агента в основной оболочке машины, а не редкая форма.
   - уровень: требования

2. В AC-10 нет зелёных проб для команд git, которые сам `AGENTS.md` называет штатной формой:
   - п.4 и О-07: `git add -- <файлы>` — так git узнаёт новый файл. Задача 002 создаёт десятки новых файлов в
     `scripts/`, `.github/`, `.claude/`;

   - критичность: существенная. Меняется сценарий AC-10 (новые строки проб). Пропущен класс законных команд, которые
