## Находки

1. Защита ветки `main` по умолчанию не действует на администратора репозитория, а в `main` пушит именно
   администратор. После решения В9 защита ветки — единственный механизм для двух правил: коммиты слияния в `main`
   (M-23) и удаление `main` (REQ-17). Хуки `pre-merge-commit`, `merge.ff only` и проверки `pre-push` для них убраны
   (Н-13). Документация GitHub, страница «About protected branches» (проба 3):
   - по умолчанию ограничения правила защиты не применяются к людям с правами администратора — «do not apply to
     people with admin permissions»;
   - применить их к администраторам можно отдельной настройкой «Do not allow bypassing the above settings» (в API —
     `enforce_admins`);
   - запрет силового пуша — исключение: он действует на всех, включая администраторов.

   В проекте слияние в `main` локальное: `git merge --ff-only` из рабочего дерева, затем пуш (proc, строка 32; AG
   п.3). Пушит владелец или агент через его учётные данные. У владельца права администратора: `gh api` на репозиторий
   показывает `"admin":true` (проба 3).

   Значит, без `enforce_admins` правило «обязательная линейная история» на пуш владельца не действует: GitHub примет
   его с пометкой об обходе правила. Коммит слияния на машине создаётся без единого стража. Хук `pre-commit` при
   `git merge --no-ff` не вызывается, вызывается только `commit-msg` (проба 4). Хук агента правила о слиянии не имеет
   (G-13: «не берём»). Для Codex CLI и Kimi Code этим же механизмом Н-09 называет «защиту ветки».

   В spec.md слов `enforce_admins` и «администратор» нет (проба 1). AC-11 (строки 686–690) проверяет только
   `allow_force_pushes`, `allow_deletions` и `required_linear_history`. Поэтому сценарий пройдёт и на защите, которая
   не держит правило для единственного, кто пушит в `main`.
   - Материал: msg п.4 «слияние только `--ff-only`» (M-23); решение В9 в log.md: «дисциплину git … закрывает защита
     ветки main на GitHub»; meth §19 «Смотреть надо на состав джоб, а не на цвет», «то же свойство другим
     синтаксисом — красный».
   - Место в spec.md: REQ-17 (строки 333–336); AC-11 (строки 686–690); О-01 (строки 802–806); expected_state
     (строки 215–218); Н-09 (строки 231–234).
   - Что сделать:
     - в REQ-17 добавить, что правила защиты применяются и к администраторам (`enforce_admins`, «Do not allow
       bypassing the above settings»);
     - в AC-11 добавить `enforce_admins.enabled: true` и пробу: пуш коммита слияния в `main` от владельца отклонён.
       Проба делается на служебной ветке с той же защитой или в репозитории для опыта, по слову владельца (К-09).

     Если включать `enforce_admins` владелец не хочет, это вопрос ему с рекомендацией (К-10). Иначе в Н-12 или Н-13
     надо честно записать, что запрет слияний в `main` для владельца держится только текстом AG п.3.
   - критичность: существенная (сценарий AC-11 проходит, хотя правило M-23 не держится; это механизм, которым
