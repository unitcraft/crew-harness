## Находки

1. Прогон «доказательство красного» в плане ищет самотест только как `test-<страж>.py` (стр. 46, 211, 214), тогда как REQ-26 требует искать его во всех
   расширениях (`test-<страж>.sh` и `test-<страж>.py`) и запускать своим интерпретатором. У всех 21 самотеста плана расширение `.py`, поэтому сейчас вред
   нулевой, но будущий самотест на `.sh` (стражи на sh, в том числе второй вид хуков) прогоном `prove-red.sh` не будет найден и «доказано N из N» не
   посчитает его. Нужно: в описание `prove-red.sh` (стр. 214) добавить «самотест ищется по обоим расширениям, запускается своим интерпретатором»
   и одну пробу в `test-prove-red.py` (самотест-заглушка на `.sh`).
   - критичность: поверхностная — все самотесты плана на Python и находятся; AC-17 расширение не проверяет; дефект проявится только при добавлении `.sh`-самотеста позже
   - уровень: план

2. Запись хука агента в `.claude/settings.json` (стр. 130–132) разорвана переводом строки прямо внутри строки JSON (после `guard-git.py\";`). Склеенная в одну строку
   команда работает (проба 3: код 2 на красной команде в корне, подкаталоге, при `CLAUDE_PROJECT_DIR` в обоих видах записи пути; код 0 без скрипта и вне git),
   но буквально скопированный из плана текст не разбирается: `json.loads` отвечает «Invalid control character». Нужно: дать значение `command` одной строкой
   (или словами «одна строка, без перевода внутри значения»).
   - критичность: поверхностная — строка DoD уровня A (разбор JSON, стр. 364) и самотест `test-guard-git.py` поймают ошибку сразу; формулировка, а не поведение
   - уровень: план

3. Проверка DNC-01 для записи `.claude/settings.json` (стр. 134–136, 397, шаг 8) названа так: «проверка — `node opencode-plugin/test/crew-deny.test.mjs`». Этот тест создаёт
   свои временные репозитории и свой файл настроек (`mkdtempSync`, `writeFileSync`), настоящий файл репозитория не читает, поэтому зелёный он будет и при любом
   содержимом записи, то есть «поведение `crew_watch` не меняется» им не доказывается. Само утверждение верно (проба 4: при настройках только с ключом `hooks`
   `projectDeny` даёт пустой список, `watchRefusal` на трёх командах возвращает `undefined`). Нужно: к DoD (стр. 397) и шагу 8 добавить прямое доказательство —
   вызов `watchRefusal(<команда из списка запретов Канона>, <корень дерева задачи>)` на дереве с готовым `.claude/settings.json` (одноразовый скрипт вне репозитория,
   код плагина не меняется), ожидаемо `undefined`; тест `crew-deny.test.mjs` оставить как «итог как в базе».
   - критичность: поверхностная — утверждение верно (проба 4), требование DNC-01 выполнится; слабое место только в том, что названное доказательство не доказывает именно это
   - уровень: план
