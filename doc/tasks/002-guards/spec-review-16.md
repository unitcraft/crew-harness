## Находки

1. Из REQ-16 молча выпало то, как донор A применяет свои правила: главные правила смотрят только исполняемую часть
   команды. Текст в одинарных и двойных кавычках и тело heredoc вырезаются до проверки. Так донор защищается от ложных
   отказов: команда, которая лишь упоминает `git add -A` или `git stash` в строке, не отклоняется. По сырой команде
   донор проверяет только правила, для которых содержимое кавычек и есть предмет: запись через PowerShell и `-m` с
   обратным апострофом. В spec.md есть только вторая половина: REQ-16, строка 332, «правила донора по сырой команде»,
   и Ф-19. Что значит «не по сырой» для остальных правил, не сказано нигде. Поиск по spec.md до «Изменений захода 1»
   (проба 1): `heredoc` — 0 строк, `исполняем` — 0, `кавыч` — только строки 333 и 605 (here-string PowerShell). AC-10
   (строки 721–730) не содержит ни одной зелёной пробы на правило, упомянутое внутри кавычек или heredoc. Последний
   абзац «Изменений захода 15» (строки 1174–1177) утверждает, что сверка правил донора полная и «молча выпавших нет».
   Это не обход хука, а обратная сторона: подсказка, исполненная по букве REQ-16, отклонит кодом 2 законные команды.
   Примеры: `grep -n "git stash" AGENTS.md` — проверяющая сессия ищет текст правила; запись файла сообщения через
   heredoc со словами `git add -A` в тексте. Донор их пропускает (проба 4).
   - Материал: A: claude-hooks/guard-git.py, шапка, строки 23–29: матчится только исполняемая часть, текст в кавычках и
     heredoc вырезается, иначе сообщение коммита или содержимое скрипта, где правило упомянуто как текст, ложно
     блокируется; донор называет это «доказанным на практике классом регресса». Строки 208–209 (`_QUOTED`, `_HEREDOC`),

     правкой» — правка названа, вырезание литералов в неё не входит.
   - Место в spec.md: REQ-16, строки 316–345 (нет правила, какая часть команды судится); AC-10, строки 721–730 (нет
     зелёных проб); «Изменения захода 15», строки 1174–1177.
