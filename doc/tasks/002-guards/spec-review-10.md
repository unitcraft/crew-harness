## Находки

1. Хук агента судит ветку rebase только по каталогу, заданному в тексте команды. Каталог, заданный самим инструментом,
   он не видит. REQ-16 (строки 316–320) перечисляет `-C`, `--git-dir`, `GIT_DIR` и смену каталога «раньше git в той
   же команде». Откуда берётся исходный каталог команды, не сказано. Строк с `cwd` и `workdir` в spec.md — 0 (проба 1).
   - В OpenCode у инструмента оболочки есть аргумент `workdir`. Описание инструмента прямо велит агенту не менять
     каталог в команде, а задавать его там: «When possible, avoid changing directories in the command and set the
     working directory here instead» (проба 4).
   - Плагин @ `b520c68` передаёт хуку `cwd: root` — корень репозитория сессии, а аргумент `workdir` отбрасывает
     (index.ts, строка 260; проба 4). Агент в окне OpenCode штатно вызывает `git rebase <ветка>` с `workdir` =
     дерево `main`. Хук видит каталог сессии, то есть ветку задачи, и пропускает команду, а git перебазирует `main`.
   - В Claude Code каталог инструментов `Bash` и `PowerShell` сохраняется между вызовами. Агент делает `cd <дерево
     main>` одним вызовом, `git rebase <ветка>` — следующим. Смены каталога «в той же команде» нет, и по тексту
     REQ-16 хук берёт неизвестно какой каталог. Донор A записал этот дрейф как наблюдённый случай: «cwd дрейфует между
     вызовами» (A: `guard-git.py`, комментарий к правилу «меняющая команда без `-C`»). Само правило убрано по Д-05,
     замены ему в REQ-16 нет.
   - Материал: log.md, ответ В-01: «rebase на ветке задачи разрешён, на main запрещён»; meth §20 «то же свойство
     другим синтаксисом — красный»; S27 (плагин); U-07.
   - Место в spec.md: REQ-16, строки 316–320; AC-10, строки 704–712 — все пробы задают каталог только в тексте
     команды; Н-12 этот путь не называет.
   - Почему существенная по шкале Н-12: обходом служит штатная форма инструмента. В OpenCode её рекомендует
     описание самого инструмента, в Claude Code это обычная последовательность двух вызовов. Умысла не нужно.
   - Что сделать: в REQ-16 записать, что исходный каталог команды — рабочий каталог инструмента из входа хука
     (`cwd` у Claude Code; в окнах OpenCode — `workdir` вызова). Смены каталога в тексте команды судятся поверх него.
     Если вход хука не несёт настоящего каталога (плагин @ `b520c68` передаёт корень сессии), то `git rebase`
     без явной ветки или `-C` — отказ. Другой путь — правка плагина, чтобы он передавал `workdir`: это изменение вне
     репозитория, его нужно вынести вопросом владельцу с рекомендацией (К-10). В AC-10 добавить пробы: вход с `cwd` =
     дерево `main` и командой `git rebase <ветка>` — отказ; тот же вызов в форме OpenCode (`workdir` = дерево `main`) —
     отказ.
   - критичность: существенная
   - уровень: требования

     меняются. Пример стоит убрать.
   - критичность: поверхностная
   - уровень: требования
