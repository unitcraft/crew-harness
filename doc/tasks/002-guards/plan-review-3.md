## Находки

1. Способ различить режимы сообщения (редактор, `-m`/`-F`) в плане не записан, а без него реализация строго по плану не сможет
   выполнить REQ-14, REQ-38 и AC-32. Хук `commit-msg` получает один аргумент — путь к файлу; режим из него не следует:
   при `-m`, `-F` и редакторе файл одинаков по форме, строка с `#` остаётся в файле во всех трёх случаях, а git убирает её только
   в режиме редактора. Спецификация прямо оставила механизм плану (spec-review-28: «режим „редактор или нет“ хуку доступен через
   окружение хука; REQ-37 выполнима обёрткой»; REQ-15/REQ-37: режим — аргумент стража, а не среда). В plan.md этого нет:
   поиск по тексту `GIT_EDITOR`, `--message-file`, `--mode` даёт 0 совпадений; строка вызова «Общий договор» (стр. 68) знает только
   `--root`, `--index`, `--commit`, `--ci`; шаг 7 («режимы редактора, сообщения и `--commit`») и шаг 9 (хуки) не называют ни
   признак, ни аргументы. Пункты `editor`, `message`, `--commit` (стр. 140–146) и «Правила стража» R1…R7 (стр. 148–154) сейчас
   стоят внутри раздела «Механизм хука агента», как продолжение списка про запись в `.claude/settings.json`, без заголовка и
   вступления: подраздел «Страж сообщения» потерял начало, где такой признак должен был стоять. Чем доказано: проба 7 (в
   одноразовом репозитории хук `commit-msg` печатает среду: `args=1`; при `-m` и `-F` `GIT_EDITOR=:`, при редакторе — команда
   редактора; файл при `-F` содержит строку `# hash line`, при редакторе — `# c`, то есть до очистки git); поиск в plan.md —
   0 совпадений. Нужно: восстановить подраздел «Страж сообщения (REQ-13…REQ-15, REQ-38)» с заголовком; записать, что
   `commit-msg` передаёт стражу `--message-file "$1"` и явный `--mode editor|message` (по значению `GIT_EDITOR` в хуке: `:` —
   `message`, иное — `editor`), страж среду не читает (REQ-37); для `pre-push`/CI — `--commit` (сообщение как сохранено); добавить
   в `test-guard-commit-message.py` и `test-commit-msg.py` пробы обоих режимов с одним и тем же файлом (строка `#` красная при
   `message`, не судится при `editor`) и пробу `--amend --no-edit`; названный остаток — `core.editor=:` без `-m` даёт `GIT_EDITOR=:`
   и режим `message` (проба 7), записать его рядом с Р-07.
   - критичность: существенная — реализация строго по плану не имеет механизма режимов, на котором стоят REQ-14, REQ-38 и сценарий
     AC-32 (красные пробы `#` при `-F`/`-m` и проход при редакторе)
   - уровень: план
