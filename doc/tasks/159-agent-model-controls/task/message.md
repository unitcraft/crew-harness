Эпик: [001-crew-service](../../001-crew-service/); связано с задача 099 (сервер сессий) и [094](../../094-console-claude-layout/task/message.md) (раскладка веб-интерфейса).

Источников: 3 (протокол ACP — «session config options», код клиента, поведение реальных агентов).
Частей системы: 3 (ACP-клиент, хаб/сервер, веб-интерфейс).
Риск: средний (агенты разные: у одних нет настроек, у других они меняются в ходе сессии).
Необратимо: нет
Причина известна: да (сегодня клиент читает только имя текущей модели из `configOptions`: `src/acp/client.nv` `model_name_of`, `src/acp/project.nv`, событие `agent_model`; список агентов `/agents` отдаёт только `id` и `label`; задавать и менять нечего)
Касается нормы или формата: нет

Ветка: task-159-agent-model-controls

## Что нужно

1. **Разбор (в `analysis.md` первой частью, до кода).** Прочитать спецификацию ACP про настройки сессии (`session/new` возвращает `configOptions` — список полей с `id`, `name`, `category` (`model`, `thought_level`, `mode`, прочие), `type: select`, `currentValue`, `options`; смена — `session/set_config_option {sessionId, configId, value}`; уведомление `config_option_update`; прежнее `session/set_mode` и `session/set_model` у части агентов) и код `src/acp/*`, `src/server/*`, `src/web/*`. Выяснить на реальных агентах, ЧТО они отдают: `opencode acp`, `kimi acp`, `codex-acp`, `claude-agent-acp` (агентов запускать только на получение ответа `initialize` и `session/new` без отправки подсказки, чтобы не тратить подписку; при отсутствии входа в аккаунт — записать, что нужно от владельца; результаты — таблицей «агент → какие настройки отдаёт → категории → значения по умолчанию» в `log.md`). Решить и записать: (а) как показать настройки ДО создания сессии (варианты: запросить у агента пробной сессией и кэшировать по агенту; взять из последней сессии этого агента; задать в настройках сервера `agents[].defaults`), (б) как применять выбор при создании (после `session/new` отправить `set_config_option` для каждого выбранного поля), (в) как показывать изменение настроек агентом (`config_option_update`).
2. **ACP-клиент.** Разбор и хранение полного набора `configOptions` по сессии (не только имя модели); команда `set_config_option` и её результат; событие хаба «настройки сессии» (весь набор) и «настройка изменена»; отказ агента или неизвестная настройка — понятная ошибка, не падение. Поддержка прежних `set_mode`/`set_model` только если реальный агент из списка выше иначе не умеет (записать).
3. **Хаб и сервер.** Конечная точка со списком настроек агента для формы создания (по решению п. 1а); сообщение сокета «задать настройку» (`session`, `config id`, `value`) и ответ; хранение выбранного в журнале сессии, чтобы при перезапуске сервера не потерять; идентификаторы и значения проверяются по списку, который отдал агент (произвольные значения агенту не передаются).
4. **Веб-интерфейс.** Форма «Новая сессия»: после выбора агента — поля модель, effort, thinking (по категориям, что агент отдал; если ничего не отдал — подпись «агент не сообщает настройки»); значения по умолчанию помечены; выбор уходит при создании. Карточка «Окружение» справа (и строка заголовка): текущая модель, effort, thinking; изменение прямо в карточке (выпадающие списки), с индикацией «применяется» и откатом при отказе агента. Тот же стиль, темы, цели нажатия не меньше 40 px; на потоке-заглушке (`?mock=1`) показаны примеры (два агента с разным набором настроек).
5. **Тесты.** Фальшивый агент `src/acp/testdata/fake_agent.mjs` расширить: отдаёт `configOptions` с категориями `model` и `thought_level`, принимает `session/set_config_option`, шлёт `config_option_update`, один режим «агент без настроек» и один «отказ в смене». Не менее 25 новых тестов: разбор набора, смена, отказ, обновление от агента, агент без настроек, сохранение в журнале и восстановление после перезапуска, конечная точка, сообщение сокета, рендер списков и откат в веб-интерфейсе. ## Критерии приёмки

AC-1. В форме «Новая сессия» выбранный агент показывает модель, effort и thinking, которые он реально отдаёт (на `opencode`, `kimi`, `codex`, `claude` — таблица результатов в `log.md`), и помечает отсутствие.
AC-2. Выбор применяется при создании сессии; в карточке сессии виден и меняется после создания; смена доходит до агента (`set_config_option`) и подтверждается его обновлением; отказ агента откатывает выбор в интерфейсе.
AC-3. Значения проверяются по списку агента, неизвестные отклоняются; выбранное сохраняется в журнале сессии и переживает перезапуск сервера.
AC-4. Не менее 25 новых тестов, красная проба; полные наборы обычный и строгий зелёные; стражи зелёные.
AC-5. В `log.md` — решения (п. 1а–в), таблица агентов, числа, что осталось. Ничего не опубликовано и не запушено.
