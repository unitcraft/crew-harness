# Разбор 100: консоль для фоновых команд плагина (crew_watch)

Задание — `task/message.md`. Источник: слова владельца в чате оркестратора, 2026-10-19: «как исключить такие тормоза без моего участия». Код — `opencode-plugin/watch.ts`, тест — `opencode-plugin/test/crew-watch-console.test.mjs`, описание — раздел про консоль в `opencode-plugin/README.md`.

## 1. Что сделано

- `watch.ts`: на Windows команда crew_watch запускается в одной скрытой консоли, общей для всей цепочки команды (раньше — без консоли). Внешний Git Bash стартует не откреплённо и скрыто (`windowsHide`), Windows даёт ему скрытую консоль; он запускает внутренний Git Bash с прежним скриптом (`timeout`, вывод в `.out`, код в `.exit` через `.exit.tmp` и `mv`) и сразу выходит. Внутренний bash вне job-объекта Node, поэтому переживает службу и конец хода. Свой Windows-pid он пишет в `<id>.pid`; запись наблюдения берёт его как pid — отмена, предел времени и проверка «оборвано» работают как раньше.
- `core.ts`: строка про консоль в описании инструмента crew_watch (русская справка crew_help не менялась: её текст заморожен golden-файлом).
- README плагина: абзац «The console of a watch». Тест crew-watch-console, строки в `package.json` и `test/README.md`.
- Переключатель `CREW_HARNESS_WATCH_NO_CONSOLE=1` возвращает старый запуск: красная проба теста, не настройка.

## 2. Воспроизведение 0xC0000142: не получилось

Красная проба «vcvars из watch падает с 3221225794» на текущем коде (`detached: true`, `stdio: ignore`, `windowsHide: true`) не воспроизведена. Проверено (везде код 0, `where cl` находит `cl.exe`): запуск через `requestWatch` и `pollWatches` 3 раза; родитель без консоли (Node и Bun, с `detached` и `windowsHide` и без); python → `subprocess.run` → `cmd` → `vcvars` и `cl`; 12 watch разом; `CreateProcessW` на `cmd.exe /c exit 0` в 12 сочетаниях флагов; окружение без `SystemRoot`, `windir`, `ComSpec`, `TEMP`.

Условие, которого не хватает: сбой, судя по заданию, зависит от способа запуска и состояния машины; гипотеза — нехватка ресурсов консоли или рабочего стола при 70 и более `conhost` (число колеблется 68–85 от чужих окон), не доказана. → не нужно в этой задаче, потому что проверяемое различие (консоль есть или нет) измеряется напрямую, а тест vcvars остаётся в наборе и сам покажет сбой.

Что измерено твёрдо: у текущего watch процесс bash без консоли (`AttachConsole` к его pid падает с ошибкой 6; у процесса со скрытой консолью — успех). Каждая консольная программа цепочки bash → cmd → vcvars → cl получает новую консоль (отдельный `conhost`): за один `vcvars64.bat` и `cl` до 7–8 новых. Тест красный на этом различии. Дополнительное свидетельство оркестратора: Stage A сборки Карины через очередь плагина падал с 0xC0000142 несколько раз подряд, из окна с консолью проходил за 75 секунд.

## 3. Варианты запуска (родитель — процесс без консоли, как служба)

| Вариант | Консоль у bash | Переживает родителя | Вывод |
|---|---|---|---|
| `detached` + `windowsHide` (было) | нет | да | причина |
| `detached: false` + `windowsHide` | да, скрытая | нет (job с `KILL_ON_JOB_CLOSE`) | отвергнут |
| `detached: false` без hide | видимое окно | нет | отвергнут |
| `cmd /c start "" /b /min` | видимое свёрнутое окно | да | отвергнут (мигает) |
| `conhost.exe --headless` | — | — | выходит с кодом 0, команда не идёт |
| общая консоль службы | у службы консоли нет, создавать пришлось бы через FFI | — | не пробовал |
| двухступенчатый (выбран) | да, скрытая | да | выбран |

Выбранное проверено в Node и в Bun (среда службы): консоль есть и скрытая, внутренний bash жив после убийства «службы», `dropWatch` останавливает его по pid. Цена: старт блокирует проход плагина около 0,4 с вместо 0,07 с.

## 4. Утечка консолей

Серия: 20 коротких команд и 5 `sleep 100` с отменой; `conhost` считался по числу, чужие процессы не убивались. Новый режим: коды 0 в 20 из 20, `conhost` 75 → 79 при живых → 79 после отмены. Старый: 80 → 85 → 80. В новом режиме после отмены +4 — не утечка консоли, а осиротевшие `timeout.exe` и `sleep.exe` отменённых команд: `taskkill /T` по pid watch их не убивает (в обоих режимах), в новом режиме они держат общую консоль. Завершившиеся сами команды консолей не оставляют. Отмена гейта или сборки оставляет работу живой → задача 101.

Лишние `bash.exe` от Claude Code (около 20 с 15 октября) — не плагин. → не нужно, потому что это оболочки инструмента Bash самого Claude Code, не crew_watch.
