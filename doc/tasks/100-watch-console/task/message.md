## Чего хочет владелец (его слова, 2026-10-19, чат оркестратора)

- «как исключить такие тормоза без моего участия» — сутки выпуска Carina 0.2.1 потеряны из-за сбоя запуска, не из-за работы.
- «Не должно быть ручных команд там, где их может сделать программа» (AGENTS.md п. 14): оркестратор запускал сборку руками из своего окна, потому что через `crew_watch` она не работала.

## Что известно (факты 2026-10-19)

- `crew_watch` (`opencode-plugin/watch.ts`, функция `start`) запускает `bash -c "…"` как `spawn(gitBash(), ["-c", script], { detached: true, stdio: "ignore", windowsHide: true, … })`: процесс без консоли.
- Любая команда в таком запуске, которая сама запускает Windows-консольные программы цепочкой (Oracle → `vcvars64.bat` → `cl`, или python → `cmd`), падает с кодом 3221225794 (`0xC0000142`, STATUS_DLL_INIT_FAILED) ДО первой команды. Те же команды из обычного окна с консолью отрабатывают (`vcvars64.bat` за 4 с, Stage A 75 с).
- Пробы интегратора: простой `cmd /c exit 0` и `vcvars` через очередь иногда проходили (rc 0), раннер и Oracle стабильно падали: значит зависит от способа запуска, а не от окружения (`SystemRoot` и прочее там было).
- На машине десятки `conhost.exe` (77), 19 на `bash.exe` — возможна утечка консолей и нехватка памяти рабочего стола; причина не доказана.

## Что нужно

1. **Воспроизведение** (красная проба до кода): тест или скрипт в `opencode-plugin/test/`, который запускает через ту же функцию `start` команду, зовущую `cmd /c "<путь к vcvars64.bat> && where cl"` (путь — из переменной окружения теста или поиска Visual Studio Build Tools; нет VS — тест пропускается явно, не молча), и показывает код 3221225794 при текущем запуске. Если воспроизвести не удалось — описать, что пробовали, и какое условие надо добавить.
2. **Причина и исправление:** найти, чего не хватает процессу (консоль, станция окон, наследование дескрипторов, `windowsHide` и `detached` вместе), и дать запуску рабочую консоль, СОХРАНИВ прежние свойства watch: переживает плагин, не мигает окнами, `.exit` пишется атомарно, `taskkill /T` по дереву, таймаут. Варианты для проверки: `detached: false`; запуск через `cmd /c start "" /b /min` или `conhost.exe --headless`; `windowsHide: false` с минимизацией; общая скрытая консоль на службу плагина; для каждого — результат пробы. Выбранное решение подтвердить тестом (vcvars проходит, 5 запусков подряд) и тестами существующих watch (`crew-watch*.test.mjs`).
3. **Утечка консолей:** проверить, закрывается ли `conhost` после завершения watch и после `taskkill`; счётчик процессов до и после серии из 20 запусков; если растёт — исправить; нет — записать в разбор.
4. **README плагина** (раздел про watch) и справка `crew_watch`: как запускается команда, что даёт консоль, известные ограничения.
5. **Проверки:** `npm test` из `opencode-plugin/` (параллельно до 4 файлов), красная проба до кода, затем зелёные; стражи 8 и больше, FAIL 0; коммит по правилам AGENTS.md (английское сообщение, `-s`, без трейлеров и без `#число`, файлы перечнем).

## Критерии приёмки

- Воспроизведение 0xC0000142 показано красным на текущем коде и зелёным после исправления (vcvars из `crew_watch` с `machine: true` проходит).
- Существующие тесты watch зелёные; свойства watch сохранены (переживает плагин, `.exit` атомарно, дерево убивается).
