# Разбор 057: перепоручение задачи с уточнённой целью

Задание — `task/message.md`. Записан оркестратором по отчёту исполнителя (инструмент записи у исполнителя отказал).

## Как было

- `crew_task reassign {n}` (`opencode-plugin/core.ts`, ветвь `reassign`): снимает прежнего исполнителя (`releaseExecutor`), собирает сводку его писем автору (`handoffOf` → `t.handoff`), увеличивает `t.attempt`, пишет новый id сессии и событие истории «передана новой сессии» (`taskEvent`), запускает сессию `host.startTask(t)`.
- Первое письмо новой сессии собирает `formatTaskLetter(t)` (для задачи-плана — `planTaskLetter`) только из полей записи задачи: `goal`, `criteria`, `boundaries`, `handoff`. Кладёт его запуск сессии (`index.ts`); id письма `taskLetterId` = номер + попытка, повтор оборванного запуска кладёт то же письмо.
- Поля для уточнения у `reassign` не было (`text` читали только `push`, `cancel`, `submit`, `rework`). Интегратор передавал исходную цель, а уточнение слал вторым письмом уже после старта; новая сессия успевала начать по старой цели — две серии старта и два отчёта (C4 по папке 045, 2026-10-15).

## Что сделано

- `reassign {n, text?}`: `text` пишется в запись задачи (`Task.refinement`: текст, время, кто) до запуска — входит в первое письмо и в повтор оборванного запуска.
- Письмо: блок «УТОЧНЕНИЕ ПРИ ПЕРЕДАЧЕ» после заголовка, перед целью, и строка «Действует уточнение: где прежняя цель ниже с ним расходится — делай по уточнению»; цель — «ЦЕЛЬ (исходная; действует уточнение выше)». У задачи-плана блок стоит перед «ИСХОДНАЯ ЗАДАЧА». Без `text` письмо прежнее.
- История — «…; уточнение при передаче: <текст>»; `crew_task view` — строка «уточнение при передаче: …»; ответ инструмента — «с уточнением цели».
- Уточнение держится до следующего `reassign` с текстом; передача без текста его не теряет.
- Описание `crew_task` («уточняй тем же вызовом, не вторым письмом»), `crew_help`, README плагина; в снимке `answer-golden.json` изменилась только строка `crew_help`.

## Другие передачи с тем же недостатком

- `order`: письмо заказа собирается один раз при постановке; уточнить — только письмом или отменой и новым заказом. Не правилось.
- Повтор оборванного запуска: недостатка нет, письмо строится из записи.
- `rework`, `push`: тот же исполнитель, новой сессии нет.
- Раунды перепроверки плана и приёмка новой сессией получают отчёт или план, а не цель.
- Письма «сессия пропала» и «застряла» (`index.ts`) советуют `reassign` без упоминания `text`. Не правились.
