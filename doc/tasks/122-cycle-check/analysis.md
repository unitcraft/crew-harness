## 2. Данные, примитивы и внешние объекты

**Данные:** стадия, номер_захода, заход_отсчёта, серия_чистых, без_проб_подряд, вне_задачи, находки_В3, проходов_по_доказательству, сужено, вердикт, источник_вердикта, сессия, источник_запуска, заход_запуска, продолжение, итог_сессии, причина_сбоя, остановка, четыре счётчика попыток; из входа без изменений: чистых_подряд, потолок_заходов, проб_в_чистом, маршрут, сдача_сжата, папка_задачи, рабочее_дерево, режим_сдачи, предложение, порядок_линз, вопрос_автора; данные фрагмента: предыдущее, запрос_вызова, открытые_запросы (всего 35 данных машины и 3 фрагмента). Внешние объекты `свод[номер_захода]` и `находки_проверки[номер_захода]` — хранилище, которое пишет исполнитель при приёме ответа сессии проверки (правило 14); в Портолане это словари данных, их пишет блок «При приёме» обращения ЗАПУСК_СЕССИИ (формат 4.4).

**Константы методики:** МИНИМУМ_ЧИСТЫХ_ПОДРЯД 1, МИНИМУМ_ПРОБ_В_ЧИСТОМ 3, ПОТОЛОК_ДОКАЗАТЕЛЬСТВА 3. Числа цикла (чистых_подряд, потолок_заходов, проб_в_чистом) — данные задачи из входа (решение 17 первоисточника).

**Определения:** `потолок_исчерпан` — из подключаемого файла `арифметика_цикла` (хеш образца 2.11 `fad927a77d32`, в продукте уже есть); `проверяющий`, `правщик`, `есть_находка_уровня`, `счётчик_доказательства`, `обновить_счётчики`, `наибольший_счётчик`, `сбросить_достигших`, `без_достигших_потолка`, `записи_сужения`, `находки_цикла` — по терминам первоисточника. `сброс_отсчёта` и `шаг_без_проб` слоя методики записаны присваиванием и условием.

**Примитивы.** Условия не зовут ни одного. Единственный — необратимый `остановить_группу_агента` (`stop_agent_group`): при входе в ОСТАНОВЛЕНО и ОШИБКУ группа процессов агента останавливается целиком (план 105: `ir_proc_kill`, `ir_agent_close`, «Проверка цикла (StopAgentGroup)»). Он идёт данными реестра (`standard_registry()`, тестовый исполнитель — `ScriptedHost`); боевого нет. `rd_task_document`, `pure_doc_status`, `rd_tree_diff` из строк плана — примитивы Раннера (`specification`, `status_equals`, `tree_diff`, СДАЧА_ДИФФ), а «Проверка цикла» получает находки и итоговую строку в ответе вложенной машины запуска сессии и файлов задачи не читает; они остаются задаче 123.

Вызов сверху (Раннер, задача 123): `machine cycle_check(вход ВходПроверки, итог ИтогПроверки)`; поля запроса — 14 полей раздела `## Вход` (стадия, цикл, вне_задачи, папка_задачи, рабочее_дерево, режим_сдачи, маршрут, чистых_подряд, потолок_заходов, проб_в_чистом, сдача_сжата, предложение, порядок_линз, вопрос_автора). ## 4. Что из таблицы не ложится на возможности интерпретатора

1. **Глубина вложенности.** Проверка вызывает вложенные машины и сама вызывается Раннером; прогонщик пары задачи 119 держит один уровень (`check_registry` называет ребёнка-вызывающего ошибкой). Поэтому сценарии 122 идут на обычном прогонщике с ключом `standalone`: ответы вложенных сторон подают шаги `answer`/`failure`. Пара «Раннер + проверка цикла» — задача 123.
2. **Ответы на паузе (правило 14)** сбрасываются как `event_ignored`, не удерживаются; после «продолжить» ЗАПУСК_СЕССИИ входится заново без открытого запроса. Закреплено сценарием `cycle-flow-pause-answer-dropped`; чинить в 123.
3. **Типы вызова** объявляются в обеих машинах и совпадают структурно (`check_nested`). Типы слоя методики записаны дословно; 121 и 124 обязаны объявить те же поля (закреплено `fit_test.nv`). Находка совещания — другой тип с тем же именем, в таблице он `MeetingFinding`.
4. **Вердикт — перечисление, а не Текст** (предложение методики, «Что движок не покрыл», п. 12): `?Вердикт` со словами журнала `clean`, `requirements`, `plan`, `question`, `restart`, `stopped`; `вердикт_из_текста` не нужна.
5. **Слова остановки и метка продолжения** — наборы литералов (`"retry_halt"`, `"session_launch_stopped_by_human"`, …; `"review"`, `"fix"`, `"not_doing"`).
6. **Строки `иначе`** двенадцати развилок и строка 6 общих событий защитные: ни одна последовательность событий их не берёт. ОТКАЗ_СЕССИИ #3 берётся (код сбоя `Timeout`).
7. **Дата слова «остановиться»** читается СТАДИЕЙ_ОСТАНОВКИ как `событие.дата` исходного события цепочки.
8. **Данное `источник_запуска`** по словарю получает имя `source`, как привязка поля `источник` фрагмента «Пауза»; формат запрещает затенение, в таблице данное названо `launch_source`.
9. **Режим «показывать и продолжать» у В3, ответ ворот вратарём-агентом** — механика исполнителя ворот, в таблицу не входят; упрощённые ворота выпуска alpha и pre-release — норма, а не механизм (решение 28).

## 5. Как проверяется равенство с методикой

1. Тест держит копию таблицы методики как данные (состояние, номер строки, «Куда» всех 71 строки; получено программой из файла методики; ОШИБКА = `ошибка_машины`) и сверяет с деревом: число строк, цель каждой строки, вид, сторона, слова ворот.
2. Тест держит копию таблицы журнала: статически (каждый код, который пишет таблица, есть у методики с теми же параметрами; каждый код проверки там записан) и на сценариях.
3. Сценарии `cycle-*`: по сценарию на каждую строку, которую можно взять, плюс сквозные; тест покрытия по метке `taken` требует, чтобы каждая строка была взята сценарием с её именем.
4. `compile → render → compile` и `convert` ru → en → ru дают равное дерево; файл `.json` — перевод `.md` побайтово.
