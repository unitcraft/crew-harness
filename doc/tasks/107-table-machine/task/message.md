Заказчик: владелец репозитория `unitcraft/crew-harness` (он же принимает результат).
Репозиторий: `unitcraft/crew-harness`, ветка `main`. Дата задания: 2026-10-19.
Эпик: [001-crew-service](../../001-crew-service/); продолжает [091](../../091-product-engine/), [102](../../102-align-glossary/) (словарь методики, `Machine[S]`, `Transition`, `Environment`, структурный журнал) и 106 (ядро: значение, вычислитель выражений, реестр примитивов; папка пока не в main, ветка задачи 106 — основа этой).
Источник: слова владельца в чате оркестратора, 2026-10-19: «цель: все возможности текущие (плагин crew-harness под opencode) + стейт-машины из методики должны быть написаны на таких стейт-машинах внутри голого продукта CrewHarness»; «по рекомендации» (строить интерпретатор после подтверждения формата: пилоты Методики на v2.1 — «Шаг агента» 97,8 % и «Совещание» 96,7 % единиц без оговорок).

Задача полная: разбор, реализация, сдача. Быстрый путь. Основа — ветка задачи 106 (ядро), цепочка слияния: 106, затем эта. Код под `src/machine/` (английские идентификаторы), тесты рядом; правки движка допустимы только если неизбежны и обоснованы; `src/chat/`, `src/acp`, `src/server` не менять.

## Что нужно

1. **Образцы и источники:** нормативный формат `state-machines/state-machine-portolan-spec.md` (версия 2.1 в `main` методики, коммит 33d2104; v2.2 выходит; читать в публичном репозитории методики, только чтение), пилоты Методики (только чтение; выписки машин на формате лежат у оркестратора, путь в промпте исполнителя), `src/machine/README.md` и код ядра (задача 106), `src/engine/` (`Machine[S]`, `Transition`, `Environment`, `Incoming`, `Waiting`, структурный журнал), `src/chat/` (машина чата — образец), черновик JSON-дерева в `draft-format-v1.md` (рабочее дерево задачи 104, раздел 6; путь в промпте исполнителя), `spikes/env/README.md` (ограничения Oracle 0.1.0 п. 1–31: без обобщённых протоколов с выводом параметров, одна папка — один юнит, вывод юнита до 4096 байт).
2. **JSON-схема машины `machine/2`:** файл JSON Schema (`src/machine/schema/machine-2.schema.json`) и проверка структуры в Нове (обязательные поля, виды состояний, события по вариантам, столбцы строк, действия, сторона, конец, данные с пометками, параметры, константы, определения, подключения); документ формата в README. Содержание — по нормативному формату (разделы 1–9, 12, 13) и словарю имён методики (латинские имена).
3. **Интерпретатор `TableMachine`:** реализует протокол `Machine` движка поверх ядра 106: загрузка машины из JSON с проверкой (правило 11: чтения выражений ⊆ «Вход», записи ⊆ данные машины; достижимость состояний; исчерпанность «Концов»; допустимость класса примитива в позиции; значения «Куда»); `step`: первая подходящая строка, «При приёме» ДО перехода (правило 14), «При входе» операции и конца, `сразу`, события по вариантам с привязкой полей, слова ворот, общие события и фрагмент «Пауза» (раздел 9 формата), умолчание развилки и `ошибка_машины`, «Куда: предыдущее / возврат_подготовки / запуск заново»; действия: `поле = выр`, `+=`, `поле[ключ] = выр` и путь `имя[ключ].поле`, `журнал(код, параметры)` (структурное событие, `текст()` значений), `для каждого`, `пусть`, `ошибка_машины`; обращение: запрос из выражений «Вход», сторона, срок тишины; конец: условие входа, ответ `Ответ(…)`/`Отказ(код, текст)`; данные: начальные значения (`вход.<поле>`), «не убывает», `пишет: механика`; проверка типов данных при записи; вызов примитивов через `PrimitiveHost` движка продукта. Состояние машины — значение `Value` (кодируется в снимок как вложенный объект), детерминизм: два прогона дают тот же журнал и данные.
4. **Прогонщик сценариев** `scenario/0`: файл JSON «события → ожидаемые состояние, структурный журнал, подмножество данных, очередь»; запуск на движке продукта с обработчиками в памяти; сравнение и понятный отчёт о расхождении; формат — в README; сценарии как данные в `src/machine/scenarios/`.
5. **Перенос машины чата** (`src/chat/`, многооборотная и однооборотная) на JSON-машину `src/machine/machines/chat.machine.json` (рукописный JSON; переводчик таблиц — следующая задача) и ДОКАЗАТЕЛЬСТВО равенства: на всех сценариях существующих тестов машины чата (`chat_test.nv`, `chat_engine_test.nv`, сценарии из `src/server/testkit.nv` или их аналоги) интерпретатор и машина на Нове дают ту же последовательность (состояние, событие журнала, данные машины, очередь); отчёт о равенстве — в `analysis.md`; расхождение — найденная ошибка либо записанное решение.
6. **Проверки:** красная проба до кода; `nova test src --jobs 4` (на временном контейнере PostgreSQL по необходимости: `src/pg/testdb.ps1`, `-Stop` после) и `--strict-effects`; не менее 200 новых проверок (схема, загрузка и проверки машины, каждая конструкция действий и строк, обращение, конец, пауза, сценарии, равенство с машиной чата, «смерть между изменениями» и «другая сторона в окне» по правилам 13 и 34(е)); стражи 8 и больше, FAIL 0; коммит по правилам AGENTS.md (английское сообщение, `-s`, без трейлеров и без `#число`, файлы перечнем).
7. **README** `src/machine/README.md` (английский): схема, интерпретатор, сценарии, перенос чата, ограничения Oracle; новые ограничения — воспроизведения в `spikes/env/repro_*` и в отчёт.

## Критерии приёмки

- Машина чата в JSON исполняется интерпретатором и даёт те же журнал, данные и очередь, что машина на Нове, на всех сценариях существующих тестов (отчёт о равенстве).
- Схема `machine/2` и проверки загрузки красные на нарушении (красные пробы: чтение вне «Входа», запись вне данных, недостижимое состояние, недопустимый класс примитива, неисчерпанные концы).
- Прогонщик сценариев показывает расхождение понятным отчётом; сценарии — данные.
- `nova test src --jobs 4` зелёный (и `--strict-effects`); не менее 200 новых проверок; стражи 8 и больше, FAIL 0.
