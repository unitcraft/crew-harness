## 1. Что сделано

Код — четыре соседние папки, потому что одна папка есть один модуль и один юнит Oracle 0.1.0 (п. 25), а вывод юнита не больше 4 КБ (п. 20):

- `src/machine/` (ядро 106): `DefFn`, `DefTable`, `eval_defs` (определения машины), проверка вызовов примитивов по реестру, функции `record_text` и `non_empty`; данные, вшитые в бинарь: `schema/`, `machines/`, `scenarios/`; 7 тестов.
- `src/machine_table/`: модель машины, разбор типов, разбор дерева `machine/2` со структурной проверкой и путём ошибки, проверки таблицы `check_machine` (54 теста).
- `src/machine_run/`: интерпретатор `table_step` и `TableMachine` по протоколу `Machine[TableState]`; состояние — значение ядра, кодируется объектом в снимок; `ScriptedHost` как `PrimitiveHost` по умолчанию; прогонщик `scenario/0` (60 тестов).
- `src/machine_chat/`: тесты равенства машины чата в JSON и машины на Нове (11 тестов).
- Данные: схемы `machine-2.schema.json`, `scenario-0.schema.json`; шесть машин (`chat`, `calc`, `actions`, `gate` с развёрнутым фрагментом «Пауза», `lenses` с набором сторон, `variants`); 56 сценариев.
- README `src/machine/README.md` (английский); `spikes/env/README.md` пп. 32–35.

## 2. Решения исполнителя и расхождения с форматом

- **События `progress` и `timeout`.** Движок знает части ответа и срок, формат 2.2 нет; машина чата различает отказ с кодом `Timeout` и срок — по формату они неразличимы. Добавлены в JSON; замечание методике.
- **`signal` и `cancel_open` в строках обращения:** чат отменяется пользователем в ожидании ответа агента, поэтому допущены.
- **Старт.** У `initial()` нет входа; машина со входом или с начальным состоянием, которое что-то заказывает, ждёт слово `start`; машина с начальным обращением к человеку (чат) стартует сразу.
- **Журнал интерпретатора:** `event_ignored`, `event_unknown`, `event_malformed`, `input_rejected`, `machine_error` (закрытый перечень причин), `machine_defect`, `machine_data`, `signal_passed`, `fork_no_match`.
- **Ошибка машины и дефект.** Ошибка — событие журнала и конец ОШИБКА, записи до ошибки остаются; дефект (`require(none)`, `non_empty("")`, ошибка типа, которую должны были снять проверки) — `machine_defect`, конец с `NoResult`, состояние как было: остановить процесс из `step` нельзя.
- **`все_данные`** пишется парами `имя=значение` в порядке данных; кодирование ША1 формата 2.2 не воспроизведено: JSON ядра полнее и проверен.

- «Смерть между изменениями» и «другая сторона в окне» (правила 13 и 34(е)): сценарии `chat-restart-before-send` и `chat-cancel-in-window` на обеих машинах и тест «death between».

## 4. Отчёт о равенстве с машиной чата

Сравниваются машина чата на Нове и `chat.machine.json` на 39 сценариях (все случаи `chat_test.nv` и `chat_engine_test.nv`: запуск, куски и ответ, десять кодов отказа и неизвестный, отмена в двух состояниях, срок и его продление, игнорируемое и неизвестное, независимость от конверта и часов, кириллица, части инструментов и разрешений, закрытые и неизвестные запросы, три перезапуска, подтверждение источника, отмена в окне между фиксацией и отправкой). Шагов больше ста, событий на уровне машины больше восьмидесяти. Сравнивается на движке над памятью: имя состояния, данные, события журнала, все строки журнала с конвертом, открытые и отправленные и отменённые запросы, очередь, подтверждённые ключи, итог, номер шага; на уровне одного `step`: приказы по порядку, переход, данные. Расхождений нет. Намеренная порча JSON (код `cancelled_while_waiting` без последней буквы) делает три теста красными с указанием шага.

## 5. Новые ограничения Oracle 0.1.0 (воспроизведения — `spikes/env/repro_engine/src/`, п. 32–35 `spikes/env/README.md`)

32. `for_in_record_list_literal`: литерал списка записей из вызовов в `for` не собирается.
33. `type_named_like_variant`: пользовательский тип с именем варианта чужого перечисления ломает использование варианта.
34. `user_type_next`: запись `Next` (также `Slot`) ломает сборку стандартной библиотеки.
35. `same_type_name_two_modules`: одноимённые записи двух модулей программы смешиваются.

Нумерация с 32 → переписать при слиянии с задачей 099 (оркестратор).

## 6. Границы и что дальше

- Формат 2.3 (нотация без двоеточия, кортеж с нуля, спред, определение `все_данные`, сужение `без_возврата_в_к_отправке`, закрытая таблица «роль → тип», нормализация хеша определений) → задача переводчика таблиц: интерпретатор следует 2.2, JSON от нотации не зависит.
- `@prepare_return` (правило 24) → не нужно в этой задаче, потому что подготовку при старте делает исполнитель, а не таблица.
- `трасса`, `номер_шага` (конверт вызова вложенной машины), вложенные машины и `передать` → задача 105 (этап вложенных машин): в движке нет вызова машины из машины.
- Запись данных пишущим примитивом → задача 105 (перенос «Совещания»): нужен протокол обновления данных `PrimitiveHost`.
- Исполнение `профиль`, `Предел запросов`, `Правит`/`проверка`, `Возвратов формы` → задача 105: у движка нет профиля, возврата формы и проверки отпечатка.
- Данные механики (`открытые_запросы`, счётчики попыток) → не нужно в этой задаче, потому что их ведёт движок.
- Файлы определений (подключение по хешу) → задача переводчика таблиц: реестр подключаемых файлов формат не задал.
- Переводчик таблиц на русском в JSON → следующая задача по плану эпика.
- Замечания методике (части ответа и срок в формате; слово другой стороны в обращении как сигнал; код журнала для отказа вызова при нарушении инварианта входа; начальное состояние с заказом требует события старта) → не нужно в этой задаче, потому что репозиторий методики только для чтения; оркестратор передал письмом.
