# ADR-0006. Публичный репозиторий: без приватных данных

## Контекст

Репозиторий `unitcraft/crew-harness` публичный. В документах и комментариях оказались пути машины владельца и имена
приватных репозиториев проекта nova. Владелец, 2026-10-07: «не надо приватных данных в публичной репе, укажи
https://github.com/nv-lang/nova».

## Варианты

1. **Сделать репозиторий приватным.** + проблема исчезает. − продукт задуман открытым.
2. **Публичный, приватное не пишем; текущие файлы вычищены.** + открытость сохраняется. − нужна дисциплина и проверка
   перед коммитом.
3. **Публичный и переписать историю.** + следов нет и в истории. − силовой пуш, он запрещён (AGENTS.md п.5); хеши
   коммитов меняются.

## Решение

Варианты 2 и 3: приватное не пишем, а уже попавшее вычищено и из истории. Не пишутся: локальные пути машины, учётные
данные, адреса стендов, имена репозиториев и проектов владельца, кроме публичных https://github.com/nv-lang и
https://github.com/unitcraft (другие его проекты не называются вовсе). Примеры путей — общие (`C:/work/...`); Нова —
https://github.com/nv-lang/nova. Текущие файлы вычищены (`a566613`, `7c5d24e`; так же в соседних репозиториях
плагинов); история переписана один раз по прямому слову владельца («почисти историю»; силовой пуш — исключение из
AGENTS.md п.5), ссылки на коммиты в документах переназначены тем же днём.

## Последствия

- \+ Репозиторий можно показывать.
- − Хеши всех коммитов до чистки сменились; старые клоны надо пересоздать.
- − Проверка перед коммитом пока ручная (поиск по `D:/`, `D:\`, `C:\Users\`); механизм (хук) — кандидат в задачу.
  Живём так: перед каждым коммитом и пушем — поиск по этим образцам; правило — [AGENTS.md](../../../AGENTS.md).

**Уточнение, 2026-10-08 (владелец, [задача 002](../../tasks/002-guards/)): механизм заведён.** Ручной поиск заменили
стражи: `scripts/guards/guard-secrets.py` (секреты и пути машины), `scripts/guards/check-private-names.py` (список
запрещённых имён вне репозитория) и `scripts/guards/guard-commit-message.py` (сообщения коммитов); их вызывают хуки git
`pre-commit`, `commit-msg`, `pre-push` и CI. Хук git обходится `--no-verify`, поэтому CI проверяет то же после пуша;
уже опубликованное стражи не вычищают.

## Границы

Публичная документация вендоров и сторонних инструментов (агенты, оркестраторы) — можно: это не проекты владельца.
