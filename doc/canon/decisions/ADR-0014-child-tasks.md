# ADR-0014. Дети задачи: плоская нумерация, отдельная сессия, таблица `task/children.md`

## Контекст

Подзадачи жили внутри одной сессии: файлы `message.N.md` и `progress.N.md` в папке родителя, один агент на всё, номера подзадач — части родителя. Владелец,
2026-10-27 (чат оркестратора): «подзадачи — это отдельные воркеры с сессиями, они должны отображаться в дереве сессий (вложенно под родительской, как у Claude
Desktop)»; «для эпика всё аналогично». Тем же днём: нумерация с точками (`232.1`) отвергнута — «нет, т.к. в трекерах такого нет»; слаг ребёнка несёт номер и слаг
родителя («ты забыл добавить номер родителя в слаг»); у задачи может не быть подзадач, «В работу» по умолчанию заводит самостоятельную задачу; таблица детей —
один файл для обоих видов родителя; правила надо записать в Каноне и закрепить стражем («куда ты записываешь все эти правила, как они будут выполняться в Крю?»).

## Варианты

1. **Подзадачи остаются внутри сессии родителя** (`message.N.md`, `progress.N.md`). + ничего не менять. − один агент, ходы не параллельны, подзадачи не видны в списке сессий.
2. **Ребёнок — своя задача и своя сессия, номер с точкой** (`NNN.N`). + связь видна в номере. − в трекерах такого нет; папка и ветка выходят из принятого вида `NNN-слаг`.
3. **Ребёнок — своя задача и своя сессия, номер плоский, связь в данных.** + номер, ветка, дерево и папка как у любой задачи; параллельные агенты; вложенность в списке сессий. −
   связь надо хранить отдельно (строка в `message.md`, таблица у родителя, `parent_session` в журнале) и проверять.

## Решение

Вариант 3.

- **Иерархия:** эпик → задача → подзадача. Ребёнок — обычная задача со своим следующим общим номером `NNN` (следующий свободный в `doc/tasks` и ветках), папкой `doc/tasks/NNN-<слаг>/`,
  веткой `task/NNN-<слаг>`, деревом `<проект>-NNN-<слаг>`; точек в номере нет. Ребёнок — отдельная сессия хаба со своим агентом и своим деревом; в списке сессий он вложен под
  сессией родителя (`parent_session` в журнале сессии); ходы родителя и детей параллельны.
- **Слаг ребёнка** — `<номер родителя>-<слаг родителя, до 20 знаков>-<слаг названия>`, например `233-232-privet-panel`: номер родителя не обрезается, обрезается слаг родителя; для
  вложенных детей берётся только прямой родитель. Задача без родителя — слаг как раньше.
- **Первая строка `task/message.md`:** `Эпик: NNN` у задачи эпика (по методике), `Родитель: NNN` у подзадачи; у самостоятельной задачи такой строки нет, как и таблицы детей. Тип ребёнка
  определяется по первой строке.
- **Таблица детей** — `task/children.md` в папке родителя (задачи или эпика), один файл и формат для обоих видов родителя: колонки «Номер, Тип, Название, Папка, Ветка, Сессия, Состояние,
  Затрагивает»; тип — подзадача / задача эпика / задача; состояние — идёт / ждёт K / готово / слита. Файл создаёт и ведёт хаб (при появлении первого ребёнка, при смене состояния,
  при слиянии, раз в 2 секунды сверяет), его можно править руками: хаб читает строки обратно. Прогресс родителя — слитые из всех.
- **Куда сливается ребёнок** — выводится из родителя: у родителя есть ветка и дерево — в ветку родителя (конфликт решает агент ребёнка, потом владелец); нет ветки — в `main` своим
  «Слить в main». Родитель закрывается последним (пока есть неслитые дети, «Слить в main» держится; «Слить подзадачи по порядку» вливает их по очереди); эпик закрывается, когда слиты все его
  задачи.
- **Лимит** `route_max_active` считается по всему хабу среди запущенных детей и задач; слово «сверх» и очередь — как прежде; работа, чьи файлы пересекаются с запущенной, ждёт её или идёт
  параллельно в своём дереве (по выбору владельца).
- **Слово владельца** — «владелец, 2026-10-27» (чат оркестратора); выбор способа оформления работы (отдельная задача / подзадача задачи K / задача эпика E / дополнить K) — за владельцем в
  карточке распознанных, по умолчанию — отдельная задача.
- **Механизм:** страж [`check-task-docs.py`](../../../scripts/guards/check-task-docs.py): если первая строка `task/message.md` — `Эпик: NNN` или `Родитель: NNN`, папка этого номера есть в `doc/tasks`, а
  если у неё есть `task/children.md` — в таблице есть строка ребёнка; формат `children.md` проверяется (правила `parent-missing`, `children-row`, `children-table`). Старые задачи без таких
  строк и дети эпика 001 (строка со ссылкой, не первой строкой) не судятся.
- **Отменено:** `message.N.md` и `progress.N.md` в родительской задаче для новых подзадач (старые читаются как есть); нумерация с точками `NNN.N` (ветки `task/NNN.N-…`, сообщения слияния
  «NNN.N: …»).

## Последствия

- \+ Подзадачи работают параллельно, видны в списке сессий, у каждой своя постановка и свой чеклист; связь проверяется машиной.
- − Связь не видна в номере: ищется по строке `message.md`, таблице и журналу. Живём так: панель задачи показывает родителя и детей.
- − Папка ребёнка живёт в его дереве, пока он не влит; таблица родителя до слияния лежит в дереве родителя. Живём так: таблица пишется в дереве родителя, а страж смотрит дерево коммита.
- − Список детей хаб держит и в файле, и в журналах сессий; расхождение (удалённая сессия) читается по строке файла.

## Границы

Не касается старых задач и эпика 001 (его журнал и имена папок прежние). Не вводит новых полей задачи, кроме перечисленных. Алгоритм старта сессии (ветка `wip/…`), перенос первой задачи в дерево
сессии и срок 30 дней без активности — отдельные решения, здесь не принимаются.
