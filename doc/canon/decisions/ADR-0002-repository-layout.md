# ADR-0002. Репозиторий — продукт целиком

## Контекст

Исходники плагина OpenCode лежали в корне репозитория. Владелец, 2026-10-07: «не нравится, что исходники в корне…
завести папку opencode-plugin»; «использовать crew-harness — как репу под новый продукт».

## Варианты

1. **Корень = плагин, новый продукт — отдельный репозиторий.** + плагин не трогаем. − две истории, общие правила и
   документы дублируются; продукт и плагин делят ящик данных на время переезда.
2. **Один репозиторий, части — папками** (`opencode-plugin/`, `service/`, `web/`, `doc/`). + одна история, один
   набор правил и решений; переезд виден целиком. − перенос плагина потребовал перезапуска живого сервиса; у частей
   разные языки и наборы тестов.

## Решение

Вариант 2. `opencode-plugin/` — плагин (TypeScript, в работе); `service/` — сервис координации; `web/` — пульт;
`doc/` — `tasks/`, `decisions/`, `process/`, `research/`, `plans/` (архив). Сделано: коммиты `5f723fa`, `07205be`.

## Последствия

- \+ README корня описывает продукт, у плагина свой README.
- − Пути установки плагина у пользователей сменились на `…/crew-harness/opencode-plugin`; провайдер ищет MCP плагина
  и по новому, и по прежнему пути.

## Границы

Папка задачи и её материалы — в `doc/tasks/`, не в коде частей.

**Уточнение, 2026-10-07 (владелец).** Правила разработки собраны в Канон — `doc/canon/`: `process.md` (бывший
`doc/process/`), `decisions/`, `plans/`; `AGENTS.md` остаётся в корне. В `doc/` кроме Канона — `tasks/` и `research/`.

**Уточнение, 2026-10-07 (владелец).** `plans/` из Канона убраны в `doc/archive/plans/`
([ADR-0007](ADR-0007-plan-in-task-epics.md)); в `doc/` кроме Канона — `tasks/`, `research/`, `archive/`.
