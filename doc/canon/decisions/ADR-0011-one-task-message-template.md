# ADR-0011. Задание задачи — по одному образцу Канона; плагин собирает его из полей, страж судит новые задачи

## Контекст

Методика формы задания не задаёт: «текст сообщения и ссылки — файлом task/message.md», раздел «Связи» — когда задач несколько
([`task-sessions.md`](https://github.com/unitcraft/ai-dev-methodology/blob/78ed758/task-sessions.md), «Порядок», пп. 2 и 7). Задания
расходились: плагин собирал из полей `crew_spawn` разделы «Цель / Критерии приёмки / Границы / Открытые вопросы» (цель — один
сплошной текст), оркестратор писал «Чего хочет владелец / Что нужно / Результат и куда он попадает / Границы». Владелец, 2026-10-17, чат
оркестратора: «я заметил, что в doc/tasks/NNN задачи и у тебя задачи совершено в разных форматах, это почему и можно ли
унифицировать?»; на предложение одного образца — «по рекомендации, делай быстрым способом».

## Варианты

1. **Один образец в Каноне, плагин собирает по нему, страж судит новые задачи.** + одна форма у всех заданий, сессия ищет цель, слова
   владельца и место результата в одном месте; отказ плагина ловит пропуск до коммита папки. − плагин требует больше полей, прежний вызов
   `crew_spawn` в проекте с папками получает отказ.
2. **Образец — только текстом Канона, без плагина и стража.** + ничего не ломается. − расхождение остаётся: плагин по-прежнему пишет свои
   разделы, проверка — только глазами приёмки.
3. **Плагин пишет пустые разделы «нет: поле не передано» вместо отказа.** + прежние вызовы работают. − задание без слов владельца и без
   места результата проходит молча, а это нормы ([AGENTS.md](../../../AGENTS.md), п. 2; методика, «Результат и куда он попадает»).

## Решение

Вариант 1. Образец — раздел «Задание task/message.md» в [process.md](../process.md). `crew_spawn` и `crew_task assign` в проекте с
папками задач собирают задание по нему из полей `owner_words`, `goal` (пунктами), `criteria`, `result`, `links`, `boundaries`;
без `owner_words` с датой и без `result` — отказ с подсказкой; `links` и `boundaries` не переданы — раздел «нет: … не передано».
Текст `message` без разделов образца — отказ. Проект без папок задач и сессия существующей задачи — без изменений. Страж
`check-task-docs.py` судит задачи, заведённые не раньше 2026-10-17 01:00.

## Последствия

- \+ Все новые задания одной формы; «Что нужно» — пунктами, а не абзацем; слова владельца и место результата обязательны.
- \+ Пропуск раздела виден до слияния: отказ плагина или красный страж.
- − Интегратор, привыкший к прежнему вызову, получает отказ и повторяет вызов с полями: цена — один лишний вызов, отказ называет поле и
  пример.
- − Плагин навязывает образец и проектам с папками задач вне этого репозитория; другой образец — отдельное решение (ключ проекта).
- − Раздел «Связи» обязателен и у одиночной задачи — строка «нет: <почему>»; отличие от методики записано в process.md.

## Границы

Не касается прежних заданий (до 2026-10-17 01:00 — не судятся и не переписываются), задач без папок (`#N`), задач-планов, писем
исполнителю и содержания разделов (дословность слов владельца и честность «нет: <почему>» судит приёмка).

Когда пересмотреть: методика задаст свою форму задания; другой проект с папками задач попросит свой образец.
