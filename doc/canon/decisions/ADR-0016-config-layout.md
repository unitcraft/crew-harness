# ADR-0016. Раскладка настроек и данных: корень экземпляра, слои, роли и наборы, подсказки в файлах

## Контекст

Пульт управления хранил всё в одной папке `data_dir` (сессии, `projects.json`, `agents.json`, `last_dir.txt`, `stt.pid`, копия настроек OpenCode), а настройки — одним файлом по аргументу `serve <файл>` и
переменными `CREW_SERVER_*`. Личные настройки, общие настройки проекта, секреты и служебные файлы лежали вперемешку; у проекта своей папки настроек не было; тексты, которые хаб говорит агентам, были
зашиты строками в коде; «независимый проверяющий» выбирался только порядком `route_reviewer_order`. Владелец, 2026-10-29 (чат оркестратора, «по рекомендации»): организовать конфиги и каталоги по образцу
индустрии (git, VS Code, Claude Code, Codex, XDG).

## Варианты

1. **Оставить `data_dir` и один файл настроек.** + ничего не менять. − данные, служебное и производное в одной куче (удалить кэш, не потеряв сессии, нельзя); общих настроек проекта нет.
2. **Корень экземпляра с фиксированными подпапками и папка `.crew-harness/` в проекте с теми же именами; слои настроек.** + привычно по образцу индустрии; ясно, что можно удалять; проект несёт общее
   (в git) и личное (вне git). − два места настроек, нужны правило слоёв и команда `config list --show-origin`.
3. **Портативный режим (папка рядом с бинарником).** + удобно переносить. − лишний способ поиска корня, лишние ветки кода.

## Решение

Вариант 2. Портативный режим **не делается**.

- **Корень экземпляра `CREW_HOME`:** аргумент `--home <папка>` → переменная `CREW_HOME` → `<домашняя папка пользователя>/.crew-harness` (на Windows `C:/Users/<имя>/.crew-harness`). Внутри корня
  фиксированные подпапки: `config/` (настройки пользователя: `config.json`, `roles.json`, `presets/`, `modes/`, `prompts/`, `secrets.json`), `data/` (то, что нельзя потерять: `projects.json`,
  `sessions/<id>/` — журнал, снимок, `acp.jsonl`, `inbox`, `images`), `state/` (служебное, можно удалить: `serve.*.log`, `stt.pid`, `last_dir.txt`), `cache/` (производное: `agents.json` каталога
  семей, `agent-config/` — копия настроек OpenCode без плагина), `tools/` (тяжёлые установки: `whisper`; переопределяется `CREW_TOOLS_DIR` или `voice.dir`).
- **Папка проекта в репозитории `.crew-harness/`** с теми же именами: `config.json` (общее, в git), `local.json` (личное, абсолютные пути; только в проекте; строка `.crew-harness/local.json` в
  `.gitignore` репозитория), `modes/`, `presets/`, `prompts/`, `roles.json`. Задачи остаются в `doc/tasks/`.
- **Слои** (нижние перекрываются верхними): значения по умолчанию в коде → `<CREW_HOME>/config/config.json` → файл сервера (`serve <файл>`, `CREW_SERVER_CONFIG`; старый способ остаётся рабочим) →
  `.crew-harness/config.json` проекта → `.crew-harness/local.json` → `<CREW_HOME>/config/secrets.json` → переменные `CREW_*` (`CREW_SERVER_*` и `CREW_STT_*` остаются, `CREW_VOICE_*` — синонимы) →
  аргументы командной строки (`--set ключ=значение`, `--home`). Режимы работы (таблицы Алулы, `modes`): встроенные в сборку → `<CREW_HOME>/config/modes/` → `.crew-harness/modes/`; роли, наборы и
  подсказки — те же слои по именам.
- **Режимы.** Каталог режимов называется `modes`; код `route_*` и папка `doc/routes` **не переименовываются**. Настройка `routes_dir` остаётся и задаёт папку режимов явно; без неё режимы ищутся по
  слоям: `.crew-harness/modes`, `<CREW_HOME>/config/modes`, затем `doc/routes` рабочей папки хаба как последний слой (встраивание копии в сборку не сделано: Нова 0.1.0 не встраивает папки; продукт
  без `doc/routes` рядом с хабом работает с режимом без шагов, пока пользователь не положит свои файлы в слой).
- **Роли и наборы.** `roles.json` — роли процесса с описанием и правилами (`dev` — исполнитель, `dev_accept` — приёмщик, не автор, `plan`, `plan_accept` и остальные этапы плагина в краткой записи,
  `integrator`). Набор (`presets/<имя>.json`) — таблица `роль → {family, model, effort}`; активный набор — настройка `preset` (пользователь, проект или сессия). Независимый шаг режима берёт семью роли
  `dev_accept` из набора сессии; `route_reviewer_order` — запасной порядок, если набора нет, семья совпала с автором или не агент настроек. Встроенный набор `default`: исполнитель и приёмщик —
  разные семьи по порядку `route_reviewer_order`. Профили и наборы плагина OpenCode **не копируются**: набор продукта — своя таблица.
- **Секреты** не в `config.json`: только переменные окружения или `<CREW_HOME>/config/secrets.json` (вне репозитория, права только владельцу). Значения секретов нигде не выводятся (`describe()`,
  `config list`, журналы, ошибки).
- **Команды:** `crew-harness config list [--show-origin]` (значение и слой: default / user / server / project / local / secret / env / arg), `config get <ключ>`, `config set <ключ> <значение>
  [--project|--local]`, `crew-harness doctor` (пути, права, схема, старые расположения), проверка файлов по схеме с ошибкой «файл:строка: причина».
- **Миграция.** Старые расположения читаются: `data_dir` из файла или `CREW_SERVER_DATA_DIR` задаёт плоскую раскладку в той папке (старые стенды работают без правки, хаб пишет строку в журнал).
  `crew-harness migrate [--from <data_dir>] [--dry-run]` переносит плоскую раскладку в `data/`, `state/`, `cache/` с резервной копией малых файлов и отчётом; без команды ничего не двигается.
- **Ключ `stt` → `voice`.** В документации и интерфейсе — «голос» (`voice`); `stt` (speech-to-text, распознавание речи) принимается как запасное имя; переменные `CREW_STT_*` остаются, `CREW_VOICE_*` —
  синонимы.
- **Подсказки в файлах.** Тексты, которые хаб говорит агентам (описания инструментов, «Распознать задачи», напоминание перед сообщением, заметка об инструменте вопросов, служебные ходы), — файлы
  `prompts/<имя>.md` по слоям; встроенный текст в коде остаётся значением по умолчанию; хаб читает файл при каждом использовании; пустой или нечитаемый файл — запасной встроенный текст и строка в журнале.
- **Пороги в настройках:** `auto_extend_confidence` (`high` по умолчанию, `medium`, `off`), `task_scope` (`session`; значение `project` не добавляется без слова владельца), `context_drop_percent`,
  `route_keep_days`, `route_max_active`, `route_confirm_word`, `route_over_limit_word`, `wip_timeout_seconds`, `agent_start_timeout_seconds`.
- **Слово владельца** — «владелец, 2026-10-29» (чат оркестратора, «по рекомендации»; согласовано).
- **Механизм:** тесты `src/config/*_test.nv` (корень, слои и приоритет, `--show-origin`, роли и наборы, миграция, секреты не выводятся, подсказки по слоям), `src/server/settings_test.nv`,
  `src/server/front/front_settings_test.nv`; команда `crew-harness doctor` судит файлы по схеме.

## Что не делается

- Портативный режим (маркерная папка рядом с бинарником).
- Переименование кода `route_*` и папки `doc/routes`.
- Копирование профилей и наборов плагина OpenCode.
- Значение `task_scope: project`.

## Последствия

- Новый запуск без настроек пишет данные в `~/.crew-harness/data/sessions`, а не в `crew-data` рядом с рабочей папкой; старые стенды с явным `data_dir` не меняются.
- Файл сервера (`serve <файл>`) — слой между пользовательским и проектным; в нём по-прежнему допустим `data_dir`.
- Каталог с `.crew-harness/local.json` в проекте обязан игнорироваться git.
