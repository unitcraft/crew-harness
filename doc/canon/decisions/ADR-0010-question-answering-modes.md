# ADR-0010. Ответ на вопросы сессий по рекомендации: настройка проекта по типам вопросов, ворота за владельцем

## Контекст

Задача [007](../../tasks/007-question-answering/): на каждый вопрос сессии ждёт владелец, хотя у большинства вопросов есть
рекомендация сессии, и он отвечает «по рекомендации». Методика отдаёт ответ человеку: ворота В4, В6, В7 стоят на нём.
Владелец, 2026-10-08/09: нужна настройка, как отвечать — владелец, по рекомендациям, другой агент; ворота остаются за владельцем
при любом режиме; режим «другой агент» вынесен в отдельную задачу; при доле закрытых вопросов ниже трети — остановка приёмки с
решением владельца.

## Решение

- Ключи проекта `answer_mode` («тип → режим»; режимы `owner` и `recommendations`, по умолчанию `owner`) и `answer_max` (предел
  автоответов подряд, по умолчанию 3). Ключи ставит только человек (правка файла и коммит); `crew_config set` их отвергает.
- Вопрос объявляет `Тип:` (`requirements`, `plan`, `implementation`, `gate`), `Рекомендация:` и `Автоответ: допустим`; «?» в
  конце строки. Закрыт вопрос только при всех условиях сразу; сомнение, сбой разбора, тип `gate`, слова ворот в тексте, сессия
  приёмки и исчерпанный предел — владельцу.
- Запись ответа — файл журнала `answers/` и событие задачи; письмо автоответа служебное («не слово владельца»); отзыв — слово
  владельца; показ — раздел «Автоответы» в `/crew`.
- Общее правило (источник ответа записывается, решения из закрытого списка у человека, ответ по настройке не сбрасывает потолок
  заходов) записано в методике (`methodology.md`, раздел 18, «Кто отвечает на воротах»); здесь — настройка проекта.

## Последствия

- \+ Владельца не ждёт вопрос с рекомендацией, объявленным разрешением и без касания ворот; без ключей поведение прежнее.
- \+ Каждый автоответ записан и отзывается словом владельца.
- − Доля закрытых вопросов мала (по замеру 20 % при пороге в треть): слова «потому что …» в рекомендации часто сами называют
  ворота, и вопрос уходит владельцу — цена принята; приёмка останавливается по порогу.
- − Словарь слов ворот открытый, полноту не гарантирует; безопасность держат три слоя, а не словарь один.
- − Отступление от методики: рекомендация закрывает вопрос без слова человека; ручной цикл судится приёмкой, механизма нет.

## Границы

Не касается ворот владельца (утверждение спецификации и плана, пуши, слияния, удаления, перезапуск службы, живая проверка), ключа
`plan_approver`, режима `agent` (отдельная задача), расширения `endsWithQuestion`, правил пуша, слияния и удаления, показа хода,
профилей моделей. Плагин ключи `answer_*` не пишет.

Когда пересмотреть: доля закрытых вопросов остаётся ниже трети после двух задач; автоответ закрыл вопрос ворот (дефект
безопасности — сразу); понадобится режим `agent`.

## Дополнение 2026-10-19: формы встроенного вопросника

Источник — слова владельца в чате оркестратора, 2026-10-19: «answer_mode: recommendations работает только для текстовых вопросов определённого вида - я был уверен, что это автоответы на вопросники, это упущение, надо доделать»; «я же тебе говорил отвечать автоматически на вопросы по рекомендациям, почему так получались что какая-то вкладка затормозила на сутки процесс, как исключить такие тормоза без моего участия»; «по рекомендации, с учетом выше сказанного тут» (принят пакет: автоответ плагина на формы, правила методики «предположение вместо ожидания» и потолок доказательства). Задача [096](../../tasks/096-form-autoanswer/). Основное решение выше не переписывается; здесь то, что к нему добавлено.

**Что решено.**

- **Формы входят в режим `recommendations`.** Форма встроенного вопросника (инструмент `question`, запись в `forms/`, вид `question`, есть варианты) закрывается самим плагином, если одновременно: (а) объединённые настройки проекта (с блоком `local`) дают `recommendations` для типа вопроса; тип формы — `default`, а если в тексте есть `Тип:` — он; (б) среди вариантов ровно один помечен «(Recommended)» и это первый вариант; (в) вопрос не из закрытого списка; (г) не исчерпан `answer_max` подряд для сессии (ответ владельца и его слово во вкладке обнуляют счёт); (д) форма не заменена новой, не устарела, не отменена Esc и не в повторе потерянного вопроса, во вкладке идёт ход (форма на экране). Нет пометки, две пометки, пометка не у первого, больше одного вопроса в форме, множественный выбор, сбой разбора, неизвестный `Тип:`, цикл на вопросе (задача 078) — вопрос остаётся владельцу, без догадок.
- **Закрытый список — владельцу при любом режиме.** Тип `gate`; ворота методики (утверждение спецификации и плана, пуш в `main`, слияние, удаление и уборка, перезапуск службы, живая проверка, решение по результату и сдаче, потолок заходов и раундов); `tag`, выпуск, публикация, asset, pin; `force`, пароль, ключ, токен, учётные данные, оплата и деньги; слова «слово владельца»; изменение ключей `answer_*`; снятие запретов и границ задачи («разрешить … вне границ», расширение объёма); общие среды. Слова ищутся в вопросе (заголовок и текст) и в тексте рекомендованного варианта (подпись и описание). Список — таблица в коде (`CLOSED_LIST`, `form-auto.ts`) с тестом на каждую строку; расширяется строкой, без правки логики. Словарь открытый и ошибается в сторону владельца: лишнее срабатывание стоит одного вопроса владельцу, пропуск — дефект безопасности.
- **Задержка и отмена.** Ключ проекта `answer_delay_sec` (по умолчанию 60; `0` — сразу). Ответ ставится не раньше чем через столько секунд после появления формы; владелец успевает ответить сам, его ответ и его слово во вкладке главнее и снимают автоответ. Ключ ставит только человек, как `answer_mode`: `crew_config set` его отвергает, плагин ключи `answer_*` не пишет.
- **Снятая оговорка.** Исключение «сессия приёмки — владельцу» для форм отменено словом владельца (2026-10-19): вопросы приёмщиков и интеграторов отдельным правилом не закрыты, остаётся закрытый список. Для текстовых вопросов (основное решение) исключение не менялось: это отдельное решение владельца (см. open-questions в разборе задачи 096).
- **Доставка.** Через ответ снаружи окна (задача [059](../../tasks/059-answer-form-from-outside/), `owner-answer.ts`) с источником `plugin`: файл `answers/auto-<форма>.json` (один на форму — имя служит отметкой «один раз»), прерывание хода, служебное письмо «Ответ по настройке проекта (answer_mode: recommendations, тип …), не слово владельца», событие задачи, строка журнала. Запись об ответе делается до прерывания хода; шаги достраиваются после перезапуска без повторного прерывания и без второго письма (правила 13 и 34(е) методики: ни повтора, ни потери). Показ: счётчики `/crew` и боковой панели, сводка в `crew_doctor` (за сутки, последнее закрытие, сколько форм ушло владельцу и по какой причине: закрытый список, нет рекомендации, предел, сомнение, сбой доставки). Отзыв — слово владельца, как выше.
- **По умолчанию выключено.** Без `answer_mode` или с `owner` поведение прежнее.

**Последствия.**

- \+ Вопросы интеграторов, исполнителей и приёмщиков с рекомендацией не ждут владельца часами: форма закрывается через минуту, если владелец не успел сам.
- \+ Каждый автоответ записан (файл, событие задачи, строка журнала) и виден в `/crew`; причины ухода к владельцу тоже.
- − Цена безопасности: по замеру на ручных ответах 2026-10-18 (разбор задачи 096) закрытый список оставил бы владельцу заметную часть вопросов, часть из них — по слову из контекста, а не из решения; сужать список можно только по накопленным данным (в отметках `forms/auto/` записаны правило и слово) и словом владельца.
- − Отступление от методики шире прежнего: рекомендация закрывает вопрос без слова человека и там, где вопрос задан не по форме блока; держат четыре слоя (ключ человека, закрытый список, предел, задержка), механизма проверки смысла нет.

**Когда пересмотреть.** Автоответ закрыл вопрос закрытого списка (дефект безопасности — сразу); доля форм, ушедших владельцу по слову из контекста, остаётся высокой после недели работы (сузить правила по данным); понадобится режим `agent`.
