# ADR-0008. Профили моделей: файл проекта — единственный источник, окно — файлом в рабочем дереве задачи

## Контекст

Задача [003](../../tasks/003-model-profiles/): владелец переключает, на каких моделях идут разработка, приёмка, планирование и
приёмка плана, и вместе с моделью меняется окно контекста. Окно в OpenCode — свойство модели в папке, берётся из файлов настроек
от корня диска; сменить его из самого OpenCode плагин не может (конфиг накладывается после плагинов). Сначала правки команд окна
шли в промежуточный «слой» в ящике плагина с командами `save` и `reset`; 2026-10-09 владелец отменил слой: забытый слой молча
перекрывал набор из файла проекта (случай `claude-limits`).

## Варианты

1. **Менять окно в самом OpenCode.** − не работает: конфиг сильнее плагина.
2. **Файл окон в корне проекта.** − накрывает рукописные настройки и вложенный проект.
3. **Файл окон с пометкой плагина в рабочем дереве каждой задачи.** + цепочка настроек доходит ровно до сессии исполнителя;
   рукописное не затрагивается.

Для правок: слой в ящике (отменён) или правка рабочей копии файла проекта сразу (принято).

## Решение

- Три ключа `model_profiles`, `profile_sets`, `profile_set` в `.opencode/crew-harness.json` (обычный JSON) — единственный источник.
  Команды окна правят их одной атомарной записью в рабочую копию, без коммита и без слоя; правка, делающая включённый набор
  недопустимым, отклоняется целиком; не-JSON не перезаписывается; `save` и `reset` убраны.
- Окно — файл `.opencode/opencode.json` с пометкой плагина в рабочем дереве задачи; корень проекта и основные папки не трогаются;
  файл без пометки не перезаписывается; строка в `info/exclude`; файл снимается, когда набора нет, задача принята или отменена.
- Снимок последнего допустимого состояния в ящике плагина (`profiles/<проект>.snapshot.json`): работающие вкладки не падают, если
  недопустимое состояние пришло коммитом. Старые файлы слоя не читаются, плагин один раз называет найденный.
- Плагин пишет только: файл окон в дереве задачи, строку `info/exclude`, три ключа рабочей копии, свои файлы в ящике.

## Последствия

- \+ Смена набора и окна действует за секунды, без перезапуска и без коммита; один источник истины.
- − Окно профиля действует только на сессии в рабочих деревьях задач; приёмка идёт в основной папке и берёт окно из общих настроек.
- − Правка командой — правка рабочей копии, которую коммитит человек; откат — правкой файла или `git restore`; профили читаются из
  рабочей копии, остальные ключи — из закоммиченного файла.
- − Плагин читает цепочку настроек OpenCode сам; `info/exclude` затрагивает все рабочие деревья репозитория.

## Границы

Касается плагина `opencode-plugin/`. Пороги сжатия не меняются. Подробности формата и команд — README плагина и спецификация
задачи 003.

Когда пересмотреть: OpenCode начнёт принимать окно от плагина поверх конфига, либо сессии приёмки начнут идти в рабочем дереве.
