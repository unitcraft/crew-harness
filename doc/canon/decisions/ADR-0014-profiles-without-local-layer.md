# ADR-0014. Профили без локального слоя: команды окна правят файл проекта прямо

## Контекст

[ADR-0008](ADR-0008-model-profiles-layer-and-window-files.md) выбрал для правок профилей слой записей в ящике плагина
(`profiles/<проект>.layer.json`) поверх закоммиченного файла проекта: правка действует сразу, без коммита, а `save` переносит
записи слоя в рабочую копию файла. На практике слой оказался тихим вторым источником истины. Случай: в проекте
`claude-limits` файл проекта называл набор `profile_set=codex-light`, а забытое локальное переключение
`/crew-sets use codex` перекрыло его — действовал набор, которого в файле нет, и ни одна команда об этом не напоминала,
пока не открыть `check`.

Слово владельца: «хочу полностью отключить слои — сделай быстрой задачей» (владелец, 2026-10-09, чат).

## Варианты

1. **Оставить слой, добавить напоминание** (в таблице, в уведомлении окна, срок давности записи). + ничего не ломается.
   − два источника остаются; напоминание ловит забытое, но не мешает слою перекрывать файл.
2. **Убрать слой: команды окна правят файл проекта сразу и атомарно.** + один источник истины; нечего сохранять и
   сбрасывать; забыть нечего. − правка попадает в рабочую копию файла без коммита: пока человек не закоммитил, она живёт
   только в рабочей копии; `use` и правки больше нельзя «взять назад» одной командой.
3. **Убрать слой и писать только через коммит.** + история правок в git. − «включить набор» перестаёт действовать сразу:
   команда окна не коммитит (плагин не коммитит) — ради этого слой и заводился.

## Решение

Вариант 2.

- Команды окна `/crew-sets use|set|unset|new|rename|delete` и `/crew-profiles set|new|rename|delete` правят три ключа файла
  проекта (`model_profiles`, `profile_sets`, `profile_set`) в рабочей копии папки настроек — одной атомарной записью, без
  коммита и без промежуточного слоя. Проверки допустимости прежние: правка, делающая включённый набор недопустимым или
  создающая висячую ссылку, отклоняется целиком, файл не меняется. Файл, который не разбирается как JSON, не перезаписывается:
  правка отказана.
- Действующие данные профилей — эти три ключа рабочей копии файла (нет файла в рабочей копии — закоммиченный файл; прежняя
  форма опций — найденный файл). Остальные ключи проекта читаются, как раньше, из закоммиченного файла. Имя включённого набора
  меняет человек: `use` или правка файла; `crew_config set` по-прежнему отказывает на `profile_set`.
- Команды `save` и `reset` убраны. Набранные в окне, они получают короткий ответ «команды больше нет, сохранять и сбрасывать
  нечего»; в меню их нет. `show`, `check` и таблицы остались.
- Снимок последнего допустимого состояния (`profiles/<проект>.snapshot.json`) остаётся без изменений: он нужен, чтобы
  работающие вкладки не падали, если недопустимое состояние пришло не через команды (коммит убрал профиль).
- Существующие `*.layer.json` не читаются и не применяются как данные и не переносятся в файл. Один раз за жизнь службы
  (первый проход) и при каждом `check` плагин называет найденный файл: «слой отключён, его записи не применяются; файл
  можно удалить». Чужие файлы он не удаляет.

## Последствия

- \+ Один источник истины: что видно в файле, то и действует; случай `claude-limits` невозможен.
- \+ Нечего забывать и не нужно решать, сохранять ли: в таблице и в `check` нет разделов о несохранённых правках.
- − Правка командой — это правка рабочей копии файла проекта, которую человек коммитит сам (плагин не коммитит); в чужой
  ветке настроек правка живёт в этой ветке. Незакоммиченное в рабочей копии видно в `git status`, но по умолчанию его
  никто не напоминает закоммитить.
- − Команда больше не откатывается своим глаголом: вернуть прежнее значение можно правкой файла или `git restore`;
  прежние `reset`/`save` для этого не годятся.
- − Данные профилей читаются из рабочей копии, остальные настройки — из закоммиченного файла: пока правка не закоммичена,
  у профилей и у остальных ключей разные источники. Это то же поведение, что у записи `crew_config set`, только для профилей
  действующее сразу.
- − Записи забытого старого слоя пропадают из действия без переноса: тот, кто на них опирался, видит один раз сообщение и
  вносит нужное в файл сам.

## Границы

Касается команд окна и чтения профилей в `opencode-plugin/`. Файл окон в рабочем дереве задачи, реестр окон и снимок из
[ADR-0008](ADR-0008-model-profiles-layer-and-window-files.md) остаются в силе; заменён только его раздел про слой
правок (вариант 2 «слой записей» и команды `save`/`reset`). Формат ключей не менялся.

Когда пересмотреть: если правки командами окна начнут теряться из-за того, что рабочая копия папки настроек живёт в
ветке, из которой их не коммитят, — тогда нужна команда или напоминание «закоммить».
