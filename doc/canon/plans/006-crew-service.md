## Правила написания на Go (чтобы перенос на Нову был почти построчным)

Нова (спецификация https://github.com/nv-lang/nova): статические типы, объявления `name type`, суммы-типы и `match`, `Option` вместо null,
`Result`/`Fail` вместо исключений, алгебраические эффекты с обработчиками, волокна + `Channel` + `select` без
`async`, сборщик мусора, нативная сборка.

- **Эффекты — интерфейсы.** Каждый эффект (`Fs`, `Proc`, `Clock`, `Store`, `Net`, `Log`) — интерфейс Go, функция
  получает его параметром; тестовые подделки — будущие обработчики эффектов Новы. Никаких глобальных `os.*`, `time.Now`
  вне реализаций эффектов.
- **Суммы-типы** — запечатанный интерфейс с методом-меткой и `switch` по типу; без `nil` как значения «нет» — `Option`
  своей структурой или явный флаг.
- **Ошибки** — значения (`error`), `panic` только для «не может быть». Ошибки с вариантами — суммы-типы.
- **Конкурентность** — горутины, каналы, `select`, `context` для отмены; без общих изменяемых карт без замка.
- **Данные** — простые записи и JSON-файлы; без рефлексии, кодогенерации и «магии» фреймворков; обобщения — по
  необходимости. Зависимости — только то, что есть или будет в Нове: JSON, файлы, процессы, TCP/HTTP, PTY.
- **Логика — чистые функции** над состоянием (как `status.ts`/`plans.ts` плагина); ввод-вывод — по краям.

## Этапы

### Этап 0 — порядок в репозитории (приоритет P0)

1. Плагин — в `opencode-plugin/` (`git mv`, история сохраняется); корневой README — о продукте; ссылки README плагина
   на `../doc`, `../LICENSE`.
2. Провайдер ищет MCP плагина и в `../crew-harness/opencode-plugin/mcp.ts`, и по прежнему пути (переходный период).
3. Переключение (по слову владельца): вливание, пути в `opencode.jsonc` и `cli.json`, перезапуск сервиса, `/crew-doctor`.

Готово, когда: плагин грузится из `opencode-plugin/`, весь `npm test` зелёный, `/crew-doctor` — «всё в порядке».

### Этап 1 — замеры (P0, до кода сервиса)

1. Лимиты подписок: 10, затем 20 фоновых агентов Claude Code (Sonnet, Opus) — как тают 5-часовое и недельное окна;
   то же для Codex и Kimi на 5 агентах.
2. Фоновый режим Claude Code (`claude --bg`, `claude agents --json`) на Windows: 20–30 сессий — память, стабильность,
   создание деревьев.
3. Сверка с официальной документацией: запуск без окна, MCP, хуки, приём картинок у Codex CLI и Kimi Code.
4. Час на Agent Orchestrator: что взять (доска, драйверы агентов, вид терминала), что не годится.

Готово, когда: записка `doc/research/` с числами и решением «на что опираемся в этапах 2–4».

### Этап 2 — сервис координации (`service/`, P1)

Перенос правил из `opencode-plugin/core.ts` по смыслу, с тестами: задачи (очередь, приоритеты, места), письма и
вопросы с ответом, обязательства, приёмщик и шаги приёмки, замок вливания, очередь машины и наблюдения, планы
(перепроверка, согласование, шаги), уборка и хвосты. Хранилище — тот же ящик на диске (сервис и плагин видят одни
задачи на время переезда). Агентам — MCP `crew` с теми же инструментами, что сейчас.

Готово, когда: тесты правил зелёные; MCP сервиса отвечает вкладке Claude Code так же, как MCP плагина.

### Этап 3 — драйверы агентов (P1)

Общий вид драйвера: запустить агента в дереве задачи с ролью и письмом, продолжить сессию, узнать «работает / ждёт /
закончил», остановить, передать картинку. Первыми — Claude Code, Codex CLI, Kimi Code. Правила — хуками агента, где они
есть (`Stop` — не закончить ход с открытым обязательством; перед командой — тяжёлое только через очередь), иначе —
напоминания, как в плагине.

Готово, когда: одна и та же задача проходит «исполнитель → приёмщик → вливание» с исполнителем на каждом из трёх.

### Этап 4 — пульт в браузере (`web/`, P1)

Страница, которую отдаёт сервис (`localhost`): доска «работает / ждёт вас / на приёмке / готово к вливанию»; карточка
задачи — история, шаги приёмки, письма; живой терминал агента (`xterm.js` + PTY сервиса); чат с агентом по его
машинному потоку; вставка и перетаскивание картинок; согласование планов; ответ на вопрос. Страница — HTML от сервера и
немного скриптов (при переносе сервиса на Нову её не трогать).

Готово, когда: владелец ведёт день работы claude-limits из браузера без окна OpenCode.

### Этап 5 — переезд проектов (P2, по слову владельца)

Сначала claude-limits, затем nova; плагин OpenCode на это время работает рядом, данные общие.

### Этап 6 — перенос сервиса на Нову (P3)

Когда в Нове будут HTTP-сервер, PTY и всё, на что опирается сервис; по модулю, тесты — те же сценарии.
