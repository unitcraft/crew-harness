# Канон CrewHarness

**Входной файл Канона** — одно окно: отсюда ссылками подтягиваются все его части, как файлы методики ссылаются друг на
друга. Кто работает с проектом — человек, агент или раннер — начинает отсюда; ссылку на этот файл достаточно знать,
чтобы найти всё остальное.

**Канон** — методика [unitcraft/ai-dev-methodology](https://github.com/unitcraft/ai-dev-methodology/tree/744e0af34dc9c7f9d4db2a91e312ee170c6642fd) плюс
дополнения и изменения проекта (владелец, 2026-10-07: «наша методика это и есть ai-dev-methodology + наши доп правила
и изменения = Канон»); «слой канона проекта» в терминах методики. Канон — единственный источник истины: код
расходится с Каноном — это находка, а не повод тихо поправить одно под другое; спор с Каноном — только новым решением
в [decisions/](decisions/README.md).

## Состав

| Часть Канона | Где |
|---|---|
| Методика — основа | [unitcraft/ai-dev-methodology](https://github.com/unitcraft/ai-dev-methodology/tree/744e0af34dc9c7f9d4db2a91e312ee170c6642fd), по ссылке, без копии; стейт-машины методики (спецификация, движок, протокол вызова, машины раннера) — [индекс](https://github.com/unitcraft/ai-dev-methodology/blob/744e0af34dc9c7f9d4db2a91e312ee170c6642fd/state-machines/README.md), файлы в Канон не копируются; язык Алула (спецификация, образцы, таблица слов, проверки) с версии 0.3.2 пакета `alula` — не в методике, а в [nv-lang/nova-alula](https://github.com/nv-lang/nova-alula/tree/main/spec), папки `spec/`, `tools/`, `docs/` |
| Отличия и дополнения к методике | [process.md](process.md) |
| Правила репозитория и машины | [AGENTS.md](../../AGENTS.md) — в корне, потому что агенты читают его оттуда при старте |
| Решения (ADR) | [decisions/](decisions/README.md) |
| Документация частей | README корня и частей (`opencode-plugin/README.md` и т.д.) |

Не Канон: задачи и всё в их папках — спецификации, планы, проверки, журналы ([doc/tasks/](../tasks/README.md)),
черновики (статус «черновик»), открытые вопросы ([doc/open-questions.md](../open-questions.md), правила — в
[process.md](process.md), «Открытые вопросы»), исследования ([doc/research/](../research/)), архив ([doc/archive/](../archive/plans/README.md)).
Новая часть Канона появляется здесь тем же коммитом, что её заводит.

Выбор версии и переход активных задач — [process.md](process.md), «Версия и переход»;
основание — [ADR-0012](decisions/ADR-0012-canon-methodology-version.md).

## Параметры для раннера

Особенности проекта, которыми его цикл отличается от методики, — здесь, а не в настройках программы: в продукте у
каждого проекта свой Канон и свой входной файл. Пояснения и причины — в [process.md](process.md).

| Параметр | Значение в этом проекте |
|---|---|
| Папка задачи | `doc/tasks/NNN-<slug>/` в репозитории; номер папки — номер задачи; заводит её плагин (`crew_spawn`) или скрипт `scripts/task-number.mjs` на ветке задачи ([process.md](process.md), «Задача, сессия, подзадача»); коммитится в основную ветку на воротах (утверждение spec, plan, сдача) |
| Задание задачи | `task/message.md` по одному образцу ([process.md](process.md), «Задание task/message.md»); плагин собирает его из полей `crew_spawn` |
| Версия методики | основа Канона — `unitcraft/ai-dev-methodology @ 744e0af34dc9c7f9d4db2a91e312ee170c6642fd` (коммит от 2026-10-19; прежняя — `a449bd2e`, история — [ADR-0012](decisions/ADR-0012-canon-methodology-version.md)); pin конкретной задачи — в её `log.md`; выбор и явный переход — [process.md](process.md), «Версия и переход»; копий основы нет |
| План задачи | `plan.md` в папке задачи, как в методике; у эпика в разделе «План» строка `Тип: эпик`, рядом с `Ветка:` |
| Ворота, которые не останавливают | В2 (профиль по умолчанию), В3 (заход засчитывается как записан) |
| Вопросы владельцу | каждый — с рекомендацией |
| Классификатор решений, судья споров, перевод входов | выкл (методика, раздел 18; раннера пока нет) |
| Размер задачи | число REQ: S — до 10, M — до 25, L — до 50, больше — предложение разбить; глубина проверки — по большему из объёма и риска (это маршрут задачи, [`task-sessions.md`](https://github.com/unitcraft/ai-dev-methodology/blob/744e0af34dc9c7f9d4db2a91e312ee170c6642fd/task-sessions.md), «Правила») |
| Маршрут задачи (опытная норма) | параметры проекта задаёт ключ `route_defaults` в `.opencode/crew-harness.json` (плагин, задача 092); в репозитории ключа нет — действуют значения методики ([`task-runner.md`](https://github.com/unitcraft/ai-dev-methodology/blob/744e0af34dc9c7f9d4db2a91e312ee170c6642fd/task-runner.md), «Параметры маршрута»); раннера и ворот В14 нет, цикл ведёт оркестратор вручную ([process.md](process.md), «Опытные нормы методики») |
| Малый маршрут (опытная норма, впереди pin — [ADR-0013](decisions/ADR-0013-proportionality-ahead-of-pin.md)) | механизм в плагине (задача 191): `route: "small"` — без цикла и приёмщика, папка из трёх строк, метки 10-минутной нормы (`crew_task contour`), тестовый контур `scripts/test-contour.ps1`/`.sh`; входные фразы владельца распознаёт оркестратор, плагин их не разбирает ([process.md](process.md), «Опытные нормы методики») |
| Вратарь и усиленный вратарь (опытная норма) | выключены: `исполнитель_повышенного_внимания` — «человек» (умолчание методики), `усиленный_вратарь` — «нет»; разрешения владельца отдавать дорогие ворота агенту для проекта не записано; ключей этих настроек в `.opencode/crew-harness.json` нет |
