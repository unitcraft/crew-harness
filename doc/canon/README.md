# Канон CrewHarness

**Входной файл Канона** — одно окно: отсюда ссылками подтягиваются все его части, как файлы методики ссылаются друг на
друга. Кто работает с проектом — человек, агент или раннер — начинает отсюда; ссылку на этот файл достаточно знать,
чтобы найти всё остальное.

**Канон** — методика [unitcraft/ai-dev-methodology](https://github.com/unitcraft/ai-dev-methodology/tree/a449bd2e218e04384d1d42e0c1bffe892495e298) плюс
дополнения и изменения проекта (владелец, 2026-10-07: «наша методика это и есть ai-dev-methodology + наши доп правила
и изменения = Канон»); «слой канона проекта» в терминах методики. Канон — единственный источник истины: код
расходится с Каноном — это находка, а не повод тихо поправить одно под другое; спор с Каноном — только новым решением
в [decisions/](decisions/README.md).

## Состав

| Часть Канона | Где |
|---|---|
| Методика — основа | [unitcraft/ai-dev-methodology](https://github.com/unitcraft/ai-dev-methodology/tree/a449bd2e218e04384d1d42e0c1bffe892495e298), по ссылке, без копии |
| Отличия и дополнения к методике | [process.md](process.md) |
| Правила репозитория и машины | [AGENTS.md](../../AGENTS.md) — в корне, потому что агенты читают его оттуда при старте |
| Решения (ADR) | [decisions/](decisions/README.md) |
| Документация частей | README корня и частей (`opencode-plugin/README.md` и т.д.) |

Не Канон: задачи и всё в их папках — спецификации, планы, проверки, журналы ([doc/tasks/](../tasks/README.md)),
черновики (статус «черновик»), открытые вопросы ([doc/open-questions.md](../open-questions.md), правила — в
[process.md](process.md), «Открытые вопросы»), исследования ([doc/research/](../research/)), архив ([doc/archive/](../archive/plans/README.md)).
Новая часть Канона появляется здесь тем же коммитом, что её заводит.

Выбор версии и переход активных задач — [process.md](process.md), «Версия и переход»;
основание — [ADR-0012](decisions/ADR-0012-canon-methodology-version.md).

## Параметры для раннера

Особенности проекта, которыми его цикл отличается от методики, — здесь, а не в настройках программы: в продукте у
каждого проекта свой Канон и свой входной файл. Пояснения и причины — в [process.md](process.md).

| Параметр | Значение в этом проекте |
|---|---|
| Папка задачи | `doc/tasks/NNN-<slug>/` в репозитории; номер папки — номер задачи; заводит её плагин (`crew_spawn`) или скрипт `scripts/task-number.mjs` на ветке задачи ([process.md](process.md), «Задача, сессия, подзадача»); коммитится в основную ветку на воротах (утверждение spec, plan, сдача) |
| Задание задачи | `task/message.md` по одному образцу ([process.md](process.md), «Задание task/message.md»); плагин собирает его из полей `crew_spawn` |
| Версия методики | основа Канона — `unitcraft/ai-dev-methodology @ a449bd2e218e04384d1d42e0c1bffe892495e298`; pin конкретной задачи — в её `log.md`; выбор и явный переход — [process.md](process.md), «Версия и переход»; копий основы нет |
| План задачи | `plan.md` в папке задачи, как в методике; у эпика в разделе «План» строка `Тип: эпик`, рядом с `Ветка:` |
| Ворота, которые не останавливают | В2 (профиль по умолчанию), В3 (заход засчитывается как записан) |
| Вопросы владельцу | каждый — с рекомендацией |
| Классификатор решений, судья споров, перевод входов | выкл (методика, раздел 18; раннера пока нет) |
| Размер задачи | число REQ: S — до 10, M — до 25, L — до 50, больше — предложение разбить; глубина проверки — по большему из объёма и риска |
