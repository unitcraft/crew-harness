# План 003 — долгое ожидание, которое переживает конец хода (`peer_watch`)

**Статус:** ЗАКРЫТ 2026-10-05.
**Где остановились:** сделано, проверено и работает у владельца (интегратор и воркеры nova ждут через `peer_watch`). Вторая половина — в провайдере
claude-code ([план 002 провайдера](https://github.com/unitcraft/opencode-claude-code-provider/blob/main/doc/plans/002-background-tasks.md)).
**Проверено:** `test/peers-watch.test.mjs`, `peers-mcp` (11 инструментов), весь `npm test`; живая проверка в песочнице.

## Цель

Окно может ждать долгое (гейт на час, сборку), не держа ход и не теряя побудку. Случай владельца 2026-10-05:
интегратор поставил ожидание вердикта гейта в фон Claude Code (`run_in_background`) и закончил ход; во вкладке
claude-code фон гибнет с концом хода (замер провайдера), гейт кончился зелёным в 12:33 — окно стояло, пока владелец
не написал.

## Решения

| № | Решение | Кто | Дата |
|---|---------|-----|------|
| 1 | Ждёт плагин (сервер OpenCode), а не окно: MCP-сервер окна claude-code живёт один ход, поэтому инструмент только кладёт задание, запускает его проход плагина | Claude, по «надо исправить» владельца | 2026-10-05 |
| 2 | Команда идёт откреплённо в Git Bash (не bash WSL из System32), код выхода — в файл: наблюдение переживает перезапуск сервиса; пропал процесс без кода — письмо «оборвано» | Claude | 2026-10-05 |
| 3 | Имя `peer_watch`: `peer_wait` уже занят (ответ на вопрос в том же ходе) | Claude | 2026-10-05 |

## Как устроено

`peer_watch {command, note?, minutes?}` (без `command` — список наблюдений вкладки) кладёт
`watches/<id>.req.json`. Проход плагина (раз в секунду) захватывает его переименованием, запускает
`timeout <минуты> bash -c <command> > <id>.out; echo $? > <id>.exit` откреплённо и пишет `<id>.json`. Появился
`<id>.exit` — письмо вкладке от плагина (будит, «не отвечай»): пометка, код (124 — истекло время), длительность,
хвост вывода (30 строк, до 3000 знаков), путь к полному выводу. Записи завершённых удаляются через сутки. Предел —
по умолчанию 120 мин, до 720.

## Приёмка

- Тест: команда со `sleep`, кавычкой и `exit 3` → одно письмо, код 3, вывод в хвосте; второго письма нет; процесс
  без кода → «ОБОРВАНО»; пределы минут; текст для 124; хвост — последние 30 строк; Git Bash не из System32.
- Живая (песочница, claude-code/haiku, окно-заглушка): ход вызвал `peer_watch {command: "sleep 20; echo watched-ok"}`
  и закончился «waiting»; через 20 с плагин разбудил вкладку письмом, ответ — «watched-ok». **Пройдено 2026-10-05.**
