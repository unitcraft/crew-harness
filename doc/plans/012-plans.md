## Отметки

| Уровень | Значки и слова |
|---|---|
| План (строка `Статус:`) | 🔴 ОТКРЫТ · 🟡 В РАБОТЕ · ✅ ЗАКРЫТ дата (фазы; коммиты) · ❌ ОТМЕНЁН дата (причина) |
| Фаза, шаг (в заголовке) | ⏳ В РАБОТЕ · ✅ СДЕЛАНО дата, коммит `hash`; не начат — без отметки |
| Критерий приёмки | ✅ ВЫПОЛНЕНО — доказательство · ⬜ не выполнен |
| Открытый вопрос | ❔ без ответа · ✅ ответ, дата, источник |

## Форма плана (шаблон, `plan_template`)

```
# План N — <название>

**Статус:** 🔴 ОТКРЫТ
**Источник:** <исходная задача: слова владельца, заказ, № строки реестра>
**Зависимости:** <что должно быть до; родитель для подплана>
**Перепроверка:** <раунды пишет плагин>

## Зачем
<с замером; что его опровергло бы>
## Что уже есть
<проверено командой — что делать не надо>
## Режим выполнения
Без упрощений: ❔ — вопрос владельцу
## Фазы
### Ф.1 — <название> [P1] [после: —]
#### Ф.1.1 — <шаг> [P2] [после: —] [где: <модули/файлы>]
Что: <одна задача — один ответ на «когда готово»>
**Приёмка:**
- ⬜ <что запустить> → <что зелёное>; доказательство: <строка вывода>; краснота: <как сломать → красное>
## Не делаем
## Открытые вопросы
- ❔ <вопрос> · адресат: <кто> · умолчание: <…> · срок: <…> · **Блокирует:** <Ф.N / всё / —>
## Решения владельца
| № | решение | дата |
```

## Критерии приёмки плана

Машиной (плагин, по тексту файла — `planProblems`):
1. Шапка: `Статус:`, `Источник:`, `Зависимости:`.
2. Разделы: «Зачем», «Что уже есть», «Режим выполнения», «Фазы», «Не делаем», «Открытые вопросы».
3. Хотя бы одна фаза и шаг; у каждого шага «Что:» и блок «Приёмка» хотя бы с одним критерием.
4. Каждый открытый вопрос — с адресатом, умолчанием, сроком и «Блокирует»; вопросов нет — строка «Открытых вопросов нет, проверено <дата>».
5. Ссылки `после:` указывают на существующие фазы и шаги; нет циклов.

Проверяющим (шаги приёмки задачи-плана — `plan_acceptance`):
- А. против исходной задачи: (А1) цель плана совпадает с источником; (А2) покрытие — таблица «требование → шаг → критерий» без пустых клеток; (А3) допущения проверены командой или помечены «найдено чтением»; очевидная альтернатива названа и отвергнута; (А4) лишнего нет — вне задачи вынесено в «Не делаем»; (А5) «Что уже есть» проверено командой; (А6) режим выполнения спрошен у владельца.
- Б. правильность составления: (Б1) приёмка каждого шага машинная — что запустить, что зелёное, строка-доказательство, проба красноты — или «приёмка глазами, потому что …»; (Б2) инструмент критерия проверен на «до» и «после»; (Б3) шаг — одна задача; (Б4) зависимости явные, держащие шаги помечены GATE; (Б5) пути, стражи, скрипты, названные в плане, существуют; (Б6) нет оценок сроков и повторов абзацев.

## Перепроверка

Раунд проводит новая сессия: не автор плана и не прошлый проверяющий. Проверяющий идёт по А1–А6 и Б1–Б6 (`check`) и
закрывает раунд вердиктом `peer_task {action: "round", n, blocking, significant, cosmetic, notes}`.

Градация — по тому, что придётся менять при исправлении:

| Градация | Что меняет исправление | Примеры |
|---|---|---|
| **Блокирующее** | план не решает задачу или ведёт к неверному результату | требование без шага; неверное допущение; критерий, который не может покраснеть; невыполнимый шаг; выход за границы |
| **Существенное** | меняет содержание плана: шаг, критерий, порядок, зависимость, границы, вопрос | неполный критерий; пропущен крайний случай; неявная зависимость; шаг больше одной задачи; нет пробы красноты |
| **Косметическое** | только текст: смысл плана не меняется | формулировка, опечатка, оформление, порядок изложения |

Правила: (1) сомнение — старшая градация; (2) всё, что меняет хоть один шаг, критерий, порядок или границу, —
не ниже существенного; (3) следующий раунд перепроверяет и градации прошлого: косметическое, оказавшееся
содержательным, — замечание того же раунда. Есть блокирующие или существенные — план автору на доработку, затем новый
раунд. **План готов к согласованию, когда два раунда подряд выявили только косметические замечания** (их автор правит
без нового раунда). После `plan_rounds_max` (4) раундов без готовности — владельцу последние замечания. Раунд пишется в
журнал задачи и в шапку плана строкой `Перепроверка: раунд N, дата — блокирующих 0, существенных 0, косметических 2`.

## Согласование и постановка задач

Готовый план — владельцу: «ждёт вас» и команда окна `/plans`: список планов на согласовании → выбор → «согласовать без
упрощений» / «согласовать, упрощения — как в плане» / «вернуть с замечаниями». Ответ — запись плагина (с датой);
проверяющий вписывает его в план («Режим выполнения», «Решения владельца») и вливает план. После вливания плагин читает
фазы и шаги из файла в целевой ветке и ставит задачи: цель — «Что», критерии — «Приёмка», границы — «Не делаем» плана и
режим выполнения, приоритет — шага, иначе фазы. Шаг стартует, когда закрыто всё из его `после:` и не идёт шаг с
пересекающимся `где:`; внутри лимитов (`spawn_limits`, `inflight_limit`). Шаг-подплан ставит задачу-план. Приёмка
задачи-шага требует отметку «✅ СДЕЛАНО» шага в файле плана в целевой ветке — проверяет плагин при `accept`.

## Тяжёлые прогоны

Тяжёлый прогон — команда, которая надолго занимает машину: полный гейт, полная сборка, полный прогон тестов,
бенчмарки. Проект называет их `heavy_commands` (подстроки); команда не из списка — тяжёлая, если занимает все ядра или
идёт дольше 2 минут. `peer_watch` с командой из списка сам ставит её в очередь машины; запуск мимо очереди отмечает
приёмщик (шаг приёмки проекта).
