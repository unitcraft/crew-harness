# Транспорт писем между машинами (исследование, не в плагине)

> Исследовательский материал, не Канон и не код плагина. Прототип написан 2026-10-06…07 и не доделан; в плагине
> CrewHarness (`opencode-plugin/`) его нет с задачи 046 (2026-10-15, вопрос владельца: «это же исследование было
> незаконченное, почему оно живёт в общей папке наравне с кодом плагина?»). Плагин отсюда ничего не импортирует —
> это проверяет `opencode-plugin/test/crew-no-research.test.mjs`; файл `remote.json` плагин не читает.

## Что это

Попытка дать вкладкам OpenCode писать проектам на других машинах (например, исполнителю на VPS) тем же
`crew_send`, что и соседям по машине. Устройство:

- `remote.ts` — **мост**: один процесс на машину (замок `remote/bridge.lock` в каталоге данных плагина) отправляет
  исходящие из `remote/outbox/` и раскладывает входящие по ящикам, как обычные письма. Маршрут — по файлу машины
  `<данные>/crew-harness/remote.json` (не в репозитории): какие проекты живут на какой машине. Приём — по `inbound`
  проекта; сессия получает письма только с машины, которой писала сама; неотправленное — в `remote/failed/`,
  отправителю — служебное письмо.
- `tailnet.ts` — **Tailscale** (рекомендованный вариант): прямой HTTP между мостами внутри сети Tailscale.
  Отправителя называет сеть (`tailscale whois`), общий секрет не нужен, у каждой машины свои права (`may_write`).
  Отказ возвращается отправителю сразу; недоступная машина — повтор с паузой 1, 2, 4… до 60 с в течение 24 ч.
  Мост слушает только адрес Tailscale (`tailscale ip -4`).
- `ntfy.ts` — **ntfy**: общий зашифрованный канал на [ntfy](https://ntfy.sh) для машин вне одной сети. Из общего
  секрета выводятся имя темы и ключ AES-256-GCM; письмо режется на части под предел 4096 байт; подделка и повтор
  отсекаются. Все машины канала равны, отправитель не проверяется.
- `github.ts` — транспорт через комментарии issue на GitHub; оставлен для сравнения, мост его не использует.

Настройки, которые мост понимал (для справки):

```json
{ "node": "home", "transport": "tailnet",
  "nodes": { "vps-1": { "projects": ["site"], "may_write": ["nova.integrator"] } } }
```

```json
{ "node": "home", "secret": "...", "projects": ["site"] }
```

(`secret` — один и тот же на всех машинах канала; новый давала функция `ntfySecret()` из `ntfy.ts`.)

## Что исследовано и измерено

- Самопроверки (папка `test/`): поддельные серверы ntfy и GitHub в памяти, два настоящих HTTP-моста на
  `127.0.0.1` с поддельным `whois`, мост с поддельным транспортом. На 2026-10-15 все четыре зелёные из этой папки.
- Один живой замер (2026-10-07, `test/ntfy-latency.mjs` на ntfy.sh): 5 из 5 писем дошли, медиана около 2 с,
  максимум 2,7 с; почти всё время — запрос публикации. Замер GitHub (`test/gh-latency.mjs`) не запускался.
- Ограничения внешних служб, учтённые в коде: у анонимного ntfy.sh лимит запросов и сообщений в день (накопившиеся
  письма уходят одним конвертом, 429 — пауза); у GitHub — вторичный лимит на создание комментариев, опрос с
  `If-None-Match` (304 не тратит лимит).

## Что работает

В самопроверках: маршрут по `remote.json`, очередь `outbox`, один мост на машину, `inbound` и `may_write`, ответы
только с машины, которой писали, возврат отказов отправителю (Tailscale); шифрование, части, отсев подделок и
повторов, подписка с продолжением после обрыва (ntfy); 304, пачки, пропуск своих комментариев, 429 (GitHub).

## Что не доделано

- Ни разу не работало внутри живого OpenCode, ни между двумя настоящими машинами, ни в настоящей сети Tailscale:
  разбор `tailscale whois --json` (`Node.Name`) написан по памяти, `tailscale ip -4` на Windows и Linux не проверен.
- Курсор ntfy живёт в памяти: после перезапуска мост читает канал с начала, письма, отправленные, пока на машине не
  было процесса OpenCode, теряются (ntfy.sh держит их около 12 ч).
- У ntfy нет личности отправителя: один секрет на всех, отказ остаётся в журнале получателя, отправитель видит
  «отправлено», даже если письмо никто не взял.
- Очередь Tailscale — в памяти: повтор переживает паузу, но не перезапуск моста (письмо остаётся в `outbox` и уходит
  снова, получатель отсекает повтор по id).
- Между машинами ходят только письма: нет `tier`, рассылки `project.all`, задач и заказов (`crew_task`, `crew_spawn`),
  `crew_watch` и состояния; `crew_list` не видит вкладок других машин.
- `remote.json` правится руками (`crew_config` его не знает), сломанный файл только пишется в журнал.
- Код очереди и пауз повторён в `github.ts`, `ntfy.ts` и `tailnet.ts`; проверки типов нет (Node срезает аннотации).

Что намечалось дальше (2026-10-07): проверка в настоящей сети Tailscale (письмо между этой машиной и VPS, ACL,
оставляющий исполнителю только порт моста); заказы между машинами (`crew_task order` интегратору проекта на другой
машине, код ходит через git); OpenCode без окон на VPS (`opencode serve`) — что нужно исполнителю без вкладки;
курсор ntfy в файле, `crew_list` с другими машинами, `remote.json` через `crew_config`, общий модуль очереди.

## Как запустить вручную

Из этой папки (`doc/research/remote-transport/`), Node 24 и новее, по одному файлу:

```sh
node test/crew-ntfy.test.mjs
node test/crew-github.test.mjs
node test/crew-tailnet.test.mjs
node test/crew-remote.test.mjs     # каталог данных — временный (XDG_DATA_HOME), настоящий ящик не трогается
```

Живые замеры обращаются к настоящим службам и публикуют сообщения:

```sh
node test/ntfy-latency.mjs [count=5] [server=https://ntfy.sh]          # новая случайная тема на каждый запуск
node test/gh-latency.mjs <owner/repo> <issue> [count=5] [pollMs=1000]  # пишет комментарии в issue
```

`remote.ts` берёт каталог данных из `opencode-plugin/paths.ts` (связь только в эту сторону: исследование читает
плагин, плагин исследование — нет). В `npm test` плагина эти файлы не входят.
