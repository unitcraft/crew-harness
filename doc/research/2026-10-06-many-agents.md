# Много параллельных агентов на Claude: альтернативы OpenCode (исследование 2026-10-06)

Повод: сервер OpenCode задыхается примерно на 8 одновременных задачах (один процесс, один главный поток, база
SQLite 5 ГБ; замер плагина: задержки потока 10–40 с при свободном плагине). Владелец спросил, что есть взамен.
Обозначения: **[V]** — проверено по источнику (ссылка), **[I]** — вывод, **[?]** — неточно или быстро меняется.

## Главное

- Сменить OpenCode на другую оболочку того же типа не поможет: такие оболочки держат все сессии в одном процессе.
  Масштабируется «один агент — отдельный процесс Claude Code в своём worktree, координация — в лёгком внешнем
  сервисе». **[I]**
- Симптом известен в трекере OpenCode: при ~8 параллельных сессиях — `SQLITE_BUSY`, база растёт без очистки.
  **[V]** <https://github.com/anomalyco/opencode/issues/21215>, <https://github.com/anomalyco/opencode/issues/16777>
- При 20–100 агентах раньше софта упрёмся в **лимиты подписки**: облачные, локальные сессии и SDK делят одни лимиты
  аккаунта (скользящее 5-часовое окно и недельный лимит; числа Anthropic не публикует). **[V]**
  <https://code.claude.com/docs/en/agent-view>, <https://code.claude.com/docs/en/claude-code-on-the-web>
- Подписка разрешена в **немодифицированном** бинарнике Claude Code, в том числе когда его запускает другая
  программа; сторонним оболочкам с собственным входом подпиской доступ закрыт (январь–февраль 2026). Правила для Agent
  SDK менялись в 2026 не раз (перевод на отдельный кредит приостановлен). **[V/?]**
  <https://code.claude.com/docs/en/legal-and-compliance>,
  <https://support.claude.com/en/articles/15036540-use-the-claude-agent-sdk-with-your-claude-plan>

## Сторонние оркестраторы нескольких Claude Code

Запускают официальный `claude` в worktree — совместимы с подпиской **[I]**.

| Инструмент | Что делает | Windows | Лицензия | Ревью / приёмка |
|---|---|---|---|---|
| Agent Orchestrator (ComposioHQ) | десктоп с демоном: worker = worktree + ветка + PR; канбан Working / Needs You / In Review / Ready to Merge; CI и ревью возвращаются агенту **[V]** <https://github.com/ComposioHQ/agent-orchestrator> | да | Apache-2.0 | ближе всего к нашему; приёмщика и замок вливания проверить или достроить **[?]** |
| Emdash | десктоп: параллельные агенты в worktree, задачи из трекеров, PR, SSH **[V]** <https://emdash.com/docs> | да | open source | диффы, PR; приёмщика нет |
| Nimbalyst (наследник Crystal) | канбан сессий, worktree **[V]** <https://github.com/nimbalyst/nimbalyst> | да | MIT | построчное принятие правок |
| Cline Kanban | карточка = терминал + worktree, зависимости между карточками с автостартом **[V]** <https://github.com/cline/kanban> | вероятно **[?]** | Apache-2.0 | цепочки задач; приёмщика нет |
| Claude Squad | TUI на tmux | нет **[V]** | AGPL-3.0 | нет |
| Conductor (conductor.build) | десктоп с параллельными агентами | только macOS **[V]** | проприетарный | ревью и вливание |
| Bernstein | детерминированный планировщик, worktree, «janitor» проверяет тесты и линт до вливания **[V]** <https://www.augmentcode.com/tools/open-source-agent-orchestrators> | да (Python) | Apache-2.0 | janitor ≈ наш чек-лист приёмки |

Облачные платформы (Cursor Cloud Agents, GitHub Copilot coding agent, OpenAI Codex cloud, Google Jules, Devin,
Factory) подписку Claude не используют: оплата их собственная. Годятся как дополнительная ёмкость за отдельные
деньги, не как замена **[I]**. Open-source оболочки (Crush, Goose, Aider, Kilo) рассчитаны на одну сессию в
процессе и не масштабируются лучше OpenCode **[I]**.

## Рекомендация

1. **Claude Code agent view (`claude --bg`) + свой тонкий сервис координации** (план 006). Официальный бинарник,
   подписка без серых зон, Windows, процесс на агента. Логика плагина — задачи, письма, приёмщик, чек-листы, замок
   вливания, планы, очередь машины — уходит в небольшой сервис с MCP для агентов; запуск задач — `claude --bg`,
   статусы — `claude agents --json`, проверки — хуками (`Stop`, `PreToolUse`). OpenCode остаётся пультом или
   заменяется панелью agent view.
2. **Agent Orchestrator** как готовая основа (альтернатива на Windows — Emdash): почти наш процесс без своего UI;
   недостающее — в его плагинные слоты. Масштаб 50+ не задокументирован **[?]**.
3. **Облачные сессии и Projects** — «выпуск пара» для задач, которым не нужна наша машина; тот же лимит подписки.

## Что попробовать первым

1. Измерить лимиты: 10, затем 20 `claude --bg` на Sonnet и Opus — как быстро тают 5-часовое и недельное окно.
2. Agent view под нагрузкой на Windows: 20–30 фоновых сессий в одном репозитории — память на процесс, стабильность
   супервизора, скорость создания worktree.
3. Прототип сервиса координации: MCP «задачи / письма / замок вливания / очередь машины» и хук `Stop`, не дающий
   завершить задачу без закрытого чек-листа; перенести одну цепочку «план → задача → приёмщик → вливание».
4. Час на Agent Orchestrator и Emdash: можно ли навесить приёмщика и замок вливания.
5. 3–5 изолированных задач в `claude --cloud` — качество PR и расход лимита.

Быстро меняется: правила подписки для Agent SDK и сторонних приложений, статус research preview у agent view и
Projects, тарифы облачных платформ.
