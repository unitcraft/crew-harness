# Правила работы в репозитории CrewHarness

Для ИИ-агентов и людей, которые правят этот репозиторий. Что за продукт — [README.md](README.md); как идёт работа —
[doc/process/](doc/process/README.md); почему так устроено — [doc/decisions/](doc/decisions/README.md).
Каждое правило ниже куплено ошибкой или прямо задано владельцем; у правила указано, что ломается без него.

## Источник истины и порядок работы

1. **Работа — задачами по методике** ([ADR-0001](doc/decisions/0001-work-by-methodology.md)): одна задача — одна
   папка `doc/tasks/NNN-<slug>/`, цикл сессий разбор → план → реализация → сдача; утверждает владелец. Без
   утверждённых `spec.md` и `plan.md` код задачи не пишется. *Без этого:* работа шла пятнадцатью «планами», из которых
   самостоятельных было три, и проверял её тот же, кто писал.
2. **Решение — раньше кода.** Смена технологии, контракта, формата данных на диске, топологии или отступление от
   этих правил — новое решение в `doc/decisions/` (MADR: варианты, выбор, негативные последствия, границы). Принятое
   решение не переписывается: дрейф — датированной вставкой, замена — новым решением со ссылкой.
3. **Слово владельца записывается с датой и источником** («владелец, 2026-10-07»), а не пересказом: иначе через
   неделю не отличить его решение от догадки исполнителя.
4. **Статус — в первой строке документа** (задачи, плана, решения), сводных таблиц статусов нет; документ обновляется
   тем же коммитом, что и работа.

## Git

5. Изменения — в отдельном рабочем дереве на своей ветке; в `main` — только `git merge --ff-only`. *Почему:* рабочая
   копия `main` у владельца — живая, её файлы загружает работающий сервис (п. 12).
6. Коммиты: сообщение по-английски; `git commit -s`; файлы — по имени (`--only` или `git add -- <файлы>`), никогда
   `git add -A` / `git add .` — в дерево попадают чужие и временные файлы; без трейлеров соавторства и упоминаний
   инструментов.
7. Никогда не `push --force`. Пуш — только после зелёных тестов (п. 9).
8. Ветки и рабочие деревья после слияния удаляются; пустые папки деревьев — тоже.

## Тесты и машина

9. Перед пушем — весь набор тестов затронутой части (`opencode-plugin`: `npm test`, 37 файлов). Пуш с красным
   набором — нарушение, даже «на минутку».
10. **Машина владельца нагружена** (гейты проектов, десятки сессий агентов): весь набор тестов одним прогоном
    подвешивает живой сервис, и окна перезапускают его сами (2026-10-07, три перезапуска за восемь минут, даже с
    низким приоритетом). Под нагрузкой — тесты по одному с паузами; во время разработки — только затронутые.
11. Тяжёлые команды проектов (гейты, сборки, полные прогоны) — только через очередь машины, не напрямую.

## Живая система

12. Рабочая копия `main` плагина (`opencode-plugin/`) подгружается работающим сервисом OpenCode на лету: правка
    файлов в ней — правка живой системы. Править — только в рабочем дереве (п. 5).
13. Сервис не перезапускает агент — только владелец. Изменение, которому нужен перезапуск (пути, переименования,
    переносы, код провайдера), готовится целиком, владелец предупреждается заранее, переключение — по его слову
    «переключай». Перед перезапуском — предупредить интегратора проекта и дождаться «готово к перезапуску».
14. Папку, в которой стоит процесс (наблюдение, вкладка сессии, слежка сервиса за файлами), Windows не удаляет и не
    переносит: сначала освободить (закрыть вкладки, остановить сервис), потом переносить.
15. Не должно быть ручных команд там, где их может сделать программа: владелец не набирает команды за агента.

## Публичность

16. Репозиторий публичный ([ADR-0006](doc/decisions/0006-public-repository.md)): ни локальных путей машины
    владельца, ни имён приватных репозиториев и проектов, ни учётных данных — в коде, документах, папках задач и
    сообщениях коммитов. Примеры путей — общие (`C:/work/...`). Язык Нова — только https://github.com/nv-lang/nova.
    Перед коммитом: поиск по `D:/`, `D:\`, `C:\Users\` в изменённых файлах. *Почему:* история git не чистится без
    силового пуша, а он запрещён (п. 7).

## Чужие репозитории

17. Репозитории других проектов (nova и др.) — только читать. Правки в них делает их интегратор или владелец; от нас
    — текст задания или письма.

## Общение с владельцем

18. Отвечать владельцу по-русски; коротко; сначала ответ, потом подробности. Сделанное и проверенное — без оговорок;
    не сделанное — так и сказать.
19. Перед переименованием, переносом и любым действием, которое меняет живую систему, — предупредить и дождаться
    согласия.
