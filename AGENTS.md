# Правила работы в репозитории CrewHarness

## Канон

**Канон** — всё, где записаны правила разработки этого проекта (владелец, 2026-10-07); «слой канона проекта» в
терминах методики. Состав:

| Часть Канона | Где |
|---|---|
| Методика — основа | [unitcraft/ai-dev-methodology](https://github.com/unitcraft/ai-dev-methodology/tree/main), по ссылке, без копии |
| Отличия и дополнения к методике | [doc/process/](doc/process/README.md) |
| Правила репозитория и машины | этот файл |
| Решения (ADR) | [doc/decisions/](doc/decisions/README.md) |
| Утверждённые спецификации и планы | `spec.md` задач в [doc/tasks/](doc/tasks/README.md), планы в [doc/plans/](doc/plans/README.md) |
| Документация частей | README корня и частей (`opencode-plugin/README.md` и т.д.) |

Канон — единственный источник истины: код расходится с Каноном — это находка, а не повод тихо поправить одно под
другое; спор с Каноном — только новым решением в `doc/decisions/`. Черновики (статус «черновик»), проверки по заходам,
журналы задач и исследования (`doc/research/`) Каноном не являются.

Для ИИ-агентов и людей, которые правят этот репозиторий. **Основа — методика
[unitcraft/ai-dev-methodology](https://github.com/unitcraft/ai-dev-methodology/tree/main)**; её правила здесь не
пересказываются. Чем проект от неё отличается — [doc/process/](doc/process/README.md); решения —
[doc/decisions/](doc/decisions/README.md). Ниже — только правила этого репозитория и этой машины; у каждого сказано,
что без него ломается.

## Порядок работы

1. **Задачи — в `doc/tasks/NNN-<slug>/`**, цикл сессий методики; **планы — в `doc/plans/`** (`NNN`, подпланы `NNN.M`,
   номера без пропусков): утверждённый `plan.md` задачи переносится туда. Два места для одного плана — две правды.
2. **Слово владельца записывается с датой и источником** («владелец, 2026-10-07»), а не пересказом: иначе через
   неделю не отличить его решение от догадки исполнителя.

## Git

3. Изменения — в отдельном рабочем дереве на своей ветке; в `main` — только `git merge --ff-only`. *Почему:* рабочая
   копия `main` у владельца — живая, её файлы загружает работающий сервис (п. 11).
4. Коммиты: сообщение по-английски; `git commit -s`; файлы — по имени (`--only` или `git add -- <файлы>`), никогда
   `git add -A` / `git add .` — в коммит попадают чужие и временные файлы; без трейлеров соавторства и упоминаний
   инструментов.
5. Никогда не `push --force`. Пуш — только после зелёных тестов (п. 8).
6. Ветки и рабочие деревья после слияния удаляются, включая пустые папки деревьев.

## Тесты и машина

7. Тесты частей: `opencode-plugin` — `npm test` (37 файлов) из `opencode-plugin/`.
8. Перед пушем — весь набор тестов затронутой части. Пуш с красным набором — нарушение, даже «на минутку».
9. **Машина владельца нагружена** (гейты проектов, десятки сессий агентов): весь набор одним прогоном подвешивает
   живой сервис, и окна перезапускают его сами (2026-10-07: три перезапуска за восемь минут, даже с низким
   приоритетом). Под нагрузкой — тесты по одному с паузами; во время разработки — только затронутые.
10. Тяжёлые команды проектов (гейты, сборки, полные прогоны) — только через очередь машины, не напрямую.

## Живая система

11. Рабочая копия `main` (`opencode-plugin/`) подгружается работающим сервисом OpenCode на лету: правка файлов в ней —
    правка живой системы. Править — только в рабочем дереве (п. 3).
12. Сервис перезапускает только владелец. Изменение, которому нужен перезапуск (пути, переименования, переносы, код
    провайдера), готовится целиком; владелец предупреждается заранее; переключение — по его слову «переключай».
    Перед перезапуском — предупредить интегратора проекта и дождаться «готово к перезапуску».
13. Папку, в которой стоит процесс (наблюдение, вкладка сессии, слежка сервиса за файлами), Windows не удаляет и не
    переносит: сначала освободить (закрыть вкладки, остановить сервис), потом трогать.
14. Не должно быть ручных команд там, где их может сделать программа: владелец не набирает команды за агента.

## Публичность

15. Репозиторий публичный ([ADR-0006](doc/decisions/0006-public-repository.md)): ни локальных путей машины
    владельца, ни имён приватных репозиториев и проектов, ни учётных данных — в коде, документах, папках задач и
    сообщениях коммитов. Примеры путей — общие (`C:/work/...`). Язык Нова — только https://github.com/nv-lang/nova.
    Перед коммитом: поиск по `D:/`, `D:\`, `C:\Users\` в изменённых файлах. *Почему:* историю без силового пуша не
    вычистить, а он запрещён (п. 5).

## Чужие репозитории

16. Репозитории других проектов (nova и др.) — только читать. Правки в них делает их интегратор или владелец; от нас
    — текст задания или письма.

## Общение с владельцем

17. По-русски; коротко; сначала ответ, потом подробности. Сделанное и проверенное — без оговорок; не сделанное — так
    и сказать.
18. Перед переименованием, переносом и любым действием, которое меняет живую систему, — предупредить и дождаться
    согласия.
